本轮只增加可选诊断工具、合成夹具及报告，没有修改正式 API、schema、前端交互或任务协议。

embedding 服务故意指向不可用的 loopback 端口，未配置账户模型连接；检索/索引覆盖的是降级路径。

## 实测结果

冷进入为新浏览器上下文，API、浏览器进程与数据库并非全冷启动。
元素就绪耗时包含 Playwright 自动等待，是观察上界；不能用它减 API 时间推断渲染耗时。

| 操作 | S | L | 样本与口径 |
|---|---:|---:|---|
| 写作页冷进入 | 369 / 567 | 398 / 476 | 各 5 次，编辑器可定位且可见 |
| 对象库冷进入 | 266 / 292 | 872 / 877 | 各 5 次，产品默认热点模式 |
| RP 冷进入 | 260 / 265 | 260 / 266 | 各 5 次，只加载当前阅读窗口 |
| 切换章节 | 30 / 70 | 36 / 83 | 各 30 次，3 批，检查目标正文前缀 |

### 大段替换

连续输入过程中没有重现与大段替换相同级别的停顿；替换为 30,000 字时，多个独立运行捕获到约 0.5～0.7 秒主线程长任务。
重型采样单独保存在 `profile-S-2026-09-07T07-03-34-035Z-trace.json` 与同名 cpuprofile。
该采样 5 次 30,000 字替换的操作中位数约 564ms，最大约 618ms。
trace 可见耗时主要落在输入事件和布局相关区段；CPU profile 大量时间归为浏览器 native/program，不能归给某个 Vue 函数。
trace 的嵌套事件时长不能直接相加成总时间。

随后完成同采集条件、不启用重型 profiler 的配对对照，各 5 次：

| 替换操作 | 应用编辑器中位数 / 最大值 | 同尺寸、字体的原生 textarea 中位数 / 最大值 |
|---|---:|---:|
| 3,000 字 | 59.7 / 61.2ms | 36.1 / 51.4ms |
| 30,000 字 | 530.4 / 560.5ms | 278.8 / 293.2ms |

来源为 `native-control-S-2026-09-07T07-56-46-620Z.jsonl`。原生控件也发生明显停顿，应用环境还有额外开销；
两组差值不是某个业务函数的 CPU 时间，不把自动化 `fill` 等同于真实粘贴或中文输入法。
优先补测真实粘贴/IME 和编辑器更新链，不据此移除本地备份或更换编辑器。

### 对象热点查询

初次独立 ASGI 计时保留 public auth，每组 10 次（`query-timings-initial.json`）；与浏览器 HTTP 基线分开：

| 数据/模式 | 请求中位数 | SQL driver 耗时中位数 | SQL 次数 |
|---|---:|---:|---:|
| S 普通 | 16.3 | 6.3 | 6 |
| S 热点 | 32.2 | 12.5 | 9 |
| L 普通 | 23.0 | 12.9 | 6 |
| L 热点 | 103.8 | 31.1 | 9 |

证据支持“热点模式有规模相关开销”，本组没有出现按对象数增加的查询次数。
请求减 SQL 的剩余量包含连接获取、commit、调度、Python 处理和响应序列化，尚未精确分段。
下一步在 [热点列表实现](../../backend/modules/world/services/core/entity_service.py) 的轻量候选、活动统计、排名和当前页装配处各加短期计时；SQL 证据指向具体语句后才做 EXPLAIN。
不能仅凭全项目排名的静态代码就宣称它是全部瓶颈。

补查公共别名计数：S/L 各 10 次，S 请求/SQL 中位数约 15.2/5.8ms、5 次 SQL；
L 约 129.5/103.0ms、8 次 SQL。代码 [别名扫描](../../backend/modules/world/services/core/entity_alias_service.py)
确认即使 API 只请求 `limit=1`，也会按每批 1,000 行扫描完整对象，再在 Python 侧筛选和计算 total。
这也解释了两档 SQL 次数不同，不能笼统说整个对象库没有随规模增加的查询。

对捕获到的 L 档别名 SELECT，在独立只读事务、5 秒 statement timeout 下执行 EXPLAIN ANALYZE：
扫描 3,000 行、估计也是 3,000 行；按 importance/name/id 排序后返回一批 1,000 行。
执行约 23.9ms，全部为 buffer hit，无磁盘读块或临时文件溢出。对应采样中该 driver 调用最高约 130.9ms；
执行计划另一次运行不含相同的数据取回成本，二者不能简单相减当作网络延迟。
证据保存在 `query-timings-expanded.json` 和 `alias-query-plan.json`。
下一步优先验证别名所需字段的精简投影/计数、重复排序及首屏公共计数的等待依赖；保留完整 total、状态和权限语义，不先增加缓存或索引。
