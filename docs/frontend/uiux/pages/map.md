# 统一地图 UI/UX 执行规范

## 1. 定位与首次进入

地图服务管理长篇世界资料的作者，以同一目录、主画布和详情区组织空间示意、底图与地点配图。
产品价值是假设：用首次地图完成时间、保存/修正次数、再次进入和作者反馈验证，不以截图或测试
通过替代真实用户验证。读者能力仅为作者端章首预览，未接入公开分享或私人互动旅程。

空态主操作为“新建地图”，无需图片或文本模型连接；已有地图后，新建降为次级操作，编辑时
“保存地图”是主操作。区域和城市可以建立纯空间图，原有世界、街区、街道和室内图片继续浏览。
图片设置与历史渐进展开，不占用首屏主要画布；正式地图视图不持续展开已经结束的图片进度。

## 2. 一套目录与画布

目录以地图节点为唯一身份根。节点拥有空间版本、已采用图片或有效后代时均可展示；
无自身画面的祖先作为目录，纯空间城市图也可跳转。移出图片不隐藏仍有空间版本的地图。

同一画布区域可查看结构或图片参考；审核新图片时进入图片参考，采用后回到结构图。
底图放在结构图元下方，区域填色保留透明度；地点配图在选中地点的详情区展示。
图片候选、旧图比较、采用、拒绝、移出和恢复仍使用原有审查语义。

地点、路线、河流和区域使用不同图形；按区域、线条、地点的顺序绘制。地点标签保持屏幕上的
可读字号，并在有限候选位置中避让。图元支持键盘选择，地点扩大命中范围；不能仅依靠颜色、
悬停或拖拽识别与操作。地图声明“不按比例”，不把行程换算成距离或显示虚假比例尺。

## 3. 空间编辑与生成

作者可以加入已有地点或手动添加标记，绘制点、折线与区域轮廓，调整控制点、锁定位置、
撤销/重做、进入城市子图、添加受限空间关系并检查冲突。提供点击放置与方向按钮作为拖拽替代。
世界资料入口携带当前项目和对象目标；地图名称/标注编辑不改写世界对象。
纯空间地图也提供标题、目录与顺序管理；绑定世界地点的地图不在此改名，已有空间版本的节点仅能
在区域与城市范围内调整层级。专注看图收起工作台标题、编辑、阅读预览与图片设置，压缩定位和缩放，
让 1280×720 屏幕的主要区域用于画布；保留退出、未保存反馈、保存、键盘选择、地点说明、子图和配图。
方向键与拖拽不会在浏览模式下改动位置，撤销与历史恢复等改图入口在退出专注后使用。
查找只匹配当前显示的图元，阅读预览不得借搜索展示隐藏地点；未定位内容明确提示待定位。

空间生成先选最多 20 个已采用地点并打开一次 Context 确认，再由文本模型按每批 5 个提取关系。
生成中可继续编辑，结果作为当前节点的候选显示；任务完成不替换已保存地图。
查看候选为只读比较，采用需重验原确认与基准版本，采用后可以继续调整。
差异列表覆盖地点、关系、图片配置和标注绑定，允许切换对照已保存版；查看或对照不覆盖本机编辑。
缺少连接、资料不足、部分批次失败和来源失效在当前操作区说明，手动制图始终可用。

补全保留已有位置和手工控制点。矛盾、未定位及来源变化作为待核对项呈现，能够定位到有关图元。
自动布局无解时不声称已经解决；几何交叉不自动生成桥梁、路口或新的连通关系。

## 4. 图片统一与校准

作者在当前节点选择已采用图片作为底图或地点配图。配图选择后立即预览缩略图，已关联图片的选项
显示地点与用途，帮助区分同名图片；选择本身不保存或修改地图。底图以三个不共线的已定位地点为锚点，
通过点击图片或数值替代操作标记对应位置；服务端计算变换并先预览，保存后才成为当前配置。
校准仅调整图片展示，不移动地点；对齐三个锚点不证明整图具有精确地理关系。
透视图或难以对齐的图片可以继续作为地点配图。

空间变动后底图标记“待复核”并退出叠加，图片仍保留；不自动付费重画。
重新校准是明确动作。图片移出后关闭相应展示层，不删除地图结构。

旧标注不按名称自动推断身份。作者可逐项绑定与解除绑定；绑定后名称、位置与跳转来自空间图元。
未校准或已失效的图片不展示由旧坐标猜测出的绑定热点，未绑定标注仍作为图片参考保存。

“添加地图画面”绑定当前已保存的节点与版本，程序生成结构参考图后进入既有图片工作流。
结构参考图计入八张总限额，不能挤掉作者显式选择的参考图。图片无烘焙文字要求、私有读取、
Prompt 检查、上传、局部编辑以及重复计费确认继续沿用原规则。

## 5. 阅读预览

“进入第 N 章时”表示章首，不猜测同章揭示先后。预览只使用服务端返回的图元和图片白名单，
不渲染作者候选、冲突原文或隐藏统计。已展示地点保持位置，未公开的地点及依赖它们的线条和
轮廓保守留白；设置地图展示章节不能覆盖世界对象与原文的可见性限制。

图片默认仅作者可见。作者确认整张图片可在某章展示时绑定内容 hash；新图片不能继承旧确认。
预览图片请求再次校验同一章节和版本，不复用作者完整底图后遮盖标签。条件不满足时仅显示
安全的空间示意。

## 6. 保存、离开与恢复

“未保存”“本机备份”和“已保存到服务端”分别显示，仅真实写入成功后声称保存或备份成功。
本机备份按账号、项目、节点保存基准版本；账户变化后不能把旧账户编辑重新写入新账户范围。
损坏备份不覆盖服务器版本，恢复旧基准备份时必须先比较版本。

服务端返回 409 时保留当前输入，允许查看服务器版、使用服务器版，或经作者明确比较后以当前
编辑创建新版；不自动覆盖或合并。服务器和本机备份同时失败时阻止静默离开，提供下载备份路径，
但不把发起下载说成已完成保存。刷新、切图与离开均保留保护路径。

晚到布局/校准预览不得覆盖请求之后的新编辑，图片任务也不能推进空间 head。
任务从服务端状态恢复；地图节点焦点使用既有路由 query commit 保存，不额外重挂整个工作台。

## 7. 验证

- 后端空间、来源、图片与版本：World 的 map_structure 与 map_atlas 测试。
- 真实 PostgreSQL：并发 CAS、不可变内容、同节点 head、项目/图片任务删除竞态。
- Vue：候选、校准失效、双重保存失败、版本比较、晚到响应、阅读白名单和键盘替代。
- Chromium：合成区域/城市地图、真实图片上传采用与校准、阅读图片读取、刷新恢复、390px 无页面溢出。
- 同时检查浅/深色语义 token、标签可读性、首屏画布面积和键盘焦点。
- 付费模型与真实生图效果通过显式实测入口验证，不由固定 PNG 或 mock 结果代替。
