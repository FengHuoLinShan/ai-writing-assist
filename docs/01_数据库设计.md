# AI 长篇小说结构化创作引擎：数据库设计 v2.0（实际实现）

## 1. 数据库设计原则

- **候选与正史分离**：AI 生成内容默认先进入 candidate / proposal；用户明确启动的自动流水线可直接写 canonical，但必须保留来源、可编辑/可回滚元数据。
- **业务删除优先状态化**：常规业务对象使用 status 字段枚举（draft / candidate / canonical / deprecated / ignored / conflicted / pending / processing / done / failed）；项目永久删除和 demo 开发库重建可硬删除。
- **Demo 阶段不保迁移历史**：schema 重构时允许直接删除并重建开发数据库，不要求为旧 demo 数据编写保留数据的迁移路径。
- **Prompt 合并，数据拆分**：生成阶段可以合并，入库按对象类型存储。
- **JSONB 存弹性字段**：只把形状仍不稳定的扩展信息放 JSONB。当前 Scene 卡以独立 `scenes` 表为权威来源；`chapter_cards.scene_cards` 只作历史兼容/冗余上下文。

## 2. 技术选型

- PostgreSQL 17（Docker 部署）
- pgvector：向量检索、对象去重、RAG embedding
- pg_trgm：名称相似、别名相似、重复对象检测
- JSONB + GIN：灵活字段和数组查询
- SQLAlchemy async（生产） / SQLite 内存引擎（测试）
- Pydantic v2 schema 校验

## 3. 完整表清单（活跃业务表 + 系统表。geo / review / timeline 模块已移除）

### 3.1 projects（小说项目）

```sql
CREATE TABLE projects (
    id UUID PRIMARY KEY,
    title VARCHAR(255) NOT NULL,
    genre VARCHAR(64),
    tone VARCHAR(64),
    language VARCHAR(16) DEFAULT 'zh' NOT NULL,
    target_length VARCHAR(32),
    current_stage VARCHAR(32),
    default_reveal_policy VARCHAR(32) DEFAULT 'author_safe' NOT NULL,
    settings JSONB DEFAULT '{}' NOT NULL,       -- 小说配置 JSON
    deleted_at TIMESTAMP,                       -- 软删除时间，NULL 表示未删除
    created_at TIMESTAMP DEFAULT now(),
    updated_at TIMESTAMP DEFAULT now()
);
```

### 3.2 core_entities（共享核心实体表 — 取代 world_entities + entity_aliases）

```sql
CREATE TABLE core_entities (
    id UUID PRIMARY KEY,
    novel_id UUID NOT NULL REFERENCES projects(id),
    entity_type VARCHAR(64) NOT NULL,     -- character/location/faction/item/concept/event/creature/skill/rule/other
    name VARCHAR(255) NOT NULL,
    aliases JSONB DEFAULT '[]' NOT NULL,   -- 别名列表 [{alias, type}]
    summary TEXT,
    public_info TEXT,                      -- 公众已知信息
    hidden_truth TEXT,                     -- 仅作者视角
    content_json JSONB DEFAULT '{}',
    importance FLOAT DEFAULT 0.5 NOT NULL,
    importance_level VARCHAR(16) DEFAULT 'normal' NOT NULL,  -- core/important/normal/temporary
    reveal_level VARCHAR(16) DEFAULT 'author_only' NOT NULL, -- author_only/hinted/revealed/fully_known
    status VARCHAR(16) DEFAULT 'draft' NOT NULL,
    embedding_text TEXT,
    embedding vector(768),                  -- bge-base-zh-v1.5: 768 维
    search_text TEXT GENERATED ALWAYS AS (  -- 虚拟生成列：name + JSONB aliases 聚合，pg_trgm GIN 索引
        name || ' ' || COALESCE(content_json->>'aliases', '')
    ) STORED,
    pinyin_string VARCHAR(1024),            -- name 的拼音字符串缓存（去重音似特征）
    created_by VARCHAR(64),
    approved_by VARCHAR(64),
    created_at TIMESTAMP DEFAULT now(),
    updated_at TIMESTAMP DEFAULT now()
);
```

### 3.3 entity_relations（对象间关系）

取代旧 `relationships` 表。source_id / target_id 为强 UUID FK → `core_entities.id`。

```sql
CREATE TABLE entity_relations (
    id UUID PRIMARY KEY,
    novel_id UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    source_id UUID NOT NULL REFERENCES core_entities(id) ON DELETE CASCADE,
    target_id UUID NOT NULL REFERENCES core_entities(id) ON DELETE CASCADE,
    relation_type VARCHAR(64) NOT NULL,
    description TEXT,
    strength FLOAT DEFAULT 0.5 NOT NULL,
    source_chapter_id UUID REFERENCES imported_chapters(id) ON DELETE SET NULL,
    caused_by_event_id UUID REFERENCES core_entities(id) ON DELETE SET NULL,
    quote TEXT,
    status VARCHAR(16) DEFAULT 'canonical' NOT NULL,
    created_at TIMESTAMP DEFAULT now(),
    updated_at TIMESTAMP DEFAULT now()
);

CREATE INDEX idx_entity_relations_novel_id ON entity_relations(novel_id);
CREATE INDEX idx_entity_relations_source_id ON entity_relations(source_id);
CREATE INDEX idx_entity_relations_target_id ON entity_relations(target_id);
```

### 3.4 entity_aliases — 已移除

`entity_aliases` 表已在 v2.0 重构中移除。别名统一存储于 `core_entities.content_json.aliases` JSONB 字段，通过 CoreEntityService.add_alias/remove_alias 管理。

### 3.5 entity_candidates — 已废弃

`entity_candidates` 表已在当前版本中废弃。当前候选对象直接复用 `core_entities.status = 'candidate'` 表达；深度导入实体抽取会写入带 `content_json._meta.auto_ingested = true` 的候选实体，后续可由用户提升为 canonical。

如需了解历史 schema，参见 `docs/archive/`。

## 4. 与原始设计的主要差异

| 项目 | 原始设计 | 实际实现 |
|------|---------|---------|
| import_records | 无此表 | 新增，用于小说文件导入跟踪 |
| character_knowledge | 使用 UUID 存储 target_id | 使用 String(36) 存储 UUID hex |
| relationships | source_id 使用 UUID 类型 | 使用 String(36) 通用引用 |
| core_entities (v2.0) | world_entities 表 + entity_aliases 表 | 合并为 core_entities 表，aliases 用 JSONB 内联 |
| characters (v2.0) | 独立 id PK + name/aliases/status/world_entity_id | entity_id PK+FK → core_entities.id，仅存人物特有字段；由 world 模块管理 |
| geo / review / timeline 模块 | 独立表和模块 | 已移除。geo 表/ review_reports / timeline_events 不再使用 |
| entity_aliases | 独立表，FK → world_entities.id | 已移除，别名存 core_entities.content_json.aliases JSONB |
| scenes 表 | 无，场景卡存 chapter_cards.scene_cards JSONB | R10 新增独立 `scenes` 表，最小叙事单元独立管理 |
| memory_events / memory_snapshots | 单体 memory_records | R10 新增事件溯源模型，替代旧的 memory_records 单体设计 |
| delta_log | 无此表 | R10 新增，结构化字段变更的 before/after 审计日志 |
| text_archive | 无此表 | R12 新增，长文本字段变更历史，与 DeltaLog 配合实现版本回滚 |
| projects.settings | 无此列 | 新增 JSONB 配置字段 |
| projects.deleted_at | 无此列 | 新增软删除时间戳 |
| core_entities.pinyin_string | 无此列 | 新增拼音字符串缓存（去重音似特征）|
| core_entities.entity_type | VARCHAR(32) | 改为 VARCHAR(64) 支持更长的类型名 |
| core_entities.embedding | vector(1024) | 改为 vector(768)（bge-base-zh-v1.5） |
| 测试引擎 | 仅提及 | 完整实现：SQLite 内存替代 pgvector（Text 存 JSON 序列化向量）|
