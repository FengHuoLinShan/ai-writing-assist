# Assistant 项目助手

Assistant 每个后台 run 在 worker 领取时冻结统一 AI 运行信封；Agent/研究/回顾重试与恢复只
累计该 run，私有预算、step 回执和供应商摘要不进入公开 Assistant wire。

架构依据为 ADR-0023。Assistant 整合注册的领域能力，不复制领域数据和采用权限。
模块协议与表职责见 `backend/modules/assistant/README.md`。

## 所有权

通用讨论从 World 移交 Assistant，保留历史物理表名、ID、消息、成果与 checkpoint 引用。
World 提供来源/成果/工作区校验 port；RP 历史、回顾和 attempt 不移交。
新增运行、操作批次、提醒和持续授权记录均按 owner + novel_id 隔离。

公开入口 `/api/assistant` 包含会话/回合、恢复/停止、批次确认/显式重试和提醒处置。

引导流程（ADR-0032）入口为 `/api/assistant/flows`：服务端注册、带版本的确定性步骤表与停点推导；流程运行复用 `assistant_runs`（`guided_flow_v1`），不建新表。已注册四个流程（同一 `flows.py` 注册表）：`continue_writing` v3（确认资料 → 候选 → 独立审查 → 可审阅；采用后经作者确认滚动规划后续章节，BR-6 只到剧情线/篇章大纲候选，窗口默认 3 章、上限 5 章，后方已规划不足 2 章时提示补足）、`new_book_opening` v1（一句构想 → 方向卡候选 → 选定方向 → 世界观骨架包逐条取舍采用 → 停在「骨架可用」，BR-5；方向卡是 Assistant 侧定向 LLM step，卡片只存运行检查点）、`editorial_revision` v1（审读台选中意见 → 桥接批注修订 → 候选可审阅 → 采用后自动改后复核，BR-4）。开始请求按流程携带输入，推进请求支持 `choice` 作者选择输入；视图 `panel` 承载当前停点的作者面向载荷。AI 输出一律候选，采用与确认语义不变；滚动规划只在流程内经作者确认触发。


`map_cold_start` v1 从地图入口开始：选择演化阅读或空间补扫范围，冻结授权预览，再由作者到演化页
独立确认费用。流程只能绑定相同 operation_id、请求和预览指纹的已授权运行；通过 Evolution typed port
监测进度，未知结果停在原回执核对，不开始、不确认、不恢复或重发模型请求。完成后由 World typed port
汇总该运行草图，作者在地图工作台按空间或层级每批最多 20 项实际变更审核，再可选到 World 原采用
入口处理候选地点，停在“地图可用”。领域确认独立执行，不做跨域原子采用。流程复用
`ASSISTANT_GUIDED_FLOWS_ENABLED` 与项目白名单，默认关闭。

Assistant 是 `world_cocreation_sessions`、`world_cocreation_messages` 的唯一通用会话实现所有者；
`assistant_runs` 保存运行，`assistant_action_batches` 保存预览与决定，`assistant_notices`
保存提示投影，`assistant_watches` 保存持续授权和待检变化。World 保留成果与 checkpoint。

## 运行原则

PydanticAI 复用 Project 当前账户客户端与冻结快照；按 author/rp/background 的有限预算
执行允许的读取和提案工具。写入按具体预览成组确认，执行前后核验基线；外部资料不构成
正史或权限。后台检查依赖已保存的持续授权，提醒的忽略不改变领域结论。
配额分两层且有意不一致：外层 task run 为 30 请求 / 1800 秒，内层 author agent 预算
为 12 请求 / 32 工具 / 4 web（更保守的内层先触顶是预期行为，不是配额丢失）。

会话历史通过消息的 `assistant_run_id` 恢复任意旧回合，包括失败、停止、待确认和部分完成
的方案。sources 保留领域结果身份及审稿覆盖/遗漏，前端只接受固定导航目的地与领域引用；
地图保留节点、导入保留原 task、世界复核保留原 run，不能用通用章节参数替换这些身份。

成组重试保留成功项的授权后置状态，并继续验证无关来源与原 confirmation。原领域复核已
失效时，作者可显式重新查证未完成项；新一轮预算和修改确认与原批次分开。范围检查发生在
预览读取之前，排除资料和旧 confirmation 外资料不能被重新纳入预览。
同预算恢复按钮只在服务端确认原任务可人工恢复且预算仍有效时展示；任务不存在与不可恢复状态
分别使用 404 与 409，不将正常生命周期分支降级为服务器错误。

领域整合新增 P20结构规划/采用、正文候选生成/原问题返修/采用/历史工作稿恢复、世界阶段成果
保存与会话推进、采用包准备、整页建议工作稿、原整理恢复与专项查漏，以及有界地图维护。
生成工具复用原队列和领域结果，并计入同一工作预算；确认操作不接受模型提供会话身份、来源
manifest 或危险执行表达式。工具存在并不代表所有产品验收已完成，未关闭项见项目能力台账。

Writing 批注工作流需要相关资料提案时，在同一项目创建禁联网的独立 Assistant 回合；
该回合只提供已有 World/Story 操作目录，生成结果仍是待确认的 action batch。
正文候选采用和资产方案确认分别重验各自来源，关闭 Assistant 时明确报告提案未运行。

工作上下文（WorkContext）自 R00 起携带作者意图与选区范围：`task_hint` 取
封闭集（不限/续写/只润色/修改/设定设计/查证/检查/整理/演绎，与前瞻契约同源），
意图行为边界随最终用户消息进入模型输入（如「只润色」=不得扩大情节、新增设定或
改动事实）；写作页干净编辑器上的选区带码点偏移（`selection_start/end`，须绑定
草稿），提交时服务端对草稿逐字复核，漂移即 `assistant_selection_stale` 失败关闭。
前瞻 FocusRequest 的 `selected_range` 由前端在干净状态随 draft+hash 发送，前瞻
据此实际分析选中段落。

## 公共查证与受控维护

作者 v3 运行使用 `search_general_fact` 与 `read_web_source`，首次开启须明确选择
`searxng-v1`。搜索摘要不作为事实引用；网页原文保留地址、标题、时间、哈希和实际覆盖。
原生渠道不会作为自动后备。模型配置、搜索服务和地图图片依赖各自返回可用条件与具体原因。

伏笔/揭示内容调整、世界书草稿编辑/发布/历史工作稿恢复、相似资料扫描已接入原领域。
结果包含精确任务与版本，受控页面继续持有图片、文件、歧义裁定和危险操作。候选重新选材
只生成另一版本，不能据此让旧 candidate 通过原知识检查。失败提醒可使用明确的新额度重查，
日配额、关闭授权和排除范围继续生效；忽略提醒不改变领域问题。


### 地图目录与来源边界

新作者运行冻结为 v6：操作 schema hash、revision 与只读工具清单随 run 保存。v1–v5 的已有运行
只解析自己的冻结清单，旧 MapNodeCreate 参数按原 schema 恢复，不因新类型字段或工具出现而扩大权限。
Evolution 的两个空间入口只提供授权预览；图片与付费确认继续在领域工作台。

地图操作覆盖草图分组审核、空间线索采用/拒绝/合并、空间及关系/行程/条件/生效区间编辑、层级节点
创建/移动/改名。空间合并按实际迁移图元计数；节点合并只保存绑定源、目标版本的合并候选预览，
尚无可执行的节点合并原语，不以修改父节点冒充合并。所有确认合计最多 20 项，执行前重验全部修订、
指纹与范围。作者空间安排保存 run、message 与原消息 hash，预览/确认/保存均重验；正文推断只能通过
逐字引文与模态的候选线索审核，不直接成为已采用地图，模型输入不提供坐标。

v6 只读工具 `map_journey`、`map_object_position` 只从空间简报中的明确行程和 Scene 截止的最后位置
给出答案；缺失、同名歧义返回 `unknown`。`map_spatial_advisories` 通过 World typed port 读取提醒，
附版本和来源，给出 Writing 候选入口或地图结构修改预览两种路径。正文定向返修继续要求原审稿与
资料确认，提醒本身不替代审稿。逐项静默是绑定当前提醒/修订指纹的 Assistant notice，引用前重验
版本、来源以及原确认中选定的地图修订；新确认未选择该地图或确认后该修订被省略时，不能用旧提醒指纹恢复内容。没有实际核对的地图版本时返回 `unknown`，不显示无问题。静默不改变 World 判断。所有地图参考消费仍受 `MAP_SPATIAL_ENABLED_CAPABILITIES`
控制，默认关闭，真实质量与作者验收尚未完成。

### 整理导入结果

作者可用自然语言启动 imports.resolve_review，并通过 review_resolution_result 查看范围内的关键问题。选定资料由 imports.accept_review 形成具体可审查批次，再调用同一 World 采用服务；模型不能自行确认。新工具不注入旧运行冻结目录；来源变化、排除范围或原 confirmation 无法证明一致时拒绝沿用。

## 深度审稿

ADR-0027 的实验 `deep_review` 复用原会话/运行/任务，通过 team-runs 创建，只读报告
仍经 Writing 领域复核和最终知识治理。并发成员资料/历史独立，shared root 30 次总请求
涵盖内部复核，保留未知用量。默认关闭；能力响应区分未启用和模型不可用。
写作检查菜单与助手处理方式可启动；阶段、遗漏、旧来源与原审稿导航在原页面显示。

## 可复用审稿方法

新协作蓝图 v2 将连续性、人物知识与世界规则方法及版本纳入冻结快照，原 v1 不变。
方法仅指导调查，不授予工具或写入权限；相反结论保留为候选/分歧，未经领域复核不能
标为已核实问题。离线三臂材料可用现有人工评审导出流程阅读，真实质量与启用仍独立验收。

## 保存资料的短期前瞻

授权范围、证据快照、任务意图和界面焦点分别用四个键表示。保存选区、光标段落、原
confirmation 与排除项沿请求进入上下文，前端两个宿主共用一个账户/项目 feed 与轮询。
逐方向拒绝保留稳定身份，旧候选处置不能覆盖更新后的 notice。润色/修改选择转到讨论的
精确替换预览，保留原选区与未发送草稿，不当作续写。

新运行显式冻结 `understanding_enabled`，旧运行恢复、查看和候选重验使用旧协议。
作者写作前瞻可以经 Evidence 消费最多三条前章回顾理解与完整正文根，生成器和独立
知识审查接收同一引用/source_map。来源版本、排除章、传递理解及 Evolution 回执均
重验；Scene 焦点与显式历史截止暂不复用此类理解。容量不足省略可选理解并说明覆盖，
不挤掉当前资料；不把作者回顾解释当成角色已知或历史首次阅读证据。

`forecast_v1` 子路由声明前缀 `/forecasts`，挂载后的完整入口是
`/api/assistant/forecasts`。feed 仅读取保存稿、领域回执和派生候选，不请求模型或创建任务。
显式 evaluate 用原 AssistantRun 和 `assistant_forecast`，最多四次请求（含复核与修复）。
语义任务、自动触发与 RP 各有默认关闭的开关。后台 forecast 与原 review 共享 active_run
和每日额度，分别保留自身稳定期与冷却期；原客户端保存设置不会覆盖新授权分区。

候选 assessment 不可变，读取先选择最新评估，再核对完整依赖和来源集合。正文、范围、
原 confirmation、排除项或主体变化会使旧结果失效。处置通过 notice.row_version CAS，
普通细节/拒绝方向不随标题变化重开。dirty 编辑器仅能查看上次保存稿。

prepare 为一个具体选择创建独立子 run 与唯一 batch，重新校验父评估，再经原领域确认。
确定性域回执可导航回原页面，缺少前置资料计入未检查。试改版本和跨域原子采用属于
[Collaboration](21_collaboration.md)，不改变普通批次的部分成功与恢复语义。


前瞻 prepare 复用 Writing 候选、Story 信息安排、World 工作稿、Imports 精确组、Evidence
focused search 与 Project author tasks。focused search 仍沿原来源 manifest、Scene 可见性
和任务；原 confirmation/排除范围不能被补查动作暗中扩大。

语义暂缓由独立 activity 写入口评估，feed 保持纯读；场景激活、章稿完成、时间和已同步
对象出场可唤醒，对象按后续章节的新出场判断，同章文本编辑不算再次出现。不可判定的
来源保留待处理说明。普通细节与明确拒绝沿物理源事项继承，不按标题合并。

后台额度同时约束用户时区的当日与滚动二十四小时，冷却不能覆盖配额恢复时刻。前瞻候选
三十天后标记失效，必要来源和采用回执保留至原项目删除级联。diagnostics 提供最近一天
的请求、未知用量、来源拒绝和队列等待告警，明确最多一千条的枚举范围。

能力目录中 `implemented_gated` 表示实现已注册、开关仍默认关闭，不表示真实模型质量通过。
明确拒绝和普通细节处置仅在相同资料边界内成为下一次输入偏好，并进入运行和缓存指纹；
运行中处置变化会拒绝旧结果发布。同一原文问题按类型和物理引用对齐，不按标题合并；
重复摘要不会提高本地锚点的证据分数。

## 本机 CLI 已不用于助手

按 [ADR-0029](../adr/0029-local-cli-image-only.md)，本机 CLI 只用于世界对象图片与地图册
页面生成。助手讨论、语义前瞻和创作协作始终使用项目账户连接；此前冻结为本机执行的运行
执行时失败关闭，不静默改走账户连接。

## 作者编辑员级意见

Assistant 的 `/editorial/*` 持有 `assistant_editorial_reviews`、`assistant_editorial_issues` 和
站内提醒投影，不拥有正文或正史。提交以 `operation_id` 幂等、冻结编辑约定/工作稿 hash/
排除范围/模型快照；逐章分片、再按所列组层级汇总，明确遗漏与部分完成。读者层只读前序
正文；作者层可查 Evidence 世界资料及 Story 当章结构。唯一原文引文、来源版本和模型权限
由服务端重验。所有意见标 `editorial_suggestion`；只有原领域真实 finding 才可称领域已核实。
作者决定保留历史；改后检查不能自动关闭。主动授权以 `editorial_v1` 存 Watch，正常保存
不触发，完成标记和未关闭问题相关结构变化才排队；设置写入核对 Watch generation。
作者可停止审读并在来源、授权和用量均可确认时续跑未完成段。审读的每个出口都落到终态：
来源、资料或编辑约定变化记为已失效，其他异常及任务崩溃（读取时按任务生命周期收敛）记为
失败以便续跑。显式保存会让审读失效的约定、设定、大纲或发布审读中的章节前，前端提示并
请作者确认；自动保存不拦截，写作页只就地提示。原创内容评测样本及量表见
`backend/evals/datasets/editorial/README.md`；独立人工标注前不得宣称强提醒精确率达标。

本机任务批准使用 Assistant facade 的 owner/novel_id/task_id 窄入口，由
Assistant service 持行锁更新 checkpoint，禁止外域直接写 AssistantRun。


ADR-0033：助手模型就绪判定接受项目快照中的已验证 Codex 连接，不以是否保存 API Key 代替可用性；工具循环仍走同一有界网关，模板重建保持未设置字段，以继承 Luna/max 而不固化历史默认模型。

地图主动提醒复用项目已有的持续授权：`ProactivePolicy.enabled` 默认关闭，仅在 world 类别、
原 owner 与当前授权代次有效，且地图参考消费已显式开启时接收变更事件。自动草图建成、
模型空间类型涌现和保存地图版本会发出真实事件；Scene 变更沿用原事件入口。服务只读本次
事件所指批次、词条或有显式 Scene 的地图信号，不轮询全书、不启动模型或队列任务。
托盘地点、涌现类型、待审核草图和空间提醒按作品、授权代次与日期合并，最多保留 20 项事件，
沿用持续授权的每日上限；提醒仅导航到地图，作者仍需独立预览与确认。展示前重新核对 owner、
授权、排除范围、24 小时有效期与来源指纹；撤销、过期或来源漂移后不展示旧内容，
忽略与稍后提醒沿用原提醒状态，通知不改变地图、World 状态或原领域结论。

评测只读入口 `read_map_spatial_evaluation_turn(db, novel_id, run_id)` 返回本 owner/作品的持久助手请求、
固定 Scene/confirmation/排除范围、实际回答、空间证据引用、操作批次预览与执行回执及数值用量。
不调用会核对并修改状态的 `get_run`，不返回执行器配置、凭据或模型历史。Scene 仅取自原请求 context；
实际读取工具日志若未持久保存则明确 unknown，不从工具目录、回答或任务 meta 推测调用成功。
