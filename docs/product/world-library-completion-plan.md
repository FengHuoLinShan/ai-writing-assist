# 世界资料库与持续共创补全计划

日期：2026-09-10。状态：计划已编制，补全实现尚未开始。

依据：[World Library 系列审查报告](../references/2026-09-09-world-library-review.md)。本计划承接原四期方向，将报告的四项未完成验收拆为可独立评审的增量，不重复建设已落地的主题目录、阅读编辑、草稿保护和规则表单。

## 1. 基线、目标与边界

本次核对的代码基线是本地 `origin/main` 指向的 `a8de5aa9e98301943e4311aa1e5a356dd1fb177e` 加 `codex/world-library-review-fixes` 未提交修复；原工作区保持不动。本次未刷新远端，开始实施或交付前重新检查实际主干、工作区与在途 PR。上一轮测试数和视觉结果见审查报告，不能替代后续实现的验证。

目标画像：长期维护长篇小说与世界设定的作者 A。最终任务是：**找到资料 → 安心局部修改 → 找回此前讨论与决定 → 从原世界状态继续推演 → 审阅成果并进入既有采用流程 → 找到此次变更影响的资料并完成选定范围复核**。

产品假设：作者愿意反复使用，是因为无需重述长期决定、无需担心改稿丢失，能看清本轮变化和实际检查范围。舒服与美观以现有[设计标准](../frontend/uiux/design-standard.md)为基础，通过任务试用验证；自动化通过不代表真实作者满意。

保留此前已确定的范围：主题目录＋类型筛选、文档阅读＋局部编辑、先确定性引用再定向语义查漏、方法与规则管理。Vault 同步、完整块编辑器、专门物理计算、自治 Agent 不在本计划中。候选与正式采用保持分离，阶段成果本体不可直接采用。

## 4. R1：世界状态真正延续，决定不会被近期消息挤掉

### 当前缺口

`buildWorldDesignCheckpointRequest()` 每次按当前收束结果重新生成 `depth=seed`，规则 ID 按位置编号，循环、切面、依赖与下游状态重新初始化；服务端 `save_design_checkpoint()` 只校验父成果种类后保存。读取时又主要从 `world_core` 恢复编辑面，因此仅补保存端不够。

### 实现范围

1. **完整读取与增量保存**：首次创建才初始化 seed；继续时读取父成果的完整 19 区域状态。本轮新增、修改、明确废弃按稳定 ID 处理，字段未提交表示保留，空值清除须是明确操作。服务端拥有合并、ID/依赖校验、来源核验与新快照生成，前端只编辑本轮提案；保存后的快照仍使用现有 `world_design_checkpoint.v1` 载体。
2. **四动作贯通生成与编辑**：拓展、连接、施压、收束都读取同一父状态和本次确认资料，产出有类型、可审阅的变化。四动作是默认关注范围，不机械限制其他必要变化；超出本轮目标的建议明确呈现，不静默写入。
3. **身份、变化与失效**：已有对象、规则、决定的 ID 不因重排变化。新增内容分配稳定 ID；显式废弃保留历史与理由，修复悬空依赖。变更日志记录来源和改变项；受影响的测试、依赖与下游准备状态标为待重查，保持其旧结果供对照，不能沿用旧“通过”。
4. **阶段成熟度**：seed/candidate/instance 表示推演深度，与正式采用无关。candidate 要有可审阅的规则、因果与日常后果；instance 要有具体人物/地点/制度实例及对应证据。覆盖不足可保存，但显示缺口；不能按轮数自动升级，也不能把未运行测试改为通过。规则复用现有验证引擎，必要的阶段判定同步契约文档。
5. **长期作者决定**：复用当前 checkpoint 的决定/authority 字段保存有效状态，决定消息保存历史文本和来源；模型只能提出决定候选。明确保留、放弃、待定及后续替代关系，经作者操作后更新当前成果；决定从共创进入下一轮上下文的装配不依赖最近 40 条消息或客户端缓存。
6. **上下文装配**：服务端按当前会话、有效父成果取出当前作用范围的全部有效决定，再加入近期消息、作者显式选入的历史和同一 confirmation 允许的资料。去重、标注权威与来源；普通聊天和候选生成使用同一装配位置。旧决定与新消息相矛盾时提示核对，模型不得暗自覆盖决定。
7. **容量边界**：保留现有校验上限并测试边界，包括决定列表、1 MiB 快照和模型预算。历史记录不因容量被丢弃；必需决定放不下时在调用模型前明确阻断并允许缩小本轮目标，不能静默裁掉、自动压缩掉否定决定或制造第二套隐性记忆。
8. **恢复与比较**：界面展示“本轮改变／继续保留／需要决定”，展开后才看系统细节；从旧成果继续会创建有父链接的新成果，不重写旧成果。推进当前会话指针仍须校验作者看到的当前基线；冲突保留提案，刷新后重新比较。

### 接口与迁移

影响 World schemas、`adoption_package_service.py`、共创服务、生成中心与 Generate 前端。新增窄的续写输入契约，包含父成果、预期基线、本轮动作和有类型变更；复用现有校验模型，不引入通用 JSON Patch 平台。完整快照读接口保持兼容；旧 seed 和旧 core checkpoint 由显式一次性初始化路径续写，不批量改写历史。

复用 suggestion 存储与会话指针，默认不新增表。更新 ADR-0021、World 文档和 Prompt 调用契约，明确决定状态的唯一权威仍为当前成果；如发现既有载体无法表达必要语义，应在编码前记录 schema/ADR 调整，不能用无校验的 `extensions` 绕过权限或类型限制。

### 验收

- 合成父成果给 19 个区域写入可区分的内容；四动作逐个续写后，未改业务内容保持、ID 稳定、历史快照不变，合法的审计元数据变化单独核对。
- 先保存“放弃某能力／某事实待定”，再累积超过 40 条消息；刷新或换设备后，普通聊天和候选请求仍包含决定且不把待定变成事实。
- 修改一条规则会使对应依赖测试失效；重排不改变身份；显式移除、悬空依赖、同名条目、超限和过期来源都有确定结果。
- 两设备从同基线推进仅一方成功；另一方保留提案。seed→candidate→instance 可走通，任何一步均不自动采用正典。

## 5. R2：完整历史能用，聊天能恢复

### R2a 历史与参考选择

- 复用已有会话列表分页和消息 `skip/limit/search`，补齐总数、翻页或“加载更早”、归档访问和搜索结果定位。稳定排序加唯一 ID，避免同时间记录漏项；检索结果能展开前后文，必要时为既有查询补最小的消息定位参数。
- 明确区分“浏览历史”和“本轮参考”：浏览不改变生成输入；作者选中后显示可移除的引用、来源会话与范围。服务端按消息 ID 回读并核对内容/归属，不能信任客户端粘贴的 assistant 文本。
- 输入区旁保留一个“历史与决定”次级入口；历史阅读、长期决定和成果定位分层呈现。返回当前讨论保留未发送输入、滚动位置、检索词和参考选择；会话切换、跨设备与账号切换仍执行现有隔离。

### R2b 聊天 operation receipt

- 按 ADR-0013 将官方共创聊天入口接入现有 `async_tasks` 和 worker；无需另一套队列或收据表。同步旧入口的兼容/废弃期按该 ADR 明确记录。
- 提交前保存 `operation_id` 与 project/session 归属。服务端指纹绑定会话、父成果、作者消息、动作、选中历史与 confirmation；相同操作返回原任务，异请求复用 ID 返回冲突。
- provider 前释放事务；写入前重验 owner/项目、来源、父成果基线和 lease。成功时原子追加作者消息与回复，并与该操作绑定；写入后丢响应、worker 重试也不能重复追加。
- 服务端活动任务可在该会话内重新发现；若现有任务查询不能限定会话，只补窄的查询契约。刷新/换设备恢复原任务状态；未知提交不自动重放。失败保留作者问题，显式重试产生可追踪的新操作；停止与旧 attempt 晚到不写入业务结果。

验收：至少 100 个会话和单会话 1,000 条合成消息可遍历、检索、定位与选入，前后分页无漏重；未选中的额外历史不因浏览或检索进入输入，近期消息与有效决定仍按 R1 装配。覆盖提交后响应丢失、成功落库后丢响应、断网刷新、换设备、确认过期、停止和重复任务投递。输入期间晚到结果不覆盖新内容，页面不要求作者理解任务 ID。

## 6. R3：从影响列表走到可核验的跨域复核

### R3a 来源定位、冻结与失效

- 影响结果复用 `TargetRef` 与领域现有深链，提供世界页、对象/人物、故事线/大纲/Scene、正文范围、地图节点/图元的具体位置。正文保留 `draft_id + source_hash + range + range_hash`，不能仅以章节号充当精确来源；地图绑定对应 revision，不把 status 当成版本。
- Story 读取经 `modules.story.facade`，正文 manifest/range 经 `modules.writing.facade`。当前地图实现属于 World，复用地图册/空间版本载体，不虚构独立 Map 后端模块。跨域读取不足时先查已有稳定接口，再只补必要契约。
- 先列声明依赖及名称/已确认别名命中，明确“已关联”和“可能提及”的差别。正文代词、改写漏检不冒充无影响；故事结构覆盖须包括计划承诺的大纲/Scene，不能仅有故事线后就标为全结构完成。
- 保存根版本、实际检索范围及引用集合指纹。根、被选来源或范围内依赖集合变化，使旧复核过期；仅核对旧命中项不够，新增依赖也必须能使旧范围失效。保留旧回执可阅读，重查建立新基线。
- 点击来源打开相应编辑器或受限来源预览，返回影响面板保留筛选与位置。有未保存输入时走离开保护。无权限、不存在或已过期分别给可执行反馈，不留下无说明的灰按钮。

验收：每类来源都有“列表→具体位置→返回”的浏览器路径；同章不同版本、范围改变、新增关联、改名和已废弃别名不会误定位或被旧回执放行。跨 owner/项目引用失败关闭，任何读取失败或截断均显示未覆盖。

### R3b 有边界的跨域语义检查

- 入口为“此次变更的影响”与现有健康面板。作者选择目标、深度 0/1、资料种类与范围后冻结确认，明确检查前后版本和未纳入部分。
- Evidence 继续拥有检索、原文回读、选中/排除与可见性编译；复用 `retrieve_focused_evidence()`、`revalidate_focused_evidence()` 及现有 confirmation 物化。World 负责领域问题、规则执行、复核回执和待处理建议，不另建索引或扩大读取授权。
- World 页面/对象、人物、Story、大纲/Scene、正文和地图结构资料分别形成来源可回读的检查包。地图检查空间声明、依据与版本一致性；地图图像的视觉几何辨识不属于本次语义覆盖。
- 将变更事实、依赖路径、已确认原则和选中来源交给有界语义 step，检查规则冲突、下游前提过时、知识层混用与需要作者裁定项。输出必须 schema 校验并能引用实际包内证据；无证据的猜测不得作为硬阻断事实。
- 复用现有分片预算、任务与回执；开始、续接和最终完成前重验同一确认、来源/hidden guard、政策与范围指纹。成功分片仅在全部相关输入相同时复用；材料变化后不能拼接新旧结果。
- 结果显示已查数量、待查数量、未覆盖原因和下一步；预算耗尽保留可继续状态。修正进入对应领域既有编辑/建议流程，World 复核不能直接改 Story、正文或地图。重新检查生成新结果，旧签收不跨版本沿用。

验收：合成跨域链植入可定位冲突、缺失依赖和无需修改的对照项；检查能定位证据且来源跳转可用。覆盖一个领域读取失败、超预算续接、途中改源/换确认、作者排除、Scene 截止点、硬错误与待裁定混合、修后重新检查。Top-K、字面命中和部分分片均不能显示为“全库检查完成”。

## 7. R4：大资料库与管理界面的舒适度

### 加载与编辑性能

当前 `worldIsland.js` 进入世界书时仍并发拉取全量页面与稿件，统一列表分页未消除入口负载。先修这条调用链：首屏只取概览、主题/必要元数据和当前页轻量卡片；打开资料才取当前正文与对应工作稿；模板、规则、引用候选和历史在打开其入口时加载。旧深链、简介、引用名称和页面编辑也要同步改为按需查询，不能让任一回退路径重拉全库。

复用现有 SQL 分页与索引；先记录查询和浏览器数据，再决定是否需优化 SQL 或长文渲染。分页足够时不新增虚拟列表依赖、缓存系统或搜索平台。

必测合成数据：100 与 1,000 份资料，含页面/工作稿/实体，长页面 1–2 万字并带分区和引用；另配 R2 的长会话。记录数据分布、设备、浏览器、commit、网络条件和冷/热缓存，在同条件下前后比较。

拟定性能目标（本计划目标值，尚未测得）：

- 列表请求不含长正文与工作稿全文；首屏传输和渲染规模随当前页而非全文总量增长。不得为凑指标隐藏资料或截掉正文。
- 在记录硬件的本地专用环境、至少 20 次重复测量中，千份资料首屏可操作 p95 ≤2.5 秒，搜索/翻页反馈 p95 ≤1 秒；长文输入到画面更新 p95 ≤100 毫秒。
- 报告 API 耗时、响应字节、请求数、浏览器长任务和输入延迟。若不达标，定位瓶颈再优化；指标改变须说明理由，不能用降低样本规模掩盖失败。

### 层级、美观与快速编辑

| 作者当前任务 | 默认界面 | 次级展开与返回要求 |
|---|---|---|
| 找资料 | 主题、类型、搜索、最近/继续编辑 | 整理、批量与规则配置按需展开；返回保留位置 |
| 读与改 | 正文为主，清楚的保存状态，就地分区编辑 | 版本、引用与比较展开后查看；无需在多个表单间重复定位 |
| 继续共创 | 当前主题、输入、本轮提案 | 历史、决定、完整模型详情按需展开；移动端一次聚焦一个任务 |
| 处理影响 | 问题摘要、证据、下一步 | 覆盖/预算/诊断渐进展开；能回到问题而不丢处理进度 |

复用现有颜色、排版和抽屉组件，不重做主题。阅读列遵守现有正文宽度与字号；状态除颜色外有文字；一个决定区域一个主要动作。键盘可完成搜索、打开、局部编辑、保存、关闭与返回；触控目标至少 44px，390/768/1440px 无页面横向溢出，浅深色均可读。

高频路径目标：从搜索命中到局部输入不超过两次显式操作；保存不要求离开正文，成功/失败反馈就地可见。不同对象路径分别计数与实测，不能只挑最快的资料页证明全库快速编辑。

### 视觉遗留与作者试用

上轮 World/Generate 11 项通过；另 7 项地图/写作差异已在干净主干复现。R4 单列这 7 项逐一判断：实际布局缺陷修代码，确认过时的预期图再更新，不降低阈值或批量接受未知差异。Today 曾出现偶发黑块，隔离运行通过；只有再次复现时再调查环境，当前不把它计作已确认业务缺陷。

全旅程试用至少观察作者完成找资料、修改恢复、续接旧决定、采纳提案、追踪影响五项任务，记录完成/放弃、耗时、误操作和是否愿意重复使用；无真实参与者时只能标为合成任务验收，作者喜好继续待验证。真实作品或模型调用需沿用已确认的数据和账户边界，不以本计划授权外送语料。
