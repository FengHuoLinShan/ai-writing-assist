# 写作页 Scene 工作台拓展优化设计

## 背景

当前写作页已经不是单纯正文编辑器。它包含 Scene 树、章节草稿、版本管理、自动保存、发布、AI 草稿生成、深度导入进度、当前 Scene 面板和 Scene 地图摘要。

本设计把写作页升级为 **Scene 驱动的正文工作台**：作者默认先理解当前 Scene 的执行目标和风险，再写正文，并通过高频的“剧情设定冲突检查”减少剧情、设定、地图状态和前后连续性的错误。

设计采用第一版可落地方案：**规则检查优先，预留 LLM 软冲突能力**。AI 工具保留为编辑器周边的弱化入口，不成为默认主流程。深度导入、断章、章节卡提取等整理能力从写作页常驻区域移出，进入独立页面或独立整理工作台。

## 目标

- 写作页默认围绕当前 Scene 写正文，而不是围绕 AI 生成、地图编辑或导入整理。
- 右侧 Scene 驾驶舱清楚展示“这一场要写什么、不能写错什么”。
- 提供一个高频主动作：`剧情设定冲突检查`。
- 检查结果可解释、可定位、可标记处理状态，并能持久化历史。
- 最近检查记录默认只显示一条，其余折叠。
- 发布时归档最近一次检查快照，便于追踪发布前状态。
- AI 修复建议可以作为辅助，但不自动改正文、Scene、地图或正史资产。
- 待确认对象默认不参与检查；用户显式打开后，相关结果标记“需复核”。
- 右侧驾驶舱模块支持用户手动排序，模块过多时自动折叠后段内容。

## 非目标

- 不把写作页改成完整 AI 审稿系统。
- 不让 AI 判断自动覆盖规则检查或结构化事实。
- 不做一键应用 AI 修复。
- 不把深度导入、断章、章节卡提取继续常驻在写作页主界面。
- 不引入新的前端技术栈。
- 不新增未经确认的多 Agent 协作机制。
- 不跨模块直接 import 其他模块的 `models.py`、`repositories.py` 或 `services.py`。

## 产品形态

写作页默认布局采用三栏骨架，并强化中间编辑器周边能力。

### 左侧：Scene / 章节树

左侧只负责导航：

- Scene 分组。
- 章节选择。
- 当前 Scene / 当前章节高亮。

左侧不承载检查详情、AI 工具或整理工具。

### 中间：正文编辑区

中间是主工作区：

- 顶部显示章节标题、当前 Scene 信息和折叠的 `AI 工具 · 待定` 胶囊。
- `AI 工具 · 待定` 第一版只作为入口，不在设计中固定具体能力。
- 编辑器上方放一个主按钮：`剧情设定冲突检查`。
- 主按钮右侧显示最近一条检查记录。
- 其他检查历史通过 `历史 ▾` 下拉折叠。
- 检查按钮和历史记录打开弹窗展示详情。

### 右侧：Scene 驾驶舱

右侧展示稳定参考信息，不承载大段检查报告。

默认模块顺序：

1. Scene 标题 / 标签 / 当前章节位置
2. 目标
3. 必须发生
4. 禁止发生
5. 核心冲突
6. 地图摘要 / 世界状态风险
7. 前后连续性摘要
8. 参考资料
9. 伏笔 / 揭示
10. 其他模块折叠

用户可以手动拖拽调整模块顺序。第一版可将顺序保存到本地偏好；跨设备同步不是第一版目标。模块过多或屏幕高度不足时，从后段模块开始折叠。

### 整理能力隔离

深度导入、断章、章节卡提取和导入后清洗属于 E 类整理能力。它们进入独立页面或独立整理工作台。写作页只保留：

- 必要跳转入口。
- 后台整理任务运行时的轻量进度入口。

整理工具不常驻挤占写作页主空间。

## 剧情设定冲突检查

`剧情设定冲突检查` 是第一版核心能力。它不是泛化审稿，而是围绕当前 Scene 和当前正文检查剧情、设定、地图状态与连续性冲突。

### 默认检查来源

默认检查：

- 当前 Scene 卡。
- 当前章节正文。
- 世界 / 地图状态。
- 前后 Scene / 章节记忆。

可选检查：

- 待确认对象。

待确认对象默认关闭。用户打开后，所有依赖待确认对象的问题项必须显示“需复核”。

### 分层判断

第一版以规则层为主，预留 LLM 层。

**规则命中**

结构化数据可以直接判断的硬冲突，例如：

- 正文写出了 Scene 禁止发生项。
- 正文没有覆盖必须发生项。
- 当前人物位置与上一 Scene / 地图状态不连续。
- 地图危机、势力状态、地点状态与正文描述冲突。
- 前后 Scene 已发生事实与当前正文不一致。

**AI 判断**

未来用于叙事软冲突，例如：

- 动机不连贯。
- 情绪跳变。
- 伏笔误揭示。
- 隐含设定不一致。
- 叙述暗示和正式设定不一致。

AI 判断必须和规则命中分开显示，不作为绝对事实。

**需复核**

以下情况显示“需复核”：

- 结果依赖待确认对象。
- 结果来自 AI 判断。
- 结果来源置信度不足。
- 某个依赖模块返回了降级摘要。

### 检查结果弹窗

检查弹窗展示：

- 检查范围。
- 检查时间。
- 是否包含待确认对象。
- 问题列表。
- 每条问题的类型、严重度、来源模块、证据摘要、定位信息和处理状态。

每条问题支持：

- 定位到正文位置。
- 打开相关 Scene。
- 打开相关地图 / 世界对象。
- 打开前后 Scene / 章节记忆来源。
- 标记为 `已处理`、`忽略` 或 `稍后`。
- 请求 AI 修复建议。

AI 修复建议只展示建议文本和依据，不自动写入正文或结构化资产。用户可以手动采纳。

### 历史记录

检查历史按 Scene / 章节持久化保存。

写作页默认只显示最近一条记录，例如：

```text
10:42 · 发现 3 个冲突
```

其他记录通过 `历史 ▾` 折叠。点击记录打开详情弹窗。

历史记录保存：

- 检查时间。
- 章节索引。
- Scene ID。
- 草稿 ID 或正文版本引用。
- 检查范围。
- 是否包含待确认对象。
- 问题摘要。
- 问题处理状态。
- AI 建议摘要。

### 发布归档

发布时归档最近一次检查快照。发布前如果最近检查存在未处理高严重度问题，前端提示用户，但第一版不强制阻断发布。用户确认后可以继续发布。

归档快照用于解释“发布前检查过什么”。后续检查记录变化不应改写历史发布说明。

## 后端设计

### 模块归属

检查记录归 `writing` 模块所有，因为入口、历史和发布归档都绑定正文写作。

跨模块读取只通过稳定接口：

- `outline` 提供当前 Scene、前后 Scene、目标、必须发生、禁止发生、核心冲突。
- `world` 提供地图摘要、人物位置、地点、势力、危机和空间风险。
- `memory` 提供前后章节 / Scene 的事实记忆摘要。
- `context` 和 LLM 只作为未来 AI 修复建议或软冲突能力，不是第一版规则检查硬依赖。

### 数据模型

建议新增：

```text
writing_conflict_checks
```

字段包括：

- `id`
- `novel_id`
- `chapter_index`
- `scene_id`
- `draft_id`
- `version_number`
- `scope`
- `include_candidates`
- `status`
- `summary_json`
- `created_at`
- `updated_at`

```text
writing_conflict_items
```

字段包括：

- `id`
- `check_id`
- `novel_id`
- `kind`
- `severity`
- `source_module`
- `source_type`
- `source_id`
- `evidence_summary`
- `location_json`
- `is_ai_judgment`
- `needs_review`
- `status`
- `ai_suggestion`
- `created_at`
- `updated_at`

处理状态：

- `open`
- `resolved`
- `ignored`
- `later`

### API

```http
POST /api/writing/conflict-checks
```

创建一次检查。请求包含：

- `novel_id`
- `chapter_index`
- `scene_id`
- `draft_id`
- 当前正文或正文版本引用
- `include_candidates`

返回检查记录和问题列表。

```http
GET /api/writing/conflict-checks?novel_id=&chapter_index=&scene_id=
```

获取最近检查记录。写作页默认取最近一条，历史下拉取更多。

```http
GET /api/writing/conflict-checks/{id}
```

获取检查详情。

```http
PATCH /api/writing/conflict-check-items/{id}
```

更新单条问题状态。

```http
POST /api/writing/conflict-check-items/{id}/ai-suggestion
```

生成 AI 修复建议。第一版可预留接口，或接入现有 AI 参考资料确认流程后再启用。

### 检查状态流

1. 用户点击 `剧情设定冲突检查`。
2. 前端先自动暂存当前正文。
3. 自动暂存成功后，前端提交检查请求。
4. 后端通过稳定接口读取 Scene、世界 / 地图摘要、前后记忆。
5. 规则层生成问题项。
6. 后端保存检查记录和问题项。
7. 前端打开检查弹窗，并刷新最近检查记录。
8. 用户更新问题处理状态或请求 AI 建议。
9. 发布时归档最近一次检查快照。

## 前端设计

### 组件边界

`writingView` 负责：

- 显示主按钮。
- 显示最近一条检查记录。
- 打开历史下拉。
- 触发检查。
- 自动暂存。
- 编辑器定位。
- 发布前提示。

检查弹窗应抽离到独立组件，例如：

```text
frontend-console/shared/conflictCheckModal.js
```

或：

```text
frontend-console/views/writingConflictPanel.js
```

避免继续扩大 `writingView.js`。

右侧驾驶舱模块渲染也应拆出轻量 helper 或组件对象，支持排序、折叠和测试。

### 响应式

窄屏下：

- Scene 树、编辑器、驾驶舱纵向排列。
- 检查按钮和最近记录换行，不挤压正文标题。
- 历史下拉宽度受限并可滚动。
- 右侧驾驶舱移动到编辑器下方，并默认折叠后段模块。

### 安全渲染

所有来自用户、AI 或 API 的动态文本必须走 `esc()` 或 `textContent`。检查问题、证据摘要、AI 修复建议和历史记录不得以未转义 HTML 写入页面。

## 异常处理

- 自动暂存失败：不运行检查，提示用户先解决保存冲突。
- Scene 缺失：允许检查当前章节正文，但提示“当前章节未关联 Scene，Scene 规则未检查”。
- 地图摘要不可用：检查继续，摘要中标记地图检查跳过。
- 前后记忆不可用：检查继续，摘要中标记连续性来源不足。
- 待确认对象参与：相关问题标记“需复核”。
- AI 建议失败：不影响检查记录，只在该问题项显示建议生成失败。
- 发布前无检查记录：提示用户可以先运行检查，但不强制阻断。

## 测试策略

后端：

- `writing` 模块规则检查服务测试。
- `writing` 冲突检查 API 测试。
- 检查记录和问题项的 `novel_id` 隔离测试。
- 发布归档最近检查快照的测试。
- 稳定接口调用测试，避免跨模块直接依赖内部实现。

前端单测：

- 写作页显示单条最近记录。
- 历史记录折叠和详情弹窗。
- 检查按钮触发自动暂存后再提交检查。
- 自动暂存失败时不运行检查。
- 问题状态更新。
- AI 建议失败提示。
- 未关联 Scene 的降级提示。
- 右侧驾驶舱排序和折叠。

E2E：

- 编辑正文。
- 暂存。
- 运行剧情设定冲突检查。
- 查看检查弹窗。
- 标记问题为 `稍后`。
- 发布前看到未处理提示。
- 确认发布。
- 发布归档检查快照。

响应式验证：

- 桌面三栏。
- 900px 两栏 / 驾驶舱下移。
- 600px 单栏。
- 检查按钮、最近记录和历史下拉不发生横向溢出。

## 分阶段落地

### 第一阶段

- 写作页 UI 重组。
- 单一 `剧情设定冲突检查` 入口。
- 最近一条检查记录和历史下拉。
- 检查记录与问题项持久化。
- 规则层检查。
- 问题弹窗、定位、处理状态。
- 发布前提示和检查快照归档。
- 右侧驾驶舱排序与折叠。
- E 类整理能力从写作页常驻区移出。

### 第二阶段

- LLM 软冲突判断。
- AI 修复建议。
- 待确认对象可选纳入检查。
- 更细的来源证据与定位。

### 第三阶段

- 跨设备同步驾驶舱排序偏好。
- 更完整的写作 AI 工具胶囊能力。
- 与独立整理页面的更完整联动。

## 验收标准

- 写作页默认进入 Scene 驱动的写作工作台，而不是工具堆叠页。
- `剧情设定冲突检查` 是唯一常驻检查主动作。
- 最近检查记录默认只显示一条，其余折叠。
- 检查结果可以定位、标记状态并持久化。
- 发布前可以看到未处理高严重度问题提示。
- 发布记录归档最近检查快照。
- 右侧驾驶舱可排序、可折叠。
- 深度导入、断章、章节卡提取不再常驻写作页主界面。
- 窄屏无横向溢出。
- 不出现未转义动态 HTML。
- 不破坏 novel_id 隔离和模块稳定接口边界。
