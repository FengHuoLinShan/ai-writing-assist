# 写作页第三阶段范围讨论稿

## 背景

写作页前两个阶段已经覆盖核心写作工作台和冲突检查能力：

- Scene 树、正文编辑、版本历史和右侧 Scene 驾驶舱已经形成主工作区。
- `剧情设定冲突检查` 已包含规则检查、历史记录、详情弹窗、AI 软冲突判断和 AI 修复建议。
- 右侧 Scene 驾驶舱已支持本地拖拽排序和高度不足时折叠后段模块。

第三阶段不应重复实现上述能力。本轮重新收敛到 **C：独立 Scene 整理工作台联动** 为主轴。AI 写作工具胶囊先保留为后续增强方向。

## 当前章节卡与 Scene 卡关系

当前系统应按以下关系理解：

- **章节**是正文的物理容器，对应 `writing_drafts.chapter_index` 和正文内容。
- **Scene 卡**是当前权威结构单元，对应 `scenes` 表。Scene 通过 `chapter_ids` 和 `scene_chunks` 映射到一个或多个章节，承载目标、核心冲突、情感节奏、必须发生和禁止发生等字段。
- **章节卡 / ChapterCard**主要是历史概念和兼容上下文。`chapter_cards.scene_cards` 不再是权威来源；当前权威来源是 `scenes` 表。
- 现有“AI 提取章节卡”入口在产品语义上应理解为“从章节正文中提取 / 更新 Scene 卡字段”，不是恢复独立 ChapterCard 工作流。

因此，第三阶段讨论时不要把“章节卡”作为新的主对象。若需要整理章节，应围绕 Scene 与章节正文的映射、对齐、复核和移动来设计。

## 选择轴

### A. 个性化 Scene 驾驶舱

把当前本地排序升级为完整偏好系统：

- 跨端同步驾驶舱模块顺序。
- 模块显示 / 隐藏开关。
- 按写作模式切换预设，例如“冲突优先”“情感优先”“地图连续性优先”。

适合解决长期使用体验，但对主流程提升偏温和。它建立在已有驾驶舱能力之上，不是第三阶段唯一高价值方向。

### B. AI 写作工具胶囊成型（后置）

把当前 `AI 工具 · 待定` 变成围绕光标和选中文本的高频动作：

- 续写当前段。
- 局部改写。
- 补强冲突。
- 补情绪 / 动作。
- 解释当前段与 Scene 目标的偏差。

边界必须清楚：AI 结果只进入建议或候选草稿，不自动覆盖正文、Scene、地图或正史资产。

该方向暂不作为第三阶段主线。后续如果推进，第一版不追求泛化 AI 写作平台，而是把写作页内最常见的“卡住一下”场景做顺：

- 无选中文本时，动作默认作用于当前光标附近段落和当前 Scene。
- 有选中文本时，动作只作用于选区，并在结果中标明来源选区。
- 输出以“可插入建议”呈现，用户点击后才写入正文。
- 所有 AI 调用继续走上下文确认记录，保留 action、scope、chapter_index 和 scene_id。
- 每个建议必须能取消、复制、插入到光标处或替换选区；第一版不做自动批量应用。

### C. 独立 Scene 整理工作台联动

把写作页里低频但复杂的整理能力外移，形成独立整理工作台。写作页只保留入口、当前任务进度和回跳能力。

整理工作台围绕 Scene 权威模型，而不是 ChapterCard：

- 深度导入后的 Scene 提取结果复核。
- 章节正文与 Scene 的映射对齐。
- 未归类章节、空 Scene、跨多章 Scene 的可视化处理。
- 断章、移动章节、合并 / 拆分 Scene。
- 从章节正文提取 Scene 字段，并展示 diff / 来源 / 置信度。

这是信息架构收益最大的方向：它可以把写作页从“编辑 + 整理 + 导入 + 复核”的混合页面中解放出来，让写作页继续保持 Scene 驱动的正文工作台。

当前 Scene 工作台采用 **A+B 融合**：

- A 的完整能力要保留：字段编辑、章节映射、复核记录、关联资产、合并 / 拆分都能在 Scene 工作台完成。
- B 的优先级要保留：第一屏和主流程先服务健康队列、章节映射、拆分 / 合并和导入后复核；字段编辑是详情层能力，不抢主线。
- Scene 工作台作为侧边栏一级入口，中文名为 `场景`，同时用小一号淡色 `Scene` 做英文辅助识别。
- 大纲页原“场景卡”子标签保留为跳转页：提示 Scene 管理已迁移到 `场景 Scene` 工作台，并提供跳转；不再维护创建、编辑、排序、删除等第二套管理 UI。
- 第一屏采用健康筛选 + Scene 列表结合：顶部展示未复核、未关联章节、缺设定、待整理等健康统计和筛选，主体仍是按章节 / Scene 顺序排列的 Scene 列表。跨多章是正常创作形态，不能作为默认风险项。
- 字段编辑第一版完整开放，但放在右侧详情层。桌面宽屏比例建议为左侧整理区约 62%，右侧详情编辑约 38%；左侧承载健康筛选、Scene 列表、章节映射、拆分 / 合并，右侧承载完整字段编辑和关联资产查看。
- 合并 / 拆分 Scene 进入第一版范围。合并可选择相邻或指定目标 Scene；拆分可按章节边界或选定断点。两者都必须先预览章节映射、字段变化和影响范围，并在二次确认后执行。
- 合并 / 拆分影响预览需要展示章节映射变化、Scene 字段变化、关联剧情线、关联伏笔 / 揭示和地图摘要影响。这些是影响提示，不自动阻塞；真正阻塞来自用户二次确认。
- 窄屏时右侧详情编辑不下沉到列表下方，改为抽屉 / 弹窗，保持 Scene 列表仍是主操作面。
- 写作页不在编辑器底部新增一块“整理入口”；只在右侧 Scene 驾驶舱标题区放一个小按钮，文案固定为 `整理`，点击后跳到 Scene 工作台并定位当前 Scene。

## 当前倾向

第三阶段当前确认以 **C：独立 Scene 整理工作台联动** 为主轴，具体采用 **A+B 融合的 Scene 工作台**。

理由：

- 写作页已经需要稳定消费 Scene 信息，但不适合继续承载断章、导入复核、批量映射调整等整理动作。
- 当前 Scene 原本分散在大纲页、写作页、深度导入流程里；独立工作台能把 Scene 管理边界收清楚。
- A+B 融合可以避免两个极端：既不做能力过窄的健康队列，也不做第一屏过重的完整大纲编辑页。健康筛选 + Scene 列表能同时支撑整理优先和日常浏览；筛选项必须使用作者能理解的语义，不暴露“缺字段”这类工程说法。
- 完整字段编辑是必要能力，但通过 62/38 的布局比例降级为详情层，主视觉仍然落在 Scene 整理和健康状态上。
- 合并 / 拆分是 Scene 整理工作台区别于普通 CRUD 列表的核心价值，第一版需要纳入；风险通过影响预览和二次确认控制。
- 健康筛选第一版固定四类：未复核、未关联章节、缺设定、待整理。不继续扩展标签，避免健康栏变成复杂规则面板。
- 侧边栏一级入口能减少作者从写作页、导入复核和结构整理之间来回寻找入口的成本。
- 大纲页保留跳转页可以避免旧路径突然失效，同时防止两套 Scene 管理界面长期并存。
- 写作页轻入口只放在 Scene 驾驶舱里，不额外占用编辑器底部空间。

AI 写作工具胶囊保留为后续方向；驾驶舱偏好增强也可以后置。

## 已确认决策

- 第三阶段主轴是 `场景 Scene` 工作台，不是 AI 写作工具胶囊。
- 入口是侧边栏一级菜单：中文 `场景`，小一号淡色 `Scene`。
- 写作页保留 Scene 使用面，右侧驾驶舱放小按钮 `整理`，不在编辑器底部增加入口块。
- 大纲页原“场景卡”保留为跳转页，不维护第二套管理 UI。
- 第一屏采用健康筛选 + Scene 列表；健康筛选固定四类：未复核、未关联章节、缺设定、待整理。
- 字段编辑完整开放，但作为右侧详情层；桌面宽屏比例约 62/38。
- 窄屏时详情编辑进入抽屉 / 弹窗。
- 合并 / 拆分 Scene 第一版就做，执行前必须影响预览和二次确认。
- 影响预览展示章节映射、字段变化、剧情线、伏笔 / 揭示、地图摘要影响。
