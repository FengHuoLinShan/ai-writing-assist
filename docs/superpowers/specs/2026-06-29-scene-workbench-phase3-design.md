# 场景 Scene 工作台第三阶段设计

## 背景

前两阶段已经把写作页收敛为 Scene 驱动的正文工作台：

- 写作页左侧有 Scene / 章节树。
- 中间区域承载正文编辑、保存、发布、版本历史和冲突检查入口。
- 右侧 Scene 驾驶舱展示当前 Scene 的目标、必须发生、禁止发生、核心冲突、地图摘要、连续性和参考信息。
- `剧情设定冲突检查` 已覆盖规则检查、AI 软冲突判断、AI 修复建议、历史记录和发布前检查快照。

第三阶段不继续把导入整理、断章、Scene 复核和结构调整塞进写作页，而是新增一个独立的 **场景 Scene 工作台**。写作页继续消费当前 Scene 信息；场景工作台负责 Scene 管理、章节映射、健康筛选和结构整理。

## 当前模型关系

当前系统应按以下关系设计：

- **章节**是正文物理容器，对应 `writing_drafts.chapter_index` 和正文内容。
- **Scene 卡**是权威结构单元，对应 `scenes` 表，通过 `chapter_ids` 和 `scene_chunks` 映射到一个或多个章节。
- **ChapterCard / 章节卡**是历史概念和兼容上下文，不作为第三阶段主对象。

跨多章 Scene 是正常创作形态。平均 Scene 至少跨 3 章时，不能把“跨多章”当成默认风险。

## 目标

- 把 Scene 管理从写作页和大纲页子标签中独立出来，形成侧边栏一级入口。
- 让作者能快速看到哪些 Scene 需要复核、缺设定、未关联章节或待整理。
- 支持 Scene 字段完整编辑，但不让字段编辑压过整理主流程。
- 支持章节与 Scene 的映射调整、合并 Scene、拆分 Scene。
- 合并 / 拆分前提供影响预览和二次确认，避免误操作。
- 写作页保留当前 Scene 信息和轻量跳转入口，不再承载批量整理能力。
- 大纲页旧“场景卡”入口保留为跳转页，避免旧路径失效，但不维护第二套管理 UI。

## 非目标

- 不把场景工作台做成新的正文写作页。
- 不在场景工作台里发布正文或编辑正文长文本。
- 不恢复 ChapterCard 作为主数据模型。
- 不把 AI 写作工具胶囊纳入本阶段主线。
- 不新增新的前端技术栈。
- 不引入新的多 Agent 协作机制。
- 不绕过 `outline` 模块稳定接口直接跨模块访问内部实现。

## 入口与导航

场景工作台作为项目侧边栏一级入口。

入口展示：

- 主标签：`场景`
- 英文辅助：`Scene`，小一号淡色字体

写作页右侧 Scene 驾驶舱标题区放一个小按钮：

- 文案：`整理`
- 行为：打开场景工作台，并定位到当前 Scene

写作页不在编辑器底部新增独立入口块，避免占用正文工作空间。

大纲页原“场景卡”子标签保留为过渡跳转页：

- 显示“Scene 管理已迁移到场景工作台”
- 提供 `打开场景工作台` 按钮
- 不再维护创建、编辑、排序、删除等完整管理 UI

## 页面布局

桌面宽屏采用左右两区：

- 左侧整理区约 `62%`
- 右侧详情编辑区约 `38%`

左侧整理区承载：

- 健康统计和筛选
- Scene 列表
- 章节映射
- 合并 / 拆分 / 移动等结构动作

右侧详情区承载：

- Scene 字段完整编辑
- 关联资产查看
- 来源与复核记录
- 影响摘要

窄屏时，右侧详情区不下沉到列表下方，改为抽屉或弹窗。Scene 列表始终保持主操作面。

## 第一屏

第一屏采用 **健康筛选 + Scene 列表**。

顶部健康筛选固定四类：

1. `未复核`：深度导入、AI 提取或批量生成后尚未人工确认。
2. `未关联章节`：Scene 没有关联章节，或存在未归类章节需要分配。
3. `缺设定`：作者写作必要信息不足，例如目标、核心冲突、必须发生、禁止发生等关键设定缺失。
4. `待整理`：系统或作者标记为疑似需要拆分、合并、移动章节或调整映射。

不在第一版继续扩展健康标签，避免健康栏变成复杂规则面板。

主体仍是按 Scene / 章节顺序排列的 Scene 列表。列表项应显示：

- Scene 序号、标题、状态、来源
- 关联章节范围
- 关键健康标签
- 目标或一句摘要
- 快捷动作：`编辑`、`整理`、`打开写作`

未归类章节也应在列表里显式出现，动作是 `分配 Scene`。

## 详情编辑

第一版完整开放 Scene 字段编辑，但作为右侧详情层，不抢主流程。

字段包括：

- 标题
- 叙事标签
- 状态
- 来源
- 目标
- 核心冲突
- 情感节奏
- 必须发生
- 禁止发生
- POV
- 章节映射摘要
- 关联资产摘要

详情区允许保存字段修改，但不直接编辑正文。正文修改仍回到写作页。

## 章节映射

场景工作台负责管理 Scene 与章节正文的映射关系。

第一版支持：

- 查看一个 Scene 关联哪些章节。
- 查看未归类章节。
- 将章节分配给 Scene。
- 将章节从一个 Scene 移到另一个 Scene。
- 按章节边界调整 Scene 映射。

映射调整不直接修改正文内容。它只修改 Scene 字段、顺序、章节映射和状态。

## 合并与拆分

合并 / 拆分 Scene 进入第一版范围。

### 合并 Scene

合并可以选择相邻 Scene，也可以指定目标 Scene。

执行前必须展示预览：

- 合并前后的章节映射变化
- 字段合并策略
- 被合并 Scene 的状态变化
- 关联剧情线、伏笔 / 揭示、地图摘要影响

合并后原则：

- 目标 Scene 保留为主 Scene。
- 被合并 Scene 标记为废弃或合并来源，不硬删除正史对象。
- 章节映射归入目标 Scene。
- 写作页 Scene 树和驾驶舱引用刷新。

### 拆分 Scene

拆分可以按章节边界或选定断点。

执行前必须展示预览：

- 拆分后的两个 Scene
- 新旧 Scene 的章节归属
- 字段继承和待补设定
- 关联剧情线、伏笔 / 揭示、地图摘要影响

拆分后原则：

- 新 Scene 进入草稿或待复核状态。
- 原 Scene 保留可追踪来源。
- 不直接修改正文。
- 写作页 Scene 树和驾驶舱引用刷新。

所有合并 / 拆分操作都必须二次确认后执行。影响预览只提示，不自动阻塞；真正阻塞来自用户确认。

## 影响预览

合并 / 拆分影响预览至少展示：

- 章节映射变化
- Scene 字段变化
- 关联剧情线
- 关联伏笔 / 揭示
- 地图摘要影响

影响预览的作用是帮助作者判断，不代替作者决策。系统不因存在关联资产而自动禁止合并 / 拆分。

## 写作页联动

写作页保留 Scene 使用面：

- Scene / 章节树继续用于导航。
- Scene 驾驶舱继续展示当前 Scene 信息。
- 冲突检查继续读取当前 Scene。
- 右侧驾驶舱标题区显示 `整理` 小按钮。

写作页不再作为 Scene 批量整理面：

- 不在底部新增整理入口块。
- 不承载合并 / 拆分 Scene。
- 不承载导入后批量复核。

从场景工作台打开写作页时，应能定位到选中 Scene 的首个关联章节。

## 大纲页联动

大纲页原“场景卡”子标签改为跳转页，不再维护完整 Scene 管理能力。

剧情线、篇章纲、伏笔、揭示仍在大纲模块内管理。它们可以在场景工作台中作为关联影响展示，但不由场景工作台替代其完整管理页面。

## 数据与模块边界

Scene 数据归属仍在 `outline` 模块。

前端工作台通过 `api.outline` 调用 Scene 相关接口。后端跨模块调用继续通过 `contracts.py` / `facade.py` / DI port，不允许生产业务代码直接跨模块 import 其他模块的 `models.py`、`repositories.py` 或 `services.py`。

场景工作台可以消费：

- `outline`：Scene、剧情线、篇章纲、伏笔、揭示
- `writing`：章节列表和草稿存在性摘要
- `world`：地图摘要
- `memory`：必要的连续性提示

这些消费应通过已有稳定接口或新增稳定接口完成。

## 状态与健康项

健康项可以由已有字段和派生规则生成，不要求第一版新增复杂持久化状态。

建议第一版规则：

- `未复核`：来源为导入 / AI 提取，且状态仍是草稿、候选或缺少人工确认标记。
- `未关联章节`：`chapter_ids` 为空，或存在未归类章节。
- `缺设定`：目标、核心冲突、必须发生、禁止发生等写作关键字段缺失到影响执行。
- `待整理`：人工标记、导入异常、映射冲突、疑似需要合并 / 拆分的结果。

## 验收标准

- 侧边栏出现一级入口 `场景`，带小一号淡色 `Scene`。
- 场景工作台第一屏显示健康筛选和 Scene 列表。
- 健康筛选固定为 `未复核`、`未关联章节`、`缺设定`、`待整理`。
- 右侧详情层可以完整编辑 Scene 字段。
- 桌面宽屏布局保持约 62/38 的主次比例。
- 窄屏下详情编辑进入抽屉或弹窗，Scene 列表仍是主操作面。
- 写作页右侧 Scene 驾驶舱显示 `整理` 小按钮，并能跳转到当前 Scene。
- 大纲页原“场景卡”子标签变成跳转页，不再维护第二套 Scene 管理 UI。
- 合并 / 拆分 Scene 有影响预览和二次确认。
- 合并 / 拆分不直接修改正文。
- 合并 / 拆分后写作页 Scene 树和驾驶舱引用能刷新。

## 测试建议

后端：

- Scene 映射调整保持 novel_id 隔离。
- 合并 Scene 正确迁移章节映射并保留可追踪状态。
- 拆分 Scene 正确生成新 Scene 和章节归属。
- 影响预览不修改数据。

前端单元测试：

- 健康筛选四类渲染和筛选行为。
- 62/38 桌面布局关键结构。
- 窄屏详情抽屉 / 弹窗行为。
- 写作页 `整理` 按钮跳转参数。
- 大纲页“场景卡”跳转页行为。

E2E：

- 从写作页当前 Scene 点击 `整理`，进入场景工作台并定位当前 Scene。
- 未归类章节可以分配到 Scene。
- 合并 / 拆分必须先展示影响预览，确认后才执行。
- 场景工作台修改 Scene 字段后，写作页驾驶舱显示刷新后的信息。
