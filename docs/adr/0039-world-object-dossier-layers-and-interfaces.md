# ADR-0039 — 世界对象档案：信息分层、开放面向与统一接口

- **状态**: Accepted / 分批实施中（C0a 档案存储与兼容接口已提交独立审修；三层聚合、消费者切换与后续阶段仍在执行；用户于 2026-10-15 采纳）
- **日期**: 2026-10-15
- **关联追踪**: ADR-0005（对象类型）、ADR-0017（事实权威）、ADR-0025（知识治理）、
  ADR-0031（依赖方向）、ADR-0035（统一项目词表与锚点规则）、ADR-0036（演化可选阅读步骤契约）、
  ADR-0038（操作目录与留痕）、ADR-0040（写作副驾驶、场景导演与统一提醒）、ADR-0041（世界推进）、
  [世界对象档案、场景导演与写作副驾驶设计](../plans/2026-10-15-world-object-dossier-and-scene-director.md) §4–§5、
  势力路线图（`.agent/tasks/2026/T-20261004-world-edit-history/TASK.md` §4）

## 背景

用户 2026-10-15 先后提出：

- 人物的详细信息，包括性格、外表、喜好、主要经历等，都要记录并持续更新维护；
- 所有世界对象的信息都要像人物一样分层，可高度自定义和扩展，并暴露好接口，能被有效利用；
- 作者设定的有效期在剧情自然覆盖时提醒作者，默认不被剧情覆盖，提供开关。

现状：

- `core_entities` 的可见性只分“公开”和“隐藏”两段文字；种族、势力、地点、规则、物件、秘密各有一张
  类型化 Profile 表，字段固定；自定义类型走 `GenericEntityProfile.data_json`。
- 来源、置信度和证据只记在整份 Profile 上，不能逐条区分作者设定、表格迁移和 AI 补全。
- `EntityProfileTemplate` 有表和修订表，从未接入管理入口。
- 人物 `Character` 是一组扁平文本字段；`current_goal`、`current_state`、`current_emotion` 被直接覆盖，
  回答不了“第 N 章时是什么”。
- `EntityRelation` 没有生效区间。按故事时间生效的对象数据只有 `CharacterKnowledge`。
- Story continuity 的实体维度对 `entity_updated` 只做字典合并，没有按对象类型注册的状态字段；
  逐字段来源链只覆盖位置、保管、锁。
- Evolution 台账已能归纳若干模式，但只给作者看；Story、Evidence、Writing 都不读取台账。
- 各模块读取对象信息的方式各不相同，没有统一接口；深度导入即将下线，档案缺少冷启动来源。

如果在 World 里直接加一批“按章节变化”的字段，会与 continuity 形成两份时间线；
如果让 Evolution 直接改写对象资料，又违背“机器结论只是候选”。

## 决策

### 1. 三层分工，适用于所有对象类型

| 层 | 归属 | 保存的内容 |
| --- | --- | --- |
| 设定 | World 对象档案 | 作者认定的稳定设定，以及作者声明的阶段性设定（带有效期） |
| 时点 | Story continuity | 故事中发生了什么，按 Scene 生效：位置、状况、持有、知情、态度、生死与存续 |
| 理解 | Evolution 台账 | 从正文归纳的倾向和模式，带证据；只是派生理解 |

- 三层各自保持现有的写入权和恢复语义，不新增第三个事实源。
- **档案的唯一写入路径**：档案条目只经 World 的档案修订入口写入，来源是作者编辑（含经助手、
  经界面）或作者采用的草稿与提案。Evolution、导演、推进、导入和助手都只能产出候选或修订预览，
  不得直接写条目。
- 生成、导演、推进和提醒只读三层的投影（§8）。
- 设定与时点冲突时（例如作者写“黑发”，第 40 章正文写“银发”），显示分歧，不自动覆盖任何一方。
  作者设定的有效期另按 §6 处理。

### 2. 面向：按类型的内核加项目扩展

**内核面向**（系统内置，有固定读取语义）：

| 类型 | 内核面向 |
| --- | --- |
| 人物 | 外貌；表达方式（情绪如何外显、习惯动作、压力下的反应、防御方式）；性格；说话方式；喜好与厌恶；习惯；能力与限制；身份与社会位置；价值观与底线；欲望与恐惧；秘密；前史 |
| 地点 | 地理与空间；感官细节（景象、声音、气味、温度、质感）；风貌与人群；资源；危险；规矩与禁忌；历史 |
| 物件 | 形制与外观；感官细节；能力与限制；代价与副作用；来历；意义 |
| 势力、组织 | 形态；理念；架构与职位；资源；规矩；对外关系；历史 |
| 种族 | 外观特征；生理与寿命；文化与习俗；语言；能力与弱点 |
| 规则 | 原理；约束；例外；代价；后果；已知范围 |
| 秘密 | 真相；知情范围；揭示计划；风险 |
| 自定义类型 | 无内核面向；可以声明“借用”某个内置类型的内核面向 |

- 现有的类型化列一一映射到内核面向（例如 `LocationProfile.hazards_json` → 危险，
  `ItemProfile.limitations_json` → 能力与限制，`RuleProfile.consequences_json` → 后果），
  不删除、不改名原有列。
- 势力面向的细节由势力路线图阶段 1 的 ADR 定义，共用本机制。

**项目面向**：作者自定义，或模型在演化中涌现。面向存放在 ADR-0035 §4 的统一项目词表中（种类为“档案面向”），
身份、修订、涌现、合并、墓碑和题材预设的规则与空间类型共用一套实现：

- 至少 2 个 Scene 的证据，经独立复核后启用；之前只显示原文说法；
- 稳定 UUID，修订不可变；模型回读既有面向并复用 ID，可以提议合并；
- 作者的决定优先，之后的演化不得覆盖。

**模板与预设**：

- 面向定义接入 `EntityProfileTemplate`，每个对象类型一套模板（含自定义类型）。
  势力路线图阶段 1 的字段模板与流派预设包共用这一机制，不另建模板系统。
- 提供修仙、西幻、都市、科幻、悬疑五个题材预设，覆盖全部对象类型，可选、可改。
- 确定性检查只读内核面向；项目面向只以文字进入简报。与 ADR-0035“检查只读计算特性”同理。
- 对象类型本身不变（ADR-0005），面向只扩展档案内容。

### 3. 档案条目

每个面向下可有多条条目，字段为：内容、来源、证据引用、可选生效区间、可见性、状态。

- **来源**：作者、作者经助手、演化采用、表格迁移、旧导入、对象补全。
- **证据**：逐字引文和来源区间；作者条目可以没有。
- **生效区间**：锚定到章节或 Scene 的 ID，不用章号；留空表示全书有效。用于作者声明的
  阶段性设定，例如“十年后”“黑化之后”“城破之后”；正文中发生的状态变化归 continuity。
  锚点的解析、Scene 重排与融合替换、锚点删除时的处理，统一按 ADR-0035 §2 的锚点规则。
- **可见性**：公开或秘密；秘密条目可关联揭示计划，读者视角按现有揭示策略过滤。
- **状态**：有效、已过时、待复核（来源失效时）、已被剧情覆盖（§6）。不删除、不改内容。
- 条目修订沿用势力路线图阶段 0 的编辑历史元数据（时间、原因、备注）。

**兼容**：

- 旧接口读取时，把每个内核面向“当前有效”的条目按确定顺序拼回原字段。
- **旧接口写回**：现有更新接口只处理请求中出现的字段（`world/services/core/character_service.py:83`
  的 `exclude_unset`），按旧字段逐个处理：
  - 写入值与当前拼接结果相同：不改任何条目（前端回传整份表单时不会误改）；
  - 写入值不同：写入值成为该面向唯一有效的作者条目，该面向其他有效条目标为“已过时”，保留原内容、
    可以恢复，并在档案界面提示“经旧接口整体改写”；一个面向对应多个旧字段时，条目记录所属旧字段，
    只收拢同一旧字段下的条目；
  - 并发保护不变：`CharacterUpdate.expected_updated_at` 与当前不一致时仍返回 409
    （`world/schemas/characters.py`），其他类型的 Profile 更新接口沿用各自的并发规则。
- `public_info` 和 `hidden_truth` 分别由公开条目和秘密条目汇总而来，旧读法不变。
- 整份 Profile 上的 `source`、`confidence`、`evidence_refs_json` 保留，迁移时作为每条条目的初始来源。
- 人物的 `current_goal`、`current_state`、`current_emotion` 保留，含义改为“作者备注的最新状态”，
  界面标注“不是按章状态”。读取方优先使用 continuity 的时点状态，缺失时才使用作者备注，并标明来源。
- **实施前置 C0**：这三个字段目前被后端 22 个非测试文件（Evidence 上下文编译；World 的模型、schema、
  contracts、repositories、去重、融合、修订、基线；Imports 的 phase1a 与表格迁移；Story 的 schema、
  p20 上下文、Scene 融合草稿、continuity 投影；RP 长记忆评测）和前端 6 个文件读取。动工前先产出
  逐字段映射表（旧列 → 内核面向或注册状态字段）和读取方清单，每个读取方标明“改读接口”或“保持旧读法”，
  并为兼容拼接加回归测试；清单未完成不开始迁移。

### 4. continuity 时点状态字段注册

扩展 P2-A 的 `field_provenance` 注册表，按对象类型新增状态字段：

| 类型 | 状态字段 |
| --- | --- |
| 人物 | 身体状况；情绪；装束与外观变化；当前目标；公开身份与伪装；生死与在场；持有物复用保管 |
| 地点 | 状况（完好、损毁、封锁、被占领等，文字）；环境变化；控制者为势力领地的只读投影 |
| 物件 | 位置、保管、所有（已有）；状况（完好、损坏、耗尽、封印等）；是否已向读者显露 |
| 势力 | 由势力路线图阶段 1 的账本 ADR 定义 |
| 规则 | 生效或失效；已知者 |
| 秘密 | 知情者变化（复用知识维度）；揭示状态（已有） |
| 自定义类型 | 作者可以声明文字型状态字段；确定性检查不读取 |

- 每个字段沿用现有的来源链（exact / unverified / conflict）、读者揭示证明和三视角读取。
- 死亡、毁灭、失效都是状态事件，不删除对象；复活、重建同样是事件。
- 关系事件补充有向、分级的“态度”文字，按 Scene 生效。人物之间、人物与势力之间、势力之间共用同一个
  态度模型。
- 未注册的自由字段继续按原样保留和合并，不迁移、不丢弃，但下游的确定性检查不读取它们。
- 演化观察抽取为注册字段产出机器事件；作者确认的事件优先，规则不变。

### 5. 经历与历史

- 人物的前史、地点和势力的历史、物件的来历都存放在 World 的对应面向，可分多段，可带故事内时间说明。
- 故事内的经历不在 World 另存，由 continuity 事件投影出对象时间线；作者或演化可以把若干事件标为
  “关键经历”并附意义说明，标记归 Story。
- 回忆或史料中写出的前史，由演化作为前史候选提出，作者采用后写入 World。

### 6. 作者设定的有效期与剧情覆盖（用户裁定）

适用于档案条目的生效区间、作者设定的关系有效期；地图（ADR-0035）和势力账本中作者声明的生效区间
采用同一规则。

- 作者设定的有效期保存在 World（条目与关系），默认优先：按截止点读取时以作者设定为准，
  正文中观察到的变化不覆盖它。
- 正文观察到的变化与作者有效期不一致时（例如作者设定同盟持续到第 60 章，第 40 章正文已写到决裂），
  生成“有效期被剧情覆盖”提醒，附双方来源，进入统一提醒（ADR-0040 §13）。作者可以：
  - 调整有效期；
  - 保持设定，将该分歧标为已知并静默（依据变化后可重新提醒）；
  - 修改正文（转 Writing 修改候选）。
- 项目开关“允许剧情覆盖作者有效期”，默认关闭。开启后，在观察点之后以正文观察为准，作者条目标为
  “已被剧情覆盖（第 N 章）”，并提醒一次。开关只改变读取规则，不改写任何数据；关闭即恢复作者优先。
- 检测由 Evolution 在读入新章节时完成，World 只保存设定和开关。
- **对齐键**：确定性检测只针对结构化项，按确定的键对齐：关系按（端点、关系类型），
  状态按（对象、注册状态字段键），地图按（图元或关系 ID、生效区间）。文字型条目（如“性格温和”）
  没有可比较的键，与正文的冲突不做确定性判断，改由演化的档案更新提案提出（模型发现、独立复核），
  进入同一处理流程。

### 7. 身份、化名、群体与类型转换

- 别名可带生效区间；“谁知道甲就是乙”继续走 `CharacterKnowledge`。
- 同一身份更换载体（转世、克隆、意识上传）是状态事件；是否拆成两个对象由作者决定，复用现有对象合并
  与 `EntityTypeTransitionService` 的预览与撤回。
- 群体（“村民”“禁军”）可以建为人物，也可以建为势力或组织。
- 对象在类型之间转换时（例如船从物件转为势力单元，ADR-0035 §5、ADR-0038 §10），面向条目随之迁移；
  无对应面向的条目转为项目面向，不丢弃。

### 8. 统一接口

| 接口 | 作用 | 归属 | 目录等级（ADR-0038） |
| --- | --- | --- | --- |
| 读取对象档案 | 按对象 ID 或查询、截止点、视角、面向和层过滤、预算读取；返回条目、来源、证据、生效区间、可见性、状态、省略说明和 `dossier_fingerprint`；查不到时返回 unknown | Evidence 汇总三层 | R0 |
| 编译对象简报 | 按 Scene 相关性和预算挑选，供生成、导演、推进使用（ADR-0040 §10） | Evidence | R0 |
| 编辑条目 | 增删改条目、生效区间、可见性 | World | R2 |
| 管理面向 | 面向定义、模板、题材预设、涌现面向审核 | World | R2 |
| 处理提案 | 档案草稿与更新提案的列表、批量采用、拒绝 | World | R3 |
| 变化通知 | 档案修订事件进入现有失效通知；导演和推进历史标为“依据已变化”；提醒重算 | World 发出 | — |
| 导入导出 | 表格与 JSON，按面向定义映射；Imports 表格迁移使用同一定义 | Imports、World | R2 |

- 读取接口同时提供 HTTP、助手只读工具和 facade 三种入口，语义一致；所有接口按 ADR-0038 §8 留痕。
- 依赖方向：Evidence 经 world facade 读设定层，经 `story.scene_source` 读时点层，经新增的只读 DI 键读
  台账（消费方 Protocol，组合根注册，先例 `evolution.require_current_world_candidate`）；
  L2 不直接导入 L3 的 evolution（ADR-0031）。
- **依赖表登记**：ADR-0031 依赖表按惯例为每个跨模块 DI 键登记一行。实施时须补登记 evidence / evolution
  一行（既有方向 evolution → evidence；evidence 读台账经新增只读 DI 键，不产生导入边），
  并实测依赖棘轮；与 ADR-0040 §10 是同一个键，只登记一次。

### 9. 冷启动与持续更新

- 世界演化阅读新增可选步骤“对象档案发现”，是 ADR-0036 §1 可选阅读步骤契约的第二个实例
  （第一个新增实例是空间发现）。开关默认值、append 与 continue 继承、失败隔离、根预算内的步骤子额度、
  覆盖四态、补扫、重算取代和契约测试都按该契约执行，本 ADR 不另定。
  - 本步骤专有部分：能力名（实施时注册）；journal 前缀；产出归 World，经 world facade 写入档案草稿与提案；
  - 面向清单与对象既有条目在批次准备时冻结，指纹记入 `consumer_read_set`，不进入方法指纹。
- 产出每个对象的档案草稿，按面向列出条目候选，每条附逐字引文和观察模态。叙述明示、人物自述、
  他人评价、推测分开；自述和评价只算“说法”，不能单独支撑事实条目。
- 之后每次演化读入新章节，生成档案更新提案：新条目、与旧条目的冲突、旧证据失效、有效期被剧情覆盖。
  冲突由作者选择：设定变了（加生效区间）、正文写错了（转 Writing 修改候选）、两者都保留。
- 台账扩类：喜好表现、能力展现、价值取向、关系态度，以及 P4-C 已规划的重要物件、规则后果；
  沿用 P4-C 的不变量和按类别补扫规则。
- 台账条目可以“采用到档案”：生成 World 档案修订预览，带台账条目 ID 和证据。
- 所有草稿和提案都不自动采用。采用经 World 的档案修订入口完成，执行前重验来源与基线。
- 依赖方向：Evolution 经 world facade 提交候选（L3→L2，ADR-0031 已允许）。

## 后果

- World：面向与条目存储、`EntityProfileTemplate` 接入、旧字段兼容读写、有效期与剧情覆盖开关、
  档案修订预览与采用入口、题材预设、类型转换迁移条目。
- Story continuity：按类型的状态字段注册、态度事件、对象时间线投影和关键经历标记。
- Evolution：对象档案发现步骤（按 ADR-0036 §1 登记）、档案更新提案、台账新类别、涌现面向、有效期覆盖检测；
  新步骤有自己的方法指纹，主理解的方法版本不变；旧运行不自动补扫，作者可按契约预览后补扫。
- Evidence：统一读取接口、对象简报、台账只读 DI 键（ADR-0031 依赖表补登记）。
- 每项能力同期注册目录项（ADR-0038），并留痕。
- 实施顺序：C0 映射表与读取方清单 → 条目存储与兼容层 → 统一读取接口 → 演化档案发现与提案。
- 风险：
  - 条目数量膨胀。按相关性选取、设字数上限，省略须披露。
  - 模型把说法当事实。靠模态标注和独立复核控制；评测单列“说法误作事实”的比例。
  - 兼容层把多条条目拼回单个文本字段时可能丢失结构。旧接口写入不同值时会把该面向收拢为一条作者条目，
    其他条目只标“已过时”、可恢复；需要回归测试覆盖“原样回传不改”和“改写后可恢复”。
  - 有效期覆盖提醒过多。按对象分组，可静默；评测单列误报率。

## 备选方案

### A. 在 World 对象上直接加一批按章变化的字段

拒绝。会与 continuity 形成第二份时间线，也绕开了 continuity 的来源证明和三视角读取。

### B. 让 Evolution 直接更新对象资料

拒绝。违背“机器结论只是候选、作者采用”的裁定，也违背 P4-C 的边界。

### C. 每类对象固定一份完整字段清单，不允许扩展

拒绝。题材差异太大（境界、义体、星座、血统、灵脉），固定清单兜不住，与地图类型的结论相同。

### D. 剧情观察默认覆盖作者有效期

不采用。用户裁定作者设定默认优先；剧情覆盖只作为提醒，开关打开后才改变读取规则。

### E. 每个模块各自读取对象数据

拒绝。现状即如此，导致生成、排演、问答看到的人物信息各不相同。统一读取接口由 Evidence 汇总三层，
各模块只调用接口。
