# ADR-0042：导演的多尺度独立探索与可选衔接

- 状态：**Proposed（草案，待采纳；分支工程验证中）**
- 2026-10-17：第一批工程实现已在 `codex/director-scales-impl` 分支交付（离线、gate 默认关）。
- 日期：2026-10-17
- 研究依据：[报告摘要与溯源](../../.agent/tasks/2026/T-20261017-director-layer-design/RESEARCH-BASIS.md)
- 配套计划：[实施计划草案](../plans/2026-10-17-director-scales-independent-exploration.md)
- 关系：拟局部修订 ADR-0040、ADR-0041；未采纳前，原决策继续有效。

## 用户已裁定的产品方向（2026-10-17）

1. 以自由描述问题为入口，优先无缝接入助手或通用 AI 工作台；智能推荐观察层级，允许手动指定。
   后续用户教程须介绍这一能力及其使用方式。
2. 可以直接临时探索，主要依靠模型自有知识，以及作者开启时的联网功能；系统建议相关项目资料，
   作者确认范围后使用，不以先建正式场景或资料齐备为前提。
3. 输出焦点和详略同样智能推荐、允许手动指定；支持直接对助手说“说详细点”等自然语言调整。
4. 助手可以按目标自主选层、按需跨层，在已确认范围与预算内完成；不要求作者逐层发出指令。
5. 首批在三层各选择少量高价值任务，优先验证独立使用和助手接入，不先将某一层做成大而全的系统。

以上五项已确认；ADR 整体仍为 Proposed，不据此启动实现或改变其他未裁定事项。

## 背景

作者希望根据当次问题选择观察尺度：沙盘看条件与局势，事件看一件事如何成立和产生后果，
场景看此时此地的行为与表达。用户明确要求每层方便单独使用，不能限定为“发现事件、展开冲突、
进入场景排演、挑素材写作”的完整流程。

现有世界推进和场景导演已有候选、资料确认、预算、历史和分支能力，可以继续复用。
但在本工作树 `a479e006bc336c0009e5207f7659609ab483e901`：

- 世界推进请求可省略 `scene_id`，服务仍从最新已写章节解析实际 Scene，不能无正文开局。
- 场景导演的输入、根记录与参考绑定 Scene，要求已有角色；素材 schema 要求完整角度和变体。
- 世界推进转导演把未来描述放在作者侧指示里，角色沿用原 Scene 资料；尚非完整候选未来状态移交。

因此只改入口名称、隐藏输出或把一个 Scene 字段改可空，都不能满足独立使用。
研究支持探索可调抽象和按需协作，但没有证明三尺度必然提高当前模型表现、减少费用或适合所有作者。
本 ADR 的入口、输出和优先级均是待验证的产品选择。

## 决策

### 1. 三种观察尺度，各自完成作者任务

| 尺度 | 独立用途 | 最小有用结果示例 |
| --- | --- | --- |
| 沙盘 | 规则/资源后果、制度和关系变化、条件比较、日常生活 | 一条有条件的影响解释，含机制、受影响者和未知 |
| 事件 | 起因、动机、行动响应、信息流、成败与余波 | 一段可信路径、一个因果补桥或原案诊断 |
| 场景 | 一句回应、一个动作、人物差异、视角、空间与氛围 | 可独立参考的局部表现或修改建议 |

尺度不是流程阶段、时间长度、人数限制或新的事实权威。两个人二十年的关系可以用沙盘视角，
十个势力的一次投票可以是事件；场景也可以只有观察、陪伴、劳作或真诚交谈。
人物关系等任务可横跨尺度，章节规划和正文写作继续由既有能力承接。

每层必须可直接开始、查看首次结果、局部修改、同起点比较、保存、离开恢复、同层继续和退出。
不要求存在上层产物，不强制进入下一层、写正文或采用。事件能力须独立可调用；不据此新建第三套工作台。

### 2. 自由问题为主，可选尺度与就地入口

以自由描述问题为主入口，优先融入既有助手或通用 AI 工作台；作者不必先找到“导演”专页。
在世界对象/设定、大纲和写作位置提供携带选中内容的就地入口，指向同一任务及结果。
复用现有世界推进、导演界面的编辑与结果能力，不预建三个独立站点或引擎。

系统根据问题和当前上下文智能推荐尺度，作者可用自然语言或界面手动指定；不要求先选层级。
推荐结果可调整，手动指定优先于推断；推荐与执行范围对作者可见。常见任务不要求先分类或填写长表；仅在缺少信息会改变目标、正确性或
安全边界时追问，否则显示最小假设与未知项。所选资料、时间基准和隐私边界仍需明确，不能静默扩大。
首次结果后按需展开时间跨度、参与者、输出焦点和推演量；这些参数分别处理。

三类意图贯穿各尺度：探索寻找可能走向；导向保留作者指定结果、查找可信路径；诊断检查已有材料。
诊断不自动改稿；导向无可信路径时报告缺项或需放宽条件，不让角色迎合作者结局。
比较、追因和局部细化是后续操作，不再叠加必选模式树。研究的 21 分支用作任务覆盖，不照搬成首屏菜单。
后续用户教程纳入自由提问、三尺度独立使用、智能推荐/手动指定、调整详略、资料与联网选择，
以及保存/恢复和可选跨尺度衔接的实例；教程不成为使用前置。

### 3. 支持已有场景与临时起点，保留证据边界

输入采用显式区分的起点契约，以下名称为拟定内部概念，不直接暴露给作者：

| 起点 | 必需语义 | 限制 |
| --- | --- | --- |
| 已有场景锚点 | 所属作品、Scene/正文版本、时间截止、已确认资料与角色可知范围 | 按当前资料重新物化同一 confirmation；不得越过截止或带回排除资料 |
| 临时假设起点 | 作者问题/片段、假设、固定条件、临时参与者及其已知/误信，可用模型知识、可选联网和已确认项目资料 | 无需正式 Scene/角色；未选项目资料不自动补入，未知角色知识不视为已知 |

临时探索主要依靠模型自有知识、作者问题与假设，以及作者开启时的联网功能；可以完全没有项目事实。
系统可建议相关项目资料，作者确认范围后使用；必须记录精确版本、来源和时间解释。
确认可沿用本次仍有效的选择与授权，不因普通补充反复弹窗；带入新资料或改变范围时才更新确认。
已有历史锚点可作为临时分支基底，假设未来变化另存候选差量。没有锚点时不暗用“最新已写 Scene”或
“整部作品所有事实”，也不声明完成了基于正史的时点/角色知识检查。

Evidence 拥有两类起点的资料编译、确认与角色投影。临时起点需要新增可版本化的确认语义，
不能伪造 Scene，或把未确认的候选差量在编译之后拼进 Context。
确认须绑定选中来源、排除项、时间基准、假设及可见性指纹；worker 使用同一确认重新物化。
无法安全物化、跨作品、过期或知识边界缺失时，在业务模型调用前停止相应任务。
无需项目资料的临时任务也记录假设和项目资料范围为空；这不禁止使用模型知识或已开启的联网资料，
也不代表角色获得隐式全知。

模型知识用于构思和一般常识，不伪称已经检索或事实核验；联网结果保留来源、读取时间和实际覆盖，
外部资料与模型推测均不自动成为作品正史，也不覆盖已确认的作者规则。联网关闭时不发起检索；
开启但不可用时如实说明，可基于模型知识继续不依赖核验的探索，需要核验的部分保留未知。
联网沿用助手既有渠道、权限和预算，不因导演推荐而自动开启，不把选中项目材料默认拼成公开检索词。

临时人物/地点使用独立候选身份空间，不冒充已采用对象；同一分支内稳定引用。
引用真实对象仍执行 owner、`novel_id`、版本与可见性校验；临时身份不能用于正式对象写入接口。

### 4. 输出按任务收窄，保留完整排演

普通问题默认一个有界任务，交付足够回答当前问题的内容。只需要一句回应时，不生成所有人的完整
表演卡、全景素材及固定数量角度；只需规则后果时，不逐人演完。输出必须带条件、依据/发挥和未知，
但可以用紧凑结构呈现。

系统智能推荐输出焦点与详略，作者可事前手动指定，也可在结果后对助手说“说详细点”“只看对白”
或“完整排演”。后续要求绑定当前问题和选定结果，沿用已确认资料、固定条件和分支；
纯展示展开不重复调用模型，需要新生成则追加局部任务/子结果，保留原版本。
“说详细点”不自动意味着换层级、扩大资料、开启联网或重写全部内容；超出原执行授权时更新预览与授权。

后端按已确认任务选择版本化输出与工作步骤，实际减少无关生成和调用；不能仅在界面折叠全量结果。
完整场景排演继续提供原有表演、素材、角度、发散度、人物重写及作者选择的多轮能力，按需展开，
不因新增轻量任务削减已授权能力。不新增低固定人物/轮数产品上限；沿用预算、容量和省略披露。

局部修订以不可变原结果为父版本，锁定作者满意部分。只重算选择项及已证实受影响内容；
如改变前提影响其他部分，先明确影响范围，不静默重写。诊断结果和实际修订是分开的操作。

### 5. 跨尺度可选、双向、可跳层

作者可选择任一结果片段继续同层、放大、看整体影响或反向追因，也可以直接沙盘与场景往返。
助手也可根据作者目标自主选层、选择相关候选并按需跨层；目标授权覆盖的资料、能力和预算内
不逐层弹窗确认。执行路线、带入条件、资料与时间解释以及进度对作者可见，作者可修改、停止或指定只做某层。
不因三层存在就固定顺序跑完；目标已满足则停止。新增资料、联网许可、超出能力/预算范围或正式采用
仍沿用相应确认门禁；目标授权不等于自动采用。

移交须绑定以下语义，具体 schema 版本由实施契约确定：

- 不可变来源运行/分支/结果版本、所选内容及其哈希；记录作者选取或助手在目标授权内选取及其理由，
  只带入所选候选差量，不含其他分支。
- 来源 confirmation、Context/隐藏守卫指纹、正文来源与读集；基底时点和假设目标时点。
- 成立条件、作者固定项、未知、未结承诺；参与者各自观察、信念、信息接触与可公开刺激。

摘要只用于阅读导航，不能替代完整受限状态。目标尺度经 Evidence 重新编译、确认和重验；
作者私密目标与导演全知内容不得整包交给角色。选定未来候选必须建立新假设分支，
保持原 Scene 截止；不得把后序正史读回旧 Scene，也不得把候选未来标成真实发生。

父结果不变。上游条件后来修改时，定位依赖它的下游结果并标记依据变化；保留历史、说明具体冲突，
由作者选择重新推演，不自动追改父分支或所有后代。

同一运行内继续和分支共享原根授权/信封，不能新建子根重置预算。目标已授权的跨能力步骤
计入同一目标总预算，各领域额度与回执可核对，沿用现有根预算/租约，不因转层重复索取已覆盖授权。
另起独立目标时建立新的明确授权根，保留来源关联，独立预览和计费；来源关系本身不继承执行权限，
不能自动补钱、转移额度或重置未知用量。

### 6. 保存、参考与采用分开

探索问题、确认资料、所选起点和不可变结果由 Story 保存；每层都能恢复，不依赖写作页仍打开。
保存探索不创建正式 Scene、World 事实、continuity、已采用剧本或正文。候选明确标识，
作者可以只收藏、对照或停止，不要求采用。

既有 Scene 参考剧本继续遵守 ADR-0040 §8 的可选参考语义与同场景消费边界。
临时结果不伪装成这种引用；如以后需用于某个正式 Scene，作者显式选目标与内容，
经新资料确认和知识/来源校验形成独立参考副本，原探索保持原样。采用到正式资产仍走所属领域既有
确认、版本/CAS 和事务，不新增自动采用。

历史沿用不可变结果、同级重来/子分支、作者删除及恢复规则。服务端成功才显示“已保存”；
仅本地备份须明确标识，两者均失败则保留当前草稿并在离开前提供可核对的保护路径。
旧运行按原协议和输出版本读取，不能把旧数据重新解释为新任务；新功能关闭后仍能读取已保存结果。

### 7. 领域职责和运行约束

| 所属模块 | 本次职责 |
| --- | --- |
| Story | 任务意图/尺度、探索起点、编排、候选结果、分支历史和依赖；复用导演、世界推进和 `simulation_v3` |
| Evidence | 来源与时间语义、假设覆盖层的确认、可见性/角色知识投影、同一确认重物化 |
| World / Writing | World 经稳定接口提供资料；Writing 提供正文来源及就地入口，按既有路径消费选定参考 |
| Project / 任务与 LLM 基建 | 已验证项目连接、secret-free snapshot、根预算/租约、幂等回执与恢复 |
| Assistant / 前端桥接 | 自由提问主入口、层级/详略推荐及手动覆盖、自然语言继续；注册领域操作、复用联网与留痕，不接管 Story 编排或另建流程事实源 |

跨模块只经 facade/contracts 或已注册 DI；不建新常驻服务、存储、通用多 Agent 平台或自治社会。
一般任务使用确定性工作流；新增调用必须有可说明职责。需要角色模拟时沿用既有有界机制和知识隔离。
按目标选层和跨层由助手在已注册的受限操作目录内选择；Story 保持任务、候选移交和执行规则的领域所有权。
不让模型改写服务端工作步骤或创建任意工具/自治团队。
不因尺度切换新增模型选择或自动回退。开发业务调用继续遵守项目 facade/snapshot 与 `gpt-6-luna/max` 约定。
未知计费/结果停止并保留回执，不盲目重试；封存评测不重跑、不重绑、不自动续跑。

### 8. 兼容与生效范围

仅在本 ADR 获采纳且相应切片完成后，按下表增补既有决策。本文不宣称旧代码已改变。

| 原决策 | 拟修订范围 | 保留范围 |
| --- | --- | --- |
| ADR-0040 §1、§5–§7 | Scene 锚点成为一种起点；新增聚焦输出，完整表演/素材不再是所有任务必填 | 已有场景入口、完整排演、人物差异与作者选择的多轮能力 |
| ADR-0040 §3、§8–§9 | 增加临时候选引用及输出版本；独立探索历史和新起点恢复 | `simulation_v3` 已有结算语义、旧协议只读、参考非采用、不可变历史与删除恢复 |
| ADR-0041 §1、§3、§6–§7 | 增加临时沙盘/事件开局、紧凑任务输出和有确认的双向候选移交 | 自由/导向、推进步、显式多步授权、候选采用与事实权威 |

ADR-0039 档案建设、统一提醒、RP 协议迁移、地图增强及其尚未完成的验收不并入本任务。
已有安全与知识规则不因旧 ADR 中“容量不足不拒绝”等表述而失效；无法满足授权/可见性时必须停止。

## 备选方案与取舍

- **只增加三个模式按钮**：修改少，但实际 Scene 依赖和全量输出仍在，不能满足独立使用。
- **自由入口，无尺度选择**：保留为简化方向；若尺度选择增加犹豫却未改善结果，应回退到此形态。
- **三个专用工作台/引擎**：定位清晰，但重复状态、交接和学习成本更高；目前没有任务证据支持。
- **强制逐层细化流水线**：便于完整生产，但排除了单层、小问题和逆向工作；不满足用户明确要求。
- **持续自治世界、多模型/多 Agent 扩张**：成本、状态和知识风险增加；没有本项目收益证据，本次不引入。

## 后果、验证与重新评估

收益假设是作者以更少前置材料解决更具体的问题，并保留已有能力；代价是新的起点确认、输出版本、
历史兼容及跨尺度依赖语义。宏观抽象未必更便宜，分解也可能丢条件或放大错误。

工程门禁覆盖隔离、确认、时间/知识、幂等、预算、保存恢复和历史兼容；模型评测与真实作者验证分列。
在相同模型、资料和总预算条件下比较现入口、自由入口和可选尺度入口，计入作者阅读、修正与恢复成本。
