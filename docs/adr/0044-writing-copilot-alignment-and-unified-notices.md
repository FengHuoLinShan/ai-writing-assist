# ADR-0044 — 写作副驾驶对齐与统一提醒

- **状态**: Proposed（产品方向由用户 2026-10-15 裁定；技术方案待评审）
- **日期**: 2026-10-15
- **关联追踪**: ADR-0023（有界 Agent 核心与项目助手）、ADR-0031（依赖方向）、ADR-0036（演化空间发现）、
  ADR-0037（地图参考维度与空间提醒）、ADR-0039（统一操作目录）、ADR-0040（操作留痕）、
  ADR-0041（世界对象档案）、ADR-0042（场景导演）、ADR-0043（世界推进）、
  [世界对象档案、场景导演与写作副驾驶设计](../plans/2026-10-15-world-object-dossier-and-scene-director.md) §7

## 背景

用户 2026-10-15 要求：原有写作副驾驶的提醒机制要与场景导演结合，导演本身就是写作副驾驶的高级扩展；
写作副驾驶的各项机制要同步对齐或重构到项目最新计划。

现状：

- 写作页右侧的 Scene 驾驶舱（`frontend-console/vue/views/writing/components/SceneCockpit.vue`）有警报、
  人物、地点、本场四个标签。警报（`sceneAlerts.js`）只在前端组合结构缺项和最近一次冲突检查的状态，
  不调用模型、不持久化、不能处置。
- 其他提醒分散在各处，入口、严重度和处置方式各不相同：
  - 冲突检查结果与来源失效、重算提示归 Writing；
  - 短期前瞻 notice 归 Assistant（`assistant_notices`：`fingerprint` 唯一、
    `unread / read / snoozed / dismissed`、`row_version` 并发控制）；
  - 编辑员级意见归 Assistant 的审读队列；
  - G8a、G8b 地图核对，以及 ADR-0037 新增的空间提醒。
- 本轮设计又新增了多种提醒：对象一致性（ADR-0042）、档案草稿与更新提案（ADR-0041）、作者有效期被剧情覆盖
  （ADR-0041 §6）、世界推进提醒（ADR-0043）。如果各自再开入口，作者无法掌握全局。
- 副驾驶仍保留即将下线的深度导入按钮与审计弹窗，场景自动提取依赖导入流程；人物、地点标签只读 World
  的局部资料，不读时点状态和台账。
- 2026-07 的方向研究曾把“警报按来源过滤”和“窄的只读 Scene 状态投影”列为候选，至今没有做。

## 决策

### 1. 统一提醒：各领域保有结论，副驾驶统一展示

- 各领域继续拥有自己的检查结论和处置，不新建问题真相表，也不新增 `review` 模块。
- 新增提醒来源登记表 `app/notice_source_registry`，与 `app/assistant_operation_registry` 相同的装配方式：
  领域插件只导出纯数据规格（来源名、类别、只读“列出提醒”的函数），由组合根物化（ADR-0031）。
- Assistant（L4）提供只读聚合接口，按章节或 Scene 返回统一条目（例如
  `GET /api/assistant/notice-feed?novel_id=&scene_id=`）。Assistant 可以读取各领域，不新增依赖边。
- 首批来源：

| 来源 | 归属 | 处置 |
| --- | --- | --- |
| 结构缺项（目标、冲突、POV、待复核、未对应章节） | Story | 统一处置（§3） |
| 冲突检查结果（规则层与 AI 复核） | Writing | 沿用条目状态 |
| 来源失效与重算提示 | Writing | 沿用现有进度 |
| 短期前瞻 | Assistant | 沿用 `assistant_notices` |
| 编辑员级意见 | Assistant | 沿用审读队列 |
| 地图空间提醒、G8a/G8b 地图核对 | 地图、Writing | 统一处置 |
| 对象一致性提醒 | Writing、Story | 统一处置 |
| 档案草稿与更新提案 | World | 沿用提案审核 |
| 作者有效期被剧情覆盖 | World、Evolution | 统一处置 |
| 演化阅读状态（新章节未读、读取失败、待复核） | Evolution | 统一处置 |
| 世界推进提醒 | Story | 统一处置 |

### 2. 统一条目字段

- 稳定键 `notice_key`（来源、类别与目标的确定性组合）；
- 来源域与类别；严重度：高、中、低、信息；
- 目标：章节、Scene、正文区间、对象、地图节点；
- 摘要与证据引用；
- 依据指纹（来源计算，用于判断是否过期）；
- 建议动作：操作目录的 `op_id`（ADR-0039），例如改正文、改档案、改地图、去查看；
- 处置状态。

读取时重验依据指纹；过期的条目标为过期，不作为当前问题展示。

### 3. 处置

- 已有处置机制的来源继续使用原机制，聚合接口只做转发：前瞻用 `assistant_notices` 的决定入口，
  冲突检查用条目状态，编辑员意见用审读队列，档案提案用 World 的提案审核。
- 没有处置机制的提示类来源使用统一处置：语义沿用 `assistant_notices`（已读、稍后、忽略，`row_version`
  并发控制），存放在独立的处置记录中，按 `notice_key` 与依据指纹记录，另支持“按类别静默”。
  聚合条目不复制进 `assistant_notices`，避免主动提醒列表混入。
- 依据指纹变化后，被忽略的条目可以重新出现；按类别静默不受影响，直到作者取消。
- 处置动作注册为目录项（R2，可恢复），按 ADR-0040 留痕。

### 4. 降噪与边界

- 按来源和类别分组；严重度排序；默认只展开中级以上；可以按类别静默。
- 主动推送沿用持续授权与每日额度，不另设额度。
- 只提示，不拦截。既有领域门禁不变，例如 AI 候选采用要求知识复核通过、发布前提示部分完成检查。

### 5. 副驾驶机制对齐

副驾驶对齐后有四个标签：本场、对象、导演、提醒。

| 现有机制 | 对齐后 |
| --- | --- |
| 本场 | Scene 结构、按截止点的时点状态视图、空间简报（ADR-0037），加导演入口 |
| 人物、地点 | 合并为“对象”标签，按类型分组；读取统一对象档案接口（ADR-0041 §8）：设定、本场时点状态、态度、倾向、关键经历；保留“查证” |
| 警报 | 改为“提醒”标签，展示统一提醒，可处置、可静默、可跳到修复动作；`sceneAlerts.js` 的确定性组合改为 Story 的结构缺项来源 |
| 状态试验（钥匙与锁） | 原接口保留；入口并入导演的“介入”（ADR-0042 §2） |
| 深度导入按钮与审计弹窗 | 随深度导入下线，替换为“演化阅读：读入本章／续读”（演化 append） |
| 场景自动提取 | 改用演化阅读的 Scene 准备（演化已经通过 Imports facade 的纯切分边界处理未整理正文） |
| AI 生成 | 消费已采用的素材剧本与角度（ADR-0042 §8）；声明 `map_spatial`、`object_dossier`、`character_pattern` 参考维度 |
| 冲突检查 | 规则层加入对象一致性确定性检查（ADR-0042 §12）；结果进入统一提醒 |
| 短期前瞻 | 作为副驾驶的“下一步建议”；人物反应以对象简报为依据、按表演卡格式输出 |
| 编辑员级意见、批注修订 | 机制不变，在统一提醒中显示入口 |
| 失效提示、重算面板 | 在统一提醒中显示；失效来源包括演化与档案修订 |
| 故事结构浮窗 | 增加人物弧线：作者计划的弧线与实际发生对照 |
| 作者写作示例 | 同时约束导演表演卡的笔触 |

- 副驾驶的全部动作注册为操作目录项（ADR-0039）并留痕（ADR-0040），助手可以代为执行。
- 状态试验、查证、冲突检查等现有 HTTP 接口保持兼容，旧前端入口在新标签上线后移除。

## 后果

- 组合根：新增 `app/notice_source_registry`。
- Assistant：聚合读接口、统一处置记录与静默规则。
- 各领域：注册只读提醒提供者；Story 承接结构缺项的计算（原在前端）。
- Writing 前端：副驾驶四个标签；移除深度导入入口与审计弹窗；场景自动提取改走演化。
- 评测：植入错误样本上的提醒召回率、真实样本上的误报率、处置后重现是否正确、过期条目是否被正确标注。
- 风险：
  - 聚合读接口调用多个来源，延迟上升。按 Scene 读取、来源并行、单来源失败时局部降级并标注，
    不影响其他来源。
  - 提醒过多造成疲劳。分组、静默、严重度排序；默认只展开中级以上。
  - 统一处置与来源处置语义不一致。已有处置机制的来源只转发，不复制状态。

## 备选方案

### A. 新建统一的问题真相表，各领域写入

拒绝。会形成与各领域结论并行的第二份状态，同步与失效都变复杂；各领域已有自己的处置。

### B. 继续在前端组合提醒

拒绝。前端无法持久化处置，也无法让助手读取或代为处理；结构缺项的计算应属于 Story。

### C. 统一提醒放在 Writing

不采用。来源横跨 World、Story、Evolution、Assistant，Writing 是 L2，读取 L3、L4 的来源需要额外 DI 键；
Assistant 作为 L4 读取各领域符合 ADR-0031，且已有 notice 与持续授权机制。

### D. 保留深度导入入口直到演化完全替代

不采用。用户已裁定深度导入下线，由世界演化替代；副驾驶入口随之替换，避免作者继续走旧流程。
