# ADR-0039 — 统一操作目录、风险分级与目标运行

- **状态**: Proposed（产品方向由用户 2026-10-15 裁定；技术方案与两项待裁定待评审）
- **日期**: 2026-10-15
- **关联追踪**: ADR-0013（operation receipt）、ADR-0023（有界 Agent，本 ADR 修订其写入确认规则的适用范围）、
  ADR-0027（有限协作）、ADR-0029（本机 CLI 只做图片）、ADR-0031（依赖方向）、
  ADR-0032（引导流程）、ADR-0038（助手地图与势力操作）、ADR-0040（操作留痕）、
  [全模块 AI 操作入口设计](../plans/2026-10-15-agent-operation-surface.md)

## 背景

用户 2026-10-15 要求：开放或增加各模块的 agent/AI 操作入口，方便 AI 自主规划和操作，完成用户的目标；
同时操作要留痕，便于以后把常用操作代码化。

现状（main `4efe7f21a`）：

- **入口少**：助手只有 47 个业务操作，分布在 6 个模块；后端约 430 个写接口大多没有 AI 入口。
  evolution、interaction、collaboration 等模块没有助手操作。
- **权限只有两档**：`suggest` 在运行内直接执行，`confirm` 由作者按批确认（一次最多 20 项）。
  操作没有声明费用、可否撤销、前置条件和产出。
- **目录发现方式无法扩展**：`available_operations` 一次返回全部操作的完整 schema，操作增多后放不进上下文。
- **自主程度受限**：
  - 单轮 Agent 有严格预算（ADR-0023）；
  - 引导流程只能由服务端注册（ADR-0032）；
  - 协作蓝图是只读调查（ADR-0027）。

  作者的跨模块目标需要多轮对话、反复确认才能完成。

ADR-0023 与 ADR-0027 明确不授权：自治多 Agent、任意代码/SQL/文件访问、绕过业务门禁、通用自治 API。
本 ADR 保持这些排除，只在“注册操作 + 作者授权 + 预算”的框架内扩大自主程度。

## 决策

### 1. 界面与 AI 共用一份操作目录

- 每个领域命令登记一个目录项。HTTP 路由和 AI 调用走同一个领域服务、同一套校验。
- 在现有 `AssistantOperation` 上加性扩展以下字段：
  - `op_id`（`模块.对象.动作`）与版本；
  - 给模型看的说明；
  - 风险等级（第 4 条）；
  - 费用类别（免费、付费模型、付费图片）；
  - 可撤销性；
  - 声明式前置条件；
  - 产出类型；
  - 目标类型；
  - 是否对 AI 开放；
  - 留痕规则（ADR-0040）。
- 领域插件仍只导出纯数据规格，经 `app/assistant_operation_registry` 物化（ADR-0031），
  不新增模块依赖边。
- 界面写路由逐步声明对应的 `op_id`，由一致性测试保证校验相同。这不改变界面的交互方式。

### 2. 覆盖原则与排除类别

- 作者能在界面上完成的创作类操作，原则上都提供目录项；读取能力以只读工具提供，
  经 Evidence 和领域 facade，遵守排除范围与可见性。推进顺序按使用频率（ADR-0040 的留痕）和价值。
- 以下类别不对 AI 开放，除非另立 ADR：
  - 凭据与模型连接；
  - 账户、登录、会话与分享；
  - 本机 CLI 配对与设备权限；
  - 删除作品、彻底清除；
  - 修改 AI 自己的授权、预算或持续授权；
  - 向系统外公开发布或导出；
  - 任意代码、SQL 和文件访问。

### 3. 按需发现

- `available_operations` 改为两个工具：
  - `find_operations`：按查询、模块和目标类型返回少量候选，只含名称、摘要、风险和费用；
  - `describe_operation`：返回单个操作的 schema、前置条件和产出。
- 每次运行冻结目录指纹；新操作只进入新运行，旧运行的冻结目录不变。

### 4. 风险分级

| 等级 | 含义 | 单轮助手 | 目标运行 |
|---|---|---|---|
| R0 | 只读 | 自动 | 自动 |
| R1 | 产生候选或建议，不改作者资产（可付费） | 自动，计入运行预算 | 在目标预算内自动 |
| R2 | 修改作者资产，可从版本历史恢复 | 按批确认 | 默认停下确认；作者可为本目标选择自动执行（待裁定） |
| R3 | 采用、发布、影响正史 | 按批确认 | 始终停下确认 |
| R4 | 超出预算的付费、外部执行或不可逆 | 单独确认 | 始终单独确认 |

- 每个目录项必须声明等级。测试检查：涉及采用或正史的操作不低于 R3，不可撤销的不低于 R4。
- 现有 `suggest` 对应 R1；`confirm` 按实际效果归为 R2 或 R3。

### 5. 目标运行

- 新增运行类型 `goal_run_v1`，复用 `assistant_runs`，不建新表；计划修订和步骤状态写在运行检查点中。
- 流程：
  1. 作者给出目标；
  2. 模型读取现状并生成计划；
  3. 作者在计划卡上审批，可删改步骤、调整预算、选择自动执行上限；
  4. 服务端引擎逐步执行；
  5. 进度按产物推导（与 ADR-0032 相同）；
  6. 失败或资料漂移时在已授权范围内重新规划。
- 计划是数据：
  - 步骤只能引用目录项，步骤数设上限（暂定 30），依赖为无环图；
  - 参数可以类型化地引用前序产出，不允许任意表达式；
  - 列表展开设数量上限。
- 每步 `operation_id = uuid5(目标运行, 步骤, 参数指纹)`，重复推进不重复执行、不重复付费（ADR-0013、ADR-0032）。
- LLM 只用于规划、重新规划，以及操作内部原有的调用；执行推进由确定性代码完成。

### 6. 授权与停点

- 审批一个计划，就授权其中声明的范围（模块、目标对象）、预算（请求、金额上限、时限）和自动执行上限。
- 运行停下请示作者的情况：
  - 遇到 R3、R4 步骤；
  - 预算用到 80%；
  - 出现结果未知的付费请求；
  - 目标对象有歧义；
  - 计划修订扩大了范围或等级；
  - 资料冲突且无法在范围内重新规划。
- 正文、网页和资料只是数据，不能扩大计划范围或授权。
- **本条修订 ADR-0023**：在作者审批的目标运行内，R0 和 R1 可以连续自动执行；
  若作者为本目标开启 R2 自动执行，R2 也可以。单轮助手的确认规则不变。

### 7. 并发、撤销与恢复

- 同一项目同时只有一个活动的目标运行。作者手动修改了目标对象时，相关步骤失败关闭并重新规划。
- 自动执行的 R2 步骤记入目标的变更清单，可以一键恢复到目标开始前的版本。恢复走领域原有的恢复操作。
- 运行可以暂停、停止和恢复。恢复不重置累计预算，取消沿用现有传播语义。

### 8. 开关与验收

- `ASSISTANT_GOAL_RUNS_ENABLED` 默认关闭，项目白名单沿用现有机制。
- 开启前须完成目标运行评测：按五类题材准备目标，评估完成率、步数、作者介入次数、费用、
  越权尝试次数（必须为 0）和执行后撤销率。评分沿用 Sol/xhigh，代理验收保留 `human_validated=false`。

## 后果

- 各模块需要按覆盖计划补充目录项。现有 47 个操作要补齐等级、费用和可撤销性等字段，
  并改用按需发现。
- Assistant 需要新增计划审批界面、执行引擎、目标预算和变更清单。
- 留痕（ADR-0040）显示反复出现的目标运行计划，可以代码化为引导流程或组合操作，
  让常见需求不再支付规划费用。
- 风险：
  - 开放面扩大后，提示注入的影响面也随之扩大；
  - 界面与 AI 两条路径的校验可能漂移；
  - 规划质量不足会浪费费用。

  这些分别由等级上限与计划审批、一致性测试、默认关闭加评测控制。

## 待裁定

1. 目标运行是否允许作者按目标开启 R2 自动执行。建议允许，默认关闭。
2. 外部 Agent（例如通过 MCP）调用产品操作：ADR-0029 已删除本机工具中继，本 ADR 不做，需要时另立 ADR。

## 备选方案

### A. 只给现有助手加更多操作，不分级、不做目标运行

不足。操作增多后目录放不进上下文；跨模块目标仍需要逐轮确认，达不到“自主规划、操作”。

### B. 由模型编写流程脚本或 DSL

拒绝。违背 ADR-0032 “模型不可定义可执行流程”，也难以校验与回放。

### C. 所有写入都自动执行，事后撤销

拒绝。采用和正史变化影响下游的生成和审稿，事后撤销不足以消除影响；付费和外部执行无法撤销。

### D. AI 直接调用 HTTP 路由

拒绝。会绕过预览、范围检查、风险等级和留痕；操作目录才是 AI 的唯一入口。
