# ADR-0010 — 公开浏览器账号：本地会话、邮箱 OTP 与 Authing 微信

- **状态**: Accepted（LLM Key 所有权与出站配置由 2026-07-29 补充决策修订）
- **日期**: 2026-07-23
- **决策来源**: 用户明确批准公开注册一期方案

## 背景

系统从共享访问令牌的封闭测试进入低用户量公开注册。现存项目属于一个待认领测试账号。
本 ADR 原先把 LLM Key 继续放在项目内；2026-07-29 根据双入口和账户设置决策，已修订为
账户级 provider 连接。当前产品只支持浏览器，不做协作、多设备管理、邮箱修改或管理员
项目访问。

## 决策

1. `account` 模块拥有本地账号、单一外部身份、浏览器会话、邮箱验证码、协议同意和安全
   事件。跨模块只通过 facade/contracts 获取当前 owner 或检查账号状态。
2. 邮箱验证码由专用私人邮箱 SMTP 发送。验证码 6 位、5 分钟、单次使用、最多 5 次错误，
   60 秒不可重发且每邮箱每小时最多 5 封。数据库只保存邮箱与验证码的 keyed HMAC。
3. 微信采用 Authing 托管登录与 OIDC authorization-code + PKCE。OIDC 入口默认关闭；
   只有完成 Authing、微信开放平台配置和真实扫码 smoke 后才能启用。
4. 邮箱身份与 Authing 微信身份永不自动绑定或合并。每个账号只有一条主身份。
5. `projects.owner_id` 是非空账号外键。项目门禁同时验证 owner 与账号 active；跨 owner
   统一表现为 404。全局设置按同一 owner 解析。经 2026-07-29 修订，LLM Key 按
   `owner_id + provider_id` 加密保存在 `account_llm_credentials`，项目不保存 Key。
6. 公开会话采用随机 HttpOnly Cookie，数据库只存 HMAC；每账号仅一个有效会话。会话有
   7 天空闲和 30 天绝对期限，写请求校验同源、XHR 和 CSRF。敏感操作要求 10 分钟内按
   原登录方式重新认证。
7. 删除申请进入 30 天 `pending_deletion`。期间项目不变但任务立即取消；到期 CLI 幂等
   清除在线数据。备份自身最多再保留 30 天，政策披露最坏约 60 天残留。
8. 运行模式明确为 `local / closed_test / public`。共享 `APP_ACCESS_TOKEN` 只属于
   `closed_test`；公开模式禁用调试 API 与 OpenAPI，并要求账号密钥、SMTP、HTTPS 基址和
   已认领 bootstrap 账号。
9. 公开模式只使用账户设置中受控的 DeepSeek/Kimi 模板与固定 HTTPS Base URL，不开放
   用户自定义兼容地址；`LLM_TRUST_ENV` 不能替代出站边界。本地测试中的窄 mock/loopback
   适配不构成公开产品能力。
10. 浏览器只保留账号标记和项目工作态缓存。首次进入账号、切换账号或退出时清除所有
    项目内容、草稿、任务恢复信息和诊断缓存，仅保留不含账号数据的主题偏好。

## 结果与非目标

一期提供登录、退出、重新认证、删除与恢复，以及仅展示账号元数据的运维 CLI。不提供邮箱
修改、身份绑定、账号合并、人工找回、恢复码、设备页面、管理员项目查看或数据导出 UI。
未来导出必须从 owner 查询全部项目，但本期不宣传为可用能力。

## 2026-07-29 补充决策

本次修订只替换原 ADR 中“Key 属于项目”和“用户可配置项目 Base URL”的部分，其余账号、
owner 门禁、会话与删除策略不变。账户连接当前提供 DeepSeek 与受开关控制的 Kimi 模板；
作者入口和 RP 入口共用同一账户连接。可恢复业务任务只持久化不含 secret 的执行快照，
执行时按项目 owner 读取所选 provider 的当前 Key，以支持 Key 轮换和既有任务增量恢复。
