# ADR-0040 — 操作留痕与常用操作代码化

- **状态**: Proposed（产品方向由用户 2026-10-15 裁定；技术方案待评审）
- **日期**: 2026-10-15
- **关联追踪**: ADR-0010（公开账户）、ADR-0013（operation receipt）、ADR-0023（有界 Agent）、
  ADR-0026（写入语义）、ADR-0031（依赖方向）、ADR-0032（引导流程）、ADR-0039（统一操作目录与目标运行）、
  [全模块 AI 操作入口设计](../plans/2026-10-15-agent-operation-surface.md) §7

## 背景

用户 2026-10-15 要求操作留痕，方便后续版本把用户常用的操作代码化实现。

现有记录各管一段，都不能回答“作者经常做哪些操作、按什么顺序做”：

- 助手运行与批次（`assistant_runs`、`assistant_action_batches`）只覆盖 AI 发起的操作；
- 长任务 `operation_id` 只用于收敛不确定的重试（ADR-0013）；
- 实体、页面、地图历史和演化回执记录内容变化，不记录发起者、入口和操作语义；
- 作者在界面上的操作既不按“操作”记录，也没有前端埋点。

## 决策

### 1. 每次目录操作调用都留痕

- 留痕挂在 ADR-0039 的操作目录上：无论发起者是界面、助手、引导流程、目标运行还是后台，
  都在同一层记录，不靠前端埋点。
- 一次调用对应一串生命周期事件：
  - 提议：AI 放进计划或方案；
  - 预览；
  - 确认、拒绝，或作者先改再确认（记录被改的参数名）；
  - 执行成功或失败（记录错误码）；
  - 之后被撤销或恢复：恢复操作作用于本次产出的修订时，按产出 ID 关联回来。

### 2. 记录字段

- 作品、账户、发生时间；
- 发起者类型，以及运行、流程、目标的 ID；
- 关联会话 ID、上一条留痕 ID 和序号，用于序列分析；
- `op_id`、目录版本和界面入口（路由名或页面名）；
- 目标类型与 ID；
- 参数形状：出现了哪些键、枚举值和数量规模；
- 结果、错误码、耗时、请求次数和费用（取自运行信封）；
- 产出的领域回执、修订和任务 ID。

### 3. 不记录内容

- 不记录正文、世界资料、提示词、模型输出和任何密钥。
- 自由文本参数只记长度和按作品加盐的 hash：可以识别“同一段文字被反复使用”，但无法还原内容。
- 每个目录项的留痕规则决定哪些参数以何种形式入库；未声明的参数默认只记“出现过”。

### 4. 写入语义

- 明细表只追加，可以设数据库 trigger 保护（与 ADR-0026 的只追加表一致）。
- “执行成功”事件与领域写入同事务提交，保证有写入就有记录。
- 提议、预览、拒绝和失败事件尽力写入：写入失败不影响业务，只把留痕标为不完整。
- 表的归属和写入端口按 ADR-0031 确定，各模块经端口写入，不新增业务模块之间的依赖边。

### 5. 保留、开关与导出

- 明细默认保留 180 天（可配置），到期后汇总为不含 ID 的统计：操作频次和操作序列频次，然后删除明细。
- 开关：
  - 本机单用户默认开启，数据只在自己的数据库中；
  - 公开账户默认关闭，需要作者主动开启（ADR-0010）；
  - 演示账户不记录。
- 只有作者本人可以查看和导出去标识的汇总；不自动上传，不跨账户合并。

### 6. 代码化循环

- 提供报告，内容包括：
  - 高频操作；
  - 参数抽象后的高频操作序列；
  - AI 提案的接受、拒绝和“先改后接受”比例；
  - 执行后撤销比例；
  - 耗时和费用。
- 报告产出的候选分四类：
  - 作者反复手动执行的序列 → 引导流程或组合操作；
  - 反复出现的目标运行计划 → 注册为引导流程（ADR-0032），省去规划费用；
  - 作者反复修改的 AI 预览 → 调整默认值或提示词；
  - 拒绝率高的操作 → 复查。
- 代码化走正常开发与评审（必要时立 ADR、补测试），以汇总数据作为依据。
  留痕不自动修改产品行为。

## 后果

- 需要新增只追加的留痕表、汇总表、记录端口、保留期任务、报告脚本或页面，以及账户级开关。
- 每个目录项需要声明留痕规则。现有 47 个助手操作和高频界面写路由优先接入。
- 新增写入开销：“执行成功”事件与领域写入同事务，需要压测确认对写路径延迟的影响。
- 风险：
  - 参数形状或 hash 可能间接泄露信息。按作品加盐、只记长度，并用合成正文做反向检查，
    确认留痕中找不到原文片段。
  - 数据量增长，靠保留期和汇总控制。

## 备选方案

### A. 前端埋点

拒绝。只能覆盖界面，覆盖不到 AI 和后台；而且依赖页面实现，容易漏记和重复记录。

### B. 复用现有领域历史和回执拼出操作序列

不足。领域历史不记录发起者、入口、拒绝和“先改后接受”，也没有统一的操作语义。

### C. 记录完整参数和内容，便于以后分析

拒绝。会把正文和资料复制进第二个存储，违背最小化原则和作者对原文的控制。

### D. 根据留痕自动生成流程并上线

拒绝。流程会改变作者体验和费用，必须经开发、评测和评审。
