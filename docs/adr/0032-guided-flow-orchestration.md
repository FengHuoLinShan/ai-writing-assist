# ADR-0032 — 引导流程（guided_flow）确定性编排层

- **状态**: Accepted / 实施中（BR-3）
- **日期**: 2026-10-09
- **关联追踪**: ADR-0023（项目助手有界单 Agent）、ADR-0027（协作蓝图）、ADR-0031（依赖方向）、
  `docs/plans/2026-10-09-guided-flow-borrowing.md` §5 BR-3、§6 用户裁定第 2 项

## 背景

成果导向创作流程（继续写下一场、按审读意见定向修订、新书开篇）需要把多个既有领域
操作按作者旅程串起来：自动衔接、只在真实选择时停。现有两种编排形态都不适用：

- ADR-0027 的 6 个协作蓝图是封闭的只读调查类型：`select_plan` 绑定团队运行且要求
  知识复核通过，预算按调查设计；业务写入不在其授权内。
- ADR-0023 的有界单 Agent 是单步调查/提案，没有多步流程的版本化编排与停点语义。

借鉴对照项目“配方”机制时只取结构与产品形态（确定性步骤表、产物派生进度、停点信号），
不取其代码与文案；其预算形同虚设、非 gateable 产物自动视为已确认等反例明确不借鉴。

## 决策

1. **Assistant 内新增 `guided_flow` 薄确定性编排层**，不是新 Agent、不是 DSL：
   流程与步骤表在服务端注册、带版本号，模型不可修改，运行期不开放任何可由模型或
   前端编写的流程定义。注册校验借鉴产物依赖 DAG：步骤只允许引用已注册操作或既有
   领域任务，构建期校验单一生产者、未知类型与环。
2. **步骤类型仅三种**：
   - `auto`：自动执行，只引用已注册 suggest 类操作，复用 uuid5 幂等执行与批次指纹；
   - `author_confirm`：作者确认，复用既有批次指纹重验，不新增确认协议；
   - `author_choice`：作者选择（如方向卡、采用/返修）。
   停点只在：真实选择、扩大授权、硬性阻断。不设“模型觉得该停”的停点。
3. **进度由领域产物推导，不存当前步骤索引**：每步的完成状态由其产物（已采用资产、
   候选、确认、任务终态）是否存在且新鲜推导；流程运行记录只冻结流程版本、输入指纹、
   授权范围与停点原因。上游产物变化按依赖反推下游失效，受保护的作者内容除外。
4. **存储复用 AssistantRun**，新增运行类型 `guided_flow_v1`，不建新表。若单会话单
   活动 run 约束与流程并行冲突，实现时按“每流程一个活动 run”裁定并在测试中钉住。
5. **开关与白名单**：`ASSISTANT_GUIDED_FLOWS_ENABLED` 默认关，项目白名单沿用既有
   部署级开关机制，不新增授权协议。
6. **依赖方向**：guided_flow 只经操作目录或 DI port 触达 World/Story/Writing/Evidence，
   不新增模块依赖边（ADR-0031 棘轮不放松）；Assistant 不能直接 import World。
7. **费用与幂等**：流程提交的任务一律携带由（流程运行、步骤、输入指纹）确定的
   `operation_id`，重复推进不产生第二个付费任务；每步预算沿用所引用操作自身的
   预算与 unknown 语义，不新建预算协议。
8. **与 ADR-0023/0027 的边界**：本层不扩大模型自治——流程推进由服务端确定性代码
   驱动，LLM 只在既有操作内部被调用；无模型可写状态、无成员互发自由文本、无
   任意工具。AI 输出一律是候选/待确认提案，采用与确认语义不变。

## 后果

- 流程价值（步数、费用、采用率）按 §8 评测方案验证；引导流程默认关闭，无测量不默认开。
- 明确不做：通用自治团队、流程内自动定稿、批量自动采用、按时间自动放行待审提案、
  多章正文候选链。
- 首个流程为流程 2 v1（首页“继续第 N 章”→ 可审阅候选，作者只做资料确认与采用两次
  决定）；BR-4/5/6 的流程按同一注册机制追加，不另起编排层。
