# ADR-0040 — 写作副驾驶 v2：场景导演、机制对齐与统一提醒

- **状态**: Proposed（产品方向由用户 2026-10-15 裁定；技术方案待评审）
- **日期**: 2026-10-15
- **关联追踪**: ADR-0017（事实权威）、ADR-0023（有界 Agent 核心与项目助手）、ADR-0025（知识治理）、
  ADR-0027（协作与角色模拟规则，统一推演协议沿用）、ADR-0031（依赖方向）、ADR-0035（空间模型 v2）、
  ADR-0036（演化可选阅读步骤）、ADR-0037（参考维度，本 ADR 追加三个维度）、ADR-0038（操作目录与留痕）、ADR-0039（世界对象档案）、
  ADR-0041（世界推进）、
  [世界对象档案、场景导演与写作副驾驶设计](../plans/2026-10-15-world-object-dossier-and-scene-director.md) §6–§7

本 ADR 合并了起草阶段的两份草案：场景导演、写作副驾驶对齐与统一提醒。

## 背景

用户 2026-10-15 要求：

- 场景推演和导演有效利用人物和世界对象的信息，辅助作者写新剧情、人物反应、场景变化、细节修正；
- 导演允许 AI 充分发散、发挥自主性，去掉人物数量等限制；
- 轮数默认一轮：作者点一下推进一轮；保留好历史“剧本”；
- 输出重点是人物的行为、表情、心理等活动，因为普通作者写人物容易同质化；
- 场景细节尽量给全，由作者挑选，组成合适的“角度”；
- 原有写作副驾驶的提醒机制要结合进来，导演本身就是写作副驾驶的高级扩展；
- 写作副驾驶的各项机制同步对齐或重构到项目最新计划；
- 演化归纳出、复核为“有支持”但作者尚未采用的倾向允许作为参考，提供开关。

现状：

- **生成上下文**：POV 人物有完整安全档案；其他人物只有外观和语言风格。台账倾向不进入生成。
  知识回执 `KnowledgeScopeReceipt` 有 included / excluded / omitted 及原因，但任何 `omitted` 都会使
  `scope_complete` 为假（`evidence/compilation/knowledge/scope.py:459`），声明 `require_scope_complete`
  的流程会停下；参考维度的省略不能直接写进 `omitted`（ADR-0037 §1 改为单独记录）。
- **人物卡与反应**：`character_card.v1` 由模型从零生成，和档案之间没有可追溯的依据；`ReactionProposal`
  没有神态、表情、肢体、潜台词，也没有“此刻注意到什么”；剧本节拍 `ScriptBeat` 没有环境和感官细节。
- **排演与推演协议**：`rehearsal_v1`、`observation_v2` 在 schema 中硬性限制每轮 1 至 3 名人物、1 至 3 个回合
  （`story/schemas.py:319`、`:333`）；`SimulationSeed.locations` 最多 4 个人物位置，`ActionIntent.audience`
  最多 3 人，移动目的地是不超过 120 字的文本而不是对象 ID（`story/observations.py:35`、`:48`、`:64`）。
  结束时一定生成剧本预览（`story/rehearsals.py:232`），作者不能在回合之间介入。`observation_v2` 不只排演在用：
  Story 的状态试验（`story/continuity/state_trial.py` 的 `ResolutionBatch`、`StateDelta`、`replay_batch`）、
  Interaction 的多角色演绎（`ensemble_v2.py`、`ensemble.py` 经 `story.facade.rehearse_round` 调用，
  运行策略 `runtime_policy.py:108` 限制最多 3 名演员）都依赖它；`interaction/schemas.py`、
  `journey_views.py`、`project/llm_runtime.py`、`assistant/api.py` 也引用了这些协议名。
- **写作副驾驶**（`frontend-console/vue/views/writing/components/SceneCockpit.vue`）有警报、人物、地点、
  本场四个标签。警报（`sceneAlerts.js`）在前端组合结构缺项和最近一次冲突检查的状态，不调用模型、
  不持久化、不能处置。排演入口在 Scene 工作台，与副驾驶分开。
- **提醒分散**：冲突检查结果与来源失效、重算提示归 Writing；短期前瞻 notice 归 Assistant
  （`assistant_notices`：`fingerprint` 唯一、`unread / read / snoozed / dismissed`、`row_version` 并发控制）；
  编辑员级意见归 Assistant 审读队列；G8a（改章 → 地图册来源核对）、G8b（改图 → 冲突检查可核对）已实现。
- **旧入口**：副驾驶仍有即将下线的深度导入按钮与审计弹窗；场景自动提取依赖导入流程；人物、地点标签只读
  World 的局部资料，不读时点状态和台账。

## 决策

### 1. 定位、归属与实施前置

- 写作副驾驶对齐后有四个标签：本场、对象、导演、提醒（§14）。场景导演是副驾驶的高级模式，在“导演”标签中
  使用，围绕作者手选的当前 Scene；可以展开为全屏导演台，手机上直接全屏。Scene 工作台原有的排演入口指向
  同一个导演。
- Story 持有统一推演协议 `simulation_v3`（§3，导演是其中一种模式）、导演运行与轮次历史；Evidence 编译对象简报；
  Writing 承载界面并可选读取导演参考剧本；Assistant 聚合统一提醒。
- 导演的所有产物都是候选，不写入 continuity、World 或正文（ADR-0017）。
- **实施前置与顺序**：本 ADR 依赖三项同为 Proposed 的机制，按以下里程碑推进，任一前置收缩时须重审
  §10 和 §12：
  1. 参考维度机制（ADR-0037 §1）；
  2. 统一对象读取接口与对象简报（ADR-0039 §8）；
  3. 统一提醒（§13），可与 2 并行；
  4. 统一推演协议 `simulation_v3` 与导演模式（§2–§9），依赖 1、2。

### 2. 一次点击推进一轮

- 默认每次点击推进一轮。作者可以明确选择“连续推进 N 轮”，N 由作者设定，开始前给出用量预览。
- 每轮开始前，作者可以给本轮指示（都可选）：想看什么、插入事件、谁登场或离场、氛围、节奏。
- 每轮结束后停下，作者可以：继续；重来（同一起点重新生成，成为同级分支）；介入后继续
  （插入事件、改变环境、递私语、调整目标或在场者，成为子分支）；从任意历史轮次继续；
  挑选素材、组合角度、存为参考剧本（§8）。状态试验（钥匙与锁）的入口并入“介入”，原接口保留。

### 3. 统一推演协议，不设产品上限

**统一协议**（用户 2026-10-15 裁定：统一原协议和新协议，下线原协议）：新增 `simulation_v3`（名称待实施确定），
取代 `rehearsal_v1` 与 `observation_v2`。各种推演是同一协议的不同模式：

| 模式 | 用途 | 入口 |
| --- | --- | --- |
| 导演轮次 | 本 ADR §2–§9 | 写作副驾驶、Scene 工作台 |
| 世界推进步 | ADR-0041 | 世界推进 |
| 状态试验 | 钥匙与锁（现 `state_trial.py`） | 原 HTTP 接口保留，内部改用本协议 |
| 观察者回合 | Interaction 多角色演绎 | RP |

- **基于 ID**：参与者、位置、目的地、受众、持有物都按对象 ID 或地图节点 ID 引用；没有对应对象的
  以“导演引入（候选）”或文字标签表示，不再用自由文本充当位置身份。
- **协议本身不设上限**：不在 schema 中限制人物数、轮数、地点数、受众数，也不限导演新引入的人物或物件。
  各入口可以有自己的运行策略，例如 RP 的 `max_actors` 仍由 `interaction/runtime_policy.py` 控制，
  写在入口策略里而不写进协议。
- **角色模拟规则沿用 ADR-0027**：每个人物的意图只用其可知信息，意图不等于结果，结算由确定性代码完成。
- **共用结算**：动作意图、资源转移、移动和信念变化的结算与回放（现 `ResolutionBatch`、`StateDelta`、
  `replay_batch`）收为本协议的共用部分，各模式不各写一套。

**下线原协议**：

- 本协议上线后，Story 的排演和状态试验不再新建 `rehearsal_v1`、`observation_v2` 运行。
- Interaction 的多角色演绎迁移到“观察者回合”模式，须先通过 Interaction 自己的评测门禁；
  通过前 RP 继续使用 `observation_v2`，这是迁移期唯一仍新建旧协议运行的入口。迁移完成后不再新建。
- 旧运行只读，按原协议解释，不重新解释、不迁移数据；引用协议名的读取方（`interaction/schemas.py`、
  `journey_views.py`、`project/llm_runtime.py`、`assistant/api.py`）同时接受新旧协议名。

**容量**：实际约束只有作者授权的预算和单次模型调用的上下文容量。容量不够时分组调用：戏份重的人物逐个详写，
背景人物合并为群像。轮次结果包含“分组与省略”字段，列出被合并或省略的人物与素材及原因；
不静默截断，不拒绝运行。

### 4. AI 自主与硬规则

AI 可以自己决定本轮谁行动、按什么顺序行动；安排未在场的人物登场或让人离场；引入意外
（环境变化、路人、消息到达、天气突变）；给出出人意料但能解释的反应；每轮附 2 至 3 个“其他可能”，
即未展开的分歧点，作者可以一键作为分支推进。

发散度分三档：保守（贴近档案与大纲）、平衡（默认）、大胆（允许反差、意外、偏离大纲）。

硬规则只有以下几条，都不限制创意：

1. 每个人物的意图只用该人物可知的信息（角色视角）；导演层是全知的。
2. 已经确定的事实（continuity 截止状态、已采用设定、作者保留项）不被改写；与之矛盾的发展标为
   “与已知事实冲突”并说明冲突点。
3. 导演新引入的人物、物件、地点、设定都标为“导演引入（候选）”，不自动建对象；作者可以一键转为
   World 候选。
4. 意图不等于成功：失败、半成功、未定都是合法结果。
5. 登场人物须与其时点位置和行程（ADR-0035 计算特性）相容，否则标为冲突，而不是悄悄改写。

### 5. 人物表演卡

每轮为每个有戏份的人物输出一张表演卡：行为（具体动作及顺序）；神态与表情（面部、眼神、微表情）；
肢体（姿态、手上的动作、与空间和物件的互动）；声音与台词（内容、语速、音量、口头禅、称呼、潜台词）；
心理（内心活动、动机、情绪变化及其触发点、自我欺骗或防御；作者可见，写入正文时受视角约束）；
注意力（此刻注意到了什么、忽略了什么）；变化（与上一轮相比，情绪、关系、目标的变化）。

每项注明依据：档案面向、台账倾向、关键经历、本轮刺激，或“导演发挥”。

### 6. 对抗同质化

- **差异化锚点**：生成时为每个人物带上锚点，来自“表达方式”“说话方式”面向（ADR-0039 §2），
  以及台账中的语言习惯和条件行为。
- **同轮差异检查**：同一轮里几个人物的情绪类型、动作和措辞高度相似时，标出并给出区分方向；
  作者可以一键只重写其中某个人物。
- **套话提示**：项目级套话清单，系统给默认值，作者可编辑。出现时标出，并给出贴合该人物的替代方向。
- **作者示例**：复用写作 few-shot 的好例和反例约束表演卡的笔触。
- **档案不足**：人物缺少表达方式等面向时直接提示“表演容易趋同”，并给出补全入口（演化提案或作者编辑）。

### 7. 场景素材与角度

- 每轮给出尽量完整的素材：环境（空间、光线、声音、气味、温度与天气、质感）、物件（在场物件及其状态变化、
  可用作道具的细节）、旁观者与群像反应、氛围与节奏、时间。
- 每条素材是一张可勾选的卡片，标注类别、涉及的对象、谁能感知（看到、听到、闻到，或只有本人内心知道）、
  来源（档案、时点状态、导演引入）、是否与已知事实冲突。
- 作者从素材和表演卡中组合角度：视角人物（该人物感知不到的素材自动标灰；内心活动只能写视角人物本人，
  选择全知除外）、叙述距离、焦点、详略与节奏。系统可以推荐 2 至 3 种角度组合。

### 8. 导演剧本只是思路，正文另写

用户 2026-10-15 裁定：导演剧本被作者选用后，只是给作者提供思路；具体正文还要另写，AI 生成或手写都可以。

- **参考剧本**：勾选的素材与选定的角度可以“存为参考剧本”，保存所选素材的内容副本、素材 ID、角度和来源轮次，
  并指向导演运行与轮次；不依赖导演历史仍然存在。
- **不是已采用剧本**：参考剧本存放在导演自己的存储中，不写入 `SceneScriptFile`，没有“采用”状态，
  不进入 `get_scene_story_basis_hash`（`story/service.py:1160`，只统计 Scene、大纲、人物卡和已采用剧本），
  也不作为 `adopted_scripts` 约束正文。作者如果想把其中内容变成正式剧本约束，可以手动复制进普通剧本文件，
  按现有流程编辑和采用；这是作者的独立编辑，不是导演产物的采用。
- **正文另写**：
  - AI 生成：`writing.generate`、`writing.targeted_revision` 可以由作者选中一份或多份参考剧本作为输入，
    走参考维度 `director_reference`（§10，ADR-0037 §1 机制）：缺失、过期或因预算省略都只提醒、不阻断；
    生成的仍是单章正文候选。
  - 手写：素材面板常驻副驾驶，可以随时查看、对照，或插入为批注。
- **依据变化**：参考剧本记录生成时的依据指纹（档案、checkpoint、台账、地图修订）。依据变化后标“依据已变化”
  并提醒，不阻止查看或作为生成参考。

### 9. 历史剧本

- 每一轮保存为不可变记录：输入指纹（档案、checkpoint、台账、地图修订）、作者指示、输出、表演卡、素材、
  分组与省略、状态差量、用量。重来生成同级分支，介入或分歧生成子分支，形成一棵树。
- 支持按时间线或树浏览、标星、命名、备注、两轮对比、从任意一轮继续。
- **保留**：导演历史不受运行明细保留期影响，没有自动清理和配额淘汰；副驾驶显示每个项目的历史用量。
- **删除**：只能由作者在界面上删除（AI 不开放，ADR-0038 §2）。可以删除单个分支或批量删除未标星的分支；
  删除前列出受影响的轮次数，以及哪些参考剧本引用了它们；删除后 30 天内可恢复，之后彻底清除。
  被引用轮次删除后，参考剧本照常可用（§8 保存了内容副本），来源标“来源轮次已删除”。
- 依据变化后，旧轮次照常可读并标为“依据已变化”。继续推进前，作者选择从新依据开始，或沿用旧依据
  （结果带标注）。参考剧本的依据变化只提醒（§8）。

### 10. 对象简报与参考维度

Evidence 新增对象简报 loader，读取 ADR-0039 §8 的统一接口，按相关性和预算选取：

- 人物：稳定设定、本场时点状态、与其他参与者的态度、相关台账倾向、关键经历、知识边界、空间位置；
- 地点和在场物件：感官细节、状况、规矩、危险、能力与代价。

规则：

- **台账倾向**（用户裁定）：复核为“有支持”的条目和作者已采用的条目都可以作为参考，标注
  “从正文归纳，不是规则”。项目开关“只用已采用条目”，默认关闭。
- **台账读取路径**：Evidence 经新增的只读 DI 键读取台账，消费方 Protocol 在 Evidence，组合根注册；
  不产生 evidence → evolution 的导入边。实施时须在 ADR-0031 依赖表补登记 evidence / evolution 一行
  （既有方向 evolution → evidence；evidence 读台账经该 DI 键），并按惯例实测依赖棘轮。
- **视角**：作者模式可见全部；角色模式只给该人物可知的内容；读者模式不使用。
- **生成正文时的分层不变**：POV 以外的人物只给外在可观察的信息，作者约束仍标为 `director_only`。
- **失效**：简报把档案修订 ID、台账修订 ID、checkpoint 指纹写入 context snapshot，走现有失效通知。
- **规模与省略**：设字数上限，数值按评测确定；被预算省略的来源记入参考维度省略记录（ADR-0037 §1），
  不写入 `omitted`，不影响 `scope_complete`；只提醒、不阻断，并向作者披露。
- 新增参考维度 `object_dossier`（档案与时点状态）和 `character_pattern`（台账倾向），规则同 ADR-0037 §1：
  缺失、为空、被排除或被省略都不使裁决降级，审查发现只是提示。首批能力：导演、`story.character_card`、
  `story.reaction`、`story.script`、`writing.generate`、`writing.targeted_revision`、
  `writing.semantic_review`、`world.ask`、`assistant.turn`。各自开关默认关闭，经 A/B 评测后开启。
- 新增参考维度 `director_reference`（作者选中的导演参考剧本，§8），首批只用于 `writing.generate` 和
  `writing.targeted_revision`，规则同上，开关默认关闭。

### 11. 人物卡 v2 与反应

- 人物卡骨架由简报确定性生成（时点状态、关系、知识直接投影）；模型只补“本场解读”，每条注明依据；
  与档案冲突的解读必须标出，作者可以将其“上升为档案条目”（走 ADR-0039 的档案修订入口）。
  `character_card.v1` 保持可读。
- 反应一次给出 2 至 4 种动机不同的选项，以表演卡格式输出，标出“与档案不一致但可能发生”的选项及
  需要的铺垫。前瞻指令 `story.character_response.v1` 的后继版本采用同一格式。

### 12. 一致性检查

- 每轮都对输出做确定性检查，只读内核面向和注册状态字段：外貌基线直接矛盾、已登记伤病或装束无交代消失、
  称呼或已采用口头禅变化、知情越界、已死亡或身在别处的人物出场、物件状况与持有矛盾、地点状况矛盾。
- 模型检查（性格与行为明显不符且无铺垫）属于参考维度，只作提示，默认关闭。
- 结果显示在该轮，也进入统一提醒（§13）。作者组合素材时，选中的冲突素材会被标出。
- 同一检查也用于正文：接入 `writing.semantic_review` 与冲突检查规则层。
- 修复方向：改正文或改档案（设定变化时加生效区间），不预设“档案永远正确”。只提示，不拦截。

### 13. 统一提醒

**原则**：各领域继续拥有自己的检查结论和处置，不新建问题真相表，也不新增 `review` 模块。

**装配**：新增提醒来源登记表 `app/notice_source_registry`，与 `app/assistant_operation_registry` 相同的装配方式：
领域插件只导出纯数据规格（来源名、类别、只读“列出提醒”的函数），由组合根物化（ADR-0031）。
Assistant（L4）提供只读聚合接口，按章节或 Scene 返回统一条目（例如
`GET /api/assistant/notice-feed?novel_id=&scene_id=`）。

- **只经登记表调用**：Assistant 的冻结出边只有 `account`、`evidence`、`project`、`story`、`writing`
  （`scripts/check_module_imports.py:102`）。聚合接口只调用 `app/notice_source_registry` 物化好的来源函数，
  不直接导入 `world`、`evolution` 等模块，也不新增冻结出边；来源函数由各领域插件提供，组合根装配。
- 依赖棘轮测试覆盖这一点：Assistant 新增代码出现对 `world`、`evolution` 的导入时 CI 失败。

**来源**：

| 来源 | 归属 | 状态 | 处置 |
| --- | --- | --- | --- |
| 结构缺项（目标、冲突、POV、地点、待复核、未对应章节） | Story | 新增后端能力：现为前端 `sceneAlerts.js` 组合，改由 Story 计算 | 统一处置 |
| 冲突检查结果（规则层与 AI 复核） | Writing | 已有 | 沿用条目状态 |
| 来源失效与重算提示 | Writing | 已有 | 沿用现有进度 |
| G8a 地图册来源核对、G8b 冲突检查地图基线 | Evolution、Writing | 已有 | 统一处置 |
| 短期前瞻 | Assistant | 已有 | 沿用 `assistant_notices` |
| 编辑员级意见 | Assistant | 已有 | 沿用审读队列 |
| 地图空间提醒 | 地图 | 待接入（ADR-0037 §4，开关默认关） | 统一处置 |
| 对象一致性提醒 | Writing、Story | 待接入（§12） | 统一处置 |
| 档案草稿与更新提案 | World | 待接入（ADR-0039 §9） | 沿用提案审核 |
| 作者有效期被剧情覆盖 | World、Evolution | 待接入（ADR-0039 §6） | 统一处置 |
| 演化阅读状态（新章节未读、读取失败、待复核） | Evolution | 待接入 | 统一处置 |
| 世界推进提醒 | Story | 待接入（ADR-0041 §9） | 统一处置 |

首批只接入“已有”来源和结构缺项；“待接入”来源随各自能力上线时注册，不预先占位。

**统一条目字段**：稳定键 `notice_key`（来源、类别与目标的确定性组合）；来源域与类别；
严重度（高、中、低、信息）；目标（章节、Scene、正文区间、对象、地图节点）；摘要与证据引用；
依据指纹（来源计算，用于判断是否过期）；建议动作（操作目录的 `op_id`，ADR-0038）；处置状态。
读取时重验依据指纹；过期的条目标为过期，不作为当前问题展示。

**处置**：

- 已有处置机制的来源继续使用原机制，聚合接口只做转发：前瞻用 `assistant_notices` 的决定入口，
  冲突检查用条目状态，编辑员意见用审读队列，档案提案用 World 的提案审核。
- 没有处置机制的来源使用统一处置记录（独立于 `assistant_notices`，避免主动提醒列表混入），按
  （`notice_key`，依据指纹）保存状态，`row_version` 并发控制：
  - 未读 → 已读：作者查看；
  - 稍后：带唤醒时间，到期回到未读；
  - 忽略：绑定当时的依据指纹；指纹变化后条目重新出现为未读；
  - 按类别静默：独立于单条状态，按（项目、来源、类别）保存，直到作者取消；不随指纹变化失效。
- 处置动作注册为目录项（R2，可恢复），按 ADR-0038 留痕。

**降级**：聚合接口并行读取各来源，单个来源超时或失败时，该来源返回“暂时无法读取”的占位条目，
其余来源照常返回；不缓存失败结果为“无提醒”。

**降噪与边界**：按来源和类别分组；严重度排序；默认只展开中级以上；主动推送沿用持续授权与每日额度。
只提示，不拦截；既有领域门禁不变（例如 AI 候选采用要求知识复核通过、发布前提示部分完成检查）。

### 14. 副驾驶机制对齐

| 现有机制 | 对齐后 |
| --- | --- |
| 本场 | Scene 结构、按截止点的时点状态视图、空间简报（ADR-0037），加导演入口 |
| 人物、地点 | 合并为“对象”标签，按类型分组；读取统一对象档案接口（ADR-0039 §8）：设定、本场时点状态、态度、倾向、关键经历；保留“查证” |
| 警报 | 改为“提醒”标签，展示统一提醒（§13），可处置、可静默、可跳到修复动作 |
| 状态试验（钥匙与锁） | 改为统一推演协议的状态试验模式（§3），原接口保留；入口并入导演的“介入”（§2） |
| 深度导入按钮与审计弹窗 | 随深度导入下线，替换为“演化阅读：读入本章／续读”（演化 append）；在演化成为默认导入入口之前保留旧按钮 |
| 场景自动提取 | 改用演化阅读的 Scene 准备（演化已经通过 Imports facade 的纯切分边界处理未整理正文） |
| AI 生成 | 可选读取作者选中的导演参考剧本（§8）；声明 `map_spatial`、`object_dossier`、`character_pattern`、`director_reference` 参考维度 |
| 冲突检查 | 规则层加入对象一致性确定性检查（§12）；结果进入统一提醒 |
| 短期前瞻 | 作为副驾驶的“下一步建议”；人物反应以对象简报为依据、按表演卡格式输出（§11） |
| 编辑员级意见、批注修订 | 机制不变，在统一提醒中显示入口 |
| 失效提示、重算面板 | 在统一提醒中显示；失效来源包括演化与档案修订 |
| 故事结构浮窗 | 增加人物弧线：作者计划的弧线与实际发生对照 |
| 作者写作示例 | 同时约束导演表演卡的笔触 |

- 副驾驶的全部动作注册为操作目录项（ADR-0038）并留痕，助手可以代为执行。
- 状态试验、查证、冲突检查等现有 HTTP 接口保持兼容；旧前端入口在新标签上线后移除。

### 15. RP 多角色演绎

Interaction 可以读取档案的角色视角投影，冻结在资料版本中；不回写作者项目，也不读取作者视角的档案、台账、
导演历史或推进记录。多角色演绎迁移到统一推演协议的“观察者回合”模式（§3），须先通过 Interaction 的评测门禁；
`max_actors` 等限制保留为 RP 的运行策略。

## 后果

- Story：统一推演协议 `simulation_v3`（导演轮次、世界推进步、状态试验、观察者回合）与共用结算；
  导演运行与轮次表、分支树、表演卡与素材模型、分组与省略字段、参考剧本存储；
  人物卡 v2、多选项反应、结构缺项计算；状态试验改用新协议，原接口保持兼容。
- 原协议下线：Story 停止新建 `rehearsal_v1`、`observation_v2` 运行；引用协议名的读取方同时接受新旧名；
  旧运行只读。
- Interaction：多角色演绎迁移到观察者回合模式，通过其评测门禁后切换。
- Evidence：对象简报 loader、三个参考维度（`object_dossier`、`character_pattern`、`director_reference`）、
  台账只读 DI 键（ADR-0031 补登记）。
- Writing：副驾驶四个标签与全屏导演台；生成可选读取参考剧本；对象一致性检查；深度导入入口替换。
- Assistant：`app/notice_source_registry`、聚合读接口（只经登记表调用来源）、统一处置记录与静默规则。
- 每项能力同期注册目录项（ADR-0038：推进一轮为 R1，存为参考剧本为 R2，提醒处置为 R2），并留痕。
- 开关 `STORY_SCENE_DIRECTOR_ENABLED` 默认关闭，经评测后开启。
- 评测：
  - 导演：人物区分度（盲评能否从表演卡认出人物）、套话率、依据真实性、素材覆盖度、
    “谁能感知”标注正确率、人物越权知情比例（目标 0）、与已知事实冲突却未标出的比例（目标 0）；
  - 统一提醒：植入错误样本上的召回率、真实样本上的误报率、处置后重现是否正确、过期条目是否被正确标注；
  - 评分沿用 Sol/xhigh，代理验收保留 `human_validated=false`。
- 风险：
  - 去掉上限后单轮用量不可控：每轮前预览；连续推进只在作者明确选择时发生。
  - 表演卡过于戏剧化、偏离作者风格：发散度可调，作者示例约束笔触。
  - 台账倾向被当成必须遵守的规则，人物变得刻板：简报标注“倾向不是规则”，反应必须给出动机不同的选项。
  - 历史长期保留占用存储：显示用量，作者可以批量删除未标星的分支。
  - 聚合接口延迟上升、提醒疲劳：来源并行与局部降级；分组、静默、严重度排序。
  - 统一处置与来源处置语义不一致：已有处置机制的来源只转发，不复制状态。
  - 协议统一牵动状态试验和 RP：共用结算先以现有状态试验与 RP 回放样例做零差异回归，RP 切换以其评测门禁为准。

## 备选方案

### A. 保留排演上限，只加人物简报

拒绝。用户明确要求去掉人物数量等限制、允许 AI 充分发散；用量由预览和一次一轮控制。

### B. 直接生成完整场景正文

拒绝。用户要求给素材由作者挑选角度；成稿式输出正是人物同质化的来源。正文由作者另写：
单章 AI 生成或手写，导演剧本只作参考。

### C. 导演作为独立页面，与副驾驶分开

拒绝。用户明确导演是写作副驾驶的高级扩展；分开会让提醒、素材和正文脱节。

### D. 导演结果直接写入 continuity

拒绝。意图不是事件；正史只来自正文和作者确认（ADR-0017）。

### E. 新建统一的问题真相表，各领域写入

拒绝。会形成与各领域结论并行的第二份状态，同步与失效都变复杂；各领域已有自己的处置。

### F. 继续在前端组合提醒

拒绝。前端无法持久化处置，也无法让助手读取或代为处理；结构缺项的计算应属于 Story。

### G. 统一提醒放在 Writing

不采用。来源横跨 World、Story、Evolution、Assistant，Writing 是 L2，读取 L3、L4 的来源需要额外 DI 键；
Assistant 经组合根登记表读取各领域来源，不新增依赖边，且已有 notice 与持续授权机制。

### H. 保留旧排演协议，新增独立的导演协议并行

拒绝。用户裁定统一并下线原协议；两套协议会让结算、回放和限制各自演化，状态试验和 RP 也要分别维护。

### I. 导演剧本采用后作为已采用剧本约束正文

拒绝。用户裁定导演剧本只提供思路；进入 story 依据 hash 会让每次导演推进都把正文标为过期，
也会把模型的发散结果变成正文约束。
