# ADR-0036 — 世界演化空间发现与地图自动冷启动

- **状态**: Proposed（产品方向由用户 2026-10-15 裁定；技术方案待评审）
- **日期**: 2026-10-15
- **关联追踪**: ADR-0012（统一地图）、ADR-0013（operation receipt）、ADR-0025（知识治理）、
  ADR-0031（依赖方向）、ADR-0035（空间模型 v2 与涌现类型）、
  [世界演化模块](../modules/22_evolution.md)、
  [地图系统增强设计](../plans/2026-10-15-map-system-enhancement.md) §6

## 背景

新建地图成本高，冷启动太长：

- 深度导入不生成地图（[地图模块](../modules/15_map.md)“上游智能整理”）。
- 地图只消费已采用资料，而从正文抽出的地点仍是候选对象。
- 地图结构生成一次最多 20 个地点、每批 5 个，每次 run 都要确认一次 Context，并且按节点逐个进行。

导入一本长篇后，作者要先逐个采用地点，再反复手动生成，才能看到一张可用的地图。

用户 2026-10-15 裁定：

- 冷启动自动进行，作者只负责审核；
- 草图允许绑定候选地点；
- 作者不填空间数据时只从原文抽取并审核；
- 地图保持示意与提醒级；
- 深度导入即将被世界演化替代并下线，冷启动不再挂在深度导入上；
- 空间类型对齐世界演化的“涌现”思想，由模型在演化中总结、按项目维护（ADR-0035 §4）。

世界演化已经逐 Scene 读取正文，完成身份解析并生成 World 候选（含地点），
每 Scene 原子提交候选与理解回执（[世界演化模块](../modules/22_evolution.md)）。
其持续发现（`discover_details`）已有一整套可复用的机制：

- 授权预览披露发现和独立复核共用的根预算；
- 每批调用在 journal 中冻结并计量，结果未知的请求不重发；
- 有界回读既有主题，并披露省略数；
- 方法指纹与 `consumer_read_set.v1`；
- 类别补扫的预览与确认（`category-rescan-preview` / `category-rescan`）。

地图目前只在 G8a 中作为建议性消费者登记，待审候选仍是 `map_atlas` 的残余 unsupported 来源。

## 决策

### 1. 空间发现是演化阅读中的可选步骤

- `ReadingRequest` 增加 `discover_spatial`（名称待实施确定）：
  - 新客户端发起的新阅读默认开启（用户选择自动），作者可在授权预览中取消；
  - 旧客户端和直接 API 调用默认关闭；
  - append 和 continue 沿用原运行的设置与方法版本，不静默升级。
- 本步骤在每个 Scene 的 World 身份解析和候选冻结之后运行，与台账发现相互独立。
- Scene 的主理解回执不等待空间步骤。空间步骤失败或额度不足时，只把该 Scene 的空间覆盖记为缺口，
  不阻断理解提交，也不影响台账发现。
- 新增两项能力，登记进 ADR-0025 知识治理注册表：
  - `evolution.spatial_discover`：抽取空间线索；
  - `evolution.spatial_review`：独立复核。

### 2. 预算与授权

- 授权预览披露本步骤的预计请求区间，并提示可能产生费用。请求共用运行的根预算、
  `budget_mode` 和 `request_limit`，不新建预算协议。
- 每批调用在 `scene_spatial_*` journal 中冻结并计量。结果未知的请求不重发，记为缺口，需要人工核对。

### 3. 地理密度预检

- 不调用模型。统计本 Scene 身份解析结果中的地点类对象，以及空间词汇的命中数。
  词汇包括系统基础词和项目空间类型的名称与别名。阈值带版本号并纳入方法指纹。
- Scene 零命中时跳过，记为“已检查、密度不足”，与“未检查”分开显示。
- 整次运行都低于阈值时，告诉作者原因（`low_spatial_density`）。

### 4. 输入与输出

**输入**：

- 本 Scene 的精确正文，不带后续 Scene；
- 本 Scene 的身份解析结果，包括已采用对象和演化 World 候选；
- 按相关性召回的项目空间类型（ADR-0035 §4），设上限并披露省略数；
- 与本 Scene 对象相关的已有空间线索和地图节点，设上限并披露省略数。

**输出**：空间线索，包括包含、方位、相邻、相通、行程声明、通行条件，以及毁城、改名等生效变化。
每条线索带：

- 端点身份引用；
- 已有项目类型的 ID，或新类型提议（名称、描述、建议的计算特性）；
- 模态（`ObservationModality`）；
- 逐字引文。

**服务端重验**：作品、Scene、来源 hash、范围和引文；身份引用必须出现在本批实际输入中。
无效项连同原因一起丢弃，不靠猜测修复。解析不了的端点保留为文字标签，进入“待放置托盘”。

### 5. 独立复核

- 线索、模态判断和新类型提议都要经过绑定本批输入的独立复核。
  复核结论为不支持或不确定的项保持待核，不产生地图效果。
- 新类型按 ADR-0035 §4 处理：至少要有两个 Scene 的证据；只出现一次的保持“涌现中”。

### 6. 线索归地图域保存

- 线索是地图域的候选记录，状态为待审、已采用、已拒绝、已被取代。
  记录携带来源引用、来源 hash、运行 ID 和回执 ID。
- 线索不是 World 事实，也不写 World 关系。
- 写入经 world 的地图 facade 完成，evolution 不依赖地图模型，符合 ADR-0031 的方向规则。
- 线索与本步骤的回执同事务提交，回执链接到该 Scene 的理解回执。

### 7. 草图由程序构建

- 运行的已提交前缀推进后，地图域用确定性方式更新草图，不调用模型。
  - 层级来自“包含”类线索，以及 World 中已采用或候选的 `located_at`/`contains` 关系；
  - 空间来自具备“跨空间”特性的连接线索。
- 布局沿用现有确定性算法（方向分层、有界网格避让），并按 ADR-0035 的特性扩展跨空间、上下和远近；
  冲突或放不下的内容标“待核对”。
- 按空间和层级分片，每片仍遵守现有单次上限（图元、关系、控制点数量）。
- 结果是节点上的候选版本，带 `auto_draft` 标记。只有候选版本的节点不进正式目录（现有规则），
  在“自动草图”视图中审核。

### 8. 允许绑定候选地点

- 草图图元可以绑定演化 World 候选地点。
- 候选被融合时，绑定跟随融合目标；候选被拒绝或删除时，绑定降级为文字标签，并提示作者。
- 采用草图节点时，作者可以勾选“一并采用地点”。这一步走 World 原有的采用入口，
  门禁不变，仍会重验回执前缀。
- 不勾选时也可以保存版本；但绑定候选对象的图元在对象采用前不进入读者预览、写作简报和空间检查，
  界面标“地点未采用”。

### 9. 从不自动采用

线索和草图一律等作者审核。新类型按 ADR-0035 §4 在复核通过后自动启用，
但只影响显示和模型上下文，不会让任何线索或草图进入正式地图。

### 10. Context 与知识范围

- 本步骤的输入进入演化运行自身的 InputManifest 和 `consumer_read_set.v1`，
  其中包括项目类型清单的修订指纹。
- 演化授权只替代“创建草图”这一步的地图 Context 确认。之后的地图 AI 操作
  （结构生成、图片）仍使用地图自己的确认流程。
- 采用时按地图现有规则重验来源 hash。

### 11. 增量、重算与补扫

- append 和 continue 只处理新 Scene。
- revise 和 `scoped_recompute` 只重算受影响的 Scene；旧回执产生的线索标“已被取代”，不删除。
- 已采用的地图不会被修改：针对已采用节点的新线索进入待审队列，新地点进入待放置托盘。
- 已读范围中没有做过空间发现的部分（旧运行或本功能上线前的运行），可以像类别补扫那样
  先预览、再由作者确认补扫。预览不发请求；确认时绑定操作 ID 与来源、方法、模型、预算指纹，
  发送前扣减额度。
- 方法指纹覆盖提示词、schema、密度阈值、特性内核版本和类型召回参数。旧结果不静默升级；
  `consumer_read_set` 未变时可以复用。

### 12. 地图登记为演化消费者

- `map_atlas` 正式消费空间线索和候选绑定。Scene 被重算或撤销导致线索失效时，
  依赖这些线索的地图节点经 G8a、G8c 的现有链路显示“待核对”，不新增失效协议。
- 这样可以收窄“待审候选”这一项 `map_atlas` 残余 unsupported 来源；
  不声称闭合 `world_canon_revision` 或 `world_knowledge`。

### 13. 深度导入不再增加阶段

- 深度导入即将下线，不为它新增空间阶段。
- 已用深度导入导入的作品，可以通过演化阅读（bootstrap）或空间补扫获得草图；
  其已有的地点对象和候选都可以绑定。

### 14. 不生成图片

自动冷启动只产生空间结构候选；图片仍走地图册现有的确认和计费状态机。

## 后果

- evolution 需要新增：阅读参数、两项能力、journal 类型、方法指纹字段和补扫入口。
- 地图域需要新增：线索记录、`auto_draft` 标记、待放置托盘，以及 ADR-0035 的项目类型。
- 阅读的费用和时长会增加。实际成本由首批题材矩阵评测和诡秘前 60 章冒烟给出；
  G7b 账本模板需要增加本步骤的指标。
- 作者完成演化阅读后，可以直接在“自动草图”中批量审核，不必先逐个采用地点。
- 风险：
  - 候选对象的质量直接影响草图质量。融合和拒绝时的绑定跟随规则必须有回归测试。
  - 演化链路仍在第四阶段实施和验收中（长篇跑通、扩类、#209 容量优化）。本步骤开工前需要和
    这些任务划分写入者，并且不能削弱主理解提交的原子性和恢复语义。

## 备选方案

### A. 挂在深度导入上（本 ADR 的初稿）

放弃。深度导入即将被世界演化替代并下线。

### B. 地图单独再读一遍正文

拒绝。会重复身份解析、预算和回执，也无法与演化 World 候选共用同一身份。

### C. 作为台账的一个新类别

拒绝。台账类别是长期派生主题；空间线索需要图结构端点，并归地图域所有。
但本步骤复用台账发现的 journal、独立复核、方法指纹和补扫机制。

### D. 作者手动触发

不采用。用户选择自动；作者仍可在授权预览中取消。

### E. 等地点采用后再建图

拒绝。正文抽出的地点默认都是候选，这样做会让自动冷启动失去意义。

### F. 由模型直接输出地图或坐标

拒绝。违背 ADR-0012 的“模型只抽关系，程序负责布局”。

### G. 高置信草图自动采用

拒绝。用户要求由作者审核；地图也不是 World 事实来源。
