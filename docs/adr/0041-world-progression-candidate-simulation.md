# ADR-0041 — 世界推进：离场人物与势力的候选推演

- **状态**: Proposed（产品方向由用户 2026-10-15 裁定；技术方案待评审）
- **日期**: 2026-10-15
- **关联追踪**: ADR-0017（事实权威）、ADR-0027（协作与角色模拟规则）、ADR-0031（依赖方向）、
  ADR-0032（引导流程）、ADR-0035（空间模型 v2）、ADR-0038（操作目录、目标运行与留痕）、
  ADR-0039（世界对象档案）、ADR-0040（统一推演协议、场景导演与统一提醒）、
  [世界对象档案、场景导演与写作副驾驶设计](../plans/2026-10-15-world-object-dossier-and-scene-director.md) §8、
  势力路线图（`.agent/tasks/2026/T-20261004-world-edit-history/TASK.md` §4.5 阶段 2、阶段 4）

## 背景

用户 2026-10-15 要求让一部分“世界”动起来：人物在大致的世界背景下自然发展，延伸出可能的剧情。
随后裁定：

- 参与者上限默认 12，作者可以自定义；
- 步数要看模型每一步实际能推进多少剧情，如果一步只推进一点点，上限就要很高才有用；
- 作者要能设定大致剧情，由模型结合世界对象和其他所需数据来推演。

现有能力都覆盖不到这一点：

- 现有排演（`rehearsal_v1`、`observation_v2`）只针对单个 Scene，且限制 1 至 3 名人物、用文本表示目的地；
  ADR-0040 提出的场景导演同样以单个 Scene 为范围，并决定把各种推演统一为 `simulation_v3`、下线原协议；
- 前瞻只给下一步的建议，不连续推进；
- 协作的世界压力检查验证设定在情境下是否成立，不推进人物；
- 演化第四阶段计划把“受控短期推进”列为后续候选；势力路线图阶段 4 列有“AI 推演（只出建议）”。

已有约束：多章只到大纲级候选，正文只做单章（2026-10-09 裁定）；行为树、效用 AI、数值平衡不做
（势力路线图 §4.6）；AI 只产生候选，正史只来自正文和作者确认（ADR-0017）。

## 决策

### 1. 定义与定位

- 世界推进：从截止 Scene 出发，让作者选定的人物、势力和群体，在已采用的世界背景下推进一段故事内时间，
  记录各自的行动与交汇，并提取可能的剧情。
- 推进是 Story 拥有的候选推演，是统一推演协议 `simulation_v3`（ADR-0040 §3）的“世界推进步”模式，
  与场景导演共用意图、结算、回放和分叉规则，粒度更粗、范围更大。
- 推进的任何产物都不是事实，不写入 continuity、World 设定或正文。

### 2. 两种推进方式

- **自由推进**：每个参与者按自己的目标和处境行动。
- **导向推进**（用户裁定）：作者设定大致剧情，可以是一段文字，也可以选中已有的篇章、剧情线或计划
  Scene 作为目标节点。
  - 目标节点默认是软目标；作者可以把某个节点标为“必达”，作为保留项。
  - 模型结合对象档案、时点状态、地图行程、势力、规则和人物动机，推演各方如何走到目标节点，
    并说明因果（动机、信息、处境）。
  - 如果要到达目标就必须让人物违背档案，或做出不可能的行程，模型不得强推，必须指出“不自然处”，
    并给出需要的铺垫或其他路径。
  - 目标节点只在导演层可见；参与者的意图阶段仍只用角色视角输入。

### 3. 输入

- **起点**：截止 Scene，默认最新已写的 Scene；状态取 continuity 作者视角。
- **参与者**：作者选择，或系统按离场时长、未完成目标、即将到期的承诺、与主线和目标节点的关联推荐。
  默认上限 12，作者可以自定义（用户裁定）。超过单次调用容量时分组调用并披露，与场景导演相同。
  势力在势力路线图阶段 1 之后可以参与；群体可以作为单一参与者。
- **背景**：已采用设定与对象档案（ADR-0039）、地图（行程与计算特性）、规则对象、势力控制（阶段 1 之后）。
  未采用的候选不进入；台账倾向按 ADR-0040 §10 的开关处理。
- **作者假设与保留项**：保留项是硬约束，例如某人物必须存活、某条路冬季不通、某目标节点必达。
- **作者有效期**：按 ADR-0039 §6 读取。

### 4. 步、步长与推进量（用户裁定）

- **默认每次点击推进一步**，与场景导演一致。作者可以选择“连续推进”，直到 N 步、到达目标节点或预算用完。
- **步长可选**：按故事内时间（一天、一周、一个月、一季、一年）；按剧情节拍（推进到下一个关键事件）；
  自动（默认：平静期跨得远，事件密集时放慢）。不要求日历系统，故事内时间能力上线后再接入。
- **每步报告推进量**：覆盖的故事内时间、发生的事件数，以及确定性指标（状态变化数、交汇数、
  目标完成或受阻数）。连续两步几乎没有推进时，提示作者加大步长。
- **步数不设低上限**：只受作者设定的连续步数和预算约束。评测测量各模型每步的平均推进量，
  据此给出按模型推荐的步长，而不是固定一个步数上限。
- **长程推进**：状态差量逐步精确保存；叙事部分用滚动摘要压缩。下一步读取精确状态与摘要，
  不回读全部历史步骤。

### 5. 每一步的流程

1. 每个参与者在角色视角下提出意图与行动：只看到自己知道的内容，加上对象简报（ADR-0040 §10）、
   当前目标和承诺；
2. 确定性交汇检测：同地、同目标、争夺同一资源、行程相交、信息传递路径（输入契约见下）；
3. 模型裁决交汇处的结果，结果有限，允许 uncertain；不交汇的行动做可行性检查后给简短结果；
   导向推进时，裁决层可以参考目标节点，但必须给出因果；
4. 在内存中应用状态差量：位置、状态字段、态度、知识、资源持有；
5. 观察投影：谁看到、谁听说；传闻按“角色说法”模态处理；
6. 确定性一致性检查：生死、行程可行性、保留项、作者有效期；违反时该行动失败或记为 uncertain。

**交汇检测的输入契约**：现有代码只有 `story/simulation.py` 按 `resource_key` 检测资源争夺，其余交汇类型
是新增能力。为让检测是确定性的，意图声明在自由文本之外必须携带结构化字段（`simulation_v3` 基于 ID 的
意图字段，ADR-0040 §3），缺失的字段不参与对应检测：

- 位置目标：地点对象 ID 或地图节点 ID（不接受纯文字地名）；
- 行程：起点、终点，可选路线引用（ADR-0035 的连接或行程声明 ID）；
- 目标对象：人物、势力、物件的对象 ID；
- 资源键：沿用 `resource_key`；
- 信息传递：信息内容的摘要键和接收者 ID。

检测规则：同一位置目标即同地；同一目标对象即同目标；同一资源键即争夺；路线引用有公共连接即行程相交；
接收者是另一参与者即信息传递。没有可用地图时，行程相交退化为“同目的地”，并在该步标注“未做路线比较”。

每一步保存为不可变记录，带输入与输出 hash；分叉绑定父步骤 hash，回放和分叉按 `simulation_v3` 的共用规则
（继承自 `observation_v2`）。
依据变化时，旧步骤标为“依据已变化”，处理方式与场景导演历史相同（ADR-0040 §9）。

### 6. 产出

- 推进记录：每步每个参与者的行动、对象时间线、态度与知识变化、推进量。
- 交汇点与可能的剧情：冲突、相遇、误会与信息差、承诺到期、势力变化、意外后果。
  每条附触发依据（档案条目、台账条目、设定、步骤 ID）。
- 导向推进另给：到达每个目标节点的路径、需要的铺垫、不自然处、可能的副线。
- 大纲级建议：可以写成 Scene 的事件，以及对现有伏笔和揭示计划的影响提示。不生成正文。

### 7. 采用路径

- 剧情钩子或路径 → `story.plan_structure` 的滚动窗口预览，作者采用为篇章、剧情线或计划 Scene。
- 交汇点 → 场景导演的起点：状态差量作为该 Scene 的假设进入导演（ADR-0040）。
- 人物近况 → 作者笔记，或作者确认后经 World 档案修订入口写入“作者备注的最新状态”（ADR-0039 §3）。
- 离场人物实际发生了什么，以作者之后写进正文、经演化读取的结果为准。
- 势力路线图阶段 2 上线后，推进结果可以另存为方案分支（只覆盖世界设定和势力账本），与其他方案对比。
  这是作者方案分支（3a），不是故事内世界线（3b）。

### 8. 历史

- 推进运行与步骤与导演历史一样一直保留到作者删除或项目删除，可按树浏览、标星、命名、对比、
  从任意一步继续。删除语义同 ADR-0040 §9：只由作者在界面删除，30 天内可恢复，AI 不开放删除。

### 9. 持续推进提醒

- 默认关闭，在项目持续授权内开启。
- 每读入若干章新正文，对“长期离场且有未完成目标”的人物做一次轻量自由推进，合并为提醒，
  进入统一提醒（ADR-0040 §13）。
- 只提醒，不写入；请求计入持续授权的请求与 token 预算；计费状态未知时停止。

### 10. 归属、依赖与预算

- Story 持有推进引擎与历史，新增推进运行表和步骤表；意图、事件、结算和回放使用 `simulation_v3` 的
  “世界推进步”模式（ADR-0040 §3），不再直接复用 `observations.py` 的旧协议，也不新建 `observation_v2` 运行。
- 读取路径：World 设定、地图、势力经 world facade（story→world 已允许）；对象简报经 Evidence；
  台账由 Evidence 经只读 DI 键读取（与 ADR-0039 §8 同一个键，ADR-0031 依赖表补登记一次）。
  Story 不新增依赖边。
- 一个推进运行使用一个根预算（请求数、工具调用数、token）。授权预览列出参与者、方式、步长、
  连续步数、预计请求次数与 token 区间，并提示可能产生费用；只记录计费状态，不估算金额（ADR-0038 §7）。
  用到 80% 时停下，计费状态未知时停下，不自动重发（ADR-0038 §6）。
- 推进历史不进入写作检索，不进入演化阅读，也不作为任何后续生成的事实来源。
- 目录项（ADR-0038）：推进一步为 R1（计入已授权运行预算）；准备推进运行为 R4（独立根预算，单独确认）；
  查看记录为 R0；采用钩子为大纲候选为 R3。按 ADR-0038 §8 留痕。
- 开关 `STORY_WORLD_PROGRESSION_ENABLED` 默认关闭，经评测后开启。

### 11. 边界

- 不做数值平衡、行为树、效用 AI、经济模拟、随机骰子系统。
- 不保证推演合理；每一步附依据，界面全程标注“推演，不是事实”。
- 不做多章正文，也不在推进后自动续写。
- 推进不修改对象档案；成长与变化只作为可能的剧情提出。
- RP 角色不读取推进记录。

## 后果

- Story：推进引擎、运行表与步骤表、导向目标与路径、推进量指标、钩子采用为大纲候选、导演起点入口。
- Story 另需：确定性交汇检测（`story/simulation.py` 只覆盖资源争夺），读取 `simulation_v3` 意图的结构化字段；
  推进依赖 ADR-0040 §3 的统一协议先落地。
- Evidence：为推进提供角色视角的对象简报（ADR-0040 §10）。
- 前端：推进视图（参与者、步长、时间线、交汇点、目标路径、钩子、分叉对比）。
- Assistant：准备推进授权、浏览钩子、引导流程 `world_progression_review`（ADR-0032 注册，默认关闭）。
- 评测：每步平均推进量（按模型）与推荐步长；钩子可用率；导向推进到达目标的比例与“不自然处”标注准确率；
  违反保留项、生死与行程约束的比例（目标 0）；角色意图越权知情的比例（目标 0）；请求数、token 与耗时。
  题材矩阵另加一部群像或种田样本。评分沿用 Sol/xhigh。
- 风险：
  - 推进结果看起来像已经发生。界面全程标注候选；推进记录不进入任何事实层或检索。
  - 用量高。默认一次一步，连续推进前预览；按模型推荐步长减少无效步骤。
  - 导向推进为到达目标而扭曲人物。必须报告不自然处，不得静默强推；评测单列。
  - 模型越权使用人物不知道的信息。意图阶段只给角色视角输入；评测单列越权比例。
  - 与势力路线图阶段 4 的“AI 推演”重复。本 ADR 即为该阶段的推演部分；阶段 4 只需补势力专属的
    一致性检查和编年视图。

## 备选方案

### A. 用游戏式模拟（数值、行为树、效用 AI）驱动世界

拒绝。势力路线图已明确不做；数值体系与多数题材无关，也会把作者推向调参而不是写作。

### B. 推进结果直接写入 continuity，作为“幕后已发生”

拒绝。违背 ADR-0017；作者之后写的正文可能与推进不同，两者会冲突。

### C. 推进后自动生成多章正文

拒绝。与 2026-10-09“多章只到大纲级候选”的裁定冲突。

### D. 固定较低的步数上限

拒绝。用户指出步数的意义取决于模型每步的推进量；固定低上限在推进量小的模型上没有用。
改为可选步长、推进量报告和按模型推荐。

### E. 放进 Collaboration 作为新配方

不采用。推进需要的意图、裁决、回放与分叉协议（`simulation_v3`）都在 Story，导演起点和大纲采用也在 Story；
放进 Collaboration 会让同一协议分两处维护。方案分支对比在势力路线图阶段 2 复用 Collaboration 的
workspace 骨架。
