# ADR-0029 — 本机 CLI 仅用于图片生成，并由服务端审核包装

- 状态：Accepted / Implementation in progress
- 日期：2026-09-28
- 授权：用户要求本机 CLI 暂不开放其他路径，仅用于生成图片，并自己加一层包装审核；
  生图场景选定「世界对象图片 + 地图册页面」两者。

## 背景

本机 CLI（Codex、Claude、Kimi、DSH、Pi）经配对的伴随进程在作者电脑上运行，
权限等同当前系统用户，工作目录不是沙箱。它原先可承接项目助手、已登录 RP、前瞻、
创作协作、RP 连续性检查和场景排演的文字 Agent。文字路径会把作品资料、导入稿件和
RP 输入交给一个有完整主机权限的进程，提示词注入可以直接变成本机命令执行；审查还发现
本机执行器下的建议工具与预算中止语义与网关路径不一致。

## 决策

1. 文字路径全部断开。项目 LLM 执行快照不再产出本机执行器；遗留的本机文字快照和
   助手运行在恢复时失败关闭，不静默改走账户连接，也不在本机执行。工具中继
   `run_local_agent` 保留并修正预算中止，仅为日后按新 ADR 重新开放。
2. 本机 CLI 只承接图片生成：世界对象图片与地图册页面。项目设置中的本机执行器
   语义变为「本机生图 CLI」；未配对时两处入口不可用，地图册仍可使用账户图片连接。
3. 审核包装层由服务端负责，模型或 CLI 的自述不构成通过依据：
   - 提示词由服务端按已确认资料拼装，作者可在提交前修改；包装指令与作者要求分开，
     作者要求只作图片描述数据。
   - 每个根任务单独确认本机主机权限；未确认的任务不会被领取。
   - 图片任务不提供任何产品工具（无 `novelcraft-tool`、无工具 socket），只下发参考图
     等输入文件；每次运行使用独立目录，结束后整目录删除。
   - 回传图片经服务端复核：PNG/JPEG 魔数与格式、Pillow 校验、单帧、字节与边长上限、
     先读尺寸再解码；通过后重编码为无元数据 PNG，再按目标用途缩放或裁切。
   - 结果只作候选：世界对象图片需作者预览后采用才替换当前图片；地图册页面沿用既有
     逐页审阅与采用流程。输入与输出字节只在单次调用期间暂存，调用结束即删除。

## 后果

- 本机文字 Agent 能力下线；相关前端审批提示只会对遗留任务出现，执行时失败关闭。
- 图片质量与生成手段取决于作者本机 CLI 的能力；服务端只保证格式、安全边界和采用确认，
  不保证画面内容正确，内容由作者审阅。
- 本机生成不产生平台模型费用，不计入账户图片连接的运行信封；作者本机订阅或工具费用
  不在平台账本内。
- 重新开放任何文字路径须另立 ADR，并先解决提示词注入到主机执行的风险。

## 2026-10-14 服务端入口缩面

G3③a 将待确认列表和批准限制为世界对象图片/地图册任务，旧文字 pending task
终止为 failed；companion claim 仅下发 mode=image，其他 pending invocation 失败关闭。
旧文本快照的 RP 续写拒绝，新的账户模型重新发起与历史回执读取保留。RP 界面不再
把图片 CLI 当作文字连接。文字 UI、工具中继与历史表的后续清理不属于本切片。

## 2026-10-14 工具中继端点下线（G3③d）

G3③d 删除服务端工具中继端点（`POST/GET /api/local-agent/companion/jobs/{id}/tools`
与 `ToolRequest`）和本机文字客户端 `local_agent/client.py`；伴随进程不再写
`novelcraft-tool` shim、不开产品工具 unix socket，非图片 job 直接失败。图片
invocation 的 `request_json` 携带空 `tools`，中继对图片本就不可达。历史工具调用表
`local_agent_tool_calls`（模型 `LocalAgentToolCall`）与迁移保留，历史回执读取保留。
`run_local_agent`（`runtime.py`，服务端中继的 worker 一半）保留在代码中但已无生产
入口；重新开放文字路径仍须另立 ADR，并届时一并恢复中继端点与客户端。
