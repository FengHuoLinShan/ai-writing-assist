# ADR-0038 — 项目助手同步支持地图与势力操作

- **状态**: Proposed（产品方向由用户 2026-10-15 裁定；技术方案待评审）
- **日期**: 2026-10-15
- **关联追踪**: ADR-0012（统一地图）、ADR-0023（有界 Agent 与项目助手）、ADR-0025（知识治理）、
  ADR-0031（依赖方向）、ADR-0032（引导流程）、ADR-0035（空间模型 v2 与涌现类型）、
  ADR-0036（世界演化空间发现）、ADR-0037（`map_spatial` 参考维度）、
  ADR-0039（统一操作目录与目标运行）、ADR-0040（操作留痕）、
  [地图系统增强设计](../plans/2026-10-15-map-system-enhancement.md) §9

## 背景

用户 2026-10-15 要求同步增强助手，帮助作者使用地图修改、势力控制等功能，范围不限于这两项。

助手现有的地图能力是“有界维护”，由 `backend/modules/world/assistant_map_tools.py` 注册四个操作：

- 把已采用地点加入地图，位置留空；
- 修改图元名称或备注；
- 创建空白地图节点；
- 处理已有地图版本。

此外还有以下限制：

- 读取地图只能经 `inspect_current` 查看作者当前选中的节点。
- 势力只能借用通用的 `world.create_entity`、`world.edit_entity`、`world.add_relation`，
  没有领地、生效区间、嵌套等语义。
- 物品与势力之间的类型转换（`EntityTypeTransitionService`）没有助手入口。
- 助手不接触世界演化。

地图增强（ADR-0035 至 ADR-0037）会带来更多新能力：结构与行程编辑、自动草图审核、
项目类型管理、演化空间发现和空间提醒。势力路线图阶段 1 还会带来势力数据模型。
如果助手不同步跟进，作者只能回到各个工作台手动操作，冷启动和日常维护的成本仍然很高。

## 决策

### 1. 地图与势力的每项新能力都同期提供助手入口

- 每项能力交付时同时注册助手操作或只读工具，不留到以后补。
- 助手只调用领域注册的操作（ADR-0023）：先生成预览，作者按批确认，执行前重验基线。
  失败、重试和恢复语义沿用现有批次机制。
- 操作由领域模块持有。地图操作归地图域，势力操作归势力域，演化入口归 evolution；
  经 `app/assistant_operation_registry` 和 DI port 接入，不新增模块依赖边（ADR-0031）。
- 本 ADR 是 ADR-0039 统一操作目录在地图与势力上的第一个实例。各操作按 ADR-0039 声明
  风险等级、费用类别和可撤销性，可以被目标运行编排，并按 ADR-0040 留痕。

### 2. 区分作者指令和模型推断

- **作者指令**：作者在对话中直接说明空间安排，例如“黑港在东海群岛里，从白塔乘船三天到”。
  - 助手把它解析成结构化预览，内容包括目标身份、关系类型、行程声明和生效区间。
  - 作者确认后保存为新的空间版本，与在地图工作台手动编辑同权。
  - 来源记为“作者经助手”，带运行 ID 和消息 ID，不要求原文引文。
  - 解析错误由预览的前后差异暴露给作者。
- **模型推断**：助手从正文或资料中推出的空间信息，例如“第 12 章暗示黑港在白塔以北”。
  - 必须附逐字引文和模态（`ObservationModality`）。
  - 作为线索候选进入地图审核队列，不直接写进已采用版本。
- **两类都不由模型给坐标**，布局由程序完成（ADR-0012）。

这一条把助手的地图能力从“只加入已知地点”扩展为“按作者指令编辑结构”。
结构生成模型“不能创造新地理事实”的规则（Prompt 体系设计“结构引导的地图图片”）保持不变：
新的地理内容只来自作者的确认。

### 3. 地图操作

以下操作由地图域注册，名称在实施时确定：

- **结构编辑**：
  - 创建、移动、合并、重命名节点和空间，调整层级；
  - 增删改关系、行程声明、通行条件和生效区间；
  - 把待放置托盘里的地点放到节点下。
- **自动草图审核**：
  - 按空间或层级准备一个审核操作，预览列出节点数、待核对项和抽样；
  - 指纹覆盖全部修订 ID，执行时调用地图域的批量审核；
  - 超过单批上限时分批，不拆成大量单项。
- **线索处置**：采用、拒绝或合并待审的空间线索。
- **类型管理**：
  - 创建、改名、调整计算特性、合并、拆分、归档项目类型，应用题材预设；
  - 处理模型提出的合并建议；
  - 作者经助手确认的改动视同作者决定，世界演化之后不得覆盖（ADR-0035 §4）。

地图图片仍由地图工作台的受控页面处理（确认、计费、ADR-0029 本机 CLI 范围），助手只负责导航。

### 4. 势力操作

- **势力路线图阶段 1 的 ADR 落地之前**：沿用现有通用操作，不在助手里模拟领地、生效区间等
  尚无数据模型的语义。
- **阶段 1 之后**由势力域注册以下操作：
  - 建立势力和势力单元；
  - 设置嵌套：组织内从属、宗主与附庸、交叉身份三类分别表达，不允许成环；
  - 设置或转移控制：控制方式类型、目标（地点、航线、单元）和按章节生效的区间；
  - 船等对象在物品与势力单元之间转换：经 `EntityTypeTransitionService` 预览档案字段迁移，可以撤回；
  - 账本条目。
- **领地图层只读**：作者可以问“第 N 章东海归谁控制”，但助手不编辑领地图层本身，
  只修改它背后的控制关系。

### 5. 空间与势力问答

- 新增只读工具（名称待定），可以查询：
  - 某地点或 Scene 的空间简报；
  - 两地之间的行程声明；
  - 某移动对象在某章的最后位置；
  - 某章的势力控制情况。
- 工具经 Evidence 和 world 地图 facade 读取，遵守排除范围、读者揭示和角色可见性。
  结果附地图版本与来源；查不到时返回 unknown，不推测。
- `assistant.turn` 把 `map_spatial` 声明为参考维度，追加到 ADR-0037 首批能力之外，
  同样默认关闭、经评测后开启。
- **空间提醒**：助手可以解释提醒，并给出两类修复方案：
  - 改正文：生成 Writing 候选；
  - 改地图：生成地图操作预览。
  作者也可以按条目静默提醒（沿用 notice disposition），忽略提醒不改变领域结论。

### 6. 世界演化入口

- 助手可以准备演化阅读或空间补扫：调用演化自己的授权预览（范围、预计请求、费用），
  作为待确认批次展示。
- 作者确认后由演化任务执行。费用计入演化运行的根预算，不占助手运行的请求预算；
  助手不能自行确认付费运行。
- 运行完成后，助手可以汇总草图状态（空间数、待核对数、新类型数），并带作者进入审核。

### 7. 引导流程

按 ADR-0032 的注册机制追加流程，默认关闭，沿用 `ASSISTANT_GUIDED_FLOWS_ENABLED` 和项目白名单：

- **`map_cold_start` v1**：
  1. 确认阅读范围和授权；
  2. 演化阅读（含空间发现），用 `operation_id` 保证幂等；
  3. 草图就绪；
  4. 作者按空间选择审核；
  5. 可选：一并采用地点；
  6. 停在“地图可用”。

  只在真实选择、扩大授权和硬性阻断处停下。
- **`faction_setup`**：等势力路线图阶段 1 完成后再定义。

### 8. 主动提醒

在项目持续授权内（默认关闭），以下事件可以合并成提醒：

- 新地点进入待放置托盘；
- 新类型涌现；
- 草图待核对项增多；
- 新的空间提醒。

### 9. 兼容与边界

- 新工具和新操作只进入新运行：作者运行协议升级版本，旧运行的冻结目录不变。
- 一次确认最多 20 项（`BatchDecision.selected`）。大范围整理交给按空间的批量审核操作或引导流程。
- 作者处在“当前章节或 Scene”范围时，结构修改仍要求到地图工作台核对整个空间版本（现有规则）。
- 不做：
  - 模型生成坐标或地图图片；
  - 自动采用；
  - 跨域原子采用（属于 Collaboration）；
  - 由助手编辑领地图层；
  - 让 RP 角色读取客观地图。

## 后果

- 地图、势力和 evolution 各自需要新增助手操作；Assistant 需要升级作者运行协议、
  新增只读工具和引导流程，并补充导航目的地（草图审核、类型管理、势力面板）。
- 助手能力需要独立评测：
  - 按五类题材准备自然语言指令，覆盖建图、改结构、行程、类型合并、势力嵌套、船的转换和问答；
  - 评估目标解析正确率、预览与意图一致率、越权和猜测坐标的拒绝率、问答 unknown 的正确率；
  - 评分沿用 Sol/xhigh，代理验收保留 `human_validated=false`。
- 风险：
  - 自然语言解析可能错指对象。预览必须显示目标身份和前后差异；
    存在同名或歧义时先让作者选择，不自行挑选。
  - 操作数量增加会挤占助手的工具预算。单轮做不完的整理应交给引导流程，而不是一轮内硬做。

## 备选方案

### A. 助手只导航，所有修改回工作台完成

不足。用户要求助手帮助作者使用这些功能；只导航无法降低冷启动和维护成本。

### B. 助手直接调用地图服务写入，不经过预览和确认

拒绝。违背 ADR-0023“写入按具体预览成组确认、执行前后核验基线”。

### C. 把模型推断的空间信息直接写进已采用版本

拒绝。违背“只产生候选、作者审核”的裁定，也会让无引文的推断进入地图。

### D. 在势力数据模型落地之前，先在助手中模拟势力语义

拒绝。会形成第二套势力数据，与势力路线图冲突。
