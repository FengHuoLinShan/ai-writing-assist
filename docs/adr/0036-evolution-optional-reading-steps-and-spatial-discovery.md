# ADR-0036 — 世界演化可选阅读步骤契约与空间发现（地图自动冷启动）

- **状态**: Accepted / 实施中（空间模型、类型词表及演化空间发现工程已落地；五题材质量评测、启用与作者验收仍待完成；产品方向由用户 2026-10-15 裁定；技术评审修订后由用户 2026-10-15 采纳）
- **日期**: 2026-10-15
- **关联追踪**: ADR-0012（统一地图）、ADR-0013（operation receipt）、ADR-0025（知识治理）、
  ADR-0031（依赖方向）、ADR-0035（空间模型 v2 与涌现类型）、ADR-0039（对象档案发现，本契约的第二个实例）、
  [世界演化模块](../modules/22_evolution.md)、
  [地图系统增强设计](../plans/2026-10-15-map-system-enhancement.md) §6

## 背景

新建地图成本高，冷启动太长：

- 深度导入不生成地图（[地图模块](../modules/15_map.md)“上游智能整理”）。
- 地图只消费已采用资料，而从正文抽出的地点仍是候选对象。
- 地图结构生成一次最多 20 个地点、每批 5 个，每次 run 都要确认一次 Context，并且按节点逐个进行。

导入一本长篇后，作者要先逐个采用地点，再反复手动生成，才能看到一张可用的地图。

用户 2026-10-15 裁定：

- 冷启动自动进行，作者只负责审核；
- 草图允许绑定候选地点；
- 作者不填空间数据时只从原文抽取并审核；
- 地图保持示意与提醒级；
- 深度导入即将被世界演化替代并下线，冷启动不再挂在深度导入上；
- 空间类型对齐世界演化的“涌现”思想，由模型在演化中总结、按项目维护（ADR-0035 §4）；
- 技术评审后：草图尽量在原有版本上做增量候选，必要时才重做；为演化的可选步骤建立统一契约。

世界演化已经逐 Scene 读取正文，完成身份解析并生成 World 候选（含地点），
每 Scene 原子提交候选与理解回执（[世界演化模块](../modules/22_evolution.md)）。
其持续发现（`discover_details`）已有一整套可复用的机制：

- 授权预览披露发现和独立复核共用的根预算；
- 每批调用在 journal 中冻结并计量，结果未知的请求不重发；
- 生成与复核可以并行，Scene 写入按顺序串行，新提议只与严格更早的提议去重（`evolution/discovery.py`）；
- 有界回读既有主题，并披露省略数；
- 方法指纹与 `consumer_read_set.v1`；
- 类别补扫的预览与确认（`category-rescan-preview` / `category-rescan`）。

本系列设计还要为演化阅读增加空间发现（本 ADR）和对象档案发现（ADR-0039 §9）。如果每个步骤各自定义开关、
journal、缺口、指纹、补扫和预算，规则会分叉，预算不足时的取舍也不确定。

地图与演化的现有衔接：

- **G8a（已实现）**：已发布正文变化后，演化回执记录受影响的地图册来源
  （`receipt.invalidated_consumers["map_atlas"]`），经 DI 键 `world.read_map_chapter_consumers`
  只读核对当前已保存地图版本，提示“待核对”；不修改地图版本或 World 正史。
- **G8b（已实现）**：Writing 冲突检查经 `world.read_map_node_heads` 读取节点当前版本，在响应中比对地图基线。
- 待审候选仍是 `map_atlas` 的残余 unsupported 来源（`evolution/consumption.py`）。
- 地图版本表 `map_atlas_revisions` 只追加，每条保存整份文档；状态只有候选、已保存、已拒绝；
  同一任务对同一节点只能有一条版本（`uq_map_revision_task_node`）。

另外，深度导入尚未退役：[世界演化模块](../modules/22_evolution.md)记录“默认导入入口仍由 deep_import 编排”。

## 决策

### 1. 可选阅读步骤契约

**适用范围**：演化阅读中，主理解（身份解析、World 候选、理解回执）之外的每个可选步骤。
现有持续发现 `discover_details` 是第一个实例，迁移到契约时行为不变；本 ADR 的空间发现、ADR-0039 的对象档案发现
和以后的新步骤都按本契约登记。台账新类别是持续发现内部的类别扩展，沿用其类别补扫，不另作步骤。

**登记**：evolution 维护一份可选步骤登记表（纯数据规格）。每个步骤声明：

- 步骤键与 `ReadingRequest` 上的开关字段；
- 抽取与独立复核两项能力，登记进 ADR-0025 的知识治理注册表；
- journal 前缀 `scene_<步骤键>_*`；
- 方法指纹的组成（提示词、schema、阈值、内核版本、召回参数）；
- 产出归属的领域和写入端口（经 facade 或 DI 键，不新增模块导入边，ADR-0031）；
- 产出的失效消费者（来源变化时由谁核对）。

**开关**：API 字段默认 `false`，旧客户端和直接 API 调用不受影响，服务端不按客户端版本判断；
新界面在授权预览中默认勾选并显式发送 `true`，作者可以取消；append 和 continue 沿用原运行的设置与方法版本，
不静默升级。

**执行位置与隔离**：

- 每个 Scene 在身份解析和候选冻结之后运行可选步骤；主理解回执不等待任何可选步骤。
- 步骤之间不读取同一 Scene 尚未提交的产出，只读主理解结果和更早 Scene 已提交的产出。
- 步骤失败、额度不足或结果未知时，只把该步骤在该 Scene 的覆盖记为缺口，不影响主理解提交、
  其他步骤和后续 Scene。

**并行与顺序**：生成与复核可以并行，写入按 Scene 顺序串行（沿用 `discovery.py`）。输入在批次准备时冻结，
记入该 Scene 的 `consumer_read_set`；新身份、新类型或新面向的提议在顺序写入时只与严格更早的提议去重。

**预算**：

- 共用运行的根预算、`budget_mode` 和 `request_limit`，不新建预算协议。
- 授权预览按步骤列出预计请求区间，并在根预算内为每个步骤划分子额度，由作者确认；主理解的额度优先保留。
- 某个步骤的子额度用尽时，只把该步骤剩余的 Scene 记为缺口，不挤占主理解和其他步骤。
- 每批调用在该步骤的 journal 中冻结并计量；结果未知的请求不重发，记为缺口，需要人工核对。

**覆盖**：按（步骤、Scene）记录四种状态：已检查；已检查但密度不足而跳过；缺口（失败、额度不足、结果未知）；
未检查。界面分开显示，不把“未检查”显示成“没有发现”。

**补扫**：已读范围中没有做过某步骤，或方法版本较旧的部分，可以先预览（不发请求）再由作者确认补扫；
确认时绑定操作 ID 与来源、方法、模型、预算指纹，发送前扣减额度。沿用 `category-rescan-preview` /
`category-rescan` 的做法。

**重算**：revise 和 `scoped_recompute` 对每个已启用的步骤只重算受影响的 Scene；旧产出标“已被取代”，不删除。
依赖被取代产出的项目词表条目按 ADR-0035 §4 重新判定。

**方法指纹**：每个步骤有自己的方法指纹，只包含方法本身；运行中会变化的项目数据（如类型清单、面向清单）
不进入方法指纹，只进入 `consumer_read_set`。`consumer_read_set` 未变时可以复用旧结果。

**契约测试**：每个登记的步骤都必须通过同一套契约测试：开关默认值、append 与 continue 继承、失败隔离、
子额度耗尽、结果未知不重发、补扫幂等、重算取代旧产出。

### 2. 空间发现：第一个新增实例

- 开关 `ReadingRequest.discover_spatial`（已登记，默认关闭）；journal 前缀 `scene_spatial_*`。
- 能力：`evolution.spatial_discover`（抽取空间线索）、`evolution.spatial_review`（独立复核）。
- 产出归地图域，经 world 的地图 facade 写入（§6）。

### 3. 地理密度预检

- 不调用模型。统计本 Scene 身份解析结果中的地点类对象，以及空间词汇的命中数。
  词汇包括系统基础词和项目空间类型的名称与别名；所用词表快照记入 `consumer_read_set`。
  阈值带版本号并纳入方法指纹。
- Scene 零命中时跳过，记为“已检查、密度不足”。
- 整次运行都低于阈值时，告诉作者原因（`low_spatial_density`）。

### 4. 输入与输出

**输入**：

- 本 Scene 的精确正文，不带后续 Scene；
- 本 Scene 的身份解析结果，包括已采用对象和演化 World 候选；
- 按相关性召回的项目空间类型（ADR-0035 §4），设上限并披露省略数；
- 与本 Scene 对象相关的已有空间线索和地图节点，设上限并披露省略数。

**输出**：空间线索，包括包含、方位、相邻、相通、行程声明、通行条件，以及毁城、改名等生效变化。
每条线索带：

- 端点身份引用；
- 已有项目类型的 ID，或新类型提议（名称、描述、建议的计算特性）；
- 模态（`ObservationModality`）；
- 逐字引文。

**服务端重验**：作品、Scene、来源 hash、范围和引文；身份引用必须出现在本批实际输入中。
无效项连同原因一起丢弃，不靠猜测修复。解析不了的端点保留为文字标签，进入“待放置托盘”。

### 5. 独立复核

- 线索、模态判断和新类型提议都要经过绑定本批输入的独立复核。
  复核结论为不支持或不确定的项保持待核，不产生地图效果。
- 新类型按 ADR-0035 §4 处理：至少要有两个 Scene 的证据；只出现一次的保持“涌现中”。

### 6. 线索归地图域保存

- 线索是地图域的候选记录，状态为待审、已采用、已拒绝、已被取代。
  记录携带来源引用、来源 hash、运行 ID 和回执 ID。
- 线索不是 World 事实，也不写 World 关系。
- 写入经 world 的地图 facade 完成，evolution 不依赖地图模型，符合 ADR-0031 的方向规则。
- 线索与本步骤的回执同事务提交，回执链接到该 Scene 的理解回执。

### 7. 草图：在已有版本上做增量候选

**构建规则**（程序完成，不调用模型）：

- 层级来自“包含”类线索，以及 World 中已采用或候选的 `located_at`/`contains` 关系。
  来源冲突时按以下优先级取父节点：已采用的 World 关系 > 已采用地图版本中的父子关系 >
  复核通过的线索 > 候选 World 关系。较低优先级的来源与较高者矛盾时不覆盖，只把该节点标为“待核对”，
  并列出各方来源。
- 空间来自具备“跨空间”特性的连接线索。
- 布局沿用现有确定性算法（方向分层、有界网格避让），并按 ADR-0035 的特性扩展跨空间、上下和远近。
- 按空间和层级分片，每片仍遵守现有单次上限（图元、关系、控制点数量）。

**增量优先**：

- 每个节点最多有一条待审的自动草图候选，带 `auto_draft` 标记。
- 有新线索时，以该节点当前的待审草图候选为基础（没有则以已保存版本为基础，再没有则从空白开始），
  只加入新增的图元和关系，生成新的候选版本，`base_revision_id` 指向基础版本。
  已有图元的位置保持不动，只为新增内容找位置。
- 被新候选取代的旧草图候选标为“已取代”：`map_atlas_revisions` 的状态约束新增 `superseded`，
  与作者拒绝区分。已保存版本从不修改；针对已保存节点的新线索同样生成以已保存版本为基础的增量候选，
  作者审核后才保存为新版本。新地点进入待放置托盘。
- **节奏**：不在每个 Scene 提交后生成。在每个阅读批次结束、运行结束或作者打开“自动草图”视图时，
  对有新线索的节点合并生成一次增量候选。每次生成使用独立的草图任务 ID，满足 `uq_map_revision_task_node`。

**必要时才整片重做**：以下情况重做该分片，仍生成新的候选并取代旧候选，不修改已保存版本：

- 方法或特性内核版本变化；
- 重算使草图依赖的线索被取代，增量无法表达删除或移动；
- 层级来源冲突改变了父节点；
- 增量放置失败（放不下或与已有图元冲突）；
- 作者手动要求重做。

只有候选版本的节点不进正式目录（现有规则），在“自动草图”视图中审核。

### 8. 允许绑定候选地点

- 草图图元可以绑定演化 World 候选地点。
- 候选被融合时，绑定跟随融合目标；候选被拒绝或删除时，绑定降级为文字标签，并提示作者。
- 采用草图节点时，作者可以勾选“一并采用地点”。这一步走 World 原有的采用入口，
  门禁不变，仍会重验回执前缀。
- 不勾选时也可以保存版本；但绑定候选对象的图元在对象采用前不进入读者预览、写作简报和空间检查，
  界面标“地点未采用”。

### 9. 从不自动采用

线索和草图一律等作者审核。新类型按 ADR-0035 §4 在复核通过后自动启用，
但只影响显示和模型上下文，不会让任何线索或草图进入正式地图。

### 10. Context 与知识范围

- 本步骤的输入进入演化运行自身的 InputManifest 和 `consumer_read_set.v1`，
  其中包括项目类型清单的修订指纹。
- 演化授权只替代“创建草图”这一步的地图 Context 确认。之后的地图 AI 操作
  （结构生成、图片）仍使用地图自己的确认流程。
- 采用时按地图现有规则重验来源 hash。

### 11. 增量、重算与补扫

- append、continue、revise、`scoped_recompute` 和补扫都按 §1 的契约执行。
- 已采用的地图不会被修改：针对已采用节点的新线索只生成增量候选（§7）。
- 空间发现的方法指纹覆盖提示词、schema、密度阈值、特性内核版本和类型召回参数；
  类型清单和词表快照只进入 `consumer_read_set`。

### 12. 地图登记为演化消费者

- `map_atlas` 正式消费空间线索和候选绑定。Scene 被重算或撤销导致线索失效时，扩展 G8a 的
  `map_atlas` 消费端口（`world.read_map_chapter_consumers` 及回执的 `invalidated_consumers["map_atlas"]`），
  使其覆盖由线索派生的节点，依赖这些线索的地图节点显示“待核对”；不新增失效协议。
- 这样可以收窄“待审候选”这一项 `map_atlas` 残余 unsupported 来源；
  不声称闭合 `world_canon_revision` 或 `world_knowledge`。

### 13. 深度导入不再增加阶段

- 深度导入即将下线，不为它新增空间阶段。
- 已用深度导入导入的作品，可以通过演化阅读（bootstrap）或空间补扫获得草图；
  其已有的地点对象和候选都可以绑定。
- **前提**：“导入后自动冷启动”以演化阅读成为默认导入入口为前提。在此之前，空间发现只在作者发起的
  演化阅读中运行；现有手动地图结构生成路径保留，作为回退，不因本 ADR 移除。

### 14. 不生成图片

自动冷启动只产生空间结构候选；图片仍走地图册现有的确认和计费状态机。

## 后果

- evolution：可选步骤登记表与共用契约测试；`discover_details` 迁移为登记表的第一个实例，行为不变，
  回归测试保持零差异；新增空间步骤的阅读参数、两项能力、journal 类型和方法指纹字段。
- 地图域：线索记录、增量草图构建、`auto_draft` 标记、待放置托盘，以及 ADR-0035 的项目类型；
  `map_atlas_revisions` 状态新增 `superseded`，需要 migration，并排查所有按状态枚举读取版本的地方；
  G8a 的地图册消费端口扩展到线索派生节点。
- 阅读的请求数和时长会增加。实际用量由首批题材矩阵评测和诡秘前 60 章冒烟给出；
  G7b 账本模板需要增加本步骤的指标。
- 作者完成演化阅读后，可以直接在“自动草图”中批量审核，不必先逐个采用地点。
- 风险：
  - 候选对象的质量直接影响草图质量。融合和拒绝时的绑定跟随规则必须有回归测试。
  - 增量放置可能让布局逐渐变差：放不下时转为整片重做，作者也可以随时要求重做。
  - 演化链路仍在第四阶段实施和验收中（长篇跑通、扩类、#209 容量优化）。契约迁移和本步骤开工前需要和
    这些任务划分写入者，并且不能削弱主理解提交的原子性和恢复语义。

## 备选方案

### A. 挂在深度导入上（本 ADR 的初稿）

放弃。深度导入即将被世界演化替代并下线。

### B. 地图单独再读一遍正文

拒绝。会重复身份解析、预算和回执，也无法与演化 World 候选共用同一身份。

### C. 作为台账的一个新类别

拒绝。台账类别是长期派生主题；空间线索需要图结构端点，并归地图域所有。
本步骤按 §1 的契约复用持续发现的 journal、独立复核、方法指纹和补扫机制。

### D. 作者手动触发

不采用。用户选择自动；作者仍可在授权预览中取消。

### E. 等地点采用后再建图

拒绝。正文抽出的地点默认都是候选，这样做会让自动冷启动失去意义。

### F. 由模型直接输出地图或坐标

拒绝。违背 ADR-0012 的“模型只抽关系，程序负责布局”。

### G. 高置信草图自动采用
