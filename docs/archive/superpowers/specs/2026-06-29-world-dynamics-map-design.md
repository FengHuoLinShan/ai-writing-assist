# 世界动态地图超级形态设计

> **Superseded（已取代）：** 旧动态地图设计记录，不是当前契约。现行实现见 `docs/modules/15_map.md` 与 ADR-0012。

## 背景

当前动态地图已经是 `world` 模块内的可用子系统，覆盖地图层级、六边形地形、地点绑定、Scene 动态标记、势力范围、聚焦模式、一级地图工作台和写作页 Scene 地图摘要。

本设计在现有地图工作台之上定义“世界动态地图”的超级进化形态：地图不再只是地理编辑器，而是小说世界状态的高密度实时总控台。它要尽可能完整反映小说构造出的世界，包括当前剧情线、主线危机、主要人物、地点、势力、资源、交通/阻隔、秘密、规则、能力体系、事件影响、AI 映射候选和历史变化。

核心目标不是把所有对象硬塞到地图上，而是通过自动布局、图层优先级、候选/正式事实流转、来源证据和可编辑检查器，让作者能掌握“世界现在如何运行”，并能在任何查看上下文里直接修正地图事实。

## 目标

- 地图默认进入“世界动态总控台”，一眼展示当前剧情线、主线危机、主要人物和最重要风险。
- 同一套地图事实支持三种视图：世界动态总控台、活地图、叙事透镜。
- 小说关键要素尽可能完整进入地图系统：地点、人物、事件、组织、资源、交通/阻隔、秘密、规则、能力体系、知识边界、危机和 AI 候选。
- 所有查看页面都能点击对象进入地图编辑闭环：对象信息框、右侧检查器、批量修改。
- LLM 结构化信息能自动映射到地图系统，但按来源和置信度区分正式事实、候选、冲突和忽略。
- 高级动态属性通过时间化事实差分计算：位置变化、状态变化、边界变化、危机扩散、资源控制变化。
- 地图高密度显示必须自动避让、聚合和降级，默认不允许文字、气泡、图表重叠。
- 用户界面默认显示名称、时间、状态文案和来源摘要，不展示技术 ID。
- 设计必须保持模块边界：每个模块增强自己的领域事实，`world/map` 统一归一化和可视化。

## 非目标

- 不把本项目改成多 Agent 协同系统。
- 不让 `imports`、`outline`、`memory` 或 `context` 直接拥有地图布局或地图 UI。
- 不让低置信、日常草稿或冲突性 AI 结果直接污染正式地图事实。
- 不把技术 ID 作为作者界面的默认显示内容。
- 不用持续动效替代信息结构；默认地图仍是可读、可点、可编辑的工作界面。
- 不在本设计中指定具体前端渲染库替换方案；若引入新运行时依赖，需另行确认或 ADR。

## 体验架构

### 三种视图

地图一级入口仍是 `地图`。默认打开“世界动态总控台”。

**世界动态总控台**

默认视图。中央是地图画布，左侧是视图模式、图层组、时间/焦点控制，右侧是动态队列和统一检查器。第一视觉层强调当前剧情线、主线危机、主要人物、当前 Scene 事件和空间连续性风险。

**活地图**

一键切换的全量视觉视图。它释放更多地图空间和视觉层，适合宏观浏览完整世界、检查势力格局、资源分布、交通阻隔和世界状态。

**叙事透镜**

一键切换的写作现场视图。它围绕当前 Scene、人物、组织、剧情线或危机收窄信息，只强化和焦点相关的地点、轨迹、事件、秘密、规则、知识边界和风险。

三种视图消费同一套地图事实，不维护三套数据。

### 查看页入口

所有核心查看页都可以进入地图上下文：

- 写作页 Scene。
- 大纲 Scene 和剧情线。
- 人物详情。
- 地点详情。
- 组织/势力详情。
- 事件详情。
- 世界对象列表和对象详情。
- AI 映射队列。

入口打开地图时携带上下文，例如 `scene_id`、`focus_entity_id`、`thread_id`、`crisis_id` 或 `map_id`。地图根据上下文进入总控台、活地图或叙事透镜，并打开相关对象信息框或右侧检查器。

### 对象信息框与检查器

地图边缘只显示轻量提示：`点击对象可修改`。

作者点击地图上的人物、地点、事件、势力、资源、候选气泡或语义气泡后，先出现对象信息框。对象信息框展示名称、Scene/章节/时间、状态文案和来源摘要，并提供：

- `修改`：进入该对象的轻量单项修改。
- `打开检查器`：进入右侧统一检查器。

右侧检查器负责复杂编辑：对象摘要、地图事实、时间化状态、来源证据、AI 候选、冲突/风险、相关世界动态、保存修改、批量修改。

## 信息层级与图层系统

### 第一视觉层

默认最强显示：

- 当前剧情线。
- 主线危机。
- 主要人物。
- 当前 Scene 事件。
- 空间连续性风险。

这些内容进入动态队列，并可使用操作型动效：轨迹高亮、危机扩散、候选闪烁、风险脉冲。

### 第二结构层

默认可见但弱化：

- 地点层级。
- 势力范围。
- 资源分布。
- 交通和阻隔。
- 组织关系。
- 战线、封锁、边界。

作者聚焦组织、地点、资源或切到活地图时，这些图层增强。

### 第三语义层

第三语义层承载：

- 秘密。
- 规则。
- 能力体系。
- 传说。
- 角色知识边界。
- AI 候选。
- 来源证据摘要。

它默认不围绕焦点人物漂浮，而是在地图上方空白区以消息气泡框发散展示，带轻微漂浮和呼吸效果，避免遮挡地图主体。

当系统检测到某个语义对象与地点强关联时，气泡才下沉并锚定到地点或地点周边。聚焦人物时，语义气泡内容跟随焦点过滤，例如只显示该人物相关秘密、规则风险、能力限制、知识边界；位置仍优先使用地图上方空白区。

### 图层密度预设

图层控制不只是开关，而是密度预设：

- 总控台：高密度但可读。
- 活地图：释放更多背景和结构层。
- 叙事透镜：只强化与焦点相关的层。
- 编辑状态：暂停或弱化背景动效和低优先级标签。

每个图层都要能解释来源、状态和可信度。

## 自动布局与避让系统

高密度地图必须有布局引擎。布局引擎每次根据视图模式、缩放级别、当前剧情焦点、对象重要性、对象状态和屏幕空间，决定对象的显示级别。

### 评分规则

对象显示优先级从以下维度综合计算：

- 当前剧情线相关性。
- 主线危机相关性。
- 是否主要人物。
- 是否当前 Scene 相关。
- 是否用户当前聚焦对象。
- 是否近期发生变化。
- 是否正式事实。
- 是否候选、冲突或待确认。
- 是否存在高风险提示。
- 对象重要性和剧情线权重。

### 显示降级阶梯

对象显示从高到低依次降级：

1. 完整标签。
2. 短标签。
3. 类型图标和状态点。
4. 聚合簇，例如 `人物 3 / 事件 2 / 候选 4`。
5. 只进入右侧检查器、动态队列或上方语义气泡带。

低优先级对象不硬挤在地图上。

### 避让规则

标签围绕锚点寻找可用位置，优先避开：

- 既有标签。
- 地图边界。
- 重要路线。
- 危机扩散区。
- 语义气泡。
- 对象信息框。
- 当前编辑命中区域。

如果无法避让，自动缩短、转为图标或聚合，不允许重叠。

### 聚合与展开

同格、相邻格或视觉距离过近的对象自动聚合。聚合簇按对象类型显示摘要。点击、悬停、放大或切换叙事透镜时展开。

### 焦点重排

切换焦点时，用过渡动画重排：

- 焦点对象展开。
- 相关对象增强。
- 背景对象收缩为图标或聚合簇。
- 上方语义气泡重新排队。
- 强地点关联的语义气泡锚定到地点或周边。

重排必须稳定，不让对象持续乱动。

## LLM 自动映射与高级动态计算

### 来源分级

LLM 自动映射按来源分级：

- 深度导入、用户明确确认启动的自动流水线：高置信结构化结果可以进入正式地图事实，但必须保留来源、可编辑标记和可回滚路径。
- 写作草稿、Scene 正文即时分析、低置信抽取、存在冲突的抽取：进入 AI 候选层，不直接写正式地图事实。

### 映射类型

自动映射覆盖三类内容：

**空间事实**

地点绑定、Scene 主地点、人物/事件/物品标记、人物位移、角色在场状态。

**世界动态**

势力范围变化、资源变化、封锁、交通阻隔、危机影响域、战线推进、城市状态变化。

**语义关联**

秘密、规则、能力体系、知识边界、传说等与人物、地点、组织、事件的关联。

### 高级动态计算链路

基础属性如名称、类型、别名、概要可以直接抽取。高级属性不能直接把 LLM 输出当结论，而是走：

```text
Observation 观察事实
→ MapFact 时间化地图事实
→ Delta 前后差分
→ WorldDynamic 世界动态事件
```

`Observation` 是原文、Scene、导入批次、LLM 抽取或人工编辑给出的证据。系统先把它归一化为 `MapFact`：对象、时间范围、空间锚点、状态维度、来源、置信度。

然后算法按 Scene 逻辑顺序比较同一对象、同一维度：

- 位置变化：同一人物、事件或物品在不同 Scene 的空间锚点不同，形成位移。结合距离、明确线路端点和阻隔检查空间连续性；在没有 Scene 时长和地图比例尺时，不推断移动速度或分钟级可达性。
- 状态变化：同一对象在同一状态维度前后值不同，例如城市从开放到封锁，人物从健康到受伤。
- 边界变化：势力、危机和资源控制区使用快照和增减 delta 表示，支持扩散动画和回放。

LLM 负责提出候选观察、解释证据和识别模糊关联。系统负责归一化、比较、校验、冲突检测和展示。

### 与现有 deep import / memory 的关系

现有深度导入 Phase 2 已有 `entities / relations / delta_events`，并在 Scene 完成后调用 `memory.capture_snapshot`。这说明当前系统已有高级属性提取的雏形。

但现状仍不足以直接支撑超级地图：

- `delta_events` 目前太通用，缺少位置、状态、边界、危机、资源等 typed observation。
- `delta_log` 没有稳定绑定地图对象、空间锚点、动态类型和审查状态。
- `memory_snapshots.full_state` 当前主要抓正史世界状态，不天然包含候选对象和地图事实。
- `get_full_state` 当前不包含 `map_markers`、`map_location_bindings`、`map_territory_tiles` 等地图状态。

因此设计要复用 memory 的事件溯源和快照思想，但由 `world/map` 新增或规范地图专用动态模型：

```text
MapObservation
MapFact
MapDelta
WorldDynamic
```

其中 `MapObservation` / `MapFact` 是持久化证据层和事实层；`MapDelta` / `WorldDynamic` 是
world/map 从 confirmed facts 计算出的确定性只读模型，不建立第二套事实表，也不由 GET
请求回写。candidate 只能作为待处理预览，不能进入有效状态或差分。

现有 `delta_log` 可以作为第一阶段承载，但需规范 `meta` 或扩展字段：

- `target_entity_id`
- `target_entity_type`
- `dynamic_type`
- `time_anchor`
- `spatial_anchor`
- `confidence`
- `review_state`
- `source_ref`

## 手动编辑模型与批量修改

### 对象信息框

对象信息框是地图内的第一编辑入口。它不显示技术 ID，默认显示：

- 对象名称。
- 类型文案。
- Scene/章节/加入地图时间。
- 当前地点或空间锚点。
- 状态文案。
- 来源摘要。
- 轻量风险提示。

操作：

- `修改`：进入单项修改。
- `打开检查器`：进入右侧检查器。

### 右侧检查器

右侧检查器是复杂编辑入口。它展示：

- 对象摘要。
- 地图事实。
- 时间化状态。
- 来源证据。
- AI 候选。
- 冲突和风险。
- 相关世界动态。
- 历史变化。
- 批量修改入口。

### 批量修改

批量修改从右侧检查器进入。默认分组：

1. 对象类型一级分类。
2. 加入地图时间二级分类。

可切换到：

- 项目加入时间。
- 剧情加入时间。

批量修改支持：

- 批量确认 AI 映射。
- 批量忽略候选。
- 批量移动对象。
- 批量改状态。
- 批量改图层显示。
- 批量合并或拆分聚合簇。

危险操作必须二次确认。

## 显示文案规则

所有作者界面默认不展示技术 ID。

显示优先级：

1. 名称：人物名、地点名、组织名、事件名、规则/秘密标题。
2. 时间：章节、Scene、剧情线阶段、加入地图时间、最近变化时间。
3. 状态文案：已确认、待确认、冲突、已忽略、已回滚、需要人工判断。
4. 来源摘要：来自第几章、哪个 Scene、哪次深度导入、哪条原文证据。
5. 技术 ID：默认隐藏，只在复制调试信息、查看原始数据、开发诊断中出现。

示例：

```text
沈砚
Scene 42 · 洛阳外城
状态：待确认移动
来源：第 12 章深度导入 · “沈砚穿过东门……”
```

## 动效、视觉表现与电影化播放

### 默认操作型动效

默认地图使用操作型动效。动效服务理解和编辑：

- 人物移动：短线滑入或轨迹高亮。
- 危机影响域：轻微扩散脉冲。
- 势力边界：低强度边缘流动。
- AI 候选：弱闪烁。
- 冲突风险：低频呼吸。
- 语义气泡：地图上方空白带轻微漂浮。
- 聚焦切换：相关对象展开，背景对象收缩。

进入修改状态后，背景流动和闪烁自动降级。

### 电影化播放

地图提供独立的 `电影化播放` 按钮。它用于复盘、展示和灵感激发，不作为默认工作状态。

播放内容：

- 主线危机推进。
- 人物旅程路线。
- 势力扩张和收缩。
- 城市封锁和解封。
- 秘密揭示。
- 知识边界变化。
- 战役、迁徙、资源流向。

播放结束回到可编辑的总控台状态。

### 低动效模式

系统提供低动效模式，关闭持续动画，只保留状态变化的短过渡。

## 数据、模块边界与模块增强计划

超级地图仍归 `world/map` 拥有。它不是新自治系统，而是地图动态编排层：消费其他模块提供的事实、时间线、快照和来源证据，然后在 `world/map` 内归一化成地图事实、地图差分、布局结果和可编辑视图。

### imports 增强

`imports` 负责深度导入流水线输入。增强点：

- 深度导入 Phase 2 输出 typed observations，而不只是通用 `delta_events`。
- observation 类型包括：位置候选、状态变化候选、边界变化候选、危机影响域候选、语义强关联候选。
- 每条 observation 带对象名称、对象类型、Scene/章节时间、原文证据、置信度、来源快照、建议动作。
- 保留 `context_snapshot_id`，用于检查器回溯。
- 不直接写地图布局，不决定对象在地图上的最终显示位置。

### memory 增强

`memory` 负责历史和差分底座。增强点：

- 将 `delta_log / memory_events / memory_snapshots` 作为地图动态计算的历史输入。
- 支持按对象、Scene 范围、动态类型、来源状态查询变化。
- 支持从 stale snapshot 触发地图动态重新计算。
- 支持把通用 delta 归一为地图可消费的变化流。
- 不拥有地图 UI，不决定对象在地图上的布局。

### outline 增强

`outline` 负责剧情结构。增强点：

- 提供剧情线当前阶段、主线/支线权重、当前危机对象。
- 提供危机相关 Scene、相关人物、地点、组织、事件。
- Scene contract 增强为能表达主地点、主要人物、核心冲突、危机强度、当前写作焦点。
- 为地图默认强调当前剧情线、主线危机、主要人物提供排序信号。
- 不写地图事实，不直接修改地图表。

### context 增强

`context` 负责证据和审计。增强点：

- 提供 LLM 映射来源证据摘要。
- 提供 context snapshot、prompt、included asset、result refs、错误状态等审计信息。
- 为右侧检查器展示“为什么系统这样映射”提供可读摘要。
- 默认不暴露完整 prompt 或技术 ID；调试入口可复制原始 refs。
- 不做剧情推理，不拥有地图事实。

### world 增强

`world` 负责核心对象语义。增强点：

- 提供可读对象名称、类型文案、状态文案、重要性、揭示等级。
- 提供人物状态维度、角色知识边界、组织/资源/规则等对象的稳定契约。
- 支持强地点关联证据：对象关系、事件发生地、人物常驻/最近地点、引用频次、绑定记录。
- 给地图语义气泡判断“是否锚定到地点”提供证据。
- 不直接拥有地图布局。

### world/map 增强

## 分阶段落地建议

### P0：可信事实底座

- 建立 `MapObservation / MapFact`。
- 打通来源证据、置信度、候选/正式状态。
- 对象信息框提供 `修改` 和 `打开检查器`。
- 实现名称、时间、状态、来源摘要优先显示。
- 将现有 deep import `delta_events` 接入地图候选流。

验收信号：每个地图事实都能回答它是什么、发生在什么时候、来自哪里、是否已确认、如何修改或回滚。

### P1：世界动态总控台

- 实现默认总控台。
- 接入动态队列。
- 接入右侧检查器。
- 默认强调当前剧情线、主线危机、主要人物。
- 提供批量修改入口。

验收信号：作者打开地图第一眼能看到当前世界动态和最重要风险。

### P2：自动布局与三视图

- 实现自动避让。
- 实现聚合簇。
- 实现上方语义气泡带。
- 实现活地图和叙事透镜。
- 实现低动效模式。

验收信号：高密度对象下无标签、气泡、图表重叠，低优先级对象自动降级或聚合。

### P3：高级动态与电影化播放

- 完整接入 typed observations。
- 计算位置变化、状态变化、边界变化、危机扩散、资源控制变化。
- 以 MapFact 为唯一持久化权威，派生 Scene 状态、差分、冲突与连续性问题。
- 实现 Scene 游标、轨道过滤、只读 Canvas 覆盖和兼容电影化播放。
- memory delta、outline 危机线等额外输入仍是后续增强，不改变当前事实边界。

验收信号：地图能回放人物旅程、势力变化、危机推进和关键世界状态变化。

## 风险与防护

| 风险 | 防护 |
|------|------|
| 信息过载 | 自动布局、降级阶梯、聚合簇、密度预设 |
| AI 污染正史 | 来源分级、候选层、冲突层、确认/忽略/回滚 |
| 跨模块耦合 | 每个模块只增强领域事实，地图统一归一化；跨模块只走稳定接口 |
| 动效干扰编辑 | 默认操作型动效，编辑时背景降级，电影化播放独立触发 |
| 用户看不懂技术数据 | 名称、时间、状态、来源摘要优先；技术 ID 默认隐藏 |
| 性能问题 | 视口裁剪、聚合、对象数量上限、低动效模式 |
| 小屏不可用 | 检查器响应式布局、气泡带收敛、图层面板可折叠 |

## 验收标准

- 高密度对象下，地图标签、气泡、图表不互相覆盖。
- 总控台第一眼能看到当前剧情线、主线危机、主要人物和最重要风险。
- 任意对象点击后出现对象信息框，信息框有 `修改` 和 `打开检查器`。
- 每条 AI 映射都有来源摘要、置信度、状态和可回滚/忽略路径。
- 批量修改能按对象类型和加入地图时间分组，并能切换项目加入时间和剧情加入时间。
- 活地图、叙事透镜、电影化播放都消费同一套地图事实。
- 用户界面默认不展示技术 ID。
- imports、memory、outline、context、world 的增强计划不绕过模块边界。
