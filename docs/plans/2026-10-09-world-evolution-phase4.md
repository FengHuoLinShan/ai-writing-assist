## 1. 目标与开始条件

服务画像 A 中写长篇的作者：把六十章以上的稿件交给世界演化后，整本书的 World 审查、
持续发现和细节台账都能实际完成，做不到的部分逐项说明原因；台账覆盖作者常查的更多细节；

### P4-A：World 有来源分组审查

把一场的 World 候选（对象、别名、关系、事件差量）按目标对象及其逐字来源分成多组。每组
单独构造审查请求，带上该组候选、精确来源区间和必要的身份上下文，大小控制在已实测的
单次容量内。每组独立冻结请求、预留根预算、保存回执和免费恢复点。候选只在本组通过后
可采用，跨组引用同一对象时按确定性规则合并。某组失败或超限时，只有该组候选待裁定，
原因写到组；单个候选的证据本身就超限时，延后粒度是这个候选，不是整场。

分组只改变审查的切分方式，不放宽审查：传闻不变成客观事实、同名不证明同一人、
角色知识边界、`require_current_prefix` 传递前缀重验、采用时的领域确认都保持。
不支持思考模型容量门的模型继续整包发送，但同样记录实际输入规模。

方法指纹随分组规则变化。旧运行中已冻结的 `capacity_deferred` 不自动重发、也不追加付费；
作者从演化面板主动选择“补审延后的场景”，先看到预计组数与调用次数，确认后才执行。

验收：合成场景的候选总量超过 45,000 字符时，拆成多组并全部审完；其中一组失败只影响
本组；重放幂等；预算与 unknown 账本正确；超限的单个候选单独待裁定；采用门对前序来源
变化仍然拒绝。在长篇副本上报告容量延后从“场”降到“候选”后的实际比例，不预设百分比。

### P4-B：长篇持续发现与质量根因

**分批。** 把每批都带的完整 `theme_index` 改成两部分：与本批观察相关的主题给全文，
用于去重的全量索引只给名称与 ID。正文按观察所在原文区间加邻接段落提供，只有整场未超限
时才给全文；裁剪范围写入覆盖说明。批次超过上限时按主题再拆，不整批放弃；只有单个主题
本身超限时才记该主题 `capacity_unsupported`。

**召回。** 召回先用 World 已解析的对象 ID（经现有身份与别名解析，World 仍是对象权威），
再用台账主题依赖，最后才用字面名兜底。每批设候选上限，排序依次为：有当前证据的主题、
同一对象、仅字面命中。超出上限的候选记为未检，并披露原因。前缀加载先测量；确需加速时
增加非破坏性的派生索引，仍从原回执重建，不成为新的事实来源。

**质量根因**，以下是待验证的修复方向，以新开发运行的结果为准：

- S3：观察阶段由宿主按原文区间标出话语归属（叙述、角色话语、转述或传闻），诊断与覆盖
  提示只能引用这个字段，不能自行判断谁在说话。修正 context 增强的结构认证，使有据的
  增强可以落账；无据时仍整项隔离。
- S6：认证“这是对某次旧事件的回忆”时，必须引用在同主题已召回候选中唯一的原文指认依据，
  由宿主检查唯一性。不唯一时降为“未知实例、待核”，次数不增，旧锚保留。
- S7：完整主题批按上面的分批规则拆小；后续场景只继承已认证的关联，S6 类错误不再向后传播。

**质量门。** 原开发 8 场作为回归开发集，先过工程门和独立 Spec 评阅（S3/S6/S7 通过，其余
不退化）。之后对封存 9 场跑一次盲验：只核对 hash，运行前不读正文和预期，跑完不再据此
调 Prompt；失败如实记录，在新版本、新样本上验证修复。另冻结一份合成长篇开发样本，专门
验证久远召回、分批与长度耗尽。原请求与响应留在仓库外私有目录。

验收：分批后同一场景的覆盖不再因主题增长整批放弃；按 ID 召回能找回只以别名出现的久远
观察；三个根因各有固定反例转成回归；质量门结论与工程门分开汇报。

### P4-C：台账扩类

建议首批四类，实施前用长篇副本的观察分布确认，必要时调整顺序：

| 类别 | 必须满足 | 与原领域的边界 |
| --- | --- | --- |
| 语言习惯（口头禅、称呼、措辞） | 逐字台词，并按 P4-B 的话语归属记到说话人；叙述里写“他常说”只算叙述主张 | 不改写正文，不评价文风 |
| 外在特征（外貌、伤痕、装束） | 有原文描写；特征变化（受伤、换装）记为变化，不算反例 | 是派生理解，不回写 World 人物资料；作者经原领域采用 |
| 重要物件（信物、随身物） | 关联 World 对象 ID，或明确标“尚未建对象” | 只记出现与意义线索；保管与所有权仍以 Story 状态为准，不形成第三个事实源 |
| 规则后果 | 关联 World 规则对象，只记正文中出现的后果 | 不推演未写出的后果，不判定设定矛盾 |

先做语言习惯与外在特征（只依赖正文证据，耦合低），再做重要物件与规则后果（需要跨域
绑定）。类别清单收敛到契约中的单一来源，去掉 API 与前端的重复硬编码；每类都要有不变量
（参照条件行为必须带条件的做法）、有效与无效样例，以及前端作者用语。

扩类会改变方法指纹，旧运行不自动补扫。作者可以对已读范围选择“补扫新类别”，先预览调用
次数再确认。覆盖按类别分别记录，面板能显示“该类别在此范围未检查”，与“已检查未检出”
分开。角色与读者视图不能从类别数量或标签推知作者秘密。

验收：每类的有效与无效夹具、按类别筛选与分页、按类别覆盖说明、补扫的预览与确认、
旧运行不变；真实开发运行中逐类独立评阅证据正确性与误报。

### P4-D：精细依赖与局部重做

**登记。** 在实际消费点登记到对象与区间粒度：Story 投影传入真实原文区间（目前是整章），
台账条目登记所用观察与来源区间，World 审查组登记候选到区间的对应。登记缺失时保守扩大，
不为显示更小的影响列表而隐藏未知。

**判定与重做。** 正文改动后，先按区间重叠找出受影响的观察，再找出依赖它们的台账条目、
World 候选和 Story 字段；未受影响的保持当前，未知的仍回退到保守后缀。重做从改动所在场
开始：重读后，如果该场的状态指纹与改前一致，就停止向后传播；不一致时，只对消费了变化
字段的后续场景重做。发现只重跑受影响的主题，World 只重审受影响的组。作者决定、人工
修正和已采用资产不被自动重写，改为“待重验”。

**补缝。** 逐个确认 world_knowledge、map_atlas、world_canon_revision 的实际消费者后接入
失效：正典修订采用后，依赖该对象的状态视图与台账条目标记待重验；地图册与世界知识按
各自的来源版本接线。确认后仍无法接入的，继续明确声明为 unsupported。

验收：在长篇副本上改早期一句，对比保守后缀基线，报告重读场景数、付费调用数与费用；
已知依赖精确列出，未知依赖保守扩大；改动无关稿件时内容指纹不变；并发改稿、重做途中失败、
离开恢复都不丢稿、不重复采用。

## 4. 产品门禁结论

```text
目标画像：A，写长篇、持续扩展世界的作者。
用户任务与情绪收益：书越写越长时，系统仍记得住、查得到；改早期稿件不必担心整本重跑。
用户会喜欢的理由：久远细节一键回到原文；未检查的范围讲清原因；改稿成本可预期。
前端舒适度判断：沿用现有演化面板与重算面板，只新增类别筛选、按类别的覆盖说明、
  “补审/补扫”预览，不新增页面；诊断仍放次级入口。
主要摩擦与风险：补审与补扫有费用，须先预览再确认；新类别可能刷屏，沿用按条目去重和
  “本轮摘要只列少量重要变化”的规则。
验证方式：诡秘前 60 章副本上的覆盖与改稿成本实测；逐类误报评阅；gpt-6.1-sol 代理作者
  试用（不代替人类验证）。
结论：调整后做。扩类先做两类低耦合的，覆盖与费用实测通过后再扩另外两类。
```

## 5. 边界与交付

World 负责对象、别名、合并与 Canon 历史；Story 负责事件、历史状态与人物知识；Evidence
负责来源回读与可见性；Evolution 负责派生理解、台账与失效；Collaboration 负责隔离提案
与采用。台账和派生索引都不成为第三套正史，机器结论不自动采用。

不做：受控短期推进、故事内时间与有效期（world_valid_time）、belief_fact_diff、旧
