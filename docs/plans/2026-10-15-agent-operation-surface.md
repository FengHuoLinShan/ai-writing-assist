# 全模块 AI 操作入口、目标运行与操作留痕

日期：2026-10-15。状态：设计讨论稿，未排期；执行者由用户安排。
任务记录：[T-20261015-agent-operation-surface](../../.agent/tasks/2026/T-20261015-agent-operation-surface/TASK.md)。
本文基于 main `4efe7f21a` 核对现状。
配套 ADR（Proposed）：
[ADR-0038 AI 操作目录：风险分级、目标运行与操作留痕](../adr/0038-ai-operation-catalog-goal-runs-and-trace.md)。
其中 §10 的地图与势力操作是本框架的第一个具体实例。

## 0. 用户要求与裁定（2026-10-15）

- 开放或增加各模块的 agent/AI 操作入口，方便 AI 自主规划、操作，完成用户的目标。
- 操作要留痕，方便后续版本把用户常用的操作代码化实现。
- 评审后裁定：目标运行允许作者按目标开启 R2 自动执行（默认关闭）；本机单用户默认记录界面操作。

## 1. 现状

**操作入口少，而且分散。**

- 助手可调用的业务操作共 47 个，分布在 6 个模块：
  - world 18 个（含地图 4 个）、story 11 个、writing 9 个、imports 5 个、project 3 个、evidence 1 个；
  - 装配有两条路径：story、writing、project、evidence 和 world 开篇插件已改为纯数据 `OPERATIONS_SPEC`，
    经 `app/assistant_operation_registry.py` 物化；world 对象、世界书页、结果、共创、复核、地图和 imports
    插件仍导出 `OPERATIONS`，自行导入 `modules.assistant.contracts`，在 `app/bootstrap.py` 中直接合并。
- 后端 HTTP 接口约 680 个，其中写接口约 430 个，大多数没有对应的 AI 操作。
- evolution、interaction（RP）、collaboration、account、local_agent 没有任何助手操作；
  evidence 只有 `evidence.focused_search`。

**权限只有两档。**

- `suggest`（9 个）：生成候选或复核，运行内可直接执行。
- `confirm`（其余）：作者按批确认，一次最多 20 项。
- 没有声明费用、可否撤销、前置条件或产出类型，模型只能靠 `label` 和参数 schema 猜。

**目录发现方式无法扩展。** `available_operations` 一次返回全部操作及其完整 JSON schema。
操作增加到数百个后，这种方式既放不进上下文，也浪费预算。

**自主程度受限。**

- 有界单 Agent 每轮内层最多 12 次请求、32 次工具调用（ADR-0023）。
- 引导流程由服务端注册，模型不能定义流程（ADR-0032）。
- 协作蓝图是封闭的只读调查（ADR-0027）。

因此作者的一个目标（例如“把第 3 章出现的新地点都整理进地图”）需要多轮对话、多次确认，
模型也不能跨轮持续推进。

**没有统一留痕。**

- 现有记录各管一段：
  - 助手运行与批次（`assistant_runs`、`assistant_action_batches`）只覆盖 AI 发起的操作；
  - 长任务 `operation_id` 只用于收敛重试（ADR-0013）；
  - 实体、页面、地图历史和演化回执记录的是内容变化，不记录“谁、经哪个入口、做了什么操作”。
- 作者在界面上的操作没有作为“操作”记录，也没有前端埋点。

## 2. 目标

1. **入口**：作者能在界面上完成的创作类操作，原则上都有对应的 AI 操作；读取有对应的只读工具。
   有安全理由的类别明确排除（第 4 节）。
2. **规划**：模型可以针对作者目标规划多步操作，在作者授权的范围、预算和风险上限内持续执行。
   失败时可以重新规划，需要作者决定时停下。
3. **留痕**：无论由谁发起（作者在界面上、助手、引导流程、目标运行、后台），每次操作都留下
   结构化、不含正文的记录，用来发现常用操作并把它们代码化。

## 3. 统一操作目录（ADR-0038 §1–§3）

**界面和 AI 共用一份目录。**

- 前置：仍导出 `OPERATIONS` 的插件先改为 `OPERATIONS_SPEC`，经注册表物化，操作快照零差异；
  之后新操作只走注册表这一条路径。
- 每个领域命令登记一个目录项，HTTP 路由和 AI 调用走同一个领域服务、同一套校验。
- 在现有 `AssistantOperation`（label、schema、prepare、apply、permission、revision）基础上扩展字段：

| 字段 | 用途 |
|---|---|
| `op_id`、版本 | `模块.对象.动作`，例如 `world.entity.transition_type` |
| 说明 | 给模型看的用途、适用场景和不适用场景 |
| 风险等级 | R0–R4，见第 5 节 |
| 费用类别 | 免费、可能计费的模型调用、可能计费的图片（只记计费状态，不估算金额，ADR-0038 §7） |
| 可撤销性 | 对应的撤销操作或“从版本历史恢复”，或者不可撤销 |
| 前置条件 | 声明式，例如“目标对象已采用”，供规划参考，执行时仍由领域校验 |
| 产出 | 产生的产物类型，例如“正文候选”“地图修订”，供引导流程和目标运行推导进度 |
| 目标类型 | 用于范围检查和留痕 |
| AI 可用 | 默认可用；第 4 节排除的类别为否 |
| 留痕规则 | 哪些参数以何种形式进入留痕（ADR-0038 §8） |

**按需发现，不一次全给。**

- 新增两个只读工具：
  - `find_operations(query, module?, target_type?)`：返回少量候选，只含名称、说明摘要、风险和费用类别；
  - `describe_operation(name)`：返回 schema、前置条件和产出。
- 每次运行冻结目录指纹；新操作只进入新运行（沿用现有规则）。
- 冻结目录里的操作已下线或版本不兼容时，执行和重放失败关闭，目标运行停下请示作者，不自动换新版本。

**界面路由逐步绑定目录项**：写路由声明自己对应的 `op_id`，由测试保证路由与 AI 调用的校验一致。
未声明的写路由列入只减不增的清单（棘轮），新增写路由必须声明 `op_id` 或写明豁免理由。
这一步不改变界面的交互方式，也不要求界面走预览加确认。

## 4. 各模块覆盖计划

“新增”一列是候选，实施时按作者使用频率（第 7 节留痕数据）和价值排序。

| 模块 | 现有 | 新增候选 | 风险说明 |
|---|---|---|---|
| world | 对象、关系、别名、世界书页、采用包、复核、地图 4 个 | 类型转换（物品↔势力等）、对象融合、编辑历史备注与恢复、图片任务准备、地图与势力（ADR-0038 §10） | 融合和采用为 R3；图片为 R4 |
| story | 大纲、Scene、卡片、剧本、剧情线、篇章、信息安排 | 伏笔与揭示调整、时间线、Scene 排序与拆合 | 结构采用为 R3 |
| writing | 生成、返修、采用、恢复、审稿、新章 | 章节改名与排序、批注处理、冲突检查、章节状态 | 采用和发布状态为 R3 |
| evolution | 无 | 准备阅读、追加、重读、补扫（经演化自己的授权预览）；台账主题的作者决定；读取回执与理解 | 付费运行按费用类别处理 |
| evidence | 专项查证 | 项目检索、来源回读、知识范围预览（已有读取工具，转为目录项） | R0 |
| imports | 整理、查漏、恢复、采用 | 深度导入下线后随之退役；表格迁移 | 退役时同步移除 |
| interaction | 无 | 作者侧 RP 设置、旅程与摘要刷新 | RP 角色运行时不开放 |
| collaboration | 经团队运行启动 | 试改与跨域原子采用的准备 | 原子采用为 R3 |
| project | 待办、去重 | 非敏感作品偏好 | 模型连接与账户不开放 |
| assistant | — | 提醒处置 | 持续授权的开启和扩大不开放 |

**永不开放给 AI 的类别**（除非另立 ADR）：

- 凭据与模型连接；
- 账户、登录、会话与分享；
- 本机 CLI 配对与设备权限；
- 删除作品、彻底清除等不可逆删除，以及删除作者长期保留的历史（如导演和推进历史）；
- 修改 AI 自己的授权、预算或持续授权；
- 向系统外公开发布或导出；
- 任意代码、SQL 和文件访问。

## 5. 风险分级（ADR-0038 §4）

| 等级 | 含义 | 例子 | 单轮助手 | 目标运行 |
|---|---|---|---|---|
| R0 | 只读 | 检索、回读、空间问答 | 自动 | 自动 |
| R1 | 产生候选或建议，不改作者资产 | 生成正文候选、复核、演化阅读 | 自动（现有 `suggest`），计入预算 | 在目标预算内自动 |
| R2 | 修改作者资产，可从版本历史恢复 | 编辑工作稿、保存地图新版本、改对象 | 按批确认 | 默认停下确认；作者可为本目标开启自动执行（默认关闭） |
| R3 | 采用、发布、影响正史 | 采用候选、发布世界书、采用结构 | 按批确认 | 始终停下确认 |
| R4 | 超出已授权预算的计费、外部执行或不可逆 | 图片生成、本机 CLI | 单独确认 | 始终单独确认 |

- 每个目录项必须声明等级。测试检查：凡是涉及采用或正史的操作不得低于 R3，不可撤销的不得低于 R4。
- 现有映射：`suggest` 对应 R1；`confirm` 按实际效果分为 R2 或 R3。

## 6. 目标运行（ADR-0038 §5–§7）

**流程**：

1. 作者说出目标。
2. 模型读取现状，生成计划：步骤只能是目录项；写明依赖、预期产物、风险等级、预计请求次数、
   停点和尚不确定的事。
3. 作者在计划卡上审批，可以删改步骤、调整预算，并选择自动执行的上限。
4. 服务端引擎逐步执行：每步先 prepare，再按等级自动执行或停下；执行前重验基线。
5. 进度按产物推导（与 ADR-0032 相同）。
6. 失败或资料漂移时，在已授权的范围和预算内重新规划；超出范围就停下问作者。

**约束**：

- 计划是数据，不是代码：
  - 步骤数设上限（暂定 30），依赖为无环图；
  - 参数可以引用前序步骤的产出，但不能写任意表达式；
  - 对前序产出列表的展开设数量上限。
- 每步 `operation_id = uuid5(目标运行, 步骤, 参数指纹)`，重复推进不重复执行，也不重复计费。
- 预算：目标有自己的根预算（请求次数、可能计费的请求次数、token、时限），所有子步骤累计；
  用到 80% 时停下请示；出现结果未知的计费请求（`AIChargeState.possible`）时停下核对。
  只记录计费状态，不估算金额。
- 授权范围：审批计划即授权一个确定的范围（`op_id` 集合、模块、目标对象、最高等级、预算、自动执行上限）。
  重新规划时由服务端确定性比较，任何扩大都必须停下由作者重新审批，不采纳模型自己的判断。
- 作者优先：
  - 同一项目同时只有一个活动的目标运行；
  - 作者手动修改了目标对象，相关步骤失败关闭并重新规划。
- 撤销：每个自动执行的 R2 步骤记入目标的变更清单，可以一键恢复到目标开始前的版本。
- 防注入：正文、网页和资料都只是数据，不能扩大计划范围或授权；计划修订若扩大了范围，
  必须由作者重新审批。

**与现有形态的关系**：

| 形态 | 由谁定义流程 | 用途 |
|---|---|---|
| 单轮助手（ADR-0023） | — | 一次性调查、提案 |
| 协作蓝图（ADR-0027） | 服务端固定 | 多成员只读调查 |
| 引导流程（ADR-0032） | 服务端固定 | 常用旅程，成本低、可预期 |
| 目标运行（本文） | 模型按目标规划 | 长尾、跨模块的目标 |

留痕显示某类目标运行的计划反复出现时，就把它代码化为引导流程或组合操作（第 7 节），
让常见需求从“模型规划”变成“确定性流程”。

## 7. 操作留痕与代码化（ADR-0038 §8–§9）

**记什么**：每次目录操作调用的生命周期，从提议、预览、确认、拒绝、作者先改再确认、执行、失败
到之后被撤销或恢复。每条记录包含：

- 作品与账户；
- 发起者：界面、助手、引导流程、目标运行或后台；
- 会话 ID、运行或流程 ID，以及数据库生成的单调序号（不用“上一条 ID”的链表，并发时允许交错）；
- `op_id` 与版本；
- 目标类型与 ID；
- 参数形状；
- 结果与错误码；
- 用量（请求次数、token、计费状态，取自运行信封）；
- 产生的领域回执 ID；
- 界面入口。

**写入**：“执行成功”事件与领域写入同事务，写在保存点中；留痕失败只回滚保存点并标记“留痕不完整”，
业务照常提交。留痕规则与参数 schema 一同受快照测试约束。

**不记什么**：

- 正文、世界资料、提示词、模型输出和密钥；
- 自由文本参数只记长度和按作品加盐的 hash，用来识别重复，但不还原内容。

**保留与隐私**：

- 明细默认保留 180 天，之后汇总为不含 ID 的统计（操作频次、操作序列频次）。
- 本机单用户默认开启，数据只存在自己的数据库里；公开账户默认关闭、需要主动开启；
  演示账户不记录。
- 只有作者本人可以导出去标识的汇总，不自动上传。

**代码化循环**：

1. 报告：高频操作、高频操作序列（参数抽象后）、AI 提案的接受、拒绝和先改后接受比例、
   执行后又撤销的比例、耗时与用量。
2. 候选：
   - 作者反复手动执行的序列 → 引导流程或组合操作；
   - 反复出现的目标运行计划 → 注册为引导流程，省去规划请求；
   - 作者反复修改的 AI 预览 → 调整默认值或提示词；
   - 拒绝率高的操作 → 复查。
3. 代码化走正常开发流程（必要时立 ADR、补测试），以汇总后的留痕数据作为依据。

**与现有记录的关系**：留痕不替代领域历史、操作回执、演化回执和助手批次，只按 ID 引用它们。

## 9. 验收

- **工程**：
  - 每个目录项都声明了等级和费用类别；
  - 越权测试：R3/R4 在任何配置下都不能自动执行，排除类别不在 AI 目录中；
  - 幂等、恢复、取消、预算耗尽和资料漂移在 PostgreSQL 下验证；
  - 留痕不含正文（用合成正文做反向检查，确认留痕中找不到原文片段）。
- **目标运行评测**：按五类题材准备目标，例如：
  - “把第 3 章出现的新地点整理进地图”；
  - “按审读意见修第 5 章，并更新伏笔表”；
  - “给东海势力建三级舰队，并设置航线控制”。

  评估指标：目标完成率、步数、作者介入次数、用量、越权尝试次数（必须为 0）、
  执行后撤销率。评分沿用 Sol/xhigh，代理验收保留 `human_validated=false`。
- **留痕**：记录完整率（每个已执行操作都有一条 applied 记录）和序列报告可以复现。

## 10. 裁定与风险

**用户已裁定（2026-10-15）**：

1. 目标运行允许作者按目标开启“可恢复修改（R2）自动执行”，开关默认关闭。
2. 本机单用户默认记录界面操作，公开账户默认关闭。

**范围外**：外部 Agent（如通过 MCP）调用本产品的操作。ADR-0029 已删除本机工具中继，本轮不做，
需要时另立 ADR。

**风险**：

- 开放面扩大以后，提示注入可能借正文或网页引导模型越权。靠计划审批、等级上限、
  “资料只是数据”和每步重验来控制。
- 界面与 AI 两条路径的校验可能漂移，靠路由与目录项一致性测试防止。
- 用量失控，靠目标根预算、80% 停点和计费结果未知时停下来控制。
- 规划质量不足，靠目标运行默认关闭、评测通过后开启来控制。
- 写接口约 430 个，不可能也不必全部开放；按留痕显示的使用频率排序推进。

## 11. 不做

- 让模型编写可执行代码、流程 DSL 或任意查询。
- 多 Agent 自治（协作蓝图仍按 ADR-0027）。
- 外部 Agent 接入（见第 10 节第 3 项）。
- 留痕记录正文或模型输出，或者跨账户自动汇总上传。
- 按留痕自动修改产品行为：代码化必须经开发和评审。
