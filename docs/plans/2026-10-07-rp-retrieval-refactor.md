# RP 检索与编译重构设计

日期：2026-10-07（Asia/Tokyo）。状态：设计建议，业务代码、schema 与 ADR 尚未修改。
关联：[第一阶段计划](2026-10-06-world-foundation-phase1.md) §5.4/M3；
实测与执行状态：[实施笔记](../../.agent/tasks/2026/T-20261006-world-foundation-phase1-impl/TASK.md)。

## 1. 已确认边界与问题

用户允许按重构思路设计，并确认允许检索片段/排序变化，以关键证据召回、知识边界及
最终 RP 质量不退化验收。D1–D6 保留：当前事实权威、生成模型与独立审查保持；新查询
仍检索，不做按需/影子免检索。私有 PG 持久缓存与 USD 20 后续验收预算沿原计划。

固定代码基线为 85fb1c7be35ae687f949863d179f5fd63c53f3c0。M0 专用 PG、本地 BGE
在 35/104 chunks 的新查询编译中位约 1.0/2.0 秒，代表性 attempt 的 search 占比约
70%/98%；原文回读及 snapshot 合计不足 20ms，暖态向量搜索约 6ms。
实测归属来自已有 M0 记录，本轮未重跑测量，不外推生产负载、TEI 费用或文学质量。

代码解释了此结构：keyword_query_terms 对每个短句单独采样至 96 n-gram，整条多句查询
仍达数百项；keyword_search 生成 OR-ILIKE 与同规模 CASE 计数排序。hybrid_search
再次展开相同词项并逐候选评分。普通 RP、Agent、ensemble 与 proactive 全部经同一
compile_interaction_story_context 入口，但没有预算前材料或编译包复用。

精确缓存能省重复检索；RP 每轮 query 随输入/回顾/近期发展变化，故必须一起优化 miss。
此次目标是缩小每轮工作量，并让以后换检索方法不牵动权限、证明、裁剪和生成审查。

## 2. 内部分工与稳定出口

保持 Evidence facade 的现有外部契约，沿 indexing / compilation 两个现有子域组织：

```mermaid
flowchart LR
  A[当前身份与来源范围复验] --> B[确定性查询规划]
  B --> C{精确材料缓存}
  C -->|未命中| D[词法/向量/metadata 召回]
  D --> E[有界候选融合与排序]
  E --> F[原文回读与可见性证明]
  C -->|有效命中| F
  F --> G[完整预算前材料]
  G --> H[按本次预算编译正文]
  H --> I[新的本次 snapshot / 使用回执]
  I --> J[生成与独立输出审查]
```

- 查询规划：只生成确定性的语义输入、词法词项和已有 metadata 参数，不调用 LLM。
- 召回/排序：消费版本化查询计划与精确 scope，返回候选及评分说明；不发布“已验证事实”。
- 材料物化：沿现有 Writing port 回读 draft/hash/范围，执行 cutoff/角色知识/排除规则，
  输出来源证明、引用激活次序、必需项、warnings 和完整预算前材料。
- 编译：按本次预算、模型/tokenizer 与渲染版本裁剪材料，沿原必需项优先级生成包。
- 使用记录：每个逻辑消费建立本次 snapshot/来源使用记录，task/attempt 身份与旧记录分开。

这些是所属模块内的函数/有限数据结构；不新增通用检索框架、服务定位器或跨模块转发层。
非 RP 调用方保持已有输入，逐条检查真实调用方后适配共用 indexing 实现。

## 3. 查询规划：完整语义输入与有界词项分开

Interaction 已有当前输入、当前局面、相关人物、未决事项、必须记住与近期发展分区。
保留这些结构至 Evidence 内部规划，不把拼接后的每个短句等权展开成 SQL 条件。

语义查询保留现有完整有界内容，用于 embedding；词法词项采用全查询总上限，建议从
64 项开始对照。优先冻结且可见的名称/别名、当前明确问题与关键动作，给当前局面和
近期发展保留配额；无词典命中的中文仍有有界 n-gram。先规范化/去重，再按确定次序选择，
不能简单取最前 64 项而让较晚输入永远失去召回机会。数量和配额是待校准参数。

RP 使用 source revision 中经截止/可见性/歧义筛选的目录；通用作者检索仍可用当前项目
词典。现有 QueryExpander 读取当前 World 目录，不能直接当作冻结 RP 的词法计划。
完整输入影响向量或引用激活时仍参与材料 key；词法词项相同不能据此复用不同完整查询。
必需身份/固定项沿直接证明路径读取，不因词项或候选上限而丢失。

## 4. 词法检索：预计算词项，使用现有 PostgreSQL 倒排索引

建议以 rag_chunks 的可重建词项投影作为目标实现：标准化中文 2–4 字 n-gram 与适用的
英文词项在索引时生成，存为 PG text[] 并用原生 GIN array_ops 的 && 召回。
这里是普通派生索引字段，不是第二份正文事实源。查询只传一个有界数组，避免按每个
词项生成文本 ILIKE 与 CASE；评分使用索引命中的词项及有界候选，不重新全量扫描正文。
PG 原生支持该数组操作符的 GIN 索引，见
[官方 GIN 文档](https://www.postgresql.org/docs/current/gin.html#GIN-BUILTIN-OPCLASSES)。

文档侧不套用查询侧的 64 项上限，否则会永久丢失后部命中。记录 lexical 方法版本，
比较完整词项带来的索引大小、写入耗时与查询选择性；没有索引规划与规模实证就不宣称
全规模常数时间。GIN 过滤不直接提供相关性排序，命中集合仍需排序/裁剪；高频词使
命中集合接近全库时，必须据实报告，而不是借任意 LIMIT 掩盖成本或召回下降。

现有 pg_trgm 扩展可以用于更小改动的试验，但不建议直接给旧数百 OR/CASE 加索引就结束：
任意 %两字% 中文模式可能没有可提取的 trigram，仍退化扫描，CASE 排序成本也仍存在。
这一限制见 [官方 pg_trgm 文档](https://www.postgresql.org/docs/current/pgtrgm.html#PGTRGM-INDEX)。
先做同族 PG 对照选择目标实现；若有界查询加 pg_trgm 已满足短词质量、延迟及规模门禁，
可以停止在较小实现，不同时维护两套生产词法索引。

novel/content mode/draft+hash manifest/章节/角色等准入仍作用于每条召回及排序前。
索引中有旧版本 chunk 不代表允许召回旧版本或未来资料。必需原文可见性仍由物化检查。
已有历史 draft 保留；词项回填只改派生索引，沿原 chapter 锁/新鲜度机制，不重算 embedding。
lexical 未就绪的范围走带版本/诊断的旧方法，不能把空索引当成“原作没有证据”。
SQLite 单测采用相同规划/评分语义的窄适配，真实索引及性能以 PG 测试为准。

## 5. 候选召回和最终评分分开

为词法、向量和既有 metadata 召回分别保留候选配额，合并后按 chunk 身份去重并统一评分。
初始每通道可试 24–48 个，融合总量建议不超过 128，最终资料候选继续以实际预算挑选。
这些不是已冻结门槛；先以关键证据召回校准，不能用无序截断替代相关性排序。

初版复用当前 Scorer 的词法/向量/关系/重要性及时间语义，消除重复词项生成和重复打分。
先不要同时改成新的 BM25/RRF 策略；仓库已有离线对照可作为候选实验，但其合成 embedding
不证明真实中文语义质量。若当前融合质量不达标，再根据失败样本比较策略。
多通道任一侧被排除/截止限制后不得用未过滤另一侧补入；无实质匹配仍不能只靠 importance
把不相关资料标成证据。

## 6. 一个私有派生缓存，支持预算前材料和编译正文

首期沿原 D4 只建一张 Evidence 私有缓存表，不建设独立候选缓存服务。
一个缓存条目保存完整预算前证据材料/证明与一个已编译正文及其编译规格：

- 材料 key 包含 owner、consumer/source、整体 revision/manifest、章/offset、人物知识与
  可见性、玩家/固定/排除/歧义策略、完整语义输入哈希、实际查询计划、候选参数、
  索引/目录指纹及检索/物化方法版本；不含与材料无关的 task ID 或输出审查结果。
- 编译正文命中另要求实际预算、tokenizer/model profile、渲染与裁剪版本一致。
  16K/8K 不同预算复用完整材料，再按本次规则编译；不能从被裁剪的 16K 正文截成 8K，
  更不能从 8K 包恢复原本丢弃的证据。首期存一个正文版本足够，多预算写入可替换派生正文。
- 同轮重复补查与跨 worker/重启走同一入口；有并发有效填充时允许幂等重复计算，
  使用唯一约束/短事务，不在 embedding I/O 期间持有数据库锁。
- 每次命中先过当前身份、项目活跃、source revision 与 scope 门禁；其后原文回读保持。
  用缓存材料中的所有相关 proof 重验，不只验旧正文最终包含的来源。缓存 body 比对失败
  或无法证明重编译语义一致时走原路径；撤权/来源失效仍阻断，DB 故障不可吞为 miss。
- snapshot/attempt/输出审查不缓存；每个输出继续独立审查，不能复用旧成功回执。

材料与正文均是敏感派生内容。ADR-0018 例外应明确预算前材料的存储，并沿原计划排除
导出、公开 API、索引、日志及备份正文。原 24h、256KiB、consumer 32MiB 为待校准建议，
容量核算覆盖材料与正文的总量；超限可以跳过缓存，不得截掉必需证据或暗增保存范围。
本设计不把减少原文回读作为性能目标：现有 <20ms 成本值得保留。未来有可信不可变证明
时再评估减少回读，不把长期权威改造前置到本轮。

## 7. 顺序、验收和观测

M1 写清内部分工、版本/key 与 ADR 缓存例外；M3 按以下切片交付：

1. 等价拆出预算前材料、按预算编译与使用记录；先保持当前检索行为，覆盖所有 RP 调用方。
2. 建确定性有界查询与词法索引，保留同方法的冷/热路径，做 PG 真实查询计划及质量对照。
3. 接入持久缓存和重复补查复用，检验不同预算、跨 worker/重启、并发和来源失效。
4. M6 单独做稳定 Prompt 前缀、精确去重及真实 usage/质量对照，不把延迟收益计成付费收益。

新旧检索按 D7 比较关键 evidence group 召回、无答案行为、关键事实和身份/秘密/规则覆盖，
以及固定/排除/同章 offset/不同角色/旧稿/来源归档/撤权场景。索引变更后的冷/热结果
应字节一致；新旧方法之间允许结果变化。必须有索引重建/缺失、词项上限、短中文词、
多句长查询、预算变化和排名后的候选覆盖检查，不删除现有有效断言换取绿灯。

沿 M0 冻结样本族，用真实 PG+BGE、相同硬件/输入对照；另加较大合成库、高频短词及
并发压力，防止小库达标掩盖线性退化。记录词项数、准入/命中/候选数、EXPLAIN
(ANALYZE, BUFFERS)、索引体积/回填耗时、p50/p95；search 分成词法 SQL、向量 SQL、
词典规划与 Python 评分，embedding、回读、渲染、snapshot 分开计量。

可供目标冻结的本地建议：M 档 search p50 <200ms，新查询暖态全链 p50 <500ms，
精确命中全链 p50 <150ms；p95、较大规模及并发目标须补基线后确定，不作上线承诺。
约 200ms embedding 必须计入全链；旧建议 retrieve <200ms 改为 search <200ms。
不同预算应观察 search 调用数下降，不能只观察 embedding hit。

离线证据不能替代最终 RP 质量。dev/holdout 按原计划冻结隔离；后续明确授权的真实模型
比较仍按同模型设置和累计 USD 20，账本包括生成、审查、返修与失败。原作泄漏/严重
关键事实错误为硬失败；自动评测不标成人类验收。生产 TEI、模型实际费率与作者反馈
目前均未实测，费用节省比例不预填。

## 8. 为什么降低修改成本

检索算法只替换候选步骤；来源权威和知识证明保持。Prompt 布局只替换编译/渲染；
检索材料可以复用。预算变化重跑便宜裁剪；来源变化使相应版本缓存失效。使用回执
保留消费者身份；跨 worker 复用不把上一 attempt 的授权或成功状态带入本次。

有限、明确的中间结果让变更落到所属函数和对应版本，不靠全文 Prompt、隐式目录或
长 SQL 绑定所有步骤；这套来源与版本边界也能复用于第一阶段世界状态/试改闭环，
但本轮不顺带建设通用世界搜索平台。
