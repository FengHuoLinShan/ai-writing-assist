# 导演多尺度独立探索：实施计划草案

日期：2026-10-17。状态：**Draft，未实施；配套 ADR 为 Proposed，尚未采纳。**

配套决策：[ADR-0042](../adr/0042-director-scales-independent-exploration.md)。
研究依据：[报告摘要、原件位置与哈希](../../.agent/tasks/2026/T-20261017-director-layer-design/RESEARCH-BASIS.md)。
文档起草记录：[任务记录](../../.agent/tasks/2026/T-20261017-director-layer-design/TASK.md)。
本计划不启动实现、付费模型运行、作者招募或发布；实施时应另按当时授权建立执行记录。

## 用户裁定同步（2026-10-17）

- 主入口采用自由描述问题，优先无缝接入助手或通用 AI 工作台；层级由系统智能推荐，允许手动指定。
- 临时探索主要使用模型自有知识和作者已开启的联网功能；系统推荐项目资料，确认范围后使用。
- 输出焦点与详略智能推荐、允许手动指定；支持“说详细点”等自然语言继续。
- 助手按目标自主选层、按需跨层，在已确认资料、能力与预算内执行，不逐层重复确认；仍可只做任一层。
- 首批三层各做少量高价值任务，重点验证独立使用和助手接入；后续用户教程包含本功能介绍和例子。
- 五项产品方向已裁定，其余设计和实施仍为草案。

## 1. 目标、范围和成功条件

让作者可以直接解决一个局势、事件或场景问题，并在本层取得有用结果；跨层是选择，不是必经步骤。
首版将自由问题融入助手或通用 AI 工作台，智能推荐尺度和详略、支持手动指定，保留就地入口，
复用现有界面与 Story 能力。保留完整场景排演和世界推进，
增加真正聚焦的任务路径；不建设三套引擎、21 个菜单、持续自治世界或新的模型选择体系。

交付按以下五项验收，不能用“增加了入口”替代：

1. 无正文、无正式 Scene、无正式角色时，也能在助手中基于模型知识直接临时探索；可选联网和经确认的项目资料。
2. 三尺度各自支持开始、首次结果、编辑、比较、保存、恢复、同层继续和退出；不强制上下游或采用。
3. 智能推荐层级/详略且可覆盖；一句回应、一个因果补桥、一个规则后果采用相应紧凑输出，支持“说详细点”。
4. 局部修改保留满意部分；允许作者指定或助手在目标授权内按需跨尺度，条件、时间、知识、分支和预算不丢失。
5. 工程正确性与当前模型/作者净收益分开报告；未经真实验证，不宣称质量、延迟或费用改善。

日常、抒情、合作、真诚对话和失败余波从首个可用版本进入用例，不强制冲突、潜台词或新钩子。

下表是本工作树事实，不代表主分支、线上或既有能力已通过作者验收。

| 现有链路 | 已有能力 | 本计划必须补齐 |
| --- | --- | --- |

| `director_schemas.py`、`models.py`、`director_service.py`、`SceneDirectorPanel.vue` | 表演/素材、分支、局部人物重写、参考剧本 | Scene 与已有角色前置；`DirectorSceneMaterials` 固定要求多角度/变体；需聚焦工作步骤 |
| `simulation_v3.py` | 引用、意图、有限结算、差量和回放 | 只复用已定义动作/状态语义，不能充当已验证的社会因果引擎 |
| `WorldProgressionPanel.vue` → `director_context.py` / `director_tasks.py` | 选交汇、作为作者侧假设指示转导演 | 仍绑定原 Scene，角色首轮公共刺激为空；需正式候选状态和角色可知移交 |
| Evidence confirmation、两条任务链与预算模块 | 来源重验、项目快照、回执和根预算 | 临时起点、紧凑输出及跨尺度的新契约需贯通 preview/start/worker/restore |

当前导演预算按每轮最多 `2N+2` 次请求预估，世界推进每步按 `N+1` 预估。
这些是代码中的预算结构，不是实际用量、延迟、费用或质量数据。封存导演/地图等评测保持原状，
不能拿新任务覆盖旧结果、替换失败、重绑或续跑。

## 3. 任务契约与数据设计

### 3.1 先收窄任务，再组织工作

以下为拟定契约字段语义，准确字段名和版本号在 M0 固化；不是当前接口承诺。

| 契约部分 | 最小内容与规则 |
| --- | --- |
| 问题 | 原问题/片段、作者固定项；意图为探索/导向/诊断，可合理推断并可修改 |
| 观察尺度 | 沙盘/事件/场景；基于问题智能推荐，可用自然语言或界面指定；记录推荐、手动覆盖与实际执行选择，不能自动扩权 |
| 起点 | 判别联合：已有 Scene 锚点或临时假设；临时起点可包含显式历史锚点，不伪造 Scene |
| 范围 | 已确认项目资料/排除、模型知识使用说明、联网选择及实际来源、基底/目标时点、临时身份与角色知识；跨度与人数另列 |
| 输出焦点 | 智能推荐局部回答、条件解释、路径/诊断或完整排演及详略；允许手动覆盖，不强制全量字段 |
| 执行 | 请求/操作幂等标识、确认指纹、预算授权、项目 LLM 快照、版本化输出 schema |
| 衍生关系 | 父结果版本、选择内容哈希、选择者及理由、固定前提与实际读集；无父产物也能开始 |

首次执行不必做额外模型分类调用；优先使用作者选择和现有上下文。无法确定尺度可先交付有限回答，
但不能据此暗跑多个模式。调用预览必须与实际工作步骤对应，范围变化则更新预览和授权。
接入助手已有有界意图识别/操作发现，推荐不单独制造一套会话或运行事实源；对话引用同一 Story 任务。
手动指定优先，后续“说详细点”绑定选中问题/结果；已有内容展开为只读操作，新内容补充沿原分支保存新版本。
详略调整不暗改尺度、资料范围、联网选择、固定条件和根预算；歧义会实质改变目标时才追问。

目标明确需要多层结果时，助手可在受限操作目录中自主选择步骤与移交材料；记录选择者、理由、
来源版本及目标关联，按目标必要性执行，不默认串行跑完三层。作者可随时限定某层或停止。
同一目标已有授权覆盖的步骤共用目标总预算及现有根额度/租约；新增领域步骤须有可核对的分配和回执，
不能重置预算。只有新资料、额外联网、超出原能力/预算范围、另起独立目标或正式采用时才走适用的新增确认。

### 3.2 临时起点与 Evidence 确认

M0 给出并在 M1 实现两类输入/确认契约。旧 Scene 契约不放松，新契约必须覆盖：

1. 无项目引用时，使用模型自有知识、作者假设/片段，以及作者已开启的联网资料；确认项目资料范围为空，
   不要求作者先写足资料，明确哪些正史约束未检查。模型推测不伪称来源证据或事实核验。
2. 选项目资料时，记录精确版本/读集、排除、有效期、截止与可见性；不自动读取全项目最新事实。
3. 临时人物、地点、物件使用候选引用类型；已有 `simulation_v3` 引用能表达的直接复用，
   缺失部分补窄联合类型，禁止用自由文本冒充正式对象 ID。
4. 明确世界事实、作者假设、角色观察和角色误信；角色只收到自己的可知包。无明确接触的信息保持未知。
5. Evidence 在编译时处理候选覆盖层，纳入 confirmation 和 hidden guard；编译后不得另行拼回全知资料。
6. preview、start、任务领取、恢复和重试都校验同一确认及正文来源；缺失/stale/越界在付费调用前失败关闭。
7. 系统建议相关项目资料，经范围确认后编译；联网复用助手既有渠道和当次权限，保留来源 URL、读取时间、
   所用内容/指纹及实际覆盖，纳入冻结输入。不开网不检索；失败/不可用明示，可继续不依赖核验的构思。
   外部资料不等同作者设定，已确认作者规则优先，公开检索不默认外发项目原文或私密内容。

沿用当前仍有效的资料选择和授权，不对普通后续补充机械重复确认；带入新资料、换范围或超授权时更新。
联网检索自身也纳入本次工具许可、预算与回执；不能先检索再补授权。

当前 `ContextCompileRequest` 中的可空 `scene_id` 及 visibility 校验不是现成的临时起点支持。
需要检查 confirmation 服务、Context scope、consumer action、角色投影和隐藏守卫的全部调用方，
补新请求类型与重物化路径；不能绕过旧 Scene/角色模式校验。

### 3.3 持久化与协议兼容

首选扩展已有导演根/分支和世界推进根/分支；事件复用推进中的紧凑任务路径，不新增事件业务模块。
两者共享窄起点/输出契约和已定义协议零件，不先合并全部表、服务和历史。

- 根记录保存来源种类/版本、不可变起点和确认指纹，保留既有 Scene 列及索引用于旧路径。
  只有新类型的临时根允许无 Scene，配套约束保证 Scene 型仍必填；不只改 ORM nullable。
- 记录助手讨论/消息到领域任务和结果的稳定关联，以及层级/详略的推荐与作者覆盖；
  保存联网许可、实际引用与模型来源类型，不保存密钥或把供应商内部推理当来源。
- `request_json` / 不可变结果承载版本化假设、候选引用、焦点和输出；已有字段不能无版本换语义。
  明确独立的任务输出 schema 版本，不把它伪称新的结算协议或强制 RP 升级。
- 旧根、轮次、步骤、参考和授权原样保留，不重写不可变数据；通过兼容读取按旧协议解释。
  仅对允许新增的元数据做可审计回填；若会触发历史不变量，改用只读旧版解释，不禁用触发器。
- 新结果保存输入/输出版本和父版本。局部修订生成新结果，保留不受影响内容；同起点重来为同级分支。
  活跃指针用已有 CAS/租约推进；跨作品的父/引用关系在服务和适用数据库约束中均拒绝。
- 独立探索历史可以不按 Scene 过滤，但始终按 owner 和 `novel_id` 过滤。区分“只看本场”与“项目探索”。
- 保留原参考剧本的 Scene 非空和 Writing 消费校验；临时探索保存使用探索历史，不插入假 Scene 参考。
  正式 Scene 引用映射在 M4 实现显式复制和新确认；不得放开 Writing 任意跨场景消费。
- Alembic 使用增量兼容迁移，验证已有数据计数、引用和查询。新路径关闭时仍可读新历史；
  不把删除新历史的降级迁移当回滚手段，不自动执行破坏性 downgrade。

### 3.4 聚焦输出和实际工作步骤

| 任务路径 | 输出 | 必须避免的无关工作 |
| --- | --- | --- |
| 沙盘问题 | 变化/影响链、机制、成立条件、受影响者、未知；可仅回答一条后果 | 所有角色逐人表演、默认无限向后推进 |
| 事件问题 | 起点、目标/信念、行动—条件—响应—后果、失败/余波；可只诊断缺口 | 强制完整长剧情、强制转场景或写正文 |
| 场景聚焦 | 选中人物/台词/动作/空间的回答和依据，按需差异方案 | 全员完整表演、固定 2–3 角度与 2–3 变体 |
| 完整排演 | 既有表演卡、素材、角度、状态变化与分支 | 静默削减已有作者指定能力 |

后端执行路径决定 schema、资料投影、提示词和预算。先采用一个有界生成步骤完成紧凑任务，
附现有确定性守卫；需要独立角色意图、结算或语义返修时才进入已授权的相应工作步骤并预览用量。
不为每个任务默认加一轮规划、多 Agent 辩论和自评。需受约束的生成/审查继续满足现有知识治理。
新增 schema 允许返回“缺条件/无法支持该路径”，不通过编造结果强行完成导向任务。

## 5. 分期：每期交付可使用的纵向切片

所有复选框为未来工作。顺序是工程依赖，不代表沙盘/事件/场景价值排序；M0 可根据作者任务调整 M2 内部顺序。
首批验证以三层少量高价值任务为一组，不先深入单层；M1 建立每层至少一条最小闭环，M2 小幅扩展并检验助手体验。
每个新增任务路径上线前都包含其正常流、失败、保存和恢复，不把交互可靠性推迟到最后一期。

### 批次总览与依赖

下表为实施范围建议，不是开工、调用真实模型或发布授权。按依赖排顺序，不在接口、迁移及
验证基线未冻结前承诺工期；每批启动时复核前一批交付和实际工作树。

| 批次 | 对应里程碑 | 作者能新增完成什么 | 启动依赖 | 本批交付边界 |
| --- | --- | --- | --- | --- |
| 第一批 | M0＋M1 | 在助手中独立探索一条规则影响、一个因果缺口、一句对白，并保存恢复 | 当前工作树基线与契约冻结 | 三条纵向闭环、旧能力兼容、最小教程 |
| 第二批 | M2 | 比较一个条件变化，检查信息差，比较人物表达与空间动作 | 第一批三任务、确认及历史工程门禁通过 | 少量任务扩展、就地入口与完整使用教程 |
| 第三批 | M3 | 锁住满意内容局部改；临时人物可按明确请求进入完整排演 | 第一批版本/角色知识底座；第二批验证过的任务输出契约 | 同层精细控制、临时完整排演、研究覆盖账本 |
| 第四批 | M4 | 按目标跨层探索、跳层或追因；将选定结果作为正式 Scene 的参考 | 第一批三尺度与第三批版本/依赖/知识门禁；第二批体验回归 | 安全移交、共享目标预算、可停止的自主路线、参考副本 |
| 第五批 | M5 | 在已验证范围使用被证明有价值的能力 | 被测切片固定代码、工程证据及相应运行/作者验证授权 | 分列工程、当前模型、作者证据，作开放/限制决定；发布另行授权 |

第五批的用例、判定规则和证据目录从第一批准备；有授权时可对已稳定切片提前验证，
无需等第四批做完才发现质量问题。若早期证据否定某任务，后续批次先收缩该任务，
不会因计划中列过就继续实现。安全/保存失败阻断该路径，其他独立路径可继续。

### 第一批实施范围建议（2026-10-17 代码核查后收敛）

**第一批交付 M0＋M1：助手里可独立使用的三个小任务，以及支撑它们的确认、历史和恢复。**
附三条简短教程示例，不等待 M2 才说明用法；M2 的任务扩展、M3 的复杂锁定和 M4 的自主跨层不纳入本批。
本节是本次规划的建议边界，未启动实现，也不把 ADR 改为 Accepted。

目标用户为正在构思或改稿的作者。产品假设是：无需先建场景、人物或寻找专页，就能得到一个
可判断、可比较的小结果，减少启动和阅读负担；该假设须后续用作者任务验证。

#### 三个固定任务与最小结果

| 编号 / 任务 | 独立输入示例 | 首次结果与退出点 | 必须覆盖的变体 / 禁止行为 |
| --- | --- | --- | --- |
| B1 沙盘：一条规则对日常的影响 | 空项目中问“这个城镇每天只有一小时重力减半，面包师的一天会怎样？先保留现有工具。” | 给出一条有条件的影响链、受影响者、成立条件和未知；作者可保存并结束 | 非冲突生活任务；无精确参数时不编造生产率；不读取最新章节，不默认跑全城人物或长期历史 |
| B2 事件：一个因果缺口的诊断或补桥 | 直接粘贴“信使不知道地址，却当天把信送到了本人手里”，要求只找缺口；随后可要求在“不靠巧合”条件下补一个环节 | 诊断指出缺失信息；明确请求补桥时才给候选路径及所需条件，不能成立时列缺项 | 临时参与者；诊断不改原案；指定结果且禁止全部有效路径时允许无解；不自动创建事件、Scene 或正文 |
| B3 场景：一个人物的一句回应 | 临时设定“A 刚失业；B 不知此事，只看见 A 很疲惫”，要求 B 真诚回应一句 | 一句对白及简短依据/未知，可选一处动作；可保存并结束 | 无正式角色、安静陪伴、误信/未知；B 不得说出失业秘密；不默认生成全员表演卡、多角度或整场正文 |

每项都支持临时开局，也覆盖已有 Scene 锚点和经确认项目资料的路径；不要求先运行另外两项。
上述示例是合成工程 fixture，不是文学质量金标。三项共用以下交互闭环：

1. 助手自由提问 → 推荐尺度与焦点，可手动覆盖 → 展示必要假设、资料范围、联网选择及执行预览。
2. 在有效授权内开始 → 显示进度/停止 → 结果卡关联唯一 Story 根、分支及结果版本。
3. 可以直接编辑并保存探索草稿；AI 结果保持不可变，明确保存的编辑形成新版本，不覆盖父结果。
4. “说详细点”或选中一项修订只补当前问题；同起点重来产生同级分支，比较固定共同起点和条件。
5. 服务器保存、离开、刷新后恢复同一任务和选中结果；停止或退出不要求采用或进入下一层。

首批的局部修订限于选中的一条影响、一个因果环节或一句对白，保留其他内容及父版本。
更改共同前提时建立新分支并说明影响，不承诺任意片段锁定或全后代依赖重算。

#### 纳入第一批的共同能力

- **两类起点与确认。** 新请求使用显式版本和起点判别；空项目资料集也由 Evidence 记录假设、
  候选身份及可见性，worker 重物化同一确认。已有 Scene 继续执行原截止、排除与来源校验。
  临时角色只依据明确观察、已知及误信回答；作者侧秘密不进入该角色输入。
- **实际紧凑执行。** B1/B2 各以一个有界生成步骤交付；B3 只对目标人物生成，使用受限角色包。
  复用确定性守卫；新增独立审查确有必要时必须反映在预览和预算中，不暗加规划、自评或全量排演。
  助手已有意图识别可推荐任务，不新增专门分类调用；助手、检索与领域执行分别留回执并可核对总授权。
- **资料与联网。** 无项目资料时可用模型知识；建议项目资料只展示可授权的候选范围，经确认后读取内容。
  可选联网复用现有 `allow_web` 与 `web_backend` 渠道，保存实际引用和读取时间并冻结入本次输入。
  关闭时零检索；不可用时明确降级为构思，需核验的判断保留未知，不新接搜索供应商。
- **助手与视图一致。** 首屏复用 `ProjectAssistant.vue` / `useProjectAssistant.js`，结果卡及已有
  专用视图定位到同一结果；只读展开零模型调用。设定、大纲、写作通过既有助手上下文带选区，
  不为本批铺设三套新页面。补齐任务与讨论/消息的稳定关联、键盘操作及窄屏反馈。
- **执行与保存可靠。** 沿用队列、Project LLM snapshot、根预算、租约、CAS 和 `never_retry`；
  重复点击不能重复扣费或创建结果，计费未知不静默重发。服务端/本地保存分别明示，两者均失败
  时保留当前草稿及离开保护。功能关闭后可以读历史，但不能继续执行。
- **旧能力兼容。** 旧 Scene 完整排演、世界推进、参考剧本和历史按原协议读取；首批保留已有
  完整排演入口，不把临时探索伪装为正式 Scene。临时起点的完整多人物排演扩展不在本批，
  临时结果转正式 Scene 参考仍留 M4；不修改旧参考表或 Writing 的同场景消费规则。

#### 实施顺序、调用方与完成证据

按下列依赖顺序实现；这是开发分段，第一批完成须全部通过，不把中间底座称为可用产品。

| 顺序 | 改动范围及同步调用方 | 退出证据 |
| --- | --- | --- |
| P0 契约收敛 | 固化三个 fixture、两类起点、输出版本、局部修订语义；核对 API → 操作注册 → service → worker → 历史 → Vue 的消费矩阵 | M0 的输入/首次结果/禁止读写/退出点齐全；实现前 `make docs-check` 基线明确 |
| P1 起点与历史 | Evidence `compilation/schemas.py`、contracts、confirmation service、compiler/知识投影与 facade；Story `director_schemas.py`、`world_progression_schemas.py`、`models.py`、`world_progression_models.py`、两类 context/service；增量 Alembic | 临时根可以没有 Scene；Scene 型仍受约束；空资料确认可重物化；旧记录、引用及不可变保护有效；按 owner/作品读写 |
| P2 三条执行路径 | `director_tasks.py`、`world_progression_tasks.py` 及预算、结果解析、Prompt/fixture；相应 API、operations 和稳定 contracts/facade；组合根及能力/任务登记按需要同步 | 三项各自从 preview 到结果落盘；调用轨迹无无关表演步骤；失败/取消/未知请求能恢复或明确停住 |
| P3 助手和结果闭环 | 新版本操作目录与临时任务授权匹配；`ProjectAssistant.vue`、`useProjectAssistant.js`、`assistantContext.js`、Vue bridge；导演/推进视图的历史与结果消费方 | 自由问题、手动覆盖、编辑、补充、同起点比较、保存恢复定位到同一任务；旧运行目录不被新能力扩权 |
| P4 兼容回归与文档 | Story/Evidence/Assistant README、数据库与整体设计、Prompt 清单/契约、能力登记；`docs/product/new-user-guide.md` 的三个例子 | 受影响模块/消费方、隔离 PostgreSQL、前端行为及文档门禁通过；新执行关闭仍可读新旧历史；真实验收另列 |

P1/P2 继续复用两个既有根：沙盘和事件落世界推进，聚焦对白落导演；不新建事件模块或通用探索引擎。
新结果用显式任务输出版本分派；旧 `DirectorRoundResult` 与推进结算结果不可被重新解释，
不为紧凑结果填充假的完整表演/结算字段。局部编辑也不得伪装成已执行的模拟回合。
若既有不可变记录无法容纳新结果，应在同域补最小版本承载；P0 先确定读写与恢复契约，再写迁移。

本次已核实的改动理由：

- `world_progression_context.py::read_progression_source()` 在 `scene_id=None` 时调用
  `_latest_written_scene()`；两个根模型的 `scene_id` 仍为非空。需新起点分支及配套约束，不能只改请求可空。
- `DirectorBudgetPreviewRequest` 要求 Scene 与至少一个正式角色；`director_budget.py` 按 `2N+2`
  预估每轮请求。紧凑输出必须有自己的实际步骤和预算，不能仅隐藏旧结果。
- `director_operations.py` 的普通作者续演与 `world_progression_operations.py` 的 R1 推进均核对
  Scene 范围。临时任务需要以项目、起点、确认、根及结果匹配授权；不能删掉旧 Scene 校验放行。
- 既有 `assistantContext.js` 已能捕获设定/大纲/写作选区，助手已有联网许可及渠道标记；
  可以复用入口和联网工具，但临时结果关联、确认和冻结来源仍是新增工作。
- 导演回合及世界推进步骤已有数据库不可变触发器；迁移保留旧结果，禁止通过关触发器重写历史。

P0 仍须落实的技术细节：新输出的具体存储承载、confirmation 序列化字段、操作目录版本和
新功能 gate 的登记名。这些是普通实现选择；本规划不虚构已完成的 schema/迁移设计。
新执行按能力默认关闭，读取历史与执行门禁分开；不改变旧能力开关的当前值。

#### 第一批验收与明确后移

第一批工程验收必须同时满足：

1. 三个任务均在无章节/无 Scene/无正式角色的隔离项目跑通，也覆盖已有 Scene 路径；
   结果、候选身份和来源可恢复，正式 World/Story/正文资产没有隐式写入。
2. B2 诊断不改稿、缺条件不硬凑结果；B3 的隐藏秘密不进入角色包；已排除/过期/后序材料、
   异 owner/作品、伪造临时或正式 ID 在模型调用前被拒绝或按契约省略并披露。
3. 三项都覆盖编辑保存、局部补充、比较、停止、双提交/双 worker、预算耗尽、未知计费、
   CAS 冲突和离开恢复；“说详细点”保持尺度、资料、联网与原根预算，旧结果哈希不变。
4. 联网关闭零请求；显式开启才调用既有渠道，来源可追溯；服务不可用不伪造检索成功。
   展示已生成内容零模型调用；紧凑生成轨迹与预算预览一致。
5. 隔离 PostgreSQL 覆盖增量迁移、旧根/回合/参考计数及引用不变、不可变约束、跨项目父引用拒绝；
   新执行 gate 关闭后新旧历史仍可读。不得对保护库或真实项目执行本批测试迁移。
6. 前端覆盖首次/空态/加载/失败、服务端与本地保存失败、刷新恢复、键盘和窄屏；
   教程仅介绍实际交付范围。离线通过只允许说明工程完成，默认关闭状态与模型/作者开放门禁另列。

后端优先扩展现有导演、推进、Evidence confirmation 和 Assistant 操作测试；PostgreSQL 与
前端回归沿用 §7 列出的文件，并补 `ProjectAssistant`、`useProjectAssistant`、`assistantContext`
的对应行为用例。同步 Prompt fixtures 和版本解析 fixtures，不扩到无关模块；运行受影响模块 lint，
收尾 `make docs-check BASE_REF=origin/main`、`git diff --check`。

后移：更多题材/任务族、任意片段锁定及依赖图重算、自主跨层/双向跳层、临时结果转正式 Scene 参考、
新采用流程、持续自动运行、批量研究及 21 分支全覆盖。首批保留完整排演旧路径，
不新建三套工作台、第三方服务、队列或 LLM 客户端。
真实模型与作者验证依 M5 单独登记范围和证据；本规划不启动调用、不复用封存评测、不授权发布。

- [ ] 画助手/通用 AI 工作台自由问题入口与设定、大纲、写作就地入口的共同任务流，核对推荐/手动指定层级与详略。
- [ ] 核查助手操作注册、讨论/消息关联、已有联网许可/渠道与教程承载位置；固化来源分类和失败语义。
- [ ] 固化 §3 起点/确认、时间/知识、输出版本、根/分支预算和历史兼容表；逐个确认真实读写方。
- [ ] 确定已有表扩展迁移及旧数据读取策略、feature gate、具体受影响测试与 docs-check 基线。

### M1：临时开局与三层各一条最小闭环

- [ ] 实现两类起点、Evidence 确认、候选身份、非破坏迁移及旧版读取。

### M2 / 第二批：少量任务扩展、助手体验与教程

**可验收结果：作者能改变一个条件作比较、查信息边界，并从当前工作位置继续同一任务。**
本批扩展以下五项，不把 §6 每个研究分支都开发成一个模式：

| 增量任务 | 输入与首次结果 | 核心验收 |
| --- | --- | --- |
| 沙盘条件对照 | 保持 B1 城镇与工具不变，将重力变化从早晨改到傍晚；解释同一生活环节的差异 | 共同基底一致，只改变指定条件；机制、代价与未知可对照，不把两份无关长文当比较 |
| 事件信息差 | “证人没看到交接，却准确说出接头暗号，哪里缺依据？” | 区分作者知道、人物知道与误信，指出缺失接触路径；不替角色补全未发生信息 |
| 事件导向路径 | 指定一次合作成功的结果，但禁止巧合和角色突然改性格 | 给最小行动—响应—后果链及代价，缺条件可失败；复用 B2，不另造规划器 |
| 场景人物差异 | 同一情境下分别给坦率人物和回避人物一句回应 | 每人独立知识包、固定情境；差异来自目标/性格/知情，不只替换措辞 |
| 场景空间诊断 | 给定门、桌、人物位置，询问某动作是否有支持 | 有资料时引用可见的空间/道具约束；缺尺寸或路线时列未知，不把模型想象当物理证明 |

实施顺序：先扩紧凑输出与输入校验，再贯通同起点比较及人物包，最后完善就地入口和教程。
复用第一批的 Story 请求、worker、预算与历史，不引入新根模型；仅当已有结构无法表达差异时
追加明确输出版本。空间资料只经 World 稳定接口 → Evidence 选择与可见性投影，不直读地图实现，
也不以本批为由扩建地图、行程计算或物理模拟。

助手识别与推荐覆盖新增任务，手动指定优先；普通“短一点/只看原因/换一种回应”绑定当前结果。
从设定、大纲、写作选区打开助手时保留原上下文、草稿与返回位置；引用范围变更再走新确认。
文档完善 `docs/product/new-user-guide.md` 的独立任务、资料/联网、对照、保存恢复示例。

受影响范围：Story 两条紧凑任务链及 schema/Prompt/预算 fixtures，Evidence 角色与空间资料投影，
Assistant 操作发现/结果关联，既有选区入口、结果组件、对应模块 README 和用户教程。
验证五项正常流及条件/知识/空间缺失，回归第一批三任务、异作品选区、过期来源、离开恢复和窄屏；
只有实际 schema 变更才增加迁移验证，不重复全库运行来代替受影响路径覆盖。

本批不做自主跨层、任意片段锁定、临时多人物完整排演、新空间引擎或第三个工作台。
产品净收益仍是待验证假设，比较结果的结构正确不能代替人物声音或因果可信度验收。

- [ ] 沙盘先支持规则/资源后果、反事实、日常生活；无需已写章节或正式 Scene。
- [ ] 事件先支持动机/因果诊断、指定结果的可信路径、信息边界；可直接输入事件片段开始。
- [ ] 场景补人物差异、空间可行性和局部诊断；每层按作者问题选择紧凑 schema。
- [ ] 三层均贯通独立编辑、同起点对照、保存/恢复、同层继续、停止和退出；单层问题不触发无关转层。
- [ ] 根据真实任务补就地入口，复用统一编辑/结果与历史能力；在没有证据前不建事件专页。
- [ ] 在既有用户教程中介绍三尺度独立用途、助手自由提问、推荐/手动指定、自然语言调详略及资料/联网选择。

退出条件：三个尺度各自完成 §1 的单层验收；不借用上游产物完成测试，非冲突任务没有被强行改写成冲突。
局势解释和事件路径为有条件候选，不产生已发生历史。

### M3 / 第三批：局部控制、临时完整排演与研究覆盖

**可验收结果：作者能保留满意部分、明确影响范围地修改其他部分，并自主选择扩成完整排演。**
按两个内部切片交付，M3-A 先建立安全的局部修订，M3-B 再接临时完整排演；两者可分别关闭新执行。

| 切片 | 任务与行为 | 依赖及交付证据 |
| --- | --- | --- |
| M3-A 选择与锁定 | 锁定事件结局和一段满意对白，只改指定动机或动作；纯展示调整不生成 | 选区绑定结果版本、稳定项标识/内容哈希；锁定项逐项保持；无法兼容时报告冲突，不偷偷解锁 |
| M3-A 影响与比较 | 修改共同前提后展示实际受影响部分；选择重算或保留旧版 | 记录实际读集与父版本；旧结果可读，依赖变化明确标记；来源粒度不足时披露保守范围，不伪称精确 |
| M3-B 临时完整排演 | 对已有临时场景明确要求“完整排演”，选择人物、轮次和预算 | 候选身份、各自知识/误信和观察传递贯通现有表演/素材流程；不创建假正式角色或 Scene；与聚焦输出分开计量 |

M3-A 的锁定以已保存的结构项及可重验文本选区为单位；不开发通用协作编辑器、任意语义自动对齐
或整个作品的依赖重算。选区失效先要求重新选择；并发修订通过 CAS 拒绝覆盖，作者编辑版本也留父关系。
父前提变化只标记实际依赖结果，不自动重跑后代；未知依赖采用保守提示并说明范围。

M3-B 在新完整排演版本里扩展候选人物引用、角色包、材料感知者及观察回执；不能把现有要求
canonical ID 的验证删掉后直接复用。首次执行前列出与聚焦任务不同的工作步骤和预算；
按已有根授权判断可继续或需补授权，不靠另建根清空已用额度。多人物状态随观察更新，
作者私密目的始终只在作者侧；能力不足的案例拒绝展开并保留紧凑结果。

受影响范围：Story 结果版本、分支/CAS、角色引用、`simulation_v3` 的适用输入与确定性校验，
Evidence 候选身份/知识投影、预算/worker checkpoint、结果编辑/比较视图；引用类型变化回归旧导演、
推进和已有 simulation 消费方。必要迁移保持原结果、旧 reference 及 trigger 不变量。
验证锁定冲突、选区漂移、并发修订、父版本不变、临时人物不越界、观察传播及中途恢复，
并保留请求轨迹证明只有作者显式展开才运行完整排演。

研究覆盖账本在本批建立为任务记录附件：对 §6 与研究摘要的 21 分支逐项写一个代表用例、
所属尺度、当前承载、状态（工程支持/待真实验证/后续试验/不适用）及原因。
至少覆盖政治/历史的制度延迟、推理的信息差、日常的非冲突体验、动作的空间约束；
只把已完成对应测试的能力列为工程支持，不用 21 行登记宣称 21 分支已实现。
制度演化、联盟内部异议等尚无产品证据的复杂任务先登记试验，不增加专属引擎。

- [ ] 锁定满意部分、局部重算、父版本不变和影响范围提示；对照固定共同起点与条件。
- [ ] 临时起点完整排演显式展开，候选身份、角色知识、预算及旧完整排演兼容贯通。
- [ ] 以 §6 能力地图扩充实际任务，不按分支各建服务；记录不适合当前实现的案例和原因。
- [ ] 验证类型差异：政治/历史看制度延迟，推理看信息，日常看体验，动作看空间；不固化为题材模板门禁。

退出条件：每个研究分支至少有明确用例与处置归属；首期已实现与后续待试清楚区分。
没有产品证据的扩充留在待试清单，不能据此宣称 21 分支全部支持。

### M4 / 第四批：目标内自主跨层、双向跳层与参考映射

**可验收结果：给定一个需要多个尺度的目标，助手在授权内选必要步骤，作者可随时限定或停止。**
本批复杂度最高，必须按 A → B → C 验证；只有 A 不代表自主跨层完成。

| 内部切片 | 交付任务 | 硬验收 |
| --- | --- | --- |
| M4-A 明确选择后移交 | 选定沙盘影响做事件；选事件写局部场景；从场景追原因或看整体影响；直接沙盘↔场景 | 六个方向均有状态移交用例，支持同层继续；条件/候选身份/时间/知识/未结事项完整，未选分支不进入目标输入 |
| M4-B 授权内自主选路 | “解释禁水规则如何影响一家人的晚餐，并给孩子一句回应”；助手决定是否需要事件层并在满足目标后停止 | 目标、许可能力、资料、联网和总预算冻结；路线及选择理由可见；不默认三层全跑，不逐层索取已有授权 |
| M4-C 正式 Scene 参考 | 将临时结果的选中对白/动作用于作者选定 Scene | 重新确认目标资料与角色知识，保存独立参考副本；原探索不变，重试不重复；Writing 仅按目标 Scene 消费 |

M4-A 的移交对象至少绑定源根/分支/结果版本、片段哈希、选择者/理由、confirmation/hidden guard、
实际读集、固定项/未知、时间基底及候选差量、参与者观察与信念。Evidence 负责目标编译与确认，
Story 保存依赖。未来候选创建假设分支；回到旧 Scene 时不得读入后序正史，摘要不替代状态。
已有世界推进转导演界面只作入口复用，当前作者侧指示不能作为完成上述移交的证明。

M4-B 优先扩展 Assistant `goal_runs/{contracts,planning,service}.py` 与现有操作注册/TaskRegistry、
Story 两条任务预算和根回执。当前 goal-run 只纳入已登记任务能力，未接入的付费能力会拒绝；
普通导演续演还要求作者 turn 和同 Scene，因此必须显式补跨领域授权与结果恢复契约，
不能仅将操作加入目录或放宽这些校验。
规划、检索、生成及必要审查全部计入同一目标总账，各领域使用有界分配并留下对应回执；
取消、失败和未知用量不能返还已消费或不明额度，重启不能重新获得全部预算。
可用同一目标执行多条有限分支；新增资料、联网、超额或正式采用才触发适用确认。
作者停止后不得启动下一步骤，在途请求按既有取消/未知结果语义保留记录。

M4-C 扩展 `director_service.py` 的参考创建入口、新参考输入及来源关联，以及
Evidence `director_reference` loader 和 Writing 实际消费方；新紧凑结果无需伪造完整角度字段。
保持旧参考 schema/结果的兼容读取；目标 Scene 不匹配、来源 stale 或知识不成立时拒绝保存。
保存参考仍不是采用到正文、事件或 World。已有 `director_candidate_transfer.py` 属于转 World
候选的另一条路径，不拿它代替跨尺度移交或参考映射，也不扩它的正式写入权限。

验证涵盖六向移交、跳层与反向追因、选错分支、父源变化、旧时点回流、隐藏秘密、源/目标跨项目、
目标完成即停、作者单层限定、预算多域争用、双 worker、崩溃恢复与未知计费；参考映射加真实
Writing 调用链的离线集成验证。通过新 gate 只关闭跨层执行时，前三批独立任务及全部历史仍可用。
若某方向无法保证语义，仅关闭该方向并保留独立探索，不宣称第四批全部完成。
本批不开发无限自主团队、成员自由互发、无限循环世界、自动采用或新的目标调度服务。

- [ ] 实现选中内容/差量的版本化移交、目标 Evidence 确认、角色可知和安全公共刺激。
- [ ] 支持作者指定或助手在目标授权内选取移交材料，记录理由；选择所需层级、按需执行和目标满足即停止。
- [ ] 覆盖沙盘↔事件、事件↔场景、沙盘↔场景，以及同层分支和反向追因；都可停在当前结果。
- [ ] 未来候选进入新假设分支，旧 Scene 截止不变；父结果修改产生新版本并提示下游实际依赖冲突。
- [ ] 同根分支及已授权跨能力步骤受同一目标总预算约束，逐领域分配与回执可核对，不逐层重复确认；
  另起独立目标才新建授权根，不继承权限、不自动重置或转移额度。
- [ ] 作者明确选择正式 Scene 后，经新确认保存独立参考副本；保留原临时探索、旧参考和采用流程。

退出条件：所选条件、时间、知识和候选身份不丢失；未选分支/排除资料不串线；
目标内跨层无需逐层指令，作者限定单层或停止会立即约束后续步骤；超范围停在适用确认点。
隐私、未来信息、过期来源、重复点击和中途取消均有实测工程证据。不能以传了一段摘要代替状态移交。

### M5 / 第五批：分列质量验证与开放决定

**交付物是一份按任务和版本作结论的证据报告及开放清单，不是“全部测试通过”的单一结论。**
使用现有评测工具与记录格式，不新建评测平台。执行前冻结代码 SHA、案例/资料哈希、模型连接、
预算、评分规则、失败处理及允许重跑条件；真实调用用新的案例与账本，封存结果不动。

| 证据轨 | 工作内容 | 完成判定与失败处置 |
| --- | --- | --- |
| 工程 | 汇总各批模块/lint、PostgreSQL、受影响浏览器流程、兼容/关闭开关/恢复证据 | 权限、知识、保存、幂等和预算硬门禁通过；不能执行的检查单列，不用单测替代浏览器或迁移证明 |
| 当前模型 | 对固定任务比较紧凑与适用旧路径、人物知识、因果条件及跨层信息保留；记录所有请求和失败 | 按预登记任务阈值判定；无可比旧路径时只做绝对任务评价，不能宣称相对提升；质量不足的任务保持关闭 |
| 作者任务 | 在相应授权范围内观察自由入口、可选尺度和适用旧入口；覆盖独立任务、局部修订与跨层 | 记录首次可用结果、阅读/修正时间、控制感、拒绝/放弃原因和延后使用；反馈矛盾或样本不足则结论保留 |
| 开放决定 | 每个任务列固定版本、支持范围、限制、回退开关与三轨结论，更新教程及能力说明 | 可限制单项任务或方向；未验证部分继续关闭；发布另按固定 origin/main SHA 与部署授权执行 |

最小评测集以 B1–B3、第二批增量、锁定冲突、临时完整排演和六向移交为任务池；
每类增加困难/失败案例，避免只挑成功演示。数量、质量阈值和费用上限在运行前按风险与授权
登记，不在看到结果后调整，不预设节省百分比或以“无法支持”返回率掩盖能力不足。
当前代码支持的旧任务才可作对照；空项目旧路径不可运行时，使用作者直接完成任务等合适基线，
明确基线差异，不能把旧路径的前置失败当新路径文学质量提升。

真实业务模型遵守现行 Codex `gpt-6-luna/max` 与 owner 已验证 Project facade/snapshot 约定；
配置不匹配停止对应运行。原始真实稿件/模型输入输出留仓库外私有目录，仓库仅保留去原文账本、
哈希与结论。质量、费用、延迟分别报告；未知请求停止并按记录核对，不自动补跑失败样本。

本批开始前先完成离线可准备部分：案例定义、评分表、去原文账本字段、工程证据索引和
按任务关闭能力的回退说明；尚无真实调用或作者验证授权时交付这些准备成果并列明剩余门禁。
不因证据准备完成而将真实验证或整批标记完成，不自动招募/发送材料或开启生产功能。

- [ ] 整理离线工程门禁及迁移/回退证据，不以它们代替当前模型和作者验证。
- [ ] 另获运行范围授权后，以新案例/新账本进行当前业务模型比较；开发业务模型和连接遵守现行约定。
- [ ] 另获相应授权后开展真实作者任务观察，记录拒绝、失败、阅读/修正与延后价值。
- [ ] 按 §8 条件决定简化入口、保留尺度、限制某任务或继续试验；发布另走授权门禁。

退出条件：每种证据的范围与未验证项可审查；未通过质量或作者门禁的路径维持关闭，
不把文献、结构化输出、固定模板通过率或工程测试当作当前产品验收。

## 6. 研究能力地图如何进入计划

下表的“早期任务”表示 M1–M2 中选择的少量试验任务族：M1 每层至少一个，M2 按实际价值小幅增加，
不要求一次做完一行所有分支。其余在 M3 依据需求扩充，不等于每项都需独立实现。

| 尺度 | 早期任务 | 后续任务与观察重点 |
| --- | --- | --- |
| 沙盘 | 资源/基础条件；反事实/条件比较；日常生活/世界体验 | 主体/制度：代表权限与内部异议；利益/联盟：承诺与协调成本；连锁影响/反馈：载体、延迟、停止条件；历史/制度演化：形成与维持机制、切换成本 |
| 事件 | 目标/秘密/代价；因果/转折；信息差/揭示 | 触发/起始条件：谁何时能行动；行动/响应/协作：意图与结果分开；结局/余波/未定事项：允许失败、僵局和结束；变体/原案诊断：固定结果与最小补桥 |
| 场景 | 局部任务/体验；动作/人物差异；对白/沉默；空间/道具；素材/局部修订 | 视角/知识/信念/注意：错误信念可合理、作者隐私不可越界；节奏/氛围/余波：安静与抒情也能完成。首批对白允许真诚表达，素材不强制完整角度 |

比较方案要改变条件、立场、知情范围或具体表现，避免只换措辞。组织不能当作单一全知人格，
未知数量不编造精确经济值；找不到可信路径不等于证明文学上不可能。

## 7. 验证矩阵与证据要求

下列是实施阶段的必需覆盖，本次文档起草没有执行它们。

| 类别 | 关键案例 | 可接受证据 |
| --- | --- | --- |
| 单层独立 | 无正文沙盘、独立事件、一句对白；只诊断且拒绝改稿；安静陪伴/劳动 | 从独立输入到退出的 API/UI 行为断言，无上下游前置或隐藏写入 |
| 身份与隔离 | 异 owner/作品、伪造正式 ID、临时对象写正式接口、跨项目父分支 | 入口、服务、worker 与适用 DB 约束拒绝；目标项目不变 |
| 资料与知识 | 同确认重物化、排除资料、后序秘密、误信、作者私密目标、过期正文/来源 | 模型调用前守卫及实际角色包检查；允许的未知明确保留 |
| 假设时间 | 原 Scene 截止＋未来候选；无历史锚点；跨尺度回到旧 Scene | 不读取未来正史、不写回原时点，候选来源及时间解释完整 |
| 输出减负 | 一句回应对完整排演；单因果补桥对完整推进 | schema/Prompt、调用轨迹与预算一致，无未展示全量生成 |
| 分支与局部改 | 同级比较、子分支、锁定内容、上游新版本、未选分支 | 不可变父结果、只改声明范围、依赖过时提示；不会串线 |
| 授权与恢复 | 重复点击、双 worker、CAS 失败、断流、取消、预算耗尽、计费未知 | 幂等/租约/信封证据，保留可恢复进度；未知时不静默重试 |

## 8. 开关、回退和重新评估

- 新路径默认关闭，按现有能力 gate 注册；旧路径状态不被草案改变，旧封存评测不自动恢复。
- 数据迁移与功能开启分开；关闭新增入口/执行不会隐藏已保存历史。故障先停止新增执行，保留回执与草稿，
  确认未知计费结果后再恢复，不重发原付费请求。
- 尺度选择增加犹豫且未改善结果：收缩为自由入口，内部仍保留任务范围与输出版本。
- 事件任务在通用界面已足够：保留独立能力和就地调用，不建设第三工作台。
- 宏观跨度导致解释不稳：缩小问题并列未知，不能补造确定性或静默换模型。
- 交接条件遗漏/返工抵消收益：先修正移交，必要时只保留各层独立任务和人工选择材料。
- 聚焦输出导致作者反复索要信息：按问题补充，不直接恢复所有任务默认全量；保留完整排演入口。

具体质量阈值在运行前按任务和风险登记，不能在看到结果后降低标准；没有基线数据时不捏造收益百分比。
安全/权限/知识/保存不变量为硬门禁，文学偏好和产品净收益分别报告。
