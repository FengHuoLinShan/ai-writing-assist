# 导演多尺度独立探索：实施计划草案

日期：2026-10-17。状态：**Draft，未实施；配套 ADR 为 Proposed，尚未采纳。**

配套决策：[ADR-0042](../adr/0042-director-scales-independent-exploration.md)。
研究依据：[报告摘要、原件位置与哈希](../../.agent/tasks/2026/T-20261017-director-layer-design/RESEARCH-BASIS.md)。
文档起草记录：[任务记录](../../.agent/tasks/2026/T-20261017-director-layer-design/TASK.md)。
本计划不启动实现、付费模型运行、作者招募或发布；实施时应另按当时授权建立执行记录。

## 用户裁定同步（2026-10-17）

- 主入口采用自由描述问题，优先无缝接入助手或通用 AI 工作台；层级由系统智能推荐，允许手动指定。
- 临时探索主要使用模型自有知识和作者已开启的联网功能；系统推荐项目资料，确认范围后使用。
- 输出焦点与详略智能推荐、允许手动指定；支持“说详细点”等自然语言继续。
- 助手按目标自主选层、按需跨层，在已确认资料、能力与预算内执行，不逐层重复确认；仍可只做任一层。
- 首批三层各做少量高价值任务，重点验证独立使用和助手接入；后续用户教程包含本功能介绍和例子。
- 五项产品方向已裁定，其余设计和实施仍为草案。

## 1. 目标、范围和成功条件

让作者可以直接解决一个局势、事件或场景问题，并在本层取得有用结果；跨层是选择，不是必经步骤。
首版将自由问题融入助手或通用 AI 工作台，智能推荐尺度和详略、支持手动指定，保留就地入口，
复用现有界面与 Story 能力。保留完整场景排演和世界推进，
增加真正聚焦的任务路径；不建设三套引擎、21 个菜单、持续自治世界或新的模型选择体系。

交付按以下五项验收，不能用“增加了入口”替代：

1. 无正文、无正式 Scene、无正式角色时，也能在助手中基于模型知识直接临时探索；可选联网和经确认的项目资料。
2. 三尺度各自支持开始、首次结果、编辑、比较、保存、恢复、同层继续和退出；不强制上下游或采用。
3. 智能推荐层级/详略且可覆盖；一句回应、一个因果补桥、一个规则后果采用相应紧凑输出，支持“说详细点”。
4. 局部修改保留满意部分；允许作者指定或助手在目标授权内按需跨尺度，条件、时间、知识、分支和预算不丢失。
5. 工程正确性与当前模型/作者净收益分开报告；未经真实验证，不宣称质量、延迟或费用改善。

日常、抒情、合作、真诚对话和失败余波从首个可用版本进入用例，不强制冲突、潜台词或新钩子。

新分支从上述提交建立，未改用 origin/main；迁移本身不修改业务代码。
下表是本工作树事实，不代表主分支、线上或既有能力已通过作者验收。

| 现有链路 | 已有能力 | 本计划必须补齐 |
| --- | --- | --- |
| `world_progression_context.py`、`world_progression_service.py`、`WorldProgressionPanel.vue` | 自由/导向、时间步、交汇、钩子、历史与预算 | 省略 Scene 仍解析最新已写 Scene；独立沙盘/事件不能依赖它 |
| `director_schemas.py`、`models.py`、`director_service.py`、`SceneDirectorPanel.vue` | 表演/素材、分支、局部人物重写、参考剧本 | Scene 与已有角色前置；`DirectorSceneMaterials` 固定要求多角度/变体；需聚焦工作步骤 |
| `simulation_v3.py` | 引用、意图、有限结算、差量和回放 | 只复用已定义动作/状态语义，不能充当已验证的社会因果引擎 |
| `WorldProgressionPanel.vue` → `director_context.py` / `director_tasks.py` | 选交汇、作为作者侧假设指示转导演 | 仍绑定原 Scene，角色首轮公共刺激为空；需正式候选状态和角色可知移交 |
| Evidence confirmation、两条任务链与预算模块 | 来源重验、项目快照、回执和根预算 | 临时起点、紧凑输出及跨尺度的新契约需贯通 preview/start/worker/restore |

当前导演预算按每轮最多 `2N+2` 次请求预估，世界推进每步按 `N+1` 预估。
这些是代码中的预算结构，不是实际用量、延迟、费用或质量数据。封存导演/地图等评测保持原状，
不能拿新任务覆盖旧结果、替换失败、重绑或续跑。

## 3. 任务契约与数据设计

### 3.1 先收窄任务，再组织工作

以下为拟定契约字段语义，准确字段名和版本号在 M0 固化；不是当前接口承诺。

| 契约部分 | 最小内容与规则 |
| --- | --- |
| 问题 | 原问题/片段、作者固定项；意图为探索/导向/诊断，可合理推断并可修改 |
| 观察尺度 | 沙盘/事件/场景；基于问题智能推荐，可用自然语言或界面指定；记录推荐、手动覆盖与实际执行选择，不能自动扩权 |
| 起点 | 判别联合：已有 Scene 锚点或临时假设；临时起点可包含显式历史锚点，不伪造 Scene |
| 范围 | 已确认项目资料/排除、模型知识使用说明、联网选择及实际来源、基底/目标时点、临时身份与角色知识；跨度与人数另列 |
| 输出焦点 | 智能推荐局部回答、条件解释、路径/诊断或完整排演及详略；允许手动覆盖，不强制全量字段 |
| 执行 | 请求/操作幂等标识、确认指纹、预算授权、项目 LLM 快照、版本化输出 schema |
| 衍生关系 | 父结果版本、选择内容哈希、选择者及理由、固定前提与实际读集；无父产物也能开始 |

首次执行不必做额外模型分类调用；优先使用作者选择和现有上下文。无法确定尺度可先交付有限回答，
但不能据此暗跑多个模式。调用预览必须与实际工作步骤对应，范围变化则更新预览和授权。
接入助手已有有界意图识别/操作发现，推荐不单独制造一套会话或运行事实源；对话引用同一 Story 任务。
手动指定优先，后续“说详细点”绑定选中问题/结果；已有内容展开为只读操作，新内容补充沿原分支保存新版本。
详略调整不暗改尺度、资料范围、联网选择、固定条件和根预算；歧义会实质改变目标时才追问。

目标明确需要多层结果时，助手可在受限操作目录中自主选择步骤与移交材料；记录选择者、理由、
来源版本及目标关联，按目标必要性执行，不默认串行跑完三层。作者可随时限定某层或停止。
同一目标已有授权覆盖的步骤共用目标总预算及现有根额度/租约；新增领域步骤须有可核对的分配和回执，
不能重置预算。只有新资料、额外联网、超出原能力/预算范围、另起独立目标或正式采用时才走适用的新增确认。

### 3.2 临时起点与 Evidence 确认

M0 给出并在 M1 实现两类输入/确认契约。旧 Scene 契约不放松，新契约必须覆盖：

1. 无项目引用时，使用模型自有知识、作者假设/片段，以及作者已开启的联网资料；确认项目资料范围为空，
   不要求作者先写足资料，明确哪些正史约束未检查。模型推测不伪称来源证据或事实核验。
2. 选项目资料时，记录精确版本/读集、排除、有效期、截止与可见性；不自动读取全项目最新事实。
3. 临时人物、地点、物件使用候选引用类型；已有 `simulation_v3` 引用能表达的直接复用，
   缺失部分补窄联合类型，禁止用自由文本冒充正式对象 ID。
4. 明确世界事实、作者假设、角色观察和角色误信；角色只收到自己的可知包。无明确接触的信息保持未知。
5. Evidence 在编译时处理候选覆盖层，纳入 confirmation 和 hidden guard；编译后不得另行拼回全知资料。
6. preview、start、任务领取、恢复和重试都校验同一确认及正文来源；缺失/stale/越界在付费调用前失败关闭。
7. 系统建议相关项目资料，经范围确认后编译；联网复用助手既有渠道和当次权限，保留来源 URL、读取时间、
   所用内容/指纹及实际覆盖，纳入冻结输入。不开网不检索；失败/不可用明示，可继续不依赖核验的构思。
   外部资料不等同作者设定，已确认作者规则优先，公开检索不默认外发项目原文或私密内容。

沿用当前仍有效的资料选择和授权，不对普通后续补充机械重复确认；带入新资料、换范围或超授权时更新。
联网检索自身也纳入本次工具许可、预算与回执；不能先检索再补授权。

当前 `ContextCompileRequest` 中的可空 `scene_id` 及 visibility 校验不是现成的临时起点支持。
需要检查 confirmation 服务、Context scope、consumer action、角色投影和隐藏守卫的全部调用方，
补新请求类型与重物化路径；不能绕过旧 Scene/角色模式校验。

### 3.3 持久化与协议兼容

首选扩展已有导演根/分支和世界推进根/分支；事件复用推进中的紧凑任务路径，不新增事件业务模块。
两者共享窄起点/输出契约和已定义协议零件，不先合并全部表、服务和历史。

- 根记录保存来源种类/版本、不可变起点和确认指纹，保留既有 Scene 列及索引用于旧路径。
  只有新类型的临时根允许无 Scene，配套约束保证 Scene 型仍必填；不只改 ORM nullable。
- 记录助手讨论/消息到领域任务和结果的稳定关联，以及层级/详略的推荐与作者覆盖；
  保存联网许可、实际引用与模型来源类型，不保存密钥或把供应商内部推理当来源。
- `request_json` / 不可变结果承载版本化假设、候选引用、焦点和输出；已有字段不能无版本换语义。
  明确独立的任务输出 schema 版本，不把它伪称新的结算协议或强制 RP 升级。
- 旧根、轮次、步骤、参考和授权原样保留，不重写不可变数据；通过兼容读取按旧协议解释。
  仅对允许新增的元数据做可审计回填；若会触发历史不变量，改用只读旧版解释，不禁用触发器。
- 新结果保存输入/输出版本和父版本。局部修订生成新结果，保留不受影响内容；同起点重来为同级分支。
  活跃指针用已有 CAS/租约推进；跨作品的父/引用关系在服务和适用数据库约束中均拒绝。
- 独立探索历史可以不按 Scene 过滤，但始终按 owner 和 `novel_id` 过滤。区分“只看本场”与“项目探索”。
- 保留原参考剧本的 Scene 非空和 Writing 消费校验；临时探索保存使用探索历史，不插入假 Scene 参考。
  正式 Scene 引用映射在 M4 实现显式复制和新确认；不得放开 Writing 任意跨场景消费。
- Alembic 使用增量兼容迁移，验证已有数据计数、引用和查询。新路径关闭时仍可读新历史；
  不把删除新历史的降级迁移当回滚手段，不自动执行破坏性 downgrade。

### 3.4 聚焦输出和实际工作步骤

| 任务路径 | 输出 | 必须避免的无关工作 |
| --- | --- | --- |
| 沙盘问题 | 变化/影响链、机制、成立条件、受影响者、未知；可仅回答一条后果 | 所有角色逐人表演、默认无限向后推进 |
| 事件问题 | 起点、目标/信念、行动—条件—响应—后果、失败/余波；可只诊断缺口 | 强制完整长剧情、强制转场景或写正文 |
| 场景聚焦 | 选中人物/台词/动作/空间的回答和依据，按需差异方案 | 全员完整表演、固定 2–3 角度与 2–3 变体 |
| 完整排演 | 既有表演卡、素材、角度、状态变化与分支 | 静默削减已有作者指定能力 |

后端执行路径决定 schema、资料投影、提示词和预算。先采用一个有界生成步骤完成紧凑任务，
附现有确定性守卫；需要独立角色意图、结算或语义返修时才进入已授权的相应工作步骤并预览用量。
不为每个任务默认加一轮规划、多 Agent 辩论和自评。需受约束的生成/审查继续满足现有知识治理。
新增 schema 允许返回“缺条件/无法支持该路径”，不通过编造结果强行完成导向任务。

## 5. 分期：每期交付可使用的纵向切片

所有复选框为未来工作。顺序是工程依赖，不代表沙盘/事件/场景价值排序；M0 可根据作者任务调整 M2 内部顺序。
首批验证以三层少量高价值任务为一组，不先深入单层；M1 建立每层至少一条最小闭环，M2 小幅扩展并检验助手体验。
每个新增任务路径上线前都包含其正常流、失败、保存和恢复，不把交互可靠性推迟到最后一期。

### M0：冻结最小任务与兼容契约

- [ ] 选择每层至少一个无上游依赖用例，含无正文、临时人物、非冲突、诊断和指定结果缺条件。
- [ ] 画助手/通用 AI 工作台自由问题入口与设定、大纲、写作就地入口的共同任务流，核对推荐/手动指定层级与详略。
- [ ] 核查助手操作注册、讨论/消息关联、已有联网许可/渠道与教程承载位置；固化来源分类和失败语义。
- [ ] 固化 §3 起点/确认、时间/知识、输出版本、根/分支预算和历史兼容表；逐个确认真实读写方。
- [ ] 确定已有表扩展迁移及旧数据读取策略、feature gate、具体受影响测试与 docs-check 基线。

退出条件：每个用例写明输入、应给出的首次结果、禁止读取/写入和退出点；无悬空的安全/事实权威决策。
只剩命名、布局等可逆选择时不阻塞；若新发现需要改变核心架构或重大语义，按适用授权范围处理。

### M1：临时开局与三层各一条最小闭环

- [ ] 实现两类起点、Evidence 确认、候选身份、非破坏迁移及旧版读取。
- [ ] 三层各选一个任务贯通 preview/start/worker/结果/局部修订/比较/保存/恢复：
  沙盘看规则改变对日常的影响，事件做一个因果补桥/诊断，场景只处理一句对白。
- [ ] 在助手中直接发起同一任务，智能推荐层级/详略，支持手动指定及“说详细点”局部补充；不要求切换专页。
- [ ] 允许基于模型知识无项目资料开局；可选联网复用已有许可，经确认带入建议的项目资料并保留来源类型。
- [ ] 开放完整排演的显式展开，保持旧 Scene 与参考路径兼容；临时开局不要求创建正式角色。
- [ ] 明示服务器保存与本地备份状态；重复提交、离开恢复和未知结果有保护路径。

退出条件：无 Scene、无正式角色时，三层各能独立得到最小有用结果并保存恢复；旧 Scene 完整排演仍可读可用；
助手自然语言和专用视图定位到同一结果，“说详细点”不暗扩资料/联网/预算；
通过请求轨迹证明未执行全量人物表演/角度步骤。此时只说明工程减负，尚不证明文学效果或真实费用降低。

### M2：首批高价值任务、助手体验与教程

- [ ] 沙盘先支持规则/资源后果、反事实、日常生活；无需已写章节或正式 Scene。
- [ ] 事件先支持动机/因果诊断、指定结果的可信路径、信息边界；可直接输入事件片段开始。
- [ ] 场景补人物差异、空间可行性和局部诊断；每层按作者问题选择紧凑 schema。
- [ ] 三层均贯通独立编辑、同起点对照、保存/恢复、同层继续、停止和退出；单层问题不触发无关转层。
- [ ] 根据真实任务补就地入口，复用统一编辑/结果与历史能力；在没有证据前不建事件专页。
- [ ] 在既有用户教程中介绍三尺度独立用途、助手自由提问、推荐/手动指定、自然语言调详略及资料/联网选择。

退出条件：三个尺度各自完成 §1 的单层验收；不借用上游产物完成测试，非冲突任务没有被强行改写成冲突。
局势解释和事件路径为有条件候选，不产生已发生历史。

### M3：局部控制与研究分支覆盖

- [ ] 锁定满意部分、局部重算、父版本不变和影响范围提示；对照固定共同起点与条件。
- [ ] 以 §6 能力地图扩充实际任务，不按分支各建服务；记录不适合当前实现的案例和原因。
- [ ] 验证类型差异：政治/历史看制度延迟，推理看信息，日常看体验，动作看空间；不固化为题材模板门禁。

退出条件：每个研究分支至少有明确用例与处置归属；首期已实现与后续待试清楚区分。
没有产品证据的扩充留在待试清单，不能据此宣称 21 分支全部支持。

### M4：目标内自主跨层、双向跳层与参考映射

- [ ] 实现选中内容/差量的版本化移交、目标 Evidence 确认、角色可知和安全公共刺激。
- [ ] 支持作者指定或助手在目标授权内选取移交材料，记录理由；选择所需层级、按需执行和目标满足即停止。
- [ ] 覆盖沙盘↔事件、事件↔场景、沙盘↔场景，以及同层分支和反向追因；都可停在当前结果。
- [ ] 未来候选进入新假设分支，旧 Scene 截止不变；父结果修改产生新版本并提示下游实际依赖冲突。
- [ ] 同根分支及已授权跨能力步骤受同一目标总预算约束，逐领域分配与回执可核对，不逐层重复确认；
  另起独立目标才新建授权根，不继承权限、不自动重置或转移额度。
- [ ] 作者明确选择正式 Scene 后，经新确认保存独立参考副本；保留原临时探索、旧参考和采用流程。

退出条件：所选条件、时间、知识和候选身份不丢失；未选分支/排除资料不串线；
目标内跨层无需逐层指令，作者限定单层或停止会立即约束后续步骤；超范围停在适用确认点。
隐私、未来信息、过期来源、重复点击和中途取消均有实测工程证据。不能以传了一段摘要代替状态移交。

### M5：分列质量验证与开放决定

- [ ] 整理离线工程门禁及迁移/回退证据，不以它们代替当前模型和作者验证。
- [ ] 另获运行范围授权后，以新案例/新账本进行当前业务模型比较；开发业务模型和连接遵守现行约定。
- [ ] 另获相应授权后开展真实作者任务观察，记录拒绝、失败、阅读/修正与延后价值。
- [ ] 按 §8 条件决定简化入口、保留尺度、限制某任务或继续试验；发布另走授权门禁。

退出条件：每种证据的范围与未验证项可审查；未通过质量或作者门禁的路径维持关闭，
不把文献、结构化输出、固定模板通过率或工程测试当作当前产品验收。

## 6. 研究能力地图如何进入计划

“首批”表示 M1–M2 中选择的少量试验任务族：M1 每层至少一个，M2 按实际价值小幅增加，
不要求一次做完一行所有分支。其余在 M3 依据需求扩充，不等于每项都需独立实现。

| 尺度 | 首批任务 | 后续任务与观察重点 |
| --- | --- | --- |
| 沙盘 | 资源/基础条件；反事实/条件比较；日常生活/世界体验 | 主体/制度：代表权限与内部异议；利益/联盟：承诺与协调成本；连锁影响/反馈：载体、延迟、停止条件；历史/制度演化：形成与维持机制、切换成本 |
| 事件 | 目标/秘密/代价；因果/转折；信息差/揭示 | 触发/起始条件：谁何时能行动；行动/响应/协作：意图与结果分开；结局/余波/未定事项：允许失败、僵局和结束；变体/原案诊断：固定结果与最小补桥 |
| 场景 | 局部任务/体验；动作/人物差异；对白/沉默；空间/道具；素材/局部修订 | 视角/知识/信念/注意：错误信念可合理、作者隐私不可越界；节奏/氛围/余波：安静与抒情也能完成。首批对白允许真诚表达，素材不强制完整角度 |

比较方案要改变条件、立场、知情范围或具体表现，避免只换措辞。组织不能当作单一全知人格，
未知数量不编造精确经济值；找不到可信路径不等于证明文学上不可能。

| 类别 | 关键案例 | 可接受证据 |

## 8. 开关、回退和重新评估

- 新路径默认关闭，按现有能力 gate 注册；旧路径状态不被草案改变，旧封存评测不自动恢复。
- 数据迁移与功能开启分开；关闭新增入口/执行不会隐藏已保存历史。故障先停止新增执行，保留回执与草稿，
  确认未知计费结果后再恢复，不重发原付费请求。
- 尺度选择增加犹豫且未改善结果：收缩为自由入口，内部仍保留任务范围与输出版本。
- 事件任务在通用界面已足够：保留独立能力和就地调用，不建设第三工作台。
- 宏观跨度导致解释不稳：缩小问题并列未知，不能补造确定性或静默换模型。
- 交接条件遗漏/返工抵消收益：先修正移交，必要时只保留各层独立任务和人工选择材料。
- 聚焦输出导致作者反复索要信息：按问题补充，不直接恢复所有任务默认全量；保留完整排演入口。

具体质量阈值在运行前按任务和风险登记，不能在看到结果后降低标准；没有基线数据时不捏造收益百分比。
安全/权限/知识/保存不变量为硬门禁，文学偏好和产品净收益分别报告。
