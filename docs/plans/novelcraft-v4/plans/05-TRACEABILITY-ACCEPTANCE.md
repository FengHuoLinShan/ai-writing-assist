# 追踪矩阵、实施工作包与整体验收

V4.0｜本文件把两份原计划中的工作转成一个长程项目，防止合并后遗漏细节，也防止不同 Agent 重复实现同一能力。

## 1. 原计划与本次决策的关系

原稿 A：`novel-assistant-audit-and-plan.md`。原稿 B：`PLAN-novel-world-cognition-map-v3.md`。完整原文保存在包内 `sources/`，未修改。来源行范围和 hash 见 06。

A 的“统一助手内核、单右侧宿主、严格权限与证据”继续保留；其对不增加默认多 Agent 的阶段边界，被用户此次明确要求扩展为可评估的两轨协作。B 的 W/C/V 分责、窄事务、历史可见性、媒体与实验要求继续保留；W 升级为明确替代 deep_import 的 E 系统，而不是额外加一条演化链。

所有原包均有下列去向。映射表示实施责任和继承要求，不表示包已开发完成。

## 5. 单一能力所有权防重复表

| 核心能力 | 唯一实现原则 | 允许的多种形式 |
|---|---|---|
| 状态归约 | Story 一个契约版本内一个解释内核 | Chapter/Scene/Map 可以有不同只读投影 |
| 来源/权限/截止点 | Evidence 的物化与重验 | 各领域可加自有执行资料，不带回排除项 |
| 身份解析 | World identity seam | 导入、写作、地图均可调用，不各建 dedup engine |
| 演化推进 | Evolution run owner | bootstrap/append/revise/scoped 四种模式 |
| LLM 与计费 | Project connection + Root envelope | 不同配方、不同真实模型，共享根额度 |
| 领域采用 | 对应 World/Story/Writing 命令 | API、助手、协作是适配入口 |
| 推荐呈现 | Assistant stable issue + feed | 侧栏、卡片、可选图标入口 |
| 地图壳/相机 | 单一 ViewerShell/camera | 嵌入、全屏、移动表现 |
| 私有媒体 | 共享加载/缓存/释放协议 | 背景、头像、物品、缩略图 |
| 新鲜度 | 后端来源与依赖回执 | 前端可额外叠加本地 dirty |

检查重复不以函数名字相同或文件数为依据。区分合理 adapter、历史版本解释和真实业务规则复制；建立“同一输入、多个入口、同一副作用/语义”对照测试才有价值。

## 7. 三类门禁分别报告

工程门禁：来源一致、数据库并发、幂等、权限、恢复、API 等价、前端状态、删除清理。

模型质量门禁：原子命题正确性、引用语义、未知保留、错误改写、创意有效差异、同预算对照。

用户门禁：首次任务完成、能否理解当前状态、采用前能否说清影响、建议是否打扰、能否找回来源和本地修改。样本、角色、设备、模型、作品与预算必须注明。

任何一个门禁通过都不能替代另外两个。百分比目标、延迟目标和帧率目标均在基线测量后冻结；当前设计图上的任何数字都不作为测量结果。

## 8. 开发 Agent 的协作分包

一个包一个明确产物与验收，不按目录让多个 Agent 同时改同一事实规则。先做契约和消费者清单，再给各执行成员互不冲突的实现范围。接口变更必须同步所有真实调用者；合并前由独立验证任务从端到端输入检查，而非只读实施者总结。

建议实施顺序：E00/I01/I02/R00/U00 先建立基线 → E01–04/C01–02/V01–05/U01–03 并行 → I03 纵切 → E05–08 主链替代 → A/R/MI/C 高级能力按实测推进。

每次提交记录：影响契约、来源/状态、修改路径、真实运行测试、未覆盖项、是否需要迁移、回退方案。没有运行命令就写未运行，不引用旧绿灯或其他分支结果。
