# V + MI：地图、场景舞台与空间智能详细计划

V4.0｜设计提案。地图基础体验与演化主链并行交付，高级智能依赖可验证的 Story 状态和 Evidence 边界。空间画面是作品的一个视图，不是另一套事实数据库。

## 1. 地图系统的五层

| 层 | 所有者/数据 | 用户得到什么 | 不得混淆 |
|---|---|---|---|
| 地理与约束 | World/Map 采用的结构与关系 | 地点层级、空间拓扑、已知规则 | 图元拖动不自动改世界地理 |
| 时态与在场 | Story 的指定截止点投影 | 人物出现、物品保管、过去节点 | 最后见到不等于现在仍在此处 |
| 证据与作用域 | Evidence 物化回执 | 来源、范围、缺失及可见性 | 可搜索到不等于当前可见 |
| 表现与媒体 | Map revision/presentation/media | 底图、场景插画、人物与物品形象 | 图片不是事实证明 |
| 智能解释与排演 | 认知 + 注册协作配方 | 缺失条件、条件路线、地理创意 | 排演不等于已经发生的行程 |

保留当前地图结构与 API seam，优先抽出一个 `MapViewerShell`。不创建孤立的“认知地图数据库”，不把 World 对象复制进地图主表。地图内的成员引用现有 identity，并保存表现选择与来源版本。

## 2. 默认作者体验

作者进入地图时直接看到一个完整的空间舞台，可切换地图、配图与场景。当前章节和场景由工作焦点推导，但可明确切换；只有确实有位置依据的对象落点。未知对象进入可搜索列表，不为了“惊艳”随机撒点。

选择地点时在唯一详情抽屉中展示：地点图、当前在场、相关场景、一项最相关信息和返回正文按钮。抽屉不再打开另一个抽屉；需要更多证据时复用同一个宿主并提供返回栈。全屏模式仍在统一 overlay 根中，退出后恢复相机、选中对象、滚动、图层和编辑草稿。

场景舞台把背景图、人物图、物品图与当前原文连接起来。无配图时使用清晰的地点信息和抽象底图，不自动付费生成图片。角色图和物品图是表现参考，不能借图片暗示未揭露身份。

### 2.1 本轮 HiFi 对应

| 画面 | 设计目的 |
|---|---|
| S20 沉浸地图 | 浮动顶栏、探索范围、唯一详情抽屉、故事回看带；地名避让面板 |
| S21 场景舞台 | 背景、在场人物、物品与原文串联 |
| S22 历史旅程 | 有据节点与未知连接分开；明确首次阅读/事后解释 |
| S23 地图编辑 | 图元布局与事实变更分离；撤销、预览与离开保护 |
| S24 条件排演 | 已知约束、缺失条件、可选设想；不造出到达时间 |
| S25 配图与校准 | 媒体、范围、校准及候选采用分离 |
| S26 形象资料 | 人物、地点、物品视觉资产与来源 |
| S36 范围与视角 | 作者、当时已知和事后解释清晰分开 |
| S39 移动地图 | 可折叠底部详情，不将桌面三栏压缩到手机 |
| S46 图片调用确认 | 实际生成范围、费用未知、回执与不自动采用 |

画面中的点位、插画和路径全部是虚构设计样例，不是生产地图事实；地图坐标为示意，不按比例。

## 3. MapSceneContext 与在场语义

建议由 Map facade 聚合只读 DTO，数据来自合法 World/Story/Evidence，而非前端拼接一串原始表。

```text
MapSceneContextV1
  view_ref; scene_ref; map_revision; presentation_revision
  location_refs[]; presence_items[]; object_links[]
  source_receipts[]; coverage; omissions; unsupported_dimensions
  freshness; generation_stamp; request_context_id
```

`view_ref` 复用全项目经验视图的引用，不创建一张总快照表。正文来源、World/Story 版本、认知、地图、媒体及方法只绑定本次实际依赖，避免任何变化使全部视图过期。

### 3.1 人物与物品位置

| presence_kind | 可以怎样显示 | 禁止表达 |
|---|---|---|
| confirmed_in_scene | 本场在这里，有原文/已确认事件 | 不自动推出角色知道此地全部秘密 |
| profile_location | 仅当前作者资料中的常驻/档案地点 | 不回填成某历史 Scene 的实际在场 |
| last_observed | 最后一次明确出现于此，显示来源位置 | 不称“当前就在这里” |
| related_only | 和地点有关，放关联列表 | 不在地图上放实心位置点 |
| unknown | 位置未确定，保留搜索入口 | 不随机定位，不用档案地兜底 |

物品另列 custody、ownership、carried_by。青竹保管铜钥匙不表示她获得所有权，也不表示每个后续场景她都随身携带。一个角色关于位置的信念是 belief layer，不应进入客观在场层。

### 3.2 历史轨迹

只把明确出现节点画为真实节点。两个节点中间没有路线证据时可画有文字标记的虚线以表达“关系待定”，但默认不标路程、交通方式、速度或到达时间。已知道路的拓扑路径与人物实际走过的路线是两套不同的命题；前者也不能自动转成后者。

地图历史不仅按章节号。需要 story position、world valid time、learned position、source revision、interpretation mode；倒叙和后揭示必须可表达。新方法产生的回顾性解释不能以“这段原文在早期出现”为由混入首次阅读视图。

## 4. 渲染、相机与智能排布

### 4.1 相机坐标

世界坐标、底图像素坐标、归一化热点坐标和屏幕坐标分开。拖动与缩放修改相机矩阵；修改地理位置或底图校准必须是显式领域操作。重绘后保留同一语义锚点，不依赖 DOM 坐标碰巧一致。

`fitSelection` / `fitScene` 以扣除顶部工具条、侧抽屉和底部时间带后的可用画布为目标。展开抽屉不应挤动每个地点的世界坐标，而是调整相机或标签布局。必要时用“被遮挡地点列表”保持可达性；不把对象藏掉却不提供入口。

### 4.2 标签策略

以真实字体测量文本边界；优先显示选中对象、当前场景地点、关键路线端点，再显示普通地名。候选标签位置按锚点上下左右尝试，不能占用浮层障碍区；碰撞时缩短次级说明、聚合或转入列表，不缩小到不可读。

使用屏幕像素级碰撞索引，缩放时带迟滞，避免标签不断出现消失。每次相机微动不重排全部排名；对正在阅读的选中标签和卡片冻结位置。几何层、标签层、媒体层、交互层分别更新，避免鼠标悬停触发全书查询或整个地图重绘。

### 4.3 地图性能工作包

先以仓库当前支持规模作为实际基线，记录真实图元、边、图片数；输入 v3 提到的 200 图元/400 约束等限制须在实施时重核 schema，不能当成无限容量承诺。

建立固定 fixture：上限图元、长中文标签、密集地点、多个图层、抽屉开关、低端移动设备、网络慢与缓存失效。候选目标是交互有稳定反馈、可用帧率与有界媒体内存；阈值需要实机测量后冻结，不能用设计截图证明性能。

## 5. 媒体、热点与保留形象

### 5.1 媒体处理

沿用专用 owner/novel 门禁，不暴露私有对象存储 key。提议将展示图提升至适合大画布的分辨率档位，例如最长边 2048、显示资源约 1MiB 上限；这些是 v3 继承的设计候选，不是已实现规格，也不替代原上传输入限制。格式、透明度、WebP 编码和内存需实测；不能对已压缩旧图声称恢复原有细节。

人物/物品透明背景须在服务端保留 alpha，背景图按真实输入转换；不要统一 RGB 破坏透明形象。缩略图和展示图分级加载，较高分辨率只在需要时取。媒体管线复用共享 `PrivateMedia`，并发上限作为可配置资源策略，不由每个组件各起一套请求。

缓存键包含 account、novel、media revision、授权作用域；切换项目或视角先释放旧图和 object URL，取消旧请求，晚到结果不得挂回当前页面。卸载、替换、失败和删除均需释放资源。

### 5.2 Presentation revision

场景背景、形象选择、热点与裁切保存在独立版本化表现资产，不修改 CanonRevision 来表达视觉布局。热点使用归一化位置，绑定源图片身份与 hash；同一图片等比例派生不会丢失定位，换图或不同裁切映射必须重验，不能悄悄沿用旧热点。

单表现修订的热点数量可先采用 v3 的 50 个候选限制，使用完整 revision CAS 处理并发；数量不足则通过有版本的 schema 扩展，不让前端绕过限制。若当前 map schema 尚不支持室内/街道变体，先标 unsupported，再在独立工作包扩展，不临时塞入不被后端理解的字段。

### 5.3 图像生成

图像生成是单独授权和计费的命令。请求冻结实际可外发的资料，不把隐藏角色身份、私人正文或未授权的整个知识库交给供应商。返回候选后先审阅，再批准为某场景/角色使用。

超时后根据 request receipt 查询是否完成，不能默认再次付费。配额、保留数量、原图与派生文件、未被引用的失败资源均需要一致清理。删除项目清除所有媒体与残留；替换图片保留/释放的规则与配额账本不能各自实现。

## 6. MI：空间智能的逐级开放

### MI00 地理依据与缺失条件

从显式位置、连接和规则给出“已知什么、缺什么”。例如夜间城门关闭，但渡口是否通行未知。输出不是“无路可走”，而是“无法在当前证据下确认夜间通行”。

### MI01 路线与时间排演

只有采用的拓扑、方向、单位和通行规则可作为规划约束。模型解释叙事意义，代码做可执行约束与图搜索。若距离和速度缺失，输出路径选择或条件比较，不给分钟数。把方案标为 hypothetical；采用方案也只是采用作者规划，实际旅程需后来正文或作者事实命令确认。

### MI02 地理—剧情联动检查

校验人物跨场景移动、携带物品、地点进入条件与时间冲突。结果每项绑定来源与受检范围；没有完整路线不能宣称没有空间漏洞。修订地图或前文时通过依赖清单使旧判断失效。

### MI03 空间创意工作坊

三条独立提案可以围绕地形阻碍、社会规则、人物选择展开。必须保留一种不扩地图的方案；新增关卡、捷径或地理规则列出会约束后文的代价。不可自动画出新城、新路后把它当成既有正史。

### MI04 多视角与多尺度

角色所知地理、读者可见地图、历史政权/道路变化、室内场景等分别经过合约和访问门禁。外观、名称、连线和地图缩略图都参与泄漏测试。早期没有能力的视图返回 unsupported，不回退作者全量。

### MI05 长期空间认知

跨章节积累移动习惯、制度约束与空间叙事经验，只能作为可重验派生理解。统计相关性不能变成地理因果；“经常出现的地方”不是当前所在地。与 C 的方法实验使用相同输入和预算对照，验证其是否改善真实场景设计，而不是只增加图层数量。

## 8. 验收与反例

地图缩放或抽屉打开后，当前地点的名字不被遮挡；不能显示的次级地点仍可从列表定位。移动端底部详情不能盖住唯一当前状态和返回正文动作。全屏进出不丢失编辑草稿，ESC 首先退出当前最上层任务而非关闭整个作品。

甲地出现与乙地出现之间没有旅程时，不造连续实线；角色档案地不能回填历史在场；钥匙保管不改变所有权；角色知道某地点不等于客观位于该地。换到早期读者视角，作者图片、标签、缓存和晚到请求都不能泄漏。图片生成失败/重复恢复时不双扣配额；项目永久删除后对象存储清理可验证。

真实验收分别记录：地图数据语义、前端交互、媒体安全/资源、模型提案质量。高保真图是设计契约，不是这四类测试已经通过的证明。
