# NovelCraft V4：演化式小说整体引擎长期总计划

版本：4.0｜2026-09-21｜状态：设计与实施计划，不是已完成的业务改造。

代码基线：`FengHuoLinShan/ai-writing-assist@b5a3ef2e660ddaa65b9bf0ac1ada48f795c53201`。本次是静态、定向跨模块审查和设计原型检查；没有运行完整 PostgreSQL、真实模型或生产应用端到端验收。依据、原计划及证据等级见 `06-SOURCES-AND-AUDIT.md`。界面中的小说、人物、文字与数字全部为虚构设计样例。

## 1. 本轮真正改变的方向

项目的目标不再是继续增加相互调用的小说工具，而是形成一个闭环：作者写作或导入正文，系统逐步建立对这本书的可验证理解；理解进入后续写作、检查、建议与地图；作者修订之后，相关理解被精确修正，而不是让作者重新管理一串抽取任务。

V4 对两份输入计划作出以下实质性整合，不是把章节拼接到一起。

| 决策 | 最终边界 | 对原计划的影响 |
|---|---|---|
| 演化系统替代深度导入 | 一个项目只有一个有效的演化写入世代；旧深度导入不再是独立编排器 | 原 W 计划扩展为 E 计划；Imports 最终只保留文件解析、来源差异与正文写入适配 |
| 事实重建与认知成长分开 | World/Story 管事实身份和状态；Collaboration 的认知子域管可修订解释与方法 | 不把“系统越来越会理解”实现为第二套正史表 |
| 推荐不是又一个认知引擎 | Assistant 消费有作用域的事实、理解与用户当前任务，生成解释性建议 | 原助手审计中的选区、作用域、轮询、引用问题进入前置工作包 |
| 地图不是独立世界 | Map 在 World 内负责空间表现与约束，人物在场和历史来自 Story，来源来自 Evidence | 地图基础体验可以独立交付；高级智能再依赖演化及认知 |
| 多 Agent 分为可靠性与创意两条轨道 | 事实不靠投票；创意不强迫共识；共同复用现有运行预算与领域操作 | 从“默认不用多 Agent”变为“按任务证明价值后启用注册配方” |
| 全前端按任务组织 | 一个主任务、一个右侧宿主、一个浮层根；不同领域共享来源与结果状态 | 不再让提醒、预测、共创、Agent 面板各自抢占界面 |
| 演化不等于自动采用 | 派生理解可以在持续授权范围内维护；正式设定和正文修改仍走领域采用 | 保留一次授权、精确采用、历史与可撤回边界 |

“不再保留旧深度导入”指替代其产品入口、运行所有权、重试恢复和阶段调度；不是抛弃已验证的解析器、逐字证据校验、身份解析、结构抽取和模型调用适配器。替代以退役清单验收，而不是靠改名宣告完成。

## 2. 一个整体，六种职责

```text
作者动作 / 正文来源变化
        │
        ▼
Writing：版本化正文与编辑命令
        │ source revision + transactional change receipt
        ▼
Evolution：读取 → 观察 → 身份解析 → 状态解释 → 校验 → 窄批次提交
        ├── World：对象身份、关系、正式设定、地图约束
        ├── Story：场景、叙事顺序、类型化事件、历史状态
        └── Evidence：原文范围、可见性、依赖与重验
                     │
                     ▼
Collaboration/Cognition：持久理解、竞争解释、开放问题、方法试验
        │                    │                    │
        ▼                    ▼                    ▼
Writing/Review          Assistant 推荐       Map/Scene 舞台
        │                    │                    │
        └────── 用户决定 → 领域命令 → 新版本/变更回执 ──┘
```

上图是职责与数据流，不表示新增六个服务、六个数据库或全局分布式事务。继续使用现有应用、PostgreSQL、异步 worker、项目 LLM 入口、运行信封、Vue 3 与 bridge。

### 2.1 每类信息只有一个权威所有者

| 信息 | 权威所有者 | 其他模块允许做什么 |
|---|---|---|
| 正文与版本 | Writing | 按指定版本、字符范围读取；提交明确修改命令 |
| 实体身份与已采用事实 | World | 引用、提出更新候选，不各建一份人物主表 |
| 场景顺序与状态事件 | Story | 读取带截止点的状态，不从当前 World 倒填过去 |
| 来源与权限证明 | Evidence | 统一检索、编译、确认、物化与验证 |
| 演化运行和推进游标 | Evolution | 展示其状态，不另起“导入推进”主游标 |
| 本书的派生理解与方法 | Collaboration/Cognition | 在合法快照下消费、提出更新，不据此自动准入正史 |
| 推荐呈现与处置 | Assistant | 排序、暂缓、展开、调用领域提案入口；不持有独立事实 |
| 地图几何、视觉与媒体选择 | World/Map | 作为有版本的表现资产；不证明人物知识或实际旅程 |
| 当前操作焦点 | 前端任务上下文 | 选择展示与请求范围；不能成为授权或事实 |

跨模块 facade 继续保持稳定。不要把大量业务判断搬进组合根；不要为了遵守形式再增加一层只转发参数的“总控服务”。

## 3. 本次再分析后的主要问题与整改顺序

### 3.1 不是所有“连接”都带来语义闭环

原审查及输入计划指出：实体和 Delta 已记录，不等于可查询历史状态发生了对应变化；同一人物的重复身份观察可能因去重而提前跳过；所有 Scene 输入预先冻结后再顺序落库，不等于后一 Scene 继承本轮前一 Scene 的解释。本计划把这些作为发布前必须验证的语义契约，而不是只检查模块接口能够互调。

本轮新增的定向核对还发现：`EventRepository.replace_scene_events()` 按 Scene 读取全部旧事件，再按 `scene_sequence` 覆盖、删除剩余行；该函数没有按来源保护作者确认事件。结合现有人工事件追加到同一 Scene 流的机制，重跑必须先解决“机器替换范围与人工确认共存”的问题。这里是静态实现风险，不是已观察到的生产数据丢失。

### 3.2 前端焦点、授权和结果身份不应共用一个模糊 hash

助手审计中的关键问题包括：选区未完整传递、后台与前台 Scene 焦点不一致、各组件各自轮询、任务意图未进入后端、整轮证据被误当成每条结论的支持。V4 不通过放宽来源校验解决“看不见建议”，而是分开授权作用域、证据快照、任务意图和界面焦点，再检查结果能否适用于此刻。

### 3.3 全部入口必须具有同一组领域副作用

API、助手、协作试改均能写入工作稿；来源失效、索引请求、演化排程不应依靠每个调用者记住补做一遍。V4 引入“领域命令 + 变更回执 + 确定性副作用投递”契约，并核对所有入口。批量纯持久化 helper 可以保留，但调用方必须显式取得并消费待交付副作用，不得返回普通成功后遗漏。

### 3.4 完成、可靠和采用是不同状态

统一结果外壳至少区分：执行状态、实际覆盖、来源新鲜度、当前任务适用性、审查状态、采用状态。局部完成不能在助手投影中折叠成全量完成；一份旧检查仍可作为历史查看，但不能计为当前有效严重问题。

## 4. 长程能力蓝图

### 4.1 第一层：可靠地理解刚刚写下的内容

从少量正文开始，不要求先建立完备设定。逐字观察、来源范围、身份解析和状态变化组成最小链。对未知、角色说法、传闻、假设、作者规划分别记录。一次授权可以推进多个 Scene，但每个状态提交都可追踪、可重验、可恢复。

### 4.2 第二层：理解不断反哺下一项真实任务

持久认知不是额外生成一份长摘要。新建的写作或调查 case 必须实际读取相关认知版本，明确列出哪些解释被使用、哪些因时态或来源变化不能用。变化触发局部重查；无变化允许 `no_change`。真实消费链未建立前，不宣称完成“认知成长”。

### 4.3 第三层：扩大认知，但不扩大未经授权的真相

逐步加入竞争动机解释、因果条件、承诺与代价、开放问题、制度规则、角色信念、读者信息分布、反事实与局部写作经验。外壳的来源、范围、方法与权限固定，内部表达可随本书形成；不预设无穷 taxonomy，也不允许模型自行迁移数据库、注册任意工具或改写安全策略。

### 4.4 第四层：推荐、创意与空间推演

推荐从“当前页面有什么未处理项”扩大为“作者正在做什么，这一步最值得注意什么”。保留一个主建议和少量可选方向；每项有依据、为什么现在、适用条件、新增叙事负担与局部行动。

地图智能从位置展示扩大为条件路线、通行约束、地理矛盾、行程准备和空间创意。明确区分已知事实、示意布局和假设方案；没有距离与路径证据就不承诺到达时间。高级角色视角与读者地图在独立安全门禁后开放。

## 5. 多 Agent 的整体定位

可靠性轨道和创意轨道共享执行底座，不共享裁判逻辑。

可靠性轨道：窄任务抽取者 → 代码检查 → 独立证据复核者 → 有限争议裁定 → 类型化候选。评审者不能只看生成者的解释；事实不能由多数同意决定。无法证明时进入待决定或未知。

创意轨道：先独立产生人物、悬念、情绪等不同方向，再对作者展示对比，不立即融合。作者选定方向或片段之后，才生成具体可预览修改。审美差异不能被可靠性裁判误判为错误。

初始上限沿用现有有限协作边界：单宿主、最多三名并发成员、一个根预算、共享租约及取消。更多角色通过分阶段复用，不以增加并发数量为目标。没有第二个真实模型连接时明确称为角色分工，不称为异构模型。

研究只能支持设计假设，不能替项目证明质量收益。受控架构研究表明多 Agent 收益依赖任务结构；无外部反馈的自我修正研究显示在其测试推理任务中可能退化；短篇创意实验同时提示个体收益与群体同质化风险。[R1–R4，详见 06]

## 6. 前端产品方向

默认导航保留“概览、写作、故事结构、世界资料、故事地图、待我决定”。运行、恢复、模型授权进入次级位置。作者不应看到 Phase2b、raw ID、JSON 或内部 token 枚举。

写作区以正文为主，伙伴区在“当前、讨论、历史”之间切换；不是三个悬浮窗。详情按三层展开：卡片要点 → 同宿主证据/备选 → 独立大任务工作区。全屏地图、全屏写作和大规模差异比较都是任务态，不覆盖底层未保存输入。

“智能排布”由可测试的界面策略决定：任务意图、内容宽度、当前焦点、输入法状态、是否阅读中、是否有未保存内容、是否已锁定选择。模型只提供结构化建议内容，不直接输出任意布局指令。

本轮设计包含 48 个工作流/状态画面及 1 个设计规范画板。它覆盖主要工作流族，不等于穷举所有字段、API 或所有输入组合。功能迁移仍须按 `04` 的等价矩阵验收。

## 7. 可并行交付的长期路线

| 里程碑 | 核心交付 | 进入下一阶段的证据 | 可并行工作 |
|---|---|---|---|
| G0 基线与保护 | 作者事件保护、状态契约、重复实现清单、入口副作用矩阵 | 不再误删人工确认；关键语义用例可复现；缺口明确 | 前端选区传递、地图壳、样例库 |
| G1 最小基础 | 演化运行/观察/类型化提交；持久认知最小读写；统一前端宿主 | 一条 Scene 提交有完整回执；一项新 case 真正消费认知 | 地图 M1：全屏、相机、媒体与对象浏览独立交付 |
| G2 整体纵切 | 原文→前序状态→后序理解→新 case→地图→修订失效 | 同一事实在各视图一致；无未来泄漏；重跑可恢复 | 小模型可靠性配方开始等预算对照 |
| G3 主链替代 | 项目级切换、旧 owner 排空、旧入口适配、旧编排退役 | 同项目只一个写入世代；历史读取与回滚路径可用 | 新统一写作/审阅前端逐页替换 |
| G4 可靠性产品化 | 注册多 Agent 配方、有限升级、部分结果与证据裁定 | 相同预算下对既定任务有实际收益；不合格任务仍用单 Agent | 创意方向独立实验 |
| G5 创意与推荐 | 独立发散、当前意图、机会建议、稳定去重与处置 | 人工任务测试：建议有用且不夺权，不重复制造问题 | 地图条件排演、制度压力测试 |
| G6 地图智能 | 真实位置/最后出现/未知、条件路线、约束解释、视觉状态 | 不伪造轨迹，不把图像当事实；抽屉避让与移动端可用 | 高级历史和受限视角安全测试 |
| G7 扩大认知 | 竞争解释、开放结构、方法试验、长书局部重算 | A–E 等预算对照；实际任务消费、纠错与遗忘均可证 | 长期作者试用，不以点击替代有效性 |
| G8 长期维护 | 大规模性能、删除清理、迁移回退、持续回归与灰度 | 工程、模型质量、用户效果三类门禁分别通过 | 按证据引入新的受限能力 |

这里的 G 不是固定周数估算。各包先得到代码与测量基线，再做容量排期；不以“AI 开发很快”省略迁移与真实验证。

**本次交付的验收授权（2026-09-23）**：作者明确指定由开发代理执行原 G7 长期作者试用与创意独立读者盲评的代理验收，并标记“代理验收，非人工试用”。执行多轮真实任务、纠错/遗忘/恢复和遮蔽方案身份的结果对照，保留原始输出、失败与评分依据；不把压缩时序验证称为长期使用，不把模型审美自评分称为人类 ground truth。此授权只替代本次人工参与门禁，不取消工程、真实模型质量、等预算、成本、安全与迁移回退验证，亦不授权生产发布。原长期人类效果目标保留为后续观测。

关键依赖：`G0 → E01/E02/E03 → E04 → G2 → E07/E08 → G3`。地图壳、媒体管线与前端统一宿主不必等待完整认知；高级历史地图必须等待可靠状态与可见性契约。C 的首次消费也不必等待所有方法演化。

## 8. 不做什么

不新增通用自治 Agent 平台，不默认迁移 LangGraph，不建立第二个任务队列，不用新世界数据库替换现有领域；不把当前 World 注入过去；不把作者点击、模型一致或图像像素当事实；不把不支持的读者视角回退成作者全量；不将所有派生更新塞进一个跨全书大事务。

也不以“傻瓜式操作”为由隐藏费用、授权、删除范围和冲突。简单应当来自合理默认、自动维护和渐进展开，而不是省略真实状态。
