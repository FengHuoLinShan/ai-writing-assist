## 动态编排与剩余修复

1. 冻结当前 Scene 的章、草稿版本、逐字区间、前序已提交回执和模型快照；超过已实测的单场规模时，优先沿章或语义边界拆分，保留旧 Scene 和历史。此次最长 Scene 6,017 字、观察最多 63 条。
2. 用无思考窄采样获得可追溯观察；唯一引文可按原文定位，少量无法定位的观察与其状态提议隔离，大量或歧义引用失败关闭。身份解析和状态结构门先运行，再按候选实际存在与否分流。
3. World/关系候选走高思考；确有关系候选才发关系请求。独立审查过长时保存待处理，不占用正式世界权限；格式失败且完整用量已知时保存原始失败并允许该 Scene 的观察/状态继续，网络或费用未知仍停下对账。
4. 独立状态复核只核有证据的状态提议；通过后短事务提交回执，后续 Scene 必须消费前序已提交理解。所有推断、人物所知和原文客观事实分开，私人 RP 不回写作品。
5. 当前代码已经实现上述条件分流和安全延后；**尚未实现超大 World 候选的有来源分组复核**。作者侧应先人工代理整理最有价值的连续篇章，逐条采用可核的对象、人物知识、地图与伏笔；其余自动候选保持待裁定。这是完成旗舰演示的内容工作，不以跑满 66 个任务替代。
