# E06 恢复语义与检查点性能测量

2026-09-21｜本机 PostgreSQL（localhost:5207，专用空库 + pgvector 扩展，
测量后已删除）。这些是**测量档位，不是性能承诺**（计划 §9）。

## 恢复语义（`backend/modules/evolution/recovery.py`）

- **分页回放**：`replay_committed_prefix` 按
  `(committed_scene_index, attempt_key)` 键集分页，页大小与总页数有界
  （`max_pages`），拒绝无界全书扫描。
- **链连续性**：每笔回执的 `previous_receipt` 必须精确链接前一笔；
  缺口 `ChainGapError` fail-closed，要求人工续接，不跳过（§7.1）。
- **检查点信任锚**：`from_scene_index` 之前的页不扫描；锚点与 head 的
  一致性经 `verify_run_checkpoint` 校验，漂移即 `CheckpointDriftError`。
- **T12 完整 fencing**：`store.save_receipt` 的游标推进以
  `owner_epoch == receipt.owner_epoch` 为条件——旧 worker 即使通过
  apply 起点检查，持久化边界也拒绝其回执，游标不被旧代际移动
  （`test_recovery.py::test_t12_midflight_epoch_switch_fences_at_persistence`）。

## 测量（`python -m tools.evolution_checkpoint_bench`）

每档种 1 笔/Scene 的链式回执（page_size=200，尾部增量=100 Scene）：

| 档位 | 全量回放 页/行/耗时 | 增量回放(尾部100) 页/行/耗时 | 检查点校验 |
|---|---|---|---|
| 1000 | 5 / 1000 / 29.46ms | 1 / 100 / 2.83ms | 4.26ms |
| 5000 | 25 / 5000 / 317.08ms | 1 / 100 / 4.52ms | 4.64ms |
| 10000 | 50 / 10000 / 628.26ms | 1 / 100 / 7.26ms | 9.59ms |

结论（本机条件下的语义验证，非承诺数字）：

- 全量回放随档位线性（5→25→50 页）——长链不逐次全书重算的依据是
  检查点命中，而不是回放变快；
- 检查点锚点命中后，三个档位的增量回放都只有 1 页/100 行，
  耗时 <10ms——恢复成本与已提交前缀长度解耦；
- 检查点校验（head 读取 + 游标比对）在各档位 <10ms。
