## 1. 审查目标与受保护边界

本轮以可造成真实用户影响的 bug 为第一优先级。能够在现有架构和稳定契约内明确修复的问题直接修复；需要产品、架构、数据迁移或风险接受决定的问题只记录，不擅自实施。

受保护边界：

- 所有业务数据始终按 `novel_id` 隔离，项目删除和 adopted 资产生命周期不得被弱化。
- API、schema、前端 wire shape 与跨模块 `contracts.py` / `facade.py` / DI port 默认保持兼容。
- LLM 配置继续经 project facade 继承，输出经过 schema 校验；普通输出不得绕过用户授权直接成为已采用资产。
- API Key、敏感输入和 provider 原始错误不得进入日志、任务结果或前端错误桶。
- 长任务必须守住租约、任务 owner、来源漂移、重试幂等和最终提交边界。
- 前端修复复用现有组件、设计 token、排版、交互层级和 CSS；禁止为了修 bug 直接写一套原始 UI 或破坏既有美术风格。
- 不以放宽断言、吞异常、跳过验证或改用真实开发库来制造“通过”。

## 5. 本轮已直接修复

### 5.1 前端正确性与安全性

在保持现有 CSS 与视觉语言不变的前提下，已完成以下直接修复：

- API 请求体不再写入错误日志；错误对象和历史日志桶递归脱敏敏感字段。
- global/project settings 的单字段重置不再覆盖其他未保存编辑。
- World、Outline、Scene、RAG 异步工作流冻结项目身份并加入同步提交锁，阻断旧项目回写与双击竞态。
- Writing 发布前冲突检查改为 fail closed；Generate 的聊天、建议与采用互斥。
- 导入在前端先校验允许扩展名与 50MB；新项目导入失败后保留并选中项目，明确引导重试，不再假装整个创建失败。
- Map 旧 island 在导航后停止所有动态重载，包括 lens/scene 路径。
- Shell 全局业务快捷键在 modal、help 或 command 面板打开时停用。

这些修复的当前验证证据见第 3 节；真实浏览器视觉门禁已使用独立 PostgreSQL 测试库完成。

### 5.2 应用生命周期清理

- 修复 `app.main.lifespan` 在运行期异常时跳过清理的问题，关闭逻辑移入 `finally`。
- 关闭时会逐一尝试 container、embedding client 与 database manager；单个 closer 失败不再阻断后续资源释放，最终以 `ExceptionGroup` 汇总。
- 后台 embedding prewarm task 被显式持有，退出时先取消并等待，避免与 embedding worker 关闭竞态。
- 回归：`tests/unit/test_app_logging.py` 与 `tests/unit/test_container.py` 共 21 项通过，Ruff 通过。

### 5.3 Token 预算离线可靠性

- 发现 `tiktoken` wheel 首次加载 BPE asset 时可能访问外网；离线会在 context 确认路径抛 `ConnectionError`，并级联破坏 imports / world / outline / writing。
- 现在可用时仍按模型使用精确 tokenizer；asset 加载失败时缓存失败结果，并使用 UTF-8 字节长度作为保守 token 上界。该上界可能更早裁剪上下文，但不会因离线而放宽预算或返回 500。
- Token 加载失败不会将外部异常内容写入业务响应或重复发起下载。
- 单元、Context 与 Writing API 最小回归均已通过；fast 全量复跑进行中。

### 5.4 LLM / embedding 诊断脱敏与熔断分类

- RAG embedding batch/per-chunk 失败此前会把原始 `str(exc)` 写入 `embedding_error` / `index_warnings`，这些字段可由 RAG API 返回。现在 writer 与 repository 两个持久化入口都先调用 `redact_diagnostic` 并截断。
- LLM retry 日志同样统一脱敏，不再依赖 provider 恰好构造了安全异常字符串。
- 进程级 LLM circuit breaker 不再把 project Key 认证失败、内容过滤或结构化/BadRequest 错误计为 provider availability failure；这些确定性客户端错误不会阻断后续项目请求。
- 新增凭据对抗回归；相关 LLM/RAG 17 项测试、breaker 定向测试与 Ruff 均通过。

### 5.5 共享引用与数值配置边界

- `TargetRef` 的 type/id 现在先 trim 再执行 `min_length`，空白字符串不再通过校验并形成空身份/hash。
- deep-import 项目设置与环境浮点值统一拒绝 `NaN` / `Infinity`；不再让非有限 timeout、置信度或 token 比例进入 workflow snapshot。
- 全局 `Settings` 的 LLM retry、circuit reset、inference timeout 和 embedding queue timeout 同样 fail-fast 拒绝非有限值；`INFERENCE_WORKER_TIMEOUT` 改为实例化时走统一校验。
- 配置与 deep-import 定向复跑 138 项通过；`TargetRef` 与 World 相关定向测试另行通过。

### 5.6 RAG、Memory 与 Settings 边界

- RAG chunk 现在拒绝 `overlap >= chunk_size`、负 overlap 和非正 chunk size，消除分片步长为 0 导致的死循环；API 同步限制 200,000 字符和动态 422。
- Memory replay 在修改状态前对 snapshot payload 和 event payload 做深拷贝，不再把回放的临时变更写回 SQLAlchemy JSON 属性。
- project effective LLM / author preferences 在 settings facade 先调用 `require_active_project()`；回收站项目返回 404，并通过共享行锁阻断与删除的 TOCTOU。
- RAG retrieval/reranker degraded warning、embedding runtime/prewarm 状态、task worker result 和心跳错误均经递归脱敏。

### 5.7 Imports / Outline 事务与诊断修复

- Deep Import artifact、phase progress、checkpoint、snapshot、retry 与审计中的 provider 错误统一脱敏，不再将原始异常写入持久化结果。
- boundary supplement 的每个 window 使用 `db.begin_nested()`；单窗口失败会回滚自己的 savepoint，不再毒化外层 session 后还继续执行。
- Outline structure dedup 和 `PlotStructurePersister` 的批处理/逐项 fallback 增加 savepoint，捕获单项 DB 失败后不再遗留 aborted transaction。
- Imports 与 Outline 的 API、parser、generator 和 task 收尾错误不再记录或返回原始 traceback。

### 5.8 Context / Writing 并发与隐私修复

- `ContextCompiler` 不再用 `asyncio.gather()` 并发驱动同一 `AsyncSession`；loader 保持顺序执行，避免 asyncpg 连接重入。
- Context loader、snapshot、Writing AI review/suggestion/conflict/publish retry 的失败日志及持久化错误统一脱敏。
- Writing candidate adopt 和最终 working draft delete 在写入前获取章节 advisory lock，并在 `FOR UPDATE` 后重读目标，阻断同章 autosave/publish 竞态。
- LLM JSON 解析失败日志只保留 label 与长度，不再记录作者/provider 原文预览；生产路径中的 `logger.exception` / `exc_info=True` 已清零并改为截断脱敏诊断。

### 5.9 World / Map 数据隔离与精度修复

- Map Fact 按 observation 查询新增 `novel_id` 条件；map dynamic 诊断和 projection 错误统一脱敏。
- World Bible 首次并发 refresh 会锁 page 行；projection `error_kind` 在写库前按列宽截断。
- alias/relation 批量写和 fusion evidence 的数据库错误不再被当成普通候选失败或“没有证据”，会正确向上抛出。
- importance / strength / confidence 的显式 `0.0` 保持原值，不再被 `or default` 覆盖；relation strength 0 不再变成 0.5。

### 5.10 配置、CI 与本地运维安全

- 所有环境驱动 `Settings` 字段改为实例化时求值；LLM profile 数值拒绝 bool、越界与非有限值，无效值会回退默认值而不伪装成 project source。
- GitHub backend CI 在前端单测后新增 `npm run build`，不再只验证 Vitest 而漏掉生产打包失败。
- `doctor.py` 会递归处理嵌套字符串、URL、Bearer 和未载入环境的 Key 模式；message 也脱敏。
- `scripts/dev_stack.py` 在依 pidfile、命令模式或端口停止进程前，必须同时确认命令特征和 cwd 属于当前仓库；PID/端口被无关进程复用时不再误终止。
