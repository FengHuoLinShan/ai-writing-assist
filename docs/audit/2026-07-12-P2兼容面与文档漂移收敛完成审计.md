# P2 兼容面与文档漂移收敛完成审计

> 日期：2026-07-12
> 实施计划：[`2026-07-12-p2-compatibility-surface-doc-drift.md`](../superpowers/plans/2026-07-12-p2-compatibility-surface-doc-drift.md)
> 结论：P2 已完成；未改变 HTTP API、数据库 schema、前端 wire shape或候选/采用语义。

## 1. 完成范围

### 1.1 权威文档

- project README 已在先前闭环中覆盖回收站、effective LLM profile、execution snapshot
  和项目级智能去重，本轮复核后不制造重复改动。
- writing 定位已从“仅承载人工草稿”改为“正文事实源与受控 candidate 生成”，并明确
  不自动采用、覆盖或发布 AI 输出。
- world 删除早期 CRUD MVP 描述，改为当前事实模块范围。
- outline/world README 明确 root facade 的冻结与新增 seam 规则。

### 1.2 World contract 与 package root

- `modules.world.contracts` 删除 10 个 HTTP Pydantic schema 重导出，只保留稳定
  dataclass，并增加显式 `__all__`。
- 删除只有测试调用的 `DuplicateSuggestion` 旧 dataclass；真实去重结果继续使用当前
  domain/schema 类型。
- `modules.world.__init__` 不再重导出 ORM、HTTP schema、contract 或 facade 函数。
  组合根和业务代码仍可显式导入 `modules.world.api`、`contracts`、`facade` 等子模块。

### 1.3 Facade 冻结和删除

- world root facade 增加显式 `__all__`；outline 保留并缩小显式 `__all__`。
- 新增 `tests/unit/test_facade_public_api.py`，同时校验 `__all__` 和模块实际公开 callable，
  防止只 import 未登记的函数静默扩大公共面。
- 删除无生产调用的 world `upsert_relationship` wrapper。
- 删除无调用的 outline facade：
  `reindex_scenes_for_deep_import_repair`、`get_deep_import_structure_counts`、
  `get_deep_import_structure_payload`、`ensure_deep_import_structure_minimums`。
- 对应 service 内部能力仍保留，因为 `ensure_structure_minimum_counts()` 内部复用
  `structure_payload()` / `structure_counts()`；删除的是无消费者的跨模块 wrapper。

### 1.4 LLM 和 RAG helper

- world Mock-db 抽取分支在没有 project context 时 fail closed，不再零参数构造
  `LLMClient()`；P0 direct-client allowlist 同步缩小。
- 删除无调用的 `get_legacy_circuit_breaker()`；仍需的全局状态通过
  `get_circuit_breaker(None)` 获取。
- RAG query/chunk embedding 使用独立 `EMBEDDING_*` 配置的 direct client 保留，
  未被误归类为 novel-scoped chat profile legacy。

## 2. 明确保留的兼容语义

以下能力仍有生产、迁移或用户数据语义，未删除：

- writing/world/outline 的 candidate/review/canonical 状态；
- creation suggestion 的 compatibility shadow 及其原子采用/忽略联动；
- 存量 Scene candidate 只读兼容；
- `batch_size` 等仍在 HTTP/task wire 中的参数；
- world model package 内为 ORM metadata 注册保留的模型兼容导出；
- RAG embedding 独立配置边界。

因此本次是删除无调用兼容面，不是以“清理”为名改变用户资产状态机。

## 5. 后续规则

1. outline/world root facade 新增函数必须同时更新 contract/README/public API snapshot，
   并在评审中说明 deletion test。
2. HTTP schemas 只能从拥有模块的 `schemas.py` 使用；跨模块数据语义优先定义独立 contract。
3. package root 不作为公共业务 API；组合根加载子模块必须显式写出子模块名。
4. 清理 candidate/compatibility shadow 前必须先证明没有存量数据和用户状态语义，不能仅按
   名称中的 legacy/candidate 判断。
