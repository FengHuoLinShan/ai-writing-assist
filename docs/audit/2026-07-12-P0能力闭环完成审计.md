## 2. P0.1 完成证据

### 2.1 项目 runtime 与隔离

- `modules.project.facade.open_project_llm_client(db, novel_id)` 是 DB-backed novel-scoped 业务调用的统一 seam；调用方无法传入 provider/Key/Base URL 绕过项目设置。
- effective profile 继续按 project/global/system 设置来源物化；缺 Key、缺 endpoint/model、缺失或已删除项目均 fail closed。
- runtime client 在成功、异常和取消路径都关闭；双项目并发 fake-provider 测试验证 `novel_id` / profile / model 不串。
- provider 诊断只记录 host，不记录完整 Base URL/query；embedding 仍使用独立 `EMBEDDING_*` 配置，不继承 project chat profile。

### 2.2 可恢复任务的冻结配置

深度导入和分阶段任务在**提交时**持久化 `llm_execution_snapshot`，而不是到 worker 真正执行时才重新选模型。该 snapshot：

- 保存 provider/model/非 secret 生成参数、字段来源、deep-import 设置和稳定 hash；
- 只保存 Base URL host 与完整 endpoint hash、extra keys 与 extra hash，不保存完整 URL/query、extra values 或 API Key；
- 恢复时继续使用提交时的 model/参数/字段来源，允许 API Key 轮换；
- endpoint 或 provider-specific `extra` 在任务中途漂移时拒绝恢复，避免把旧任务静默发往新端点。

Phase 1/2/3 都消费这份冻结配置。`high_quality=true` 传递到 Scene、World Phase 2a/2b 和 Outline Phase 3，实际 request model 为 `deepseek-v4-pro`；普通运行使用 snapshot profile model。
Phase 1b enrichment 的旧 4096 默认上限已修正为 32768，与其他结构化阶段统一；该值也在提交时进入 snapshot，不在 worker 恢复时受新 env/default 影响。
同时，Phase 1b payload 现在由 effective project `enrich_max_tokens` 生成，
Phase 2 context snapshot 记录活跃调用的实际 32768，Phase 3 新增并冻结
`structure_max_tokens=32768`；三者的项目设置、真实请求和 provenance
不再相互漂移。Phase 2/3 移除了只改变 token 上限的阶梯重试；
同预算故障重试、schema/format repair 和业务质量 replacement rerun 仍保留。

### 2.3 可观测性与兼容收口

- managed LLM provenance 记录 `step_name`、`novel_id`、profile source、脱敏 summary/hash 和**实际 request model**；profile 默认 model 只作 `default_model` 保留。
- worker 使用 task-local collector，并在成功、失败和取消路径把 `managed_llm_steps` 合并进 result；Writing candidate 也保留同样的脱敏 provenance。
- 评测/手动 inline stage seam 现在也设置 running/失败状态、聚合
  managed provenance，并用独立 session 定期更新 heartbeat，避免长时
  World/Outline 评测被 worker stale scanner 误取消。
- RAG reranker 启用时先召回 `2 * top_k`，重排失败由 retrieval 外层降级到原排序并返回 warning。当前 RAG baseline 未证明质量达标，因此 `RERANKER_ENABLED` 保持默认关闭。
- 旧 `modules.world.facade.run_entity_extraction` 及其 DI 注册已删除，World 正式评测只复用 imports `world_objects` 阶段。
- `SceneSegmentationService` 保留为兼容/测试工具，但 batch 和 single-chapter 方法均已使用 project runtime context manager；direct-client AST 例外已删除，生产主路仍是 Phase 0/1a/1b。

## 8. Contract 与安全结论

本轮没有破坏性修改 HTTP API、数据库 schema 或前端必需 wire
contract。新增 task/result 信息是脱敏、加性的执行与 provenance
证据。API Key、完整 Base URL query、小说正文、raw prompt 和 raw LLM
output 不进入 snapshot/journal/report。novel 隔离、schema 校验、用户授权、
preview/apply 和软回滚语义保持不变。
