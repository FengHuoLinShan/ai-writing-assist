# 核心业务场景与预期行为描述

> 本文档基于代码库实际状态与架构讨论产出，面向 E2E 测试编写和 AI 辅助 Debug。
> 采用 Given-When-Then (BDD) 格式，区分正常流与异常/边界流。

---

## 场景 1：项目创建与管理

### 【业务场景名称】

用户创建、选择、编辑、删除小说项目。项目是系统的根聚合，所有其他模块通过 `novel_id` 关联。

### 【用户视角链路】

#### 正常流：创建项目

**Given** 用户在首页
**When** 用户点击"新建项目"，填写标题（必填），可选填写题材、风格基调、目标规模
**Then**
- 项目创建成功，`language` 默认 `"zh"`，`default_reveal_policy` 默认 `"author_safe"`
- 前端跳转到该项目的工作台（写作视图），URL 变为 `/workbench/:projectId/writing`
- `projects` 表新增一行，`id` 为 UUID，`created_at` 记录创建时间

#### 正常流：列表选择

**Given** 用户已在首页
**When** 页面加载
**Then**
- 展示所有已创建项目列表，每个项目显示标题、题材标签、创建时间
- 用户点击任一项目 → 进入工作台
- 分页参数 `skip` / `limit` 控制列表数量，默认每页 20 条

#### 正常流：编辑项目

**Given** 用户在工作台
**When** 用户点击项目名称进入编辑模式，修改标题或题材后保存
**Then**
- `projects` 表对应行 `title` / `genre` / `tone` / `target_length` 更新
- `updated_at` 自动更新
- 前端项目名称面包屑同步刷新

#### 异常流：删除项目（回收站二次确认）

**Given** 用户选择删除项目
**When** 用户点击"删除项目"
**Then**
- 前端弹出确认对话框："确定要删除项目《XXX》吗？删除后可在回收站中恢复。"
- 用户确认 → 项目标记为软删除（移至回收站），数据不动
- 回收站中再次确认删除 → 级联删除项目下所有关联数据（world / outline / writing / memory / rag 等所有 `novel_id` 关联行），不可恢复
- 404：项目不存在或已删除，返回错误

#### 边界流：空标题

**Given** 用户创建项目
**When** 标题为空或纯空格
**Then**
- 后端返回 422 Validation Error
- 前端显示"请输入项目标题"

### 【数据与状态契约】

| 层级 | 变更 |
|------|------|
| 前端 UI | 项目列表刷新；面包屑更新；确认对话框 |
| `projects` 表 | INSERT / UPDATE / 软删除标记 |
| 关联表 | 回收站二次确认后级联 DELETE（world / outline / writing / memory / rag 等所有模块数据） |

## 场景 2：文件上传与章节导入

### 【业务场景名称】

用户上传本地小说文件（txt/epub/html/mobi/azw3），系统自动解析分章，存入正文章节库。

### 【用户视角链路】

#### 正常流：上传并解析

**Given** 用户在写作工作台
**When** 用户点击"导入小说"，选择本地文件（如 `novel.txt`，150 章，总大小 8MB）
**Then**
- 前端显示上传进度条
- 后端校验文件格式（白名单：`.txt .epub .html .htm .mobi .azw3`）和大小（≤50MB）
- 文件名做 `os.path.basename` 处理，防止路径穿越
- 选择合适的解析器（txt→chardet 编码检测 + 章节正则分割；epub→ebooklib；html→beautifulsoup4）
- 解析结果逐章写入 `writing_drafts` 表，每章 `version_number = 1`
- `import_records` 表新增一条记录，记录 `file_name / file_type / file_size / total_chapters / imported_chapters / status`
- 前端显示导入结果：共解析 N 章，成功 M 章
- 导入完成后提示用户："已导入 M 章，是否启动深度导入？"

#### 异常流：格式不支持

**Given** 用户选择文件
**When** 文件扩展名不在白名单（如 `.pdf`）
**Then**
- 后端返回 400："不支持的文件格式，仅支持 txt/epub/html/htm/mobi/azw3"
- 前端显示错误提示，文件不进入解析流程

#### 异常流：文件过大

**Given** 用户选择文件
**When** 文件超过 50MB
**Then**
- 后端返回 413："文件大小超过限制（最大 50MB）"
- 前端显示错误提示

#### 异常流：编码检测失败

**Given** 用户上传 txt 文件
**When** chardet 无法确定编码，或解析出空内容
**Then**
- `import_records.status` 标记为 `failed`，`error_message` 记录具体错误
- 前端显示"导入失败：无法识别文件编码，请尝试另存为 UTF-8"

#### 边界流：空文件

**Given** 用户上传文件
**When** 文件内容为空或解析后无有效章节
**Then**
- `import_records.status` 标记为 `failed`，错误信息"文件中未检测到有效章节"
- 不创建任何 `writing_drafts` 行

#### 边界流：并发限制

**Given** 导入 150 章
**When** 每章写入 `writing_drafts` 并触发 RAG 索引任务
**Then**
- 系统限制并发 RAG 索引任务数，防止任务队列爆炸

### 【数据与状态契约】

| 层级 | 变更 |
|------|------|
| 前端 UI | 上传进度条；导入结果提示（成功 M 章）；错误信息 |
| `import_records` 表 | INSERT 一行，status=`done`/`failed` |
| `writing_drafts` 表 | 每章 INSERT 一行，version_number=1，status=`draft` |
| `async_tasks` 表 | 每章自动入队 `rag_index_chapter` 任务（受并发限制） |

## 场景 3：深度导入流水线（三遍 Workflow）

### 【业务场景名称】

用户触发深度导入，系统自动执行三遍流水线：Scene 切分 → Entity 增量提取 → 剧情结构分析。全自动执行，中间不需要用户确认。完成后用户可手动修改结果。

### 【用户视角链路】

#### 正常流：启动深度导入

**Given** 用户已完成文件导入（场景 2），章节正文已入库
**When** 用户点击"启动深度导入"，选择章节范围（默认 1 ~ 最后一章）
**Then**
- 前端提交 `POST /api/imports/deep`，返回 `workflow_id`
- 前端显示三阶段进度条（Phase 1: 40% / Phase 2: 40% / Phase 3: 20%）
- `async_tasks` 表创建一条记录，type = `deep_import`，`status = "running"`，`phase = "scene_segmentation"`
- Workflow 自动推进，用户可关闭浏览器，后台继续执行

#### 正常流：Phase 1 — Scene 切分（并行）

**Given** workflow 进入 Phase 1
**When** 系统按 5 章/批 + 1 章 Overlap 拆分为 N 个子任务
**Then**
- N 个 `scene_segmentation` 子任务入队并行执行
- 每个子任务：读取 5 章正文 → LLM 切分 Scene → 输出 `scenes[]`（含 title / goal / core_conflict / emotional_beat / narrative_tag / scene_chunks）
- 子任务完成后写入 `scenes` 表
- Overlap 机制：第 i 批末尾 1 章与第 i+1 批首章重复，LLM 自主判断跨批 Scene 归属
- 异形章节处理：
  - 高密度设定章（非对话说明性文字 >75%）→ 降权为背景上下文
  - 缝合章（章内视角跳切/时间断层）→ 不强行切分，整章交给 LLM
  - 日常章（无 Delta 变更）→ 标记 `narrative_tag = "transition"`
- Phase 1 进度 = 40% × (已完成子任务数 / 总子任务数)

#### 正常流：Phase 2 — Entity 增量提取（串行）

**Given** Phase 1 全部完成，`scenes` 表已有数据
**When** Workflow 推进到 Phase 2
**Then**
- 单个 `entity_extraction` 任务入队执行
- 按 `scene_index` 顺序串行处理每个 Scene：
  1. 加载当前 Memory（前 N-1 个 Scene 已确认实体列表）
  2. LLM 调用 `entity_extraction.md` prompt，输入：Scene 正文 + Memory 上下文
  3. LLM 单次输出双产物：`entities[]` + `relations[]` + `delta_events[]`
  4. 去重检测（3 层：LLM 指定 link → Name Embedding → Content Embedding）
  5. 新实体直接入库 `core_entities`，`status = "canonical"`，`content_json._meta.auto_ingested = true`
  6. Delta 变更写入 `delta_log`（Scene 内坍缩后）
  7. 更新 Memory 累积上下文
  8. 触发 Memory 增量快照 `capture_snapshot(scene_index)`
- Phase 2 进度 = 40% × (已处理 Scene 数 / 总 Scene 数)
- 单 Scene LLM 调用失败 → 重试 3 次 → 仍失败则跳过该 Scene，记录 warning

#### 正常流：Phase 3 — 结构分析（单次）

**Given** Phase 2 全部完成
**When** Workflow 推进到 Phase 3
**Then**
- 单个 `structure_analysis` 任务入队执行
- 输入：全量 Scene 摘要 + 坍缩后 Delta 变更流（仅非 Valley/Transition Scene）+ 实体索引
- LLM 输出：`plot_threads[]` / `outline_arcs[]` / `foreshadowing_plans[]` / `reveal_plans[]`
- 四类产物分别写入对应表
- Phase 3 完成 → workflow 标记 `status = "done"`

#### 异常流：Phase 1 部分批次失败

**Given** Phase 1 某批 LLM 调用连续重试 3 次后仍失败
**When** 子任务标记 `failed`
**Then**
- Workflow 记录该批次失败
- 其他批次不受影响，继续完成
- Phase 1 完成后，Workflow 检测到失败子任务 → 降级策略：对该批 5 章做逐章 Scene 切分（单章 LLM 调用）
- 若逐章仍失败 → 机械分章（每章 = 1 Scene，`narrative_tag = "draft"`，不调用 LLM）

#### 异常流：用户关闭浏览器后重新打开

**Given** 深度导入正在后台执行
**When** 用户重新打开页面，进入该项目工作台
**Then**
- 前端自动查询当前 workflow 状态（`GET /api/tasks/{task_id}`）
- 显示当前 Phase 和进度条
- Phase 1：显示 "正在分析剧情结构... (Scene 切分: 15/30 批已完成)"
- Phase 2：显示 "正在提取世界对象... (第 12/38 个剧情段)"
- Phase 3：显示 "正在生成剧情线..."

#### 边界流：重复导入

**Given** 章节范围已有 Scene / Entity 数据
**When** 用户再次对相同章节范围启动深度导入
**Then**
- 系统检测到已有数据 → 弹出警告："第 1-50 章已有剧情结构和世界对象数据，重新导入将覆盖现有数据。是否继续？"
- 用户确认 → 旧数据标记为 deprecated（不硬删除），新数据写入

#### 边界流：小规模导入

**Given** 用户只导入了 3 章
**When** 启动深度导入
**Then**
- 章数不足 5 章 1 批 → 直接作为 1 个批次处理（不做 Overlap）
- Phase 2 串行处理 1-2 个 Scene
- 流程不变

### 【数据与状态契约】

| 层级 | Phase 1 | Phase 2 | Phase 3 |
|------|---------|---------|---------|
| 前端 UI | 三阶段进度条 | 进度条更新 | workflow 完成提示 |
| `async_tasks` 表 | INSERT, type=`deep_import`, phase=`scene_segmentation` | phase=`entity_extraction` | phase=`structure_analysis`, status=`done` |
| `async_tasks` 表 | N 个子任务 INSERT | 1 个任务 INSERT | 1 个任务 INSERT |
| `scenes` 表 | INSERT N 行 | — | — |
| `core_entities` 表 | — | INSERT 新实体, status=`canonical` | — |
| `characters` 表 | — | INSERT 新人物 | — |
| `entity_relations` 表 | — | INSERT 新关系 | — |
| `delta_log` 表 | — | INSERT 变更记录（Scene 内坍缩） | — |
| `memory_snapshots` 表 | — | 每个 Scene 完成时 INSERT | — |
| `plot_threads` 表 | — | — | INSERT 剧情线 |
| `outline_arcs` 表 | — | — | INSERT 篇章纲 |
| `foreshadowing_plans` 表 | — | — | INSERT 伏笔计划 |
| `reveal_plans` 表 | — | — | INSERT 揭示计划 |

## 场景 4：手工写作工作台

### 【业务场景名称】

用户在写作工作台中创作正文。左侧 Scene/Chapter 树导航，中间编辑器，右侧 Scene 卡面板。编辑器内容为前端暂存，点击"保存"后入库为正文版本。

### 【用户视角链路】

#### 正常流：进入工作台

**Given** 用户选择项目
**When** 进入工作台
**Then**
- URL 变为 `/workbench/:projectId/writing`
- 左侧导航栏显示核心创作环：📁写作 / 📋大纲 / 🌍世界（写作默认高亮）
- 左侧面板：Scene 树（一级节点）+ Chapter 折叠（二级节点）
  ```
  ├── Scene 1「初入江湖」(3章)
  │     ├── 第1章 穿越
  │     ├── 第2章 测试
  │     └── 第3章 启程
  ├── Scene 2「师门冲突」(4章)
  │     └── ...
  ```
- 中间编辑器：加载上次编辑位置，或默认最新 Scene 的第一个 Chapter
- 右侧面板：当前 Scene 卡（goal / core_conflict / emotional_beat / must_happen / must_not_happen / narrative_tag）
- Scene 卡数据来源于 outline 模块，写作工作台只读展示
- 用户可在右侧面板搜索角色/实体名 → 浮窗显示轻量详情（不跳转视图）

#### 正常流：撰写并保存正文

**Given** 用户在编辑器里写正文
**When** 用户点击"保存"（或 Ctrl+S）
**Then**
- 编辑器内容写入 `writing_drafts` 表，`version_number` 自增（同一 chapter_index 每次保存新版本）
- 自动入队 `publish_chapter` 后台任务：
  - Step 1：RAG 分块索引（含向量化），重试 3 次
  - Step 2：~~Memory 快照~~（已移除，改为 Scene 级别触发）
- 前端 Toast 提示："已保存（版本 N）"
- 如果当前 Chapter 未关联 Scene → 自动推断归属 Scene（根据 `scene_chunks` 反查），或追加到最近的 Scene

#### 正常流：断章操作

**Given** 用户在某 Scene 内写了 8000 字
**When** 用户选中一段文字，右键 → "在此处断章"
**Then**
- 编辑器内当前位置插入章节分隔
- 前端左侧树刷新：当前 Chapter 拆分为两个 Chapter
- `writing_drafts` 表：新增一个 Chapter 记录
- Scene 的 `scene_chunks` 更新：物理映射区间调整
- 不触发 RAG 索引（等用户保存时触发）

#### 正常流：创建新 Scene

**Given** 用户写完一段剧情，觉得该新建一个 Scene
**When** 用户在编辑器里选中一段文字，右键 → "创建新 Scene"
**Then**
- `scenes` 表新增一行，`scene_index` 自动递增，`source = "manual"`
- `scene_chunks` 记录物理映射：`[{"chapter_id": "uuid", "start_pos": 0, "end_pos": 2500}]`
- `narrative_tag` 默认为 `"draft"`（用户可后续在 outline 视图修改）
- 左侧树刷新，新 Scene 节点出现

#### 正常流：切换 Scene 导航

**Given** 用户在写作中
**When** 点击左侧 Scene 树中的另一个 Scene
**Then**
- 编辑器内容自动保存到 `viewStates`（前端暂存，不触发后端保存）
- 编辑器加载目标 Scene 的第一个 Chapter
- 右侧 Scene 卡面板刷新为目标 Scene 信息
- URL 不变（Scene 切换不更新路由）

#### 正常流：查看版本历史

**Given** 用户在某章写了好几版
**When** 用户点击"版本历史"
**Then**
- 弹窗列出该 Chapter 的所有版本：版本号 / 创建时间 / 字数
- 用户点击某个历史版本 → 弹窗内预览该版本内容
- 用户点击"恢复此版本" → 该版本内容写入编辑器（前端暂存），用户需点击"保存"才入库

#### 正常流：AI 章节卡提取

**Given** 用户写完了正文
**When** 用户点击"提取章节卡"（编辑器工具栏按钮）
**Then**
- 调用 LLM 从当前 Scene 正文中提取 Scene 卡字段
- 右侧 Scene 卡面板更新为 AI 提取结果
- 数据写入 `scenes` 表
- 用户可直接在右侧面板编辑 Scene 卡字段（编辑操作触发 outline 模块 API）

#### 异常流：网络中断

**Given** 用户正在写作
**When** 网络断开
**Then**
- 编辑器内容保留在 `viewStates`（前端 Proxy 响应式状态）
- "保存"按钮置灰，显示"离线"
- 网络恢复后，自动重新连接，提示"已恢复连接，点击保存同步最新内容"

#### 边界流：多 Tab 冲突

**Given** 用户在同一项目的两个浏览器 Tab 中编辑同一章
**When** Tab A 保存后，Tab B 再保存
**Then**
- Tab B 保存时检测到 `version_number` 冲突
- 后端返回 409 Conflict："该章节已被其他会话更新，请刷新后重新编辑"
- 前端提示用户，保留编辑器内容，用户可手动合并

#### 边界流：空内容保存

**Given** 用户编辑器内容为空
**When** 用户点击"保存"
**Then**
- 前端拦截，提示"正文内容为空，确定保存？"
- 用户确认 → 允许保存空内容（标记为占位章）

### 【数据与状态契约】

| 层级 | 变更 |
|------|------|
| 前端 UI | Scene 树刷新；编辑器内容切换到目标 Scene；右侧 Scene 卡面板更新；Toast 提示；进度条 |
| `writing_drafts` 表 | INSERT 新版本 (version_number 自增)；UPDATE 内容；DELETE 单版本/整章 |
| `scenes` 表 | INSERT 手动创建的 Scene；UPDATE Scene 卡字段；scene_chunks 更新断章映射 |
| `async_tasks` 表 | 保存时入队 `publish_chapter` (RAG 索引) |
| `rag_chunks` 表 | RAG 索引任务更新（替换旧 chunk） |

## 场景 5：世界对象管理

### 【业务场景名称】

用户管理小说世界中的核心对象（人物/地点/势力/物品/概念/事件等）、人物档案、实体关系、别名、版本回滚。AI 深度导入自动入库的对象均可手动编辑。不再使用候选池（AI 抽取直接入正史）。

### 【用户视角链路】

#### 正常流：浏览世界对象

**Given** 用户在 worldView（通过左侧导航栏 🌍世界 进入）
**When** 页面加载
**Then**
- 按实体类型分组展示（自由字符串，常用示例：character / location / faction / item / concept / event / rule / power_system / secret / legend / resource）
- 每个实体显示：名称 / 类型标签 / 重要性星标 / 摘要摘要
- 支持按 entity_type 和 status 过滤
- 分页列表，默认每页 20 条
- 支持搜索（名称 / 别名）

#### 正常流：手动创建实体

**Given** 用户在 worldView
**When** 用户点击"新建实体"，填写名称（必填）、类型（必选）、摘要、公开信息、隐藏真相、重要性
**Then**
- `core_entities` 表新增一行，`status = "canonical"`，`created_by = "manual"`
- 创建时自动调用去重检测
- 若去重检测到高度相似（similarity_score ≥ 0.90）的已有实体 → 前端提示"已存在相似实体《XXX》，确定创建新实体？"
- 用户确认 → 正常创建；用户取消 → 不创建

#### 正常流：编辑实体

**Given** 用户在 worldView 查看实体详情
**When** 用户修改实体字段（summary / public_info / hidden_truth / importance 等）
**Then**
- 结构化字段（importance / status / entity_type）→ 自动 Diff，变更写入 Delta Log（`source = "manual_edit"`）
- 文本字段（summary / public_info / hidden_truth）→ 直接更新 `core_entities` 表
- 文本字段首次从无到有（如 `hidden_truth: null → "xxx"`）→ 额外写入一条摘要式 Delta
- 文本字段异步归档到 Text Archive（带 `scene_index` 锚点）
- 人物档案特殊字段（personality / desire / fear / secret / weakness）→ 更新 `characters` 表

#### 正常流：管理别名

**Given** 用户在 entity 详情页
**When** 用户点击"添加别名"，输入别名字符串和类型（name / title / nickname / translation / abbreviation）
**Then**
- 别名写入 `core_entities.content_json.aliases` JSONB 字段
- 去重检查：别名不与已有别名重复（大小写不敏感）
- 别名不创建新实体行
- 前端实时显示别名标签列表，支持删除

#### 正常流：管理实体关系

**Given** 用户在 worldView 查看关系图谱
**When** 用户创建关系（source_id + target_id + relation_type + description）
**Then**
- `entity_relations` 表新增一行
- 校验：source_id ≠ target_id（不自环）
- 校验：source_id 和 target_id 均存在且属于同一 novel_id
- 去重：同 source_id + target_id + relation_type 不重复创建
- 前端图谱/列表刷新

#### 正常流：合并实体

**Given** 用户发现两个实体其实是同一个（如 AI 重复抽取的"张三"和"张老三"）
**When** 用户选择候选实体，点击"合并到目标实体"
**Then**
- 执行深度合并（9 步事务）：
  1. 排他锁（SELECT FOR UPDATE）锁定双方
  2. 别名继承（候选别名 → 目标 aliases）
  3. 关系迁移（候选的关系边重定向到目标，duplicate 边标记 deprecated）
  4. 自环清理（迁移产生的 source_id=target_id 边标记 deprecated）
  5. Character 同步（合并 character 扩展行数据）
  6. 文本字段合并（summary / public_info / hidden_truth 拼接）
  7. 冲突归档（content_json.meta.conflict_notes 记录不一致字段）
  8. 候选标记 `status = "merged"`
  9. 确保目标 `status = "canonical"`
- 全程在一个数据库事务内完成
- 前端：候选消失，目标实体信息刷新

#### 正常流：实体版本回滚

**Given** 用户误修改了实体
**When** 用户进入实体详情 → "版本历史" → 点击某个历史状态 → "回滚到此版本"
**Then**
- 结构化字段：通过 Delta Log 逆向重放到目标时间点，更新 `core_entities` 表
- 文本字段：从 Text Archive 查询 `scene_index <= 目标时 Scene` 的最新快照，覆盖当前值
- 回滚操作本身也生成一条 Delta（`source = "manual_rollback"`）
- 废弃 EntityRevision 表和 `entity_revisions` 表，统一走 Delta + Text Archive

#### 正常流：管理人物档案

**Given** 用户在 worldView 的 character 子标签
**When** 用户创建/编辑人物
**Then**
- `characters` 表操作：`entity_id` FK → `core_entities`
- 人物特有字段：role / personality / desire / fear / secret / weakness / stance / voice_style / appearance / current_goal
- 创建人物时自动在 `core_entities` 中创建对应行（`entity_type = "character"`）
- 人物知识边界（CharacterKnowledge）独立管理

#### 正常流：管理人物知识边界

**Given** 用户在 character 详情页
**When** 用户添加知识条目（目标实体 + knowledge_level + known_content）
**Then**
- `character_knowledge` 表新增一行
- knowledge_level：`unknown` / `rumor` / `partial` / `full` / `false_belief`
- `false_belief` 时必填 `misconception` 字段
- 知识变更同时写入 Delta Log（`category = "CHARACTER_KNOWLEDGE"`）
- `source_scene_index` 记录信息来源 Scene

#### 边界流：去重高性能场景

**Given** 导入结束后大量实体入库
**When** 去重检测触发
**Then**
- 词法初筛：pg_trgm `search_text` 虚拟列（覆盖 name + aliases），`top_k = 30`
- 语义初筛：pgvector cosine similarity，`top_k = 30`
- 合并候选集（词法 ∪ 语义的并集）
- 多路信号级联评分：rapidfuzz 形似 + pinyin 音似 + 子串包含 + 语义余弦 + 长度差异 + 行政区划前缀冲突 + trigram Jaccard
- 可选 LR 模型评分（`DEDUP_MODEL_ACTIVE` 环境变量控制），失败回退级联
- 三个阈值：`DEDUP_AUTO_MERGE_THRESHOLD`（自动合并）、`DEDUP_REVIEW_THRESHOLD`（需人工）、`DEDUP_DISCARD_THRESHOLD`（忽略）

### 【数据与状态契约】

| 层级 | 变更 |
|------|------|
| 前端 UI | 实体列表/详情/图谱刷新；抽屉浮窗；合并确认弹窗；版本历史弹窗 |
| `core_entities` 表 | INSERT / UPDATE / status=`merged`（合并场景）；别名内联在 JSONB |
| `characters` 表 | INSERT / UPDATE（人物特有字段） |
| `character_knowledge` 表 | INSERT / UPDATE / DELETE |
| `entity_relations` 表 | INSERT / UPDATE / status=`deprecated`（迁移去重） |
| `delta_log` 表 | INSERT（结构化字段变更 + 知识变更 + 回滚记录） |
| `text_archive` 表 | INSERT（长文本字段变更归档） |
| `entity_revisions` 表 | 废弃，不再写入 |

## 场景 6：大纲与结构管理

### 【业务场景名称】

用户在 outline 视图中管理剧情线、篇章纲、Scene 卡片、伏笔/揭示计划。支持手动增删改、拖拽排序、AI 结构生成。

### 【用户视角链路】

#### 正常流：浏览剧情结构

**Given** 用户在 outlineView（通过左侧导航栏 📋大纲 进入）
**When** 页面加载
**Then**
- 三个子标签：剧情线 / 篇章纲 / Scene（默认 Scene 标签）
- Scene 标签：时间线式排列，每个 Scene 卡片显示：scene_index / title / narrative_tag 标签 / goal 摘要 / 所属 Arc
- 剧情线标签：列表展示，线程类型（主线/支线/隐藏线）区分颜色
- 篇章纲标签：列表展示，按 arc_index 排序

#### 正常流：手动创建/编辑 Scene 卡

**Given** 用户在 outlineView 的 Scene 标签
**When** 用户点击"新建 Scene"或编辑已有 Scene 卡
**Then**
- 可编辑字段：title / goal / core_conflict / emotional_beat / must_happen / must_not_happen / narrative_tag
- narrative_tag 选项：`inciting_incident` / `rising_action` / `climax` / `valley` / `transition` / `hook` / `payoff`
- 手动创建的 Scene 默认 `narrative_tag = "draft"`
- 保存后 `scenes` 表更新
- 写作工作台右侧 Scene 卡面板自动刷新（keepAlive 保持挂载）

#### 正常流：拖拽调整 Scene 顺序

**Given** 用户在 outlineView 的 Scene 标签
**When** 用户拖拽 Scene 卡片到新位置
**Then**
- `scenes.scene_index` 批量重排
- 结构锁：如果用户正在 writingView 编辑该 Scene → 拖拽操作暂入队列，编辑器失焦后再应用
- 相关联的 `scene_chunks` 和 `chapter_ids` 无需调整（只改逻辑顺序，不改物理映射）

#### 正常流：AI 生成剧情结构

**Given** 用户在 outlineView
**When** 用户点击"AI 生成剧情结构"，选择章节范围
**Then**
- 调用 `POST /api/outline/generate`
- 内部流程：编译上下文 → LLM 调用 `structure_plot.md` prompt → 去重检测 → 持久化 plot_threads + outline_arcs
- 返回结果中的 extra_sections（伏笔/揭示/风险/问题）作为展示信息，不持久化（等第三遍流水线统一处理）
- 前端显示生成结果：新增 N 条剧情线，M 个篇章纲
- 若章节范围已有数据 → 警告提示

#### 正常流：管理伏笔与揭示

**Given** 用户在 outlineView 的伏笔标签
**When** 查看伏笔列表
**Then**
- 显示所有伏笔计划：名称 / 状态（planned → seeded → reinforced → paid_off） / 埋点 Scene / 计划收束 Scene
- 回收率统计：已回收 X / 总数 Y = Z%
- 高亮标记"已积压"伏笔（超过 10 个 Scene 未推进）
- 用户可手动创建/编辑/标记回收伏笔

#### 异常流：删 Scene 后的级联处理

**Given** 用户删除一个 Scene
**When** 确认删除
**Then**
- `scenes` 行标记 `status = "deprecated"`（软删除）
- 关联的 chapter_ids 中的 Chapter 不删除（正文保留），但脱钩
- 左侧 Scene 树刷新
- OutlineArc 的 `related_thread_ids` 如果引用了该 Scene 相关的线程 → 不级联修改

#### 边界流：Scene 与 Chapter 的 M:N 缝合

**Given** 第 5 章前 1500 字属于 Scene 1，后 1500 字属于 Scene 2
**When** 用户在编辑器里查看第 5 章
**Then**
- 通过 `scene_chunks` 精确定位：`[{"chapter_id": "ch5", "start_pos": 0, "end_pos": 1500}]` 属于 Scene 1
- 右侧 Scene 卡面板根据光标位置动态切换（光标在前 1500 字 → 显示 Scene 1；后 1500 字 → 显示 Scene 2）

### 【数据与状态契约】

| 层级 | 变更 |
|------|------|
| 前端 UI | outlineView 三标签列表刷新；Scene 卡片拖拽；写作工作台右侧面板联动 |
| `scenes` 表 | INSERT / UPDATE / 批量重排 scene_index / status=`deprecated` |
| `plot_threads` 表 | INSERT / UPDATE / DELETE |
| `outline_arcs` 表 | INSERT / UPDATE / DELETE |
| `foreshadowing_plans` 表 | INSERT / UPDATE / DELETE / status 状态流转 |
| `reveal_plans` 表 | INSERT / UPDATE / DELETE |

## 系统性开发计划

> **For agentic workers:** REQUIRED SUB-SKILL: 实施本计划时使用 `subagent-driven-development`（推荐）或 `executing-plans`，逐轮拆成独立 issue / PR。每一轮必须先补测试，再实现，再同步文档。

**目标**：让系统完整支持本文档 6 个用户场景、2 个后台能力附录，以及所有正常流、异常流、边界流。

**架构路线**：不引入新的前端框架、队列、图数据库或向量数据库。后端继续保持 8 个活跃模块边界：`project`、`imports`、`writing`、`outline`、`world`、`memory`、`rag`、`context`；跨模块只通过 `contracts.py` / `facade.py`。深度导入使用现有 PostgreSQL `async_tasks` 作为可恢复 workflow 载体，业务对象运行时删除优先状态化，项目永久删除例外。

**技术栈**：FastAPI、async SQLAlchemy、PostgreSQL/SQLite 测试、pgvector/pg_trgm、现有 LLM client、PostgreSQL-backed task queue、Vanilla JS SPA、Vitest、Playwright。

### 计划边界与优先级

本计划按“可跑通用户主路径”优先，而不是按模块平均推进。优先级顺序：

| 优先级 | 目标 | 判定标准 |
|--------|------|----------|
| P0 | 数据安全与主链路闭环 | 项目创建 → 文件导入 → 深度导入 → 写作 → 世界/大纲编辑可完整跑通 |
| P1 | Spec 明确的异常/边界流 | 不支持格式、超大文件、重复导入、多 Tab 冲突、软删除、novel_id 隔离均有测试 |
| P2 | 高价值可视化与效率功能 | 关系图、离线队列、实体详情面板、拖拽排序、右键编辑器操作 |
| P3 | 算法增强 | 批量并行 overlap、LR 去重模型、RAG 权重调优、复杂上下文裁剪优化 |

### R0：现状基线与契约收敛

- 明确 workflow 物理载体：继续用 `async_tasks` 承载 workflow 状态，不新增独立 workflow 表，除非后续 ADR 明确推翻。
- 建立场景覆盖矩阵：每个 Given-When-Then 至少关联一个后端测试、一个前端单测或一个 Playwright E2E。

### R2：深度导入 Workflow 可恢复闭环

**目标**：让场景 3 形成真实后台三阶段流水线，用户关闭浏览器后仍能查看进度和结果。

**后端任务**：
- `imports/workflow.py`：固化三阶段状态机：`scene_segmentation → entity_extraction → structure_analysis → done`。
- `imports/tasks.py`：任务运行期间持续写入 `task.progress` 与 `task.result`，前端轮询 `GET /api/tasks/{task_id}` 即可恢复显示。
- `imports/scene_segmentation.py`：实现 5 章/批 + 1 章 overlap；小于 5 章时单批无 overlap。
- `imports/scene_segmentation.py`：实现批次失败降级：批量重试 3 次 → 单章切分 → 机械分章。
- `imports/scene_entity_extraction.py`：按 `scene_index` 串行处理，单 Scene LLM 失败重试 3 次，失败后记录 warning 并跳过。
- `world`：深度导入创建实体、关系、delta 时强制 `novel_id` 一致，并标记 `auto_ingested`。
- `outline`：结构分析写入 `plot_threads`、`outline_arcs`、`foreshadowing_plans`、`reveal_plans`。
- 重复导入：检测目标章节范围已有 Scene / Entity / Plot 数据，未 `force=true` 时返回确认需求；确认后旧数据标记 `deprecated`，新数据写入。

**前端任务**：
- `writingView`：启动深度导入时选择章节范围。
- `writingView`：三阶段进度条显示 Phase 1/2/3 文案、降级 warning、失败 Scene 摘要。
- 页面重开：从最近的 running task 或保存的 `task_id` 恢复进度。

## 附录 A：后台自动功能（非用户直接操作）

### A1. RAG 混合检索

**触发时机**：保存正文章节时自动入队 `publish_chapter` → `rag_index_chapter` 任务

**物理切块参数**：
- 子块：600-800 字（700-900 tokens）
- Overlap：18%（约 100-150 字）
- 每块强制标注 `scene_id` 标签
- embedding 失败不阻塞（chunk 仍创建，`embedding_status = "failed"`）

**父子检索流水线**：
1. 用户 Query → 向量检索子块（精确命中细节）
2. 命中子块携带 `scene_id` → 自动捞出父块（Scene 元数据 + Delta 摘要）
3. 上下文拼装：子块原文 + Scene 结构摘要

**检索模式**：search / context / extraction，支持 entity_id / character_id / thread_id / chapter_index 精确过滤

### A2. 上下文编译（Scene-Centric Compiler v2）

**输入**：Scene + POV Character + Delta Stream + Foreshadowing

**输出**：`CompiledContext` IR（非 Markdown），经 `MarkdownRenderer` 转为 LLM Prompt

**9 段 Tier 输出**：

| Tier | 段 | 截断策略 |
|------|-----|----------|
| P0 | Writing Objective（任务） | 永不截断 |
| P0 | Scene Blueprint（Scene 卡） | 永不截断 |
| P1 | POV Knowledge（知识边界，伪装模式） | 最后截断 |
| P1 | Delta Timeline（自上一 Scene 后的世界线变化） | 最后截断 |
| P2 | Open Narrative Obligations（伏笔/揭示义务） | 按条截断 |
| P2 | Retrieval Evidence Packs（RAG 父子证据包） | 按包截断 |
| P3 | Style Assets（风格素材） | 优先截断 |
| P0 | Hard Constraints（约束引擎输出） | 永不截断 |
| P4 | Compiler Warnings（风险提示） | 最先截断 |

**双模式**：Writing 模式输出 Delta 摘要；Debug 模式输出全量 Snapshot

**ConstraintEngine**：动态生成硬约束，来源：
- StaticConstraints（代码写死）
- KnowledgeConstraints（CharacterKnowledge 三态：unknown→禁止 / restricted→限制 / misunderstood→按误判表现）
- ForeshadowingConstraints（status=seeded 且 payoff_scene > 当前 Scene → 禁止提前揭示）
- SceneConstraints（`must_not_happen` 直接列出）

**Tier 驱逐顺序**：P4 → P3 → P2（按条）→ P1（Delta 20→15→10）→ P0 不截断

## 附录 B：系统枚举与状态流转

### 状态流转

```
draft → candidate → canonical → deprecated
  ↓         ↓
ignored  conflicted
              ↓
          pending → running → done / failed / cancelled
```

原则：业务运行时优先状态化删除；项目永久删除和 demo 开发库重建可硬 DELETE。

### Delta Log category 枚举

```
CHARACTER_PROPERTY    — 角色属性变更 (HP/灵力/状态)
RELATIONSHIP          — 关系差分 (亲密度/阵营)
GLOBAL_PLOT_LINE      — 全局线索变更 (伏笔激活/揭示)
CHARACTER_KNOWLEDGE   — 角色知识边界变更
ENTITY_CREATED        — 新实体创建
ENTITY_UPDATED        — 实体字段更新
ENTITY_MERGED         — 实体合并
MANUAL_ROLLBACK       — 用户手动回滚
```

### narrative_tag 枚举

```
inciting_incident  — 激励事件（新改变的引发点）
rising_action      — 冲突升级
climax             — 阶段高潮
valley             — 低谷/过渡（不进第三遍输入）
transition         — 纯过渡/日常（不进第三遍输入）
hook               — 黄金三章钩子
payoff             — 爽点释放/打脸完成
draft              — 手动创建默认值
```

### 前端视图路由

```
/projects                        → projectView（独立布局，无侧边栏）
/workbench/:pid/writing          → writingView（默认落地页）
/workbench/:pid/outline          → outlineView
/workbench/:pid/world            → worldView
/workbench/:pid/context          → contextView（AI 工具层，可折叠）
/workbench/:pid/rag              → ragView（AI 工具层，可折叠）
/workbench/:pid/generate         → generateView（AI 工具层，可折叠）
```

核心创作环（writing/outline/world）KeepAlive 保持挂载。AI 工具层 Lazy Load。
跨视图跳转遵循"抽屉优先，跳转兜底"原则。
