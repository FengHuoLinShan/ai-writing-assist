# 作者编辑台内容评测包

`../editorial_cases.json` 是原创合成文本，四层覆盖明确连续性错误、多种合理解释、刻意留白和无主要问题。每段正文的 SHA-256 固定；改动样本须显式建立新版本，不覆盖旧结果。`evals/tests/test_editorial_dataset.py` 只验证样本完整性，不证明编辑质量。

## 零费用预检

在任何真实模型调用前，先核对：测试目标是专用可丢弃 PostgreSQL 库和演示副本；服务端编辑开关及项目授权范围明确；工作稿、编辑约定与排除项已冻结；账号连接可用但密钥不进入评测文件；提示词契约和 worker 注册通过；共享付费账本无未结清请求；作者另行给出本轮总费用上限与模型。缺少其中任何一项，不启动付费请求。公开只读演示源不得用于评测。

## 固定评分方式

逐条记录原始输出、引文核对、来源哈希、模型请求与用量、费用回执以及评阅者。按 0/1/2 分评六项：来源误读（0 为严重误读，2 为准确）、强意见误报、重大问题漏报、方向可执行性、作者声音尊重、改后判断。记录每项的原文依据与理由，不只给总分。强提醒精确率的分母是全部强提醒，只有独立人工标注后才可对照 ≥90% 目标；本轮 Codex 自评只能标为“单人 AI 评阅”，不得登记达标。

建议结果文件按 `case_id` 保存 `manifest_hash`、`brief_version`、`report`、`issues`、`requests`（模型、请求 ID、已知输入/输出 token、未知用量标记、费用回执）及 `scores`（六项分数、理由、评阅者）。正文样本本身留在版本库；含私人文本或密钥的运行资料不入库。
