# 作者编辑台内容评测包

`../editorial_cases.json` 是冻结的 v1 基线，保留四层原创合成样本和原有正文哈希。`../editorial_cases_v2.json` 是追加版本：逐字保留 v1 四例，并新增 19 例原创中文合成短章（每例 1–3 章），覆盖设计稿 S01–S17；S13 用早置/中置线索作位置对照，S14 用未获知/已获知角色知识作正反对照。样本不含用户稿件或已出版作品文本。版本、完整性和正文 SHA-256 由 `evals/tests/test_editorial_dataset.py` 验证。合成样本只用于发现回归风险，不证明小说审读质量。

## 固定评分方式

逐条记录原始输出、引文核对、来源哈希、模型请求与用量、未知用量标记、费用回执及评阅者。保留既有六项评分，并新增九项分项；每项 0/1/2。报告分布、均值、误报率及其分母、评阅者分歧；**不合成一个文学质量总分**。

| 评分项 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 来源误读（既有） | 严重误读 | 部分准确 | 准确且范围匹配 |
| 强意见误报（既有） | 多项无据强报 | 有少量误报 | 无明显无据强报 |
| 重大问题漏报（既有） | 漏掉主要问题 | 发现部分影响 | 抓住主要问题 |
| 方向可执行性（既有） | 不可执行或扩大改写 | 方向可用但不够聚焦 | 最小且可执行 |
| 作者声音尊重（既有） | 泛化作者表达 | 保留意思但削平声音 | 保留有意声音特征 |
| 改后判断（既有） | 错称已解决 | 判断部分准确 | 准确保留“仍在/可能改善/无法判断” |
| 有意形式误判 | 把开放、留白、不可靠叙述或无钩子写成确定错误 | 提及意图仍推必改 | 结合线索与范围描述效果，留作者决定 |
| 口味伪装错误 | 把审读者喜好报成缺陷 | 标为偏好但仍高优先或返修 | 默认不报；当前没有单独的风格偏好入口 |
| 理解与不喜欢区分 | 混成一个负面读者结论 | 有区分但证据不清 | 区分可理解性、歧义与审美反应 |
| 回看线索与替代解释 | 不找反证或把未读当不存在 | 找到一类但未核来源/覆盖 | 引用支持和反证，标清未审范围 |
| 最小修订与层级 | 大改、选区修结构问题或扩大范围 | 方向可用但路径不清 | 给最小方向；需取舍时才列备选，结构决策交作者 |
| 作者声音与过度修改 | 删除非目标语气、句法或信息 | 留住意思但明显泛化 | 只改 finding 所需范围并保留声音 |
| 意见聚合与处理负担 | 同根因拆成多卡或重复症状 | 部分聚合但仍需重复处置 | 每个根因一条主意见，多处依据折叠 |
| 伦理呈现边界 | 未请求即指控、泛化或宣称 clearance | 有具体依据但口吻仍裁断 | 当前产品不提供该入口；不生成未经请求的伦理观察 |
| 外部事实克制 | 无资料也断言史实 | 表示疑问但仍推理作答 | 标为待外部查证，不纳入小说内严重度 |

采纳率仅作行为指标，不单独代表质量。以后试跑还应记录每千字强意见数、全部意见数、唯一根因数、finding/根因比、unchecked 比例、跨章引用、作者处理动作、非目标改动比例、改后复核三态、耗时与掌控感。单人 AI 评阅不能登记为独立人工精确率；意见分歧应保留，不以多数票抹平解释差异。

## 后续对照试跑方案（尚未授权/运行）

- **样本**：v2 的全部 23 例：旧四例 `unique_key_contradiction`、`bell_ambiguous`、`intentional_blank`、`quiet_clean`；新增 S01–S12、S13 早/中位置对照、S14 未确认/已确认知识对照、S15–S17。每例 1–3 章；不混入真实小说文本。两条件使用相同 brief、正文哈希、章节范围与排除项。
- **对照**：baseline 提示词从 `origin/main` 起始 SHA `00d861283e34bdc0ef3f34ee5605c71e1f89c553` 冻结；candidate 提示词从本分支固定提交冻结。两臂使用同一代码、ReviewPass、方向校验规则、输入范围和执行环境，仅切换 system prompt，以免把提示词效果与单方向校验变化混在一起。固定同一 owner 已验证的连接、provider/model/effort/wrapper、样本版本；随机化运行顺序，盲化输出标签后交两名独立评阅者。当前产品没有提示词切换开关，未来须用隔离的评测运行方式完成，不增加产品入口。
- **请求数**：23 例 × 2 条件 = 46 次审读。每章最多 1 次读者层及 1 次作者层请求，三章以内合成最多再 1 次；上限估算 7 次/审读、合计不超过 322 次模型请求。代码中的 4 次请求上限是单次 worker execution 限额，resume 会重置，不能替代整次评测总预算。启动前仍需额外设置全局总请求停止条件；出错、用量未知或达到费用上限立即停止并核账。
- **评阅安排**：两名评阅者独立标注全部输出，评理解/偏好、引文与覆盖、问题强度、最小修订、意见聚合、声音保留及用户负担；先各自记录再讨论分歧。估计每份 10–15 分钟，共约 7.7–11.5 小时，另计分歧讨论；这是假设性人力估算，不是费用授权。真实目标读者招募另行估算。
- **费用与授权**：暂不提供美元预测，因为实际 owner 连接、计费口径和当日费率尚未核验。运行前需作者明确总费用上限与评阅者/费用安排，并单独授权真实模型试跑；其后核验项目要求的 `gpt-6-luna/max` 连接和当日费率，按请求量重新预算。本文件和通过的离线门禁均不构成该授权。

结果记录按 `case_id` 保存条件、`manifest_hash`、brief 版本、报告与 finding、请求模型/请求 ID/已知 token/未知用量标记/费用回执、分项分数与理由、评阅者及分歧。私人原文、密钥和含真实用户数据的原始输出不得进入版本库。
