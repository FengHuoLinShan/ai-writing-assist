# 作者编辑台内容评测包

`../editorial_cases.json` 是冻结的 v1 基线，`../editorial_cases_v2.json` 是保留 v1 四例后的扩展，二者的正文与哈希不改。v2 的 23 例中明确正例约 5 例，且 S01 与 v1 的唯一钥匙矛盾属于同一情节，因此 v3 增加对应正反例，并以伤势连续性错误替换 S01。`../editorial_cases_v3.json` 保留 v2 其余样本，新增客观记录冲突、解谜/复仇目标失配、连载承诺失配，以及主动主角/被动人物对照。每例含 1–3 个原创短章和评估分母标签；没有用户稿件或已出版作品文本。完整性和正文 SHA-256 由 `evals/tests/test_editorial_dataset.py` 验证。合成样本只用于发现回归风险，不证明小说审读质量。

## v3 正例、对照例与评分分母

`expected_result` 是评测 oracle，不得拼入送给模型的 brief 或正文：`report` 表示应指出具体失配，`no_report` 表示应保持沉默，`unchecked` 表示应明确留待核对。v3 共 29 例：11 个应报、17 个不应报、1 个应标未核对。新增正例分别对应客观记录矛盾、明示谜题承诺、复仇目标承诺、连载“下回揭晓”承诺及主角行动承诺；另有 1 个制度性被动角色对照。

两组须分别报告 `report` 正例召回（命中数 / 11）、`no_report` 对照误报率（误报数 / 17）及 `unchecked` 正确标记率（正确数 / 1），同时列出绝对计数。不要把不同分母合成单一质量分。

附平凡基线：永远返回零意见会得到 0/11 正例命中、11/11 漏报、0/17 对照误报；对唯一 `unchecked` 样本也得到 0/1 正确标记。它仅是分类下限参照，不是模型输出或文学质量总分。

## 固定评分方式

逐条记录原始输出、引文核对、来源哈希、模型请求与用量、未知用量标记、费用回执及评阅者。保留既有六项评分，并新增九项分项；每项 0/1/2。报告分布、均值、误报率及其分母、评阅者分歧；**不合成一个文学质量总分**。

| 评分项 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 来源误读（既有） | 严重误读 | 部分准确 | 准确且范围匹配 |
| 强意见误报（既有） | 多项无据强报 | 有少量误报 | 无明显无据强报 |
| 重大问题漏报（既有） | 漏掉主要问题 | 发现部分影响 | 抓住主要问题 |
| 方向可执行性（既有） | 不可执行或扩大改写 | 方向可用但不够聚焦 | 最小且可执行 |
| 作者声音尊重（既有） | 泛化作者表达 | 保留意思但削平声音 | 保留有意声音特征 |
| 改后判断（既有） | 错称已解决 | 判断部分准确 | 准确保留“仍在/可能改善/无法判断” |
| 有意形式误判 | 把开放、留白、不可靠叙述或无钩子写成确定错误 | 提及意图仍推必改 | 结合线索与范围描述效果，留作者决定 |
| 口味伪装错误 | 把审读者喜好报成缺陷 | 标为偏好但仍高优先或返修 | 默认不报；当前没有单独的风格偏好入口 |
| 理解与不喜欢区分 | 混成一个负面读者结论 | 有区分但证据不清 | 区分可理解性、歧义与审美反应 |
| 回看线索与替代解释 | 不找反证或把未读当不存在 | 找到一类但未核来源/覆盖 | 引用支持和反证，标清未审范围 |
| 最小修订与层级 | 大改、选区修结构问题或扩大范围 | 方向可用但路径不清 | 给最小方向；需取舍时才列备选，结构决策交作者 |
| 作者声音与过度修改 | 删除非目标语气、句法或信息 | 留住意思但明显泛化 | 只改 finding 所需范围并保留声音 |
| 意见聚合与处理负担 | 同根因拆成多卡或重复症状 | 部分聚合但仍需重复处置 | 每个根因一条主意见，多处依据折叠 |
| 伦理呈现边界 | 未请求即指控、泛化或宣称 clearance | 有具体依据但口吻仍裁断 | 当前产品不提供该入口；不生成未经请求的伦理观察 |
| 外部事实克制 | 无资料也断言史实 | 表示疑问但仍推理作答 | 标为待外部查证，不纳入小说内严重度 |

采纳率仅作行为指标，不单独代表质量。以后试跑还应记录每千字强意见数、全部意见数、唯一根因数、finding/根因比、unchecked 比例、跨章引用、作者处理动作、非目标改动比例、改后复核三态、耗时与掌控感。单人 AI 评阅不能登记为独立人工精确率；意见分歧应保留，不以多数票抹平解释差异。

盲评 JSONL 由 `evals.review.load_editorial_blind_reviews()` 导入校验，`case_id` 存随机盲号；每条包含全部 15 项分数与理由、输出引文、意见命中/误报标记和漏报说明。导入器不计算合成总分。

## v3 对照运行方案与上限

- **样本**：v3 全部 29 例；两条件使用相同 brief、正文哈希、章节范围、排除项和 worker 输入。`expected_result`、case ID、评测重点只供评测/盲评，不拼入模型输入。每例 1–3 章，均为原创合成文本。
- **对照**：baseline `_SYSTEM` 来自 `00d861283e34bdc0ef3f34ee5605c71e1f89c553`；candidate `_SYSTEM` 来自本分支固定提交 SHA（记录在任务笔记和运行账本）。两臂共用同一代码、ReviewPass、validator、连接快照和范围，只切换 system prompt。执行顺序随机化，结果用随机盲号另行映射。
- **全局硬上限**：29 例 × 2 条件 × 每审读最多 7 请求 = **406 次请求**。一例两组冒烟所用请求包含在 406 内，不在全量阶段重跑。worker 每次 execution 的 4 请求限额不能替代跨续跑总账；runner 在每次 provider 请求前持久化全局计数并拒绝超限。
- **运行器**：`evals/editorial_prompt_ab.py` 只接受本机 `codex_luna_runtime_test` PostgreSQL、本分支固定候选提交与仓库外私有输出路径。先以 S01 两组做 14 请求冒烟，确认两臂各 7 请求、来源覆盖和至少一条通过来源验证的意见；全部通过后再用同一私有账本跑剩余样本。
- **停止与恢复**：case 先写 `started`；同一 case 只执行一次。出错或用量未知时终止该 case，结果不确定时绝不重放；未知用量同时暂停后续付费调用并等待核账。同一外部依赖连续 3 次不可用则暂停全体。
- **盲评安排**：本轮不做评分。作者另开 Claude Sonnet 5.5 任务，按本文件 15 项量表逐项给理由/原文引用并标记 finding 命中、误报或漏报。盲号输出目录不含分组名、提示词、SHA 或分支名。
- **授权与费用**：本轮授权仅限 Codex `gpt-6-luna/max`，硬上限 406 次请求；runner 每次 provider 请求前核验 owner Codex 连接、provider/model/effort 和 adapter。配置不符、出错、未知用量或达到上限时停止，不回退模型。实际费用只按可用 usage/账单回执登记，不补造估算值。

结果记录按 `case_id` 保存条件、`manifest_hash`、brief 版本、报告与 finding、请求 ID、已知 token、未知用量标记、费用回执、分项分数和评阅者。原始输出及盲号映射只在仓库外私有目录保存。
