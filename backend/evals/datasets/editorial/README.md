# 作者编辑台内容评测包

`../editorial_cases.json`、`../editorial_cases_v2.json`、`../editorial_cases_v3.json` 均为冻结历史版本，正文、完整文件和哈希不改。`../editorial_cases_v4.json` 保留 v3 全部 29 例，只修复 S09 的出题说明和 S18 的交班规则歧义，再新增三组跨章正例/已解释原因对照。35 例均为原创合成文本，每例 1–3 章，不含用户稿件或已出版作品文本。正文 SHA-256 与历史版本哈希由 `evals/tests/test_editorial_dataset.py` 验证。合成样本只用于发现回归风险，不证明小说审读质量。

## v4 正例、对照例与评分分母

`expected_result` 是评测 oracle，不得拼入送给模型的 brief 或正文：`report` 表示应指出具体失配，`no_report` 表示应保持沉默，`unchecked` 表示应明确留待核对。v4 共 35 例：14 个应报、20 个不应报、1 个应标未核对。新增正例覆盖跨章时间线、身份关系、物件状态；各自配有正文已说明改期、收养关系或修复过程的对照。

两组分别报告正例命中 case 数 / 14、对照误报 case 数 / 20 和误报意见条数、`unchecked` 正确数 / 1，并附零意见基线。另单列三条新增跨章正例；再与 `unique_key_contradiction`、`S02_objective_record_conflict` 合并报告五条跨章重点样本。另单列三条“正文已交代原因”对照。不要把分母合成单一质量分。

零意见基线为：0/14 正例命中、14/14 漏报、0/20 对照误报、0/1 `unchecked` 正确。它仅是分类参照，不是模型输出或文学质量总分。

## 固定评分方式

盲评沿用 15 项评分 schema；每项取 0、1、2 或适用时填 `null`，并给出理由和输出原文引句。评阅者须读完每份输出后逐项独立判断；严禁用脚本为没有逐项判断的条目填默认分或默认理由。作者可以对同一盲评包复评一次，保留两轮原始评分。

| 评分项 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 来源误读 | 严重误读 | 部分准确 | 准确且范围匹配 |
| 强意见误报 | 多项无据强报 | 有少量误报 | 无明显无据强报 |
| 重大问题漏报 | 漏掉主要问题 | 发现部分影响 | 抓住主要问题 |
| 方向可执行性 | 不可执行或扩大改写 | 方向可用但不够聚焦 | 最小且可执行 |
| 作者声音尊重 | 泛化作者表达 | 保留意思但削平声音 | 保留有意声音特征 |
| 改后判断 | 错称已解决 | 判断部分准确 | 准确保留“仍在/可能改善/无法判断” |
| 有意形式误判 | 把开放、留白、不可靠叙述或无钩子写成确定错误 | 提及意图仍推必改 | 结合线索与范围描述效果，留作者决定 |
| 口味伪装错误 | 把审读者喜好报成缺陷 | 标为偏好但仍高优先或返修 | 默认不报；当前没有单独的风格偏好入口 |
| 理解与不喜欢区分 | 混成一个负面读者结论 | 有区分但证据不清 | 区分可理解性、歧义与审美反应 |
| 回看线索与替代解释 | 不找反证或把未读当不存在 | 找到一类但未核来源/覆盖 | 引用支持和反证，标清未审范围 |
| 最小修订与层级 | 大改、选区修结构问题或扩大范围 | 方向可用但路径不清 | 给最小方向；需取舍时才列备选，结构决策交作者 |
| 作者声音与过度修改 | 删除非目标语气、句法或信息 | 留住意思但明显泛化 | 只改 finding 所需范围并保留声音 |
| 意见聚合与处理负担 | 同根因拆成多卡或重复症状 | 部分聚合但仍需重复处置 | 每个根因一条主意见，多处依据折叠 |
| 伦理呈现边界 | 未请求即指控、泛化或宣称 clearance | 有具体依据但口吻仍裁断 | 当前产品不提供该入口；不生成未经请求的伦理观察 |
| 外部事实克制 | 无资料也断言史实 | 表示疑问但仍推理作答 | 标为待外部查证，不纳入小说内严重度 |

依赖意见的五项（方向可执行性、作者声音尊重、最小修订与层级、作者声音与过度修改、意见聚合与处理负担）在空报告中填 `null`；有意见时评分。改后判断仅适用于修订稿复核，本批不是修订稿复核，填 `null`。其他九项仍须读后逐项评分，但**15 项评分均值只在有意见的输出上计算**；空报告用 case 结果描述，不纳入均值，避免模板化分数影响结论。`null` 不计入分布和均值。

采纳率仅作行为指标，不单独代表质量。单名 AI 评阅者不是独立人工精确率。盲评 JSONL 由 `evals.review.load_editorial_blind_reviews()` 校验；`case_id` 为随机盲号，每个 finding 有独立命中/误报判断，case 结果另记漏报或未核对判断。导入器不计算合成总分。

## 揭盲前固定的汇总口径

以下口径在任何本轮真实模型调用和盲评分前确定，揭盲后不再调整：

1. **主指标**按 A、B 组分别报告：`report` 正例命中 / 14；`no_report` 误报 case / 20 及误报意见总条数；`unchecked` 正确 / 1；正例中被判为误报的意见条数；并列零意见基线。
2. **跨章重点**分别报告新增的三条跨章正例，并报告五条跨章重点合计（新增三例加 `unique_key_contradiction`、`S02_objective_record_conflict`）。另报告三条“正文已交代原因”对照中被误报为矛盾的 case 数与意见条数。
3. **15 项评分**每组逐项报告 0/1/2 计数、非空样本数和均值；均值仅使用有意见的输出，`null` 不计入。不合成总分，不以单项均值代替主指标。
4. **配对结果**列出每个盲号对应 case 的 A/B 结果及结论不同项。若作者复评一次，还须报告两轮 `case_outcome` 一致数 / 总 case 数、finding 分类一致数 / 总 finding 对数、每个评分项的分数完全一致率，以及每项评分中相同理由文本数 / 两轮配对非 `null` 项数。
5. **固定局限**：B 组输出可能带前文章节依据，盲评者可能据此推测分组；单名 AI 评阅者；样本是微型原创合成文本；`unchecked` 只有 1 例。不得事后调整采纳门槛。

## 采纳门槛

只有 B 相对 A 同时满足以下条件才采纳账本：

- 正例命中至少 12/14；
- 对照误报 case 不比 A 多出 1 例以上；
- 三条“正文已交代原因”对照中，被误报为矛盾的不超过 1 例。

未满足时如实报告，保留失败结果，不调整门槛。

## A/B 运行计划与安全边界

- **样本**：v4 全部 35 例；相同 brief、正文哈希、章节范围、排除项和执行 worker。`expected_result`、case ID、评测重点只供评测/盲评，不拼入模型输入。每份 blind 文件包含该例全部章节。
- **A 组**：系统提示词取提交 `4133ff93b6e3c27e59e967831dbe4d4322f329a2`；账本关闭。`ReviewPass` schema 仍含 `carry_forward`，但 A worker 忽略该字段，这是已知局限。
- **B 组**：系统提示词与账本均取固定提交 `346ac97e6af8167a5f23f766dc25d4a927b93676`。两组共用本分支同一 worker、validator、输入范围和执行环境，只通过现有 `db.info` 内部 seam 切换账本。提示词和账本 SHA 写入私有 manifest 与任务笔记。
- **全局硬上限**：35 例 × 2 组 × 每审读最多 7 次 = **490 次请求**，冒烟和中止运行中已预留的请求都计入。重启运行须把前一账本的预留数作为 budget offset，并把旧账本 manifest/state 哈希写入新 manifest；旧输出不复用。当前 81 章均短于 12000 字，每章最多一次读者调用和一次编辑调用，最多 8 个合并节点只需一次合并，因此本数据集的新一轮最多 388 次请求。worker 单次执行的 4 次请求限额不能替代跨续跑总账；每次 provider 请求前先持久化 reservation，账本计数与回执必须一致。
- **冒烟**：先用 `unique_key_contradiction` 跑 A/B，总计不超过 14 次请求。确认每组计数与回执匹配、B 原始记录包含已核验的前文账本条目，且至少一条前文依据通过 finding validator 后再跑全量。
- **并行与停止**：两组及不同 case 的执行顺序先随机打乱，单进程最多并行两个审读；每个审读使用独立数据库会话，章节/分段仍顺序执行。输出目录用独占文件锁阻止第二个进程同时消费同一账本；reserve 在事件循环内同步计数。case 先持久化 `started`；同一 case 不重放。出错或用量未知时停止对应 case；用量未知时停止新的模型请求。相同外部依赖连续 3 次不可用即暂停全局；暂停前已预留的并行请求仍计费并记账。
- **模型与数据库**：只用 Codex `gpt-6-luna/max`。运行开始前重新核验 owner 已验证连接、`open_project_llm_client()` 的 provider/model/effort 与 wrapper，以及本机专用 PostgreSQL `codex_luna_runtime_test`；不符即停，不回退其他模型。独立连接验证的 provider 请求单独记账，本轮不发送单独的验证生成请求，manifest/summary 记录为 0。
- **权限与交付**：原始请求/输出及映射在仓库外 0700 私有目录，文件 0600；blind 包不含 A/B 名称、SHA 或分支名，映射存放在 `blind/` 之外。作者另开 Claude Sonnet 5.5 盲评，本轮不评分、不揭盲。不得推送、开 PR、合并或部署。
