# 全链路前端→后端可测试流程验证 Spec

## Why

项目已有 101 个 E2E 测试全部通过，但对照 `docs/前端到后端可测试流程清单.md` 的 84 条用户流程，仍有大量流程缺少 E2E 覆盖。部分 API 端点虽有 CRUD 测试，但缺少"前端用户操作视角"的端到端验证（如：点击"提取档案"后前端正确轮询并显示 AI 建议、点击"保存并分析"后草稿落库且 analysis_status 正确返回）。需要系统性补齐缺失的 E2E 测试，确保从前端用户角度每个功能都能正常使用。

## What Changes

- 补齐流程清单中缺失的 E2E 测试（约 30+ 条），按模块分批实施
- 修复测试中发现的 API bug（如端点返回格式不匹配前端期望）
- 跳过需要用户手动确认的流程（如删除项目、合并候选），在测试中标记 `@pytest.mark.skip(reason="需手动确认")`

## Impact

- Affected code: `backend/tests/e2e/test_*.py`、可能涉及 `backend/modules/*/api.py` 的 bug 修复
- Affected specs: 无 breaking change

## ADDED Requirements

### Requirement: E2E 测试覆盖全部用户可见流程

系统 SHALL 通过 E2E 测试覆盖流程清单中所有非跳过的用户流程，确保从前端用户角度每个功能都能正常使用。

#### Scenario: 用户点击"确认候选"后候选晋升为正史实体
- **WHEN** 用户对候选执行 accept 操作
- **THEN** 候选状态变为 accepted，对应的正史实体被创建

#### Scenario: 用户点击"保存并分析"后草稿落库且返回 analysis_status
- **WHEN** 用户提交 save-and-analyze 请求
- **THEN** 草稿安全入库，返回 draft_id 和 analysis_status

#### Scenario: 用户点击"提取档案"后前端轮询并显示 AI 建议
- **WHEN** 用户提交 character extract 任务
- **THEN** 任务创建成功，轮询返回完成状态，character 的 ai_suggestions 字段被更新

#### Scenario: 用户查看地点详情
- **WHEN** 用户请求地点详情
- **THEN** 返回地点完整信息含 world_entity 关联数据

#### Scenario: 用户查询路径可达性
- **WHEN** 用户提交路径计算请求
- **THEN** 返回 RouteCalculationResult 含 is_reachable 和路径信息

#### Scenario: 用户查看地点势力和人物
- **WHEN** 用户请求地点势力/人物列表
- **THEN** 返回该地点关联的势力关系和当前所在人物

#### Scenario: 用户管理人物知识
- **WHEN** 用户添加/编辑/删除人物知识
- **THEN** 知识 CRUD 操作正确执行

#### Scenario: 用户管理记忆提案
- **WHEN** 用户确认/拒绝记忆提案
- **THEN** 提案状态变更，确认时执行多路分发

#### Scenario: 用户运行复查
- **WHEN** 用户提交复查请求
- **THEN** 返回复查报告

#### Scenario: 用户获取章节草稿
- **WHEN** 用户请求章节草稿和章节卡
- **THEN** 返回最新草稿内容和对应章节卡信息
