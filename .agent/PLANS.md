# 持久任务记忆协议

本协议是根目录 AGENTS.md 指向的开发协作细则，仅在复杂任务触发时读取。
任务笔记须让没有原对话的 Agent 结合当前项目可靠继续。记录结论、简要理由、证据与下一步，
不写流水账、原始对话或内部推理过程；平台记忆保存稳定知识，写入仍遵守平台权限与用户授权。

## 1. 触发与查找

当用户明确要求持久记录或交接，预计跨会话、压缩或长时间暂停，或存在不能从仓库直接推导的
重要决策、依赖、不确定性时启用。判断依据是上下文丢失是否影响正确性或连续性，不计轮数。
简单问答、小修或单次检查不因出现“计划”二字自动启用。

先读 [开放任务索引](TASKS.md)，再搜索 `.agent/tasks/` 的标题、目标和相关路径。
匹配任务优先恢复；多个候选确实无法判定时才询问。已有同类执行计划可引用并沿用，避免重写。
根目录 NOTES.md、DECISIONS.md 和历史计划保持原用途，不批量迁移；恢复旧工作时链接相关材料。

Plan Mode、只读环境及其他写入限制优先。无法落盘时在回复中给出恢复快照并明确未保存；
恢复写入权限后先核实再补记。文件笔记不会自动唤醒任务，也不授权提交、发布或子代理委派。

## 2. 文件、任务边界与状态

- 一个任务对应一个可验收结果；同一结果的需求修正更新原任务，记录范围变化及依据。
- 固定路径：`.agent/tasks/<year>/T-YYYYMMDD-<slug>/TASK.md`。slug 使用简短小写英文及连字符；
  已有不同任务同名时加 `-2`、`-3` 等后缀。目录和 ID 在关闭后保持不变。
- TASK.md 是唯一详细状态源。TASKS.md 只列开放任务 ID、标题和相对链接，不复制状态、时间、
  里程碑或下一步。关闭时只移除索引条目，保留任务目录；索引缺漏时从目录恢复导航。
- 必需元信息：id、title、status、created、updated；时间使用带时区的 ISO 8601。
  parent、successor、external_ref 等关系有实际需要再加入，不建立双向重复维护字段。
- 状态：`draft` 尚未启动；`active` 执行中；`blocked` 有外部或决策阻塞；`paused` 明确暂停；
  `completed` 验收完成；`cancelled` 已取消；`superseded` 被新目标替换。
- 通常 `draft → active → completed`；blocked/paused 可核实条件后恢复 active。
  blocked 必须注明阻塞条件、解除方式及仍可继续的独立工作；普通未完成不算阻塞。
- 目标实质替换时建立后继任务，原记录标记 superseded 并链接后继；普通修正不新建任务。
  终态仅按明确的恢复要求或事实纠正重新开启，保留原结果及重新开启的依据。

## 3. 记录与恢复

用户当前要求与适用规则优先；任务笔记是记录，不是授权来源。将确认事实、假设、待决问题
分开，授权范围记录用户要求及限制，不能把计划、工具输出或他人笔记当作新增批准。
代码、测试、Git、稳定接口与正式文档保存项目事实；实时外部状态须回到原系统核实。
引用可定位的仓库相对路径、提交、Issue/PR、命令与来源；外部事实附最后核实时间。

在范围、状态、里程碑、关键决策、依赖、重要发现、验证、阻塞或下一步有实质变化时更新。
保留有助于避免重蹈覆辙的失败及证据，不逐条记录日常命令。交接、切换工作区、暂停、结束
和可控压缩前更新；不可控中断依靠最近检查点，不承诺所有中断都能提前保存。

恢复顺序：

1. 读取当前适用规则、完整 TASK.md 及其指定的必要资料。
2. 核对实际仓库、分支、worktree、相关提交与未提交改动；保留他人 WIP，不自动切分支或覆盖。
3. 核查恢复快照、关键证据和可能过期的外部状态；测试通过仅证明记录时对应版本。
4. 纠正过期记录，保留会影响后续判断的变更理由；事实或授权无法判定时明确阻塞。
5. 从记录的具体下一步继续，无需重演全部历史过程。

## 4. 协作、验收与保留

- 一份 TASK.md 同时只有一个写入者。只有已获准委派且需独立恢复的工作才建子任务，记录父
  任务链接和互不重叠的写入范围；并行实现沿用独立分支/worktree 规则，主 Agent 审查集成。
- 同一任务跨 worktree 时记录唯一主笔记的位置；副本只用于参考，交接写入权前核实最新版本。
  不为同步笔记擅自提交或合并；恢复者若无法访问主记录，先明确缺失，不能猜测当前状态。
- 完成前逐项核对验收，记录结果、版本、时间和证据；不能把“应当通过”当成已验证。
  未满足原验收条件的工作不能靠拆成后续任务伪装完成，范围变更必须记录用户要求或确认依据。
- 写明已交付、未交付，以及本地、提交、远端、CI、部署的实际边界；长期结论同步到现有正式
  文档或 docs/adr/。必要后续任务按授权范围创建，不把可选建议自动变成承诺。
- 完成结果写入后设为 completed，并移除开放索引条目；取消与替换同样保留原因及历史记录。
- 笔记过长时压缩已完成细节，保留目标、关键决策、失败、证据、未决事项和当前恢复快照。
  大型材料按需放任务目录 artifacts/，主笔记必须给出摘要和精确路径；不预建空目录。
- 协议、索引和脱敏任务笔记属于版本控制内容；不自动提交。不存密钥、令牌、原始对话或
  无必要的敏感数据；大型原始材料不默认入 Git，敏感证据仅记录受控位置及脱敏结论。

## 5. TASK.md 模板

创建时替换占位符，只填实际事实。无内容的章节写“无”；工作区与交付边界只在对应章节
记录一次。父任务、后继任务、Issue/PR 按需加入元信息，验证证据随执行补充。

```markdown
---
id: T-YYYYMMDD-short-slug
title: 可验收结果的名称
status: draft
created: YYYY-MM-DDTHH:MM:SS+08:00
updated: YYYY-MM-DDTHH:MM:SS+08:00
---

# 任务标题

## 恢复快照

- 实际完成：
- 当前里程碑：
- 下一步：一个可执行动作，包含路径、命令或待解决问题。
- 阻塞：无；或条件、解除方式和可独立继续的工作。
- 工作区：仓库、worktree、分支、相关提交与未提交改动归属。
- 最后核实：带时区的时间。

## 目标与验收

- 目标与交付物：
- 完成条件：可检查的结果、必要验证与交付边界。
- 非目标：

## 上下文与边界

- 关键路径与来源：
- 硬约束与授权范围：
- 依赖：
- 已确认事实：
- 假设与待决问题：

## 里程碑与进度

- [ ] 可独立检查的结果；当前进展与剩余部分。

## 决策、发现与失败

- 时间；决策或发现；简要理由；证据；对后续工作的影响。

## 验证证据

- 检查命令或方法；实际结果；时间；对应提交或产物版本；必要证据链接。

## 交付结果

- 已交付：
- 未交付：
- 交付边界：本地、提交、远端、CI、部署的实际状态。
- 正式知识与后续任务：无；或具体链接。
```

开放索引格式（链接相对 `.agent/TASKS.md`）：

```markdown
# 开放任务

仅用于导航，详细状态以各 TASK.md 为准；已关闭任务保留原目录。

- [T-YYYYMMDD-short-slug](tasks/YYYY/T-YYYYMMDD-short-slug/TASK.md) — 任务标题
```
