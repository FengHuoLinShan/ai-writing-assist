六个原阻断案例在最终冻结版本全部完成，真无解控制仍返回无解。原跨层直接依赖缺陷已修：首波一次规划的七步路线全部完成；最终波另遇原生模型格式错误，被安全拒绝并完整保留，不能宣称自主跨层可靠性验收通过。功能保持默认关闭，ADR-0042 仍为 Proposed。

## 根因与修复

| 原案例 | 原因 | 修复与保留边界 |
| --- | --- | --- |
| b2-bridge | 首次候选使用未获知身份/联系信息，应阻断；返修审查另把补桥单元要求成重复诊断缺口 | 审查绑定真实 system/schema；新增条件不授权人物立即知情，仍审行动因果 |
| m2-goal | 工作流 mode=start 被误当输出 mode，审查缺少当前导向合同；首波还暴露“缺条件就无解”的提示过严 | 区分生命周期与结果模式；先检查有依据且获允许的行动能否建立条件，未证实条件不当作已发生；无支持路径/固定约束冲突仍可无解 |
| m2-voices / private | 单目标生成被要求一次答全部目标；首波 private 的第二单元又因导演删除服务端空投影槽而在生成前阻断 | 单元仅交当前目标；候选没有正式投影时不构造空槽，有内容投影和所有实际发出的知识/控制包仍必须保留 |
| m2-spatial-missing | 专用诊断禁止对白、允许未知，审查却按能力族名称要求非空对白 | 用真实单元指令/schema核验；缺尺寸继续未知，不补造参数 |
| m3-full-unknown | 完整作者目标被强求到单张有限知情表演卡上；初始静态知识不足以描述后续正式观察 | 单卡按当前本人知识包，统筹按本轮全部素材/观察；原确认投影、隐藏守卫与 Scene 截止不变 |
| Goal 跨层 | 参数引用间接前序结果，却没声明该直接来源的 depends_on；提示/schema未披露这一严格要求 | 补直接依赖合同说明；验证器不改，不自动补边或重规划 |

共享返修缺陷：原来只收到问题类型，缺少本单元候选和安全定位。现在仅回传自身 candidate、类型/级别、能在该 candidate 内验证的 excerpt；不回传审查 message/source_key、隐藏资料或合并的他人/锁定内容。完整起点仍作为事实冲突、禁令与知识上限的审查背景，不作为单元交付清单。

规范审查另发现旧来源指纹漂移：对持久 `EventOutputV1` 归一化顶层无解字段，会让合法旧结果在数据库未变时失效。归一化现仅在新生成的 `GeneratedEventOutputV1` 解析入口执行；旧读取、编辑、包封与指纹算法不变。旧顶层、双处相同、旧合法双处冲突载荷均保持原序列化，既有回执可重验，真实来源/确认变化仍拒绝。
