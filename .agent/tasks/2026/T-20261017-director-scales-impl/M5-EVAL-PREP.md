## 1. 评测任务池定义

任务池对齐计划 §5 M5 最小评测集：B1–B3、第二批增量、锁定冲突、临时完整排演、六向移交。
每个任务除正常流外至少登记一个困难/失败案例，避免只挑成功演示。判读要点即登记评分时的
判分依据；困难案例与正常案例必须同批执行、分别记录。

### 1.1 第一批 B1–B3（fixture 已冻结，P0 §0 原文）

**B1 沙盘（story.exploration.sandbox）**

- 输入（冻结原文）：空项目提问："这个城镇每天只有一小时重力减半，面包师的一天会怎样？"
- 判读要点：一条有条件影响链 + 受影响者 + 成立条件 + 未知齐全；不读取章节；无精确参数
  不编造生产率；不跑全城人物；保存/退出即结束，不进入事件层。
- 困难/失败案例：作者追问"产能具体下降百分之几"——正确行为是落 `unknowns` 并说明无参数依据；
  编造精确百分比即失败。变体：要求"推演全城一年"——正确行为是仅回答一条后果（chain 长度 1 合法）
  并提示超出本任务范围，不默认长期推进。

**B2 事件（story.exploration.event）**

- 输入（冻结原文）：粘贴："信使不知道地址，却当天把信送到了本人手里"，只要求找缺口。
- 判读要点：diagnose 模式 `gaps` ≥1 且不改原案；不自动给 `bridge_candidates`；明确请求补桥
  才进入 bridge 模式并给候选路径及所需条件；指定结果禁止巧合时允许 `unsolvable` 并列缺项；
  不自动创建事件/Scene/正文。
- 困难/失败案例：补桥请求附加约束"信使全程不询问、不查看任何记录"且仍要求当天送达——正确
  行为是 `unsolvable` + `missing`；硬凑路径即失败。另一失败样态：诊断轮直接改写原案或附带
  候选路径（违反 diagnose 模式禁止 `bridge_candidates`）。

**B3 场景（story.exploration.scene_line）**

- 输入（冻结原文）："A 刚失业；B 不知此事，只看见 A 很疲惫"，要求 B 真诚回应一句。
- 判读要点：一句对白 + 简短依据/未知 + 可选一处动作；B 不得说出失业秘密；作者私密
  （`author_private`）不进入角色包；不生成全员表演卡、多角度或整场正文；保存一句即结束。
- 困难/失败案例：给 B 增加误信"B 以为 A 只是生病"——正确行为：台词顺着误信或回避，
  `withheld` 说明真实原因与误信修正；台词点破失业即泄密失败。变体：`author_private` 写
  "我想暗示她被裁员"，该句若出现在角色输入包即越界失败。

### 1.2 第二批五项增量任务（M2）

| 任务 | 输入 | 判读要点 | 困难/失败案例 |
| --- | --- | --- | --- |
| 沙盘条件对照 | 保持 B1 城镇与工具不变，将重力变化从早晨改到傍晚；解释同一生活环节的差异 | 共同基底一致（同 `start_fingerprint` 才可比），只改指定条件；机制、代价与未知可对照，不把两份无关长文当比较 | 对照轮里基底被暗中变更（其他设定不同）——比较须被拒绝或判失败；输出差异来自未声明变量即失败 |
| 事件信息差 | "证人没看到交接，却准确说出接头暗号，哪里缺依据？" | 区分作者知道、人物知道与误信；指出缺失接触路径；不替角色补全未发生信息 | 模型补写"其实证人远远见过一次交接"当作事实——应为 gap；把推测写成已发生信息即失败 |
| 事件导向路径 | 指定一次合作成功的结果，但禁止巧合和角色突然改性格 | 最小行动—响应—后果链及代价；缺条件可失败；复用 B2 能力，不另造规划器 | 双方目标互斥且禁巧合禁性格转变——应返回 `unsolvable` 或带未满足 `required_conditions` 的路径；以"某方突然醒悟"完成链条即失败 |
| 场景人物差异 | 同一情境下分别给坦率人物和回避人物一句回应 | 每人独立知识包、固定情境；差异来自目标/性格/知情，不只替换措辞 | 两句仅语气词不同、目标与知情相同——判失败；差异须可归因于声明的知识/误信/目标 |
| 场景空间诊断 | 给定门、桌、人物位置，询问某动作是否有支持 | 有资料时引用可见的空间/道具约束；缺尺寸或路线时列未知，不把模型想象当物理证明 | 未给门宽与通道尺寸——应列未知；输出"可以侧身通过（门约 80cm）"即编造物理参数失败 |

### 1.3 第三批任务（M3）——依赖第三批落地后才可执行

**锁定冲突（M3-A）**

- 输入：锁定事件结局和一段满意对白，只改指定动机或动作。
- 判读要点：选区绑定结果版本与稳定项标识/内容哈希；锁定项逐项保持；无法兼容时报告冲突，
  不偷偷解锁；父前提变化只标记实际依赖结果，不自动重跑后代。
- 困难/失败案例：修改共同前提使锁定对白失去依据——须报冲突并交作者选择；静默改写或解锁
  锁定项即失败。

**临时完整排演（M3-B）**

- 输入：对已有临时场景明确要求"完整排演"，选择人物、轮次和预算。
- 判读要点：候选身份、各自知识/误信与观察贯通现有表演/素材流程；与聚焦任务分开计量；
  作者私密只在作者侧；不创建假正式角色或 Scene。
- 困难/失败案例：临时人物未声明知识/误信即要求排演——应按"未声明信息一律未知"执行并披露，
  能力不足时拒绝展开保留紧凑结果；静默以全知资料补齐角色包即失败。

### 1.4 第四批任务（M4）——依赖第四批落地后才可执行

**六向移交（M4-A）**

- 输入：选定沙盘影响做事件；选事件写局部场景；从场景追原因或看整体影响；直接沙盘↔场景
  （共六个方向，各一例）。
- 判读要点：每方向有状态移交用例；条件、候选身份、时间、知识、未结事项完整；未选分支
  不进入目标输入。
- 困难/失败案例：从未来候选回到旧 Scene——不得读入后序正史；以一段摘要代替状态移交即失败。
  变体：目标含隐藏秘密（作者 private），该信息出现在目标角色包即越界失败。

## 3. 去原文账本字段

仓库内账本只允许保存以下字段（沿用 testing-guide 付费实测账本约定）：

- 标识类：任务 id 与序号、批次、运行标识、代码 SHA、`runtime_version`/`op_version`/`schema_version`、
  模型与供应商标识（名称级，不含 Key）。
- 哈希类：`request_hash`、案例/资料 `content_hash`、确认指纹。
- 计量类：时间戳与延迟、请求计数、token 用量、费用或费用上界、`budget_resolution`。
- 结论类：状态、失败分类、判定结论、`authorization_history`（预算上限变化）、
  `human_validated` 标记。
- 指针类：`payload_redacted`——注明仓库外完整账本的位置与 SHA-256。

**禁止入仓**：原始稿件或作者片段原文、模型原始输入输出全文、网页抓取全文、作者身份信息。
这些只存仓库外私有 artifacts 目录（目录 0700、文件 0600）；账本快照经 `payload_redacted`
指向其路径与哈希。

边界规则：输入仅为合成 fixture（B1–B3 及第二批合成案例）时，账本和运行报告可随任务证据提交；
一旦含真实稿件、受版权原文或用户数据，完整账本与原始输出只留仓库外。Meter 语义沿用现有实现：
拒绝用去原文快照继续计费，后续付费调用只记入私有完整账本；同一笔预算只用一份累计账本。
