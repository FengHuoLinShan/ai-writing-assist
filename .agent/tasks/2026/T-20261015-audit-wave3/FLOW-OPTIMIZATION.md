## 首轮范围

- 保持跨 Scene 的已提交前序屏障及正文、owner、租约、独立复核、采用门禁。
- 对符合当前 Luna 范围授权的 Scene，让语义补全和 World 抽取重叠；各分支内部依赖不变，
  共同结果收齐后再做状态复核及提交。有限预算、旧协议和不符合条件的路径保留原顺序。
- 复用现有会话门与并发排空工具。数据库访问互斥，provider I/O 不占会话门；落定时重读并合并，
  不用两个过期返回值覆盖同一冻结负载。失败或取消保留已发请求与结果，不以重试掩盖未知。
- 沿现有 diagnostics / paid receipt 记录安全数值；不新增表、依赖或遥测框架。
  槽位等待、provider 调用、客户端及分支墙钟分列；重叠分支不可相加当成整场耗时。
  provider 方法进入次数不等于已发原生或付费请求数，后者以唯一原生回执核对。
- 不调整模型、Prompt、默认空间勾选或并发数；本轮不拆可选步骤的来源、失效及恢复协议。

## 工程验收

1. 用事件控制证明两项生成重叠，复核仍绑定各自输入；数据库访问互斥、逆序落定不丢日志。
2. 覆盖任一分支失败、取消、旧 unknown、来源漂移、有限预算和恢复重入；已知结果不重发，
   未核清结果不扩大授权或推进主提交。
3. 确认计时 collector 在并行调用中隔离，重试不会重复计算同一等待；失败和取消仍保留已知数值。
   缓存及用量缺项为 null，合法 0 保留，旧回执不能被补成完整计量。
4. 完成受影响 Evolution / Imports / Project / LLM 回归、适用 PostgreSQL 检查、lint、文档与独立审查。
