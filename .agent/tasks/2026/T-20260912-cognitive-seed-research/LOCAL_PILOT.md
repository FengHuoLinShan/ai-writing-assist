# 逐章自由记忆的本地模型开发试验

本试验开始将研究从手工机制转到真实模型输出。它只测试短篇材料的自由记忆更新、状态继承和有限事实查询，不测试自动数据库迁移、程序演化、主动工具选择或文学质量。材料和评分均由研究者编制，尚未独立人工验证，属于开发集。

## 模型与运行范围

使用本机已下载模型，LM Studio 报告的标识为 `google/gemma-4-12b-qat`、Q4_0、12B，临时实例为 `cognitive-seed-pilot`，载入上下文 4096。该名称与量化信息来自本机运行时，不作为权重来源或模型能力的独立认证；本轮尚无权重文件 hash。

首次加载前没有驻留模型，HTTP 服务未运行。模型估计占用 6.66 GiB，运行时允许加载。CLI 盘点自动唤醒了 LM Studio 服务；研究临时启动的 HTTP 接口只绑定 `127.0.0.1:1234`。完成后卸载本研究实例，并在没有其他模型或任务接管的情况下停止本轮启动的 HTTP 服务。

使用 LM Studio 原生 `/api/v1/chat`，`store=false`，不提供任何 MCP/插件集成或续接 ID；不同请求不继承服务端聊天。无 OpenAI 账户密钥或外部推理 API 调用。文档确认了原生接口的输出、推理关闭、用量与会话存储字段。[LM Studio 原生接口](https://lmstudio.ai/docs/developer/rest/chat)

连通性检查已返回 `{"ready":true}`，HTTP 200，输出 6 tokens，推理 tokens 为 0；原始可分享记录见 [local-smoke.json](local-smoke.json)。这仅证明本地推理通路可用。

## 材料与输入隔离

[stream-source.json](stream-source.json) 包含共同的两章及四条后续轨迹：

- r17：可靠材料揭示始终存在的旧规则，人物尚未获知。
- r29：故事内正式改制，旧规则对早期时点仍有效。
- r43：作者追溯修订当前版本，附真实替换章节，旧稿保持历史身份。
- r61：新增观察仍不足，作者明确保留未决设定。

这些解释标签只用于报告。更新模型看到实际章节或作者说明，不看到轨迹原因标签、其他轨迹后续或评分文件。两章共同状态只生成一次，然后独立复制给各轨迹；评价输出不回流到记忆更新。

[stream-oracle.json](stream-oracle.json) 独立保存五项查询的预期值和理由。运行模型的 `run` 路径不读取它；只有结束后的离线 `score` 才读取。外部模型没有文件工具，实际输入全文及其 hash 都保存在运行日志。

## 比较条件与限制

`memory` 条件每次只用上一份自由状态与新材料形成下一份完整状态，内部没有预设人物、事件或规则表。v1 要求外层 JSON；格式失败后 v2/v3 改用模型自行组织的文本。评价时只提供该状态与已见来源编号。

`raw_prefix` 条件直接提供同轨迹全部已见原文、作者说明与替换版本，不提供模型记忆。两条件使用同一模型、系统规则、题目和每请求上限；不同轨迹交替评价顺序。

这是一项记忆压缩与边界诊断，不是最终公平的 Agent 总体能力比赛：`memory` 在这一轮没有原文回读工具，额外付出了状态构建成本；它被要求每章重写完整状态，也尚不能自主选择不写、局部更新或改变工作方式。发现差距后，需要加入同等原文读取权限与可选择行动的条件，才能讨论完整认知种子的增益。

总量冻结为 15 个研究请求：共同章节更新 2 次、共同状态上的历史充分性检查 1 次、四条后续各更新 1 次并评价两个条件。连通性请求另记，不混入研究成绩。每请求最多 1024 输出 tokens、最多 180 秒；整轮最多 1200 秒，无自动重试。温度为 0，推理关闭，不保证不同设备或运行时上的逐字确定性。

输入在发送端不截断，过长输入失败；本轮需检查实际输入/输出 token 记录。未专门验证 LM Studio 超长上下文行为，不能据此宣称更长小说的上下文保护已通过。

## 评价口径

五项查询分别检查初二规则、初四规则、是否发生故事内改制、人物是否确知、前两章当时是否已经证明红蜡含义。回答格式为 yes/no/unknown，附来源编号和短理由；v3 使用每题一行的文本格式，避免嵌套 JSON 的传输失败。这个格式只约束评价输出，不规定持久认知结构。

主分支每条件 20 项选择，标签中 no 占 16 项。必须报告“始终回答 no”的 16/20 对照，不能把高总分直接当成理解能力。还要逐项观察 r29 的早晚差异、r61 的未知和来源/版本理由。

离线脚本只检查选择及来源编号是否存在。引用编号存在不证明该来源支持回答；理由的语义核查另记。没有独立人工文学评审，不报告用户满意度或创作改善。

## 运行证据与观察

执行脚本为 [stream_pilot.py](stream_pilot.py)。每轮请求前生成 manifest 固定材料、脚本和提示 hash；本说明是在执行期间整理，不是外部预注册。各轮数据不混合计分。

当前已观察到：第一章更新把守闸人的一句话保存为 `红蜡.function=持有者夜间可通行`，没有在该字段标出不确定性。该说法的角色来源仍在另一个字段中，因而需要检查后续是否能恢复其证据身份，不能仅凭这一字段断言所有后续任务都失败。

v1 在第二个请求返回后因 JSON 结构错误失败；实际输出 342 tokens，未达到 1024 上限。最终文本还把第二章匿名旅客、本地店主与第一章陈船主混合记录。原失败保存在 [v1 manifest](local-pilot-v1/manifest.json)，对应脚本和材料保存在该目录的 snapshot。不能把格式失败计作后续题目的语义错误或成功。

v2 改为自由文本记忆后，发现评价提示示例含实际来源编号和具体答案，可能造成示例引用或选择偏置，因而在任何评价请求之前中断。已验证进程退出 130、模型 idle；原始 manifest 与脚本有快照，当前 [v2 manifest](local-pilot-v2/manifest.json) 记录中断原因。未完成请求的 token 用量未知，不填零。

v3 去除具体编号和答案示例，并增加输入协议检查；材料和 oracle 没有改变。[v3 manifest](local-pilot-v3/manifest.json) 记录新的冻结参数。该轮已完成 15/15 次请求，耗时 732.131 秒；前两版保留用于故障审计，不择优混入第三版成绩。

模型原生推理内容不落盘；仅保留最终回复、显式记忆、请求和计量信息。早期产物不构成认知涌现或长期收益的证据。

## 选对答案仍可能用错依据

对照原文和保存状态的核查发现以下问题，详细证据见 [来源核查](local-pilot-v3/source-review.json)。核查者为本研究 Assistant，不是独立人工评审。

1. r29 记忆明确保存“签名并非旧规法定条件”，回答却仍把初二的签名现象当成必要条件。这个错误发生在使用已保存信息时，不能简单归为遗忘。
2. r29 原文条件对初四沿用旧规，并把守闸人最初的话当成前两章已有的证明。直接提供完整材料也没有自动解决时间与来源身份问题。
3. r17 记忆条件的历史问题虽然选 no，却用后续发现解释早期证据是否充分。同题在共同状态阶段的理由原本只依据前两章；标签分数隐藏了后续依据回流。
4. r43 记忆把作者给出的新设定说成守闸人明确说过的话；保存状态还漏掉新的完整双条件，并沿用关于红蜡通行功能的旧疑问。当前五题多围绕红蜡，未充分覆盖这项记忆缺口。
5. r61 记忆保留作者未决说明，q1/q2 回答 unknown；原文条件则从伴随现象推断必要条件并回答 no。这个开发例值得继续研究，但还不能区分重述、组织方式与额外推理的贡献。

全部 40 个回答的来源编号都存在，但已有引用缺失、说话者误归和时点误用。这直接说明“编号合法”和“语义受到支持”必须分开评价。

## 材料自审与后续比较

本组结果适合发现问题，尚不足以证明认知涌现。模型主要使用熟悉的人物、地点、物品、情节和悬念分区；在作者未决轨迹新增了作者说明分区。是否因为这些分区而改善回答，需要保持内容不变的组织消融，不能由分区出现直接推定。

后续比较需加入同等原文可用性的记忆条件，并记录构建/更新成本；不把每章全量重写固化成正式研究流程。优先检验时点与来源身份的使用：允许选择保留原状态、局部更新、重组和回读；采用冻结旧状态回答历史问题，或在当前状态中明确请求对应作用域，分别与原文回读对照。

新增题目应平衡肯定、否定、未决及角色已经获知的情形；显式说明未来时点是否假定没有另行改制；区分“必须具备”与“具备即可”，不将材料未给出的充分性当作真值。当前 oracle 和成绩不因这些设计修订而回改，所有材料已经成为开发数据。
