## 目标与验收

- 目标：以表格、事件流水呈现世界/剧情变化，保留前期伏笔/人物习惯，并在演化进程中主动发现、积累和修订新的注意点，供作者自行取舍。

## 上下文与边界

- 用户要求检查现状并讨论如何实现；AI 的首要职责是整理、查证和提出后果候选，作者保留文学表达与最终选择。
- 业务读写保留 owner + novel_id、来源回读、Context confirmation、版本/CAS、采用与撤销。
- 历史事实、未来计划、隔离试演三个依据不可混为已发生事实。作者全景不得直接回流为角色可见资料。
- 发生时间、叙述顺序和资产版本分别表示；未知世界时间与场外活动不靠模型补成事实。
- 用户补充明确：伏笔、人物习惯等信息以表格/流水账呈现，不追求文学性，正文写不写由作者决定，本项目无需管理。此前“保存叙述方案”建议被此边界替换，不作为后续待实现项。
- 用户再次补充：演化进程中要涌现、自学习需要注意的点并记录。设计为作品内的证据化持续理解，能够发现未事先手工标注的规律、例外、关联和未解问题；不把机器推测自动写成正式世界设定。

## P0 输出物清单（实施入口，尚未实现）

P0 仅用合成来源、内存替身和手写发现包验证契约及最小数据流；不接生产读模型、真实台账视图、真实数据库或模型，不建 UI、migration 或通用发现引擎。P1 才接真实全景/台账读取。复用现有类型和纯验证函数不等于接入生产读取。

- [ ] 条目契约：机器可校验的稳定主题/条目身份与独立修订；范围、主张性质、依据有效性、作者决定四轴；发生实例与来源引用分离；关联对象、条件、历次出现/例外和竞争解释；有类型的目标引用及绑定依据/状态。附条件行为有效/无效样例，伏笔与承诺仅做字段覆盖检查。
- [ ] 发现输出契约：新增/增强/收窄/例外/待核实变化包；目标条目与预期修订、操作幂等身份、输入依赖、方法指纹；每项主张绑定支持/反证。扫描请求范围、实际覆盖、失败/跳过/方法不支持范围与结果分别表达。允许合法的不确定输出，拒绝结构非法或伪造证明进入可用结果。
- [ ] 作者修正作用域结构：确切人物、场景、观察/条目修订及适用条件；默认当前实例；扩大范围追加版本且由作者主动提交。作者决定、来源有效性、方法复核状态分别保存，不用来源/方法变化自动改作者决定。
- [ ] 依赖层与契约版本结构：不可变来源 manifest、场景截止点、被引用目标版本、抽取/聚合方法及语义配置、契约版本、依赖层；支持 source_changed/method_changed/target_changed 等可定位原因。方法变化保留旧条目和作者决定，仅受影响派生层标建议复核；来源/范围资格独立重验。
- [ ] 合成夹具与固定预期：条件行为贯通主样本（出现→聚合→明确反证→修订→来源/方法变化）；同一发生的回忆/重抽去重；低置信候选、无法归并身份、部分扫描、来源缺失、方法不支持、同主题竞争解释；格式非法/引文不匹配失败；作者决定保护、视角隐藏存在不泄漏与目标版本变化。伏笔/承诺仅做契约广度样例，不开发三条端到端流程。
- [ ] 最小数据流走通的证据：一个可运行的离线检查入口/定向测试及其实际结果，绑定契约/夹具/实现版本；记录逐步输入输出、计数、主题修订与重验原因。没有真实发现器结果时明确只证明契约和流程，不声称预测了模型全部失败方式。具体存放路径在获准实施时按现有模块惯例确定，复用测试框架，不另建工具平台。

完成 P0 要求六项均有实际产物与检查证据；本清单本身不是完成证据。背景调查、旧评审和历史测试保留为依据，不能代替本节执行。

## 当前 P1 接入约束

- 引用方声明、维护有类型的目标引用（所属领域/类型/对象/版本）；被引用方仍拥有正式身份，正常发布版本/合并/退役变化。Story 的道具使用记录可引用 World 物品，二者记录身份不同而指向同一物品；不得创建第二个正式物品身份。目标变化使绑定待重验，不静默重绑，分歧留待裁定，不新增跨域 master identity。
- 扫描覆盖与展示结果分开。对有权获知的作者范围，明确显示“未检查”“已检查未检出”“已检出但未展示”；部分扫描可同时有未检查区间和已展示结果，不能用一个互斥总状态压扁。未检出仅限实际扫描范围/方法支持的主张类型；失败、来源缺失或方法不支持不能算已检查未检出。
- “已检出但未展示”首版用于作者主动筛选等有权限的情况。角色/读者视角不得由该标签、数量、名称或原因透露隐藏条目存在；使用与隐藏条目数量无关的通用视角说明，服务端过滤实际内容。记录被来源/质量门拒绝与视角过滤不是同一件事，具体诊断仅给有权作者。
- 扩大修正作用域的入口仅在条目详情内：非阻塞、可折叠、可忽略，不弹窗、不自动进入待裁定；作者主动点击“扩大适用范围”后才进入确认流。系统提议无提交前不生效，普通窄修正保存不受其阻塞。
- 方法变化不自动降低置信，也不改作者决定。旧条目/作者确认记录保留，受影响派生解释追加“方法已变更，建议复核”；当前是否适用由来源、范围与能力资格单独判断，确认不能豁免来源漂移或权限重验。旧版本仍可回开，重验产生新修订。

### 涌现与自学习闭环（本轮新增要求，尚未实施）

- P2：长程召回/聚合与一种注意点持续发现；接注意触发和修正作用域；实际模型输出在冻结样本上独立评阅，补充 P0 不能预见的失败，不追认其已在合成夹具中验证。
- P3：扩展发现类别，补齐既有排演的纯记录终点。
- P4：受控短期未来推进、精细重算、规模优化与复杂方法迁移。基础重验标记、权限和作者决定保护不得推迟。
- 作者验收示例：早期三次记录甲在紧张时摩挲戒指，后期试演出现紧张但没有该动作。台账回开三次具体出处，并在本次对应范围确已扫描且方法支持时显示“此范围内未检出相关记录”；不标记为反例、不作异常高亮、不提示必须补动作。未扫描/方法不支持时显示相应未检查原因。另查伏笔时同时展示作者计划兑现位置、实际出现记录与未核实范围。
- 必须补覆盖：倒叙、同章多场、版本回开、来源缺失、改稿后过期、跨项目拒绝、并发保存冲突、未保存草稿保护与窄屏。
- 持续发现验收：久远细节召回、重复来源不重复计数、反例修订、来源删除失效、人工拒绝不被覆盖、试演与正文隔离、后见理解不泄漏早期角色、发现扫描失败可见、增量重跑幂等。衡量关键注意点漏检/误报与证据正确性，不以注意点数量越多越好。
- 产品验收关注细节召回/来源准确、跨场景聚合、未知与推测标识、修改后失效和操作成本；不以文学质量、正文采用率或是否描写某细节验收。

### 用户工作包建议第一轮评审（历史依据，执行以 P0 清单及当前约束为准）

- 总判断认可：需要统一读视图、来源化细节、发现闭环与作者纠正；复用已有领域事实与契约，统一展示不形成第二套事实权威。
- 顺序修正：P1 同时具备 owner/novel_id、依赖基线、来源回开、基础过期/失败标识；P4 只扩大精细重算与规模优化。真实作者试用与小型冻结样本从首个可用切片开始，不统一拖到 P4。
- 收窄 P0：先选伏笔、条件行为与承诺三个代表案例；复用 SourceRevisionRef、StoryPosition、ObservationEnvelope、checkpoint/basis，增补窄条目/发现输出契约。世界绝对时间、完整因果边和每条前后状态按实际支持可缺省，不要求先补齐通用模型。
- 语义拆轴：历史/计划/试演表示记录归属；观察/信念/推测表示主张模态；来源已核验/有争议表示依据状态；作者未裁决/修正/拒绝表示作者决定。同一试演含行为与角色信念，不能塞进单一互斥类型。
- 版本一致指一份不可变依赖清单与场景截止点，不要求全库共用一个版本号；重排、规则/契约版本与扫描方法更新也参加 freshness/重建决定。
- 支持数需分开发生实例数、来源数和生成次数；同一事件的回忆/重述不能计为多次行为。hash 可追溯但不能独自证明独立支持或主题同一性。
- 负证据修正：全文扫描没有找到仅证明该扫描范围未找到记录，不能证明行为未发生或伏笔已废弃。戒指例子没有该动作不是反例；明确否定行为/同条件相反行为才可能构成反证，仍需核查上下文。
- 只读事件流/台账与发现更新输出分开：变更包可审查，应用需重验来源、基线与条目修订并保持幂等；GET/只读 facade 不顺便生成或写入学习结果。
- Cognition 复用有边界：retention 当前拒绝截止阅读且主题身份按内容 hash 派生，不能直接承担持久主题的逐次修订；需领域契约与薄接入，保持作者解释和历史角色输入隔离。不能因已有 JSONB 就把异质业务塞入无约束字段，也不预先新增通用事实库。
- 派生发现采用成功提交后可恢复的 PG 任务，累计预算包含召回/模型发现/审查/重试；失败不得回滚已提交场景或显示全部已检查。先自动保存来源绑定候选，作者仅为冲突、修正或提升正式设定作决定，不逐条审批所有观察。
- 作者收件箱首版保留查看依据、修正/拒绝/关注；合并、拆分、重绑定等高级维护按真实案例再实现，不把作者变成台账管理员。
- 推荐切片：P0 案例与窄契约 → P1 已有资料全景+只读细节台账+基础失效 → P2 历史召回/聚合+一种注意点增量发现与反例修订 → P3 扩展发现类别和既有排演记录终点 → P4 扩大受控未来推进与规模优化。演示/冻结样本/安全回归贯穿各阶段。
- 分支刷新：核查时 codex/world-foundation-phase1-plan 已到 ee9a1ba20，新增知识方言契约和边界夹具；工作树干净，状态视图仍声明 world_valid_time/belief_fact_diff 等 unsupported。第一阶段任务仍记录 RP 质量与费用门失败，本轮未重跑。该门禁保留，新增作者只读能力按实际依赖安排验证，不能把全部 RP 质量问题无条件变成离线台账的启动前置。

### 第二轮补充评审与已确认边界（历史依据，执行以 P0 清单及当前约束为准）

- 用户明确接受：领域事实权威、非状态细节观察、语义四轴、P1 基础失效/权限/验证、未描写不构成反例、发生数/来源数分离、Cognition 仅复用机制、重要决定裁决、方法版本/发现位置/分层指标。以上为方案已确认边界；没有业务实施/数据/模型运行授权。
- P0 广度与深度：三个案例检查语义广度；仅条件行为走无模型的贯通最小数据流。伏笔/承诺做契约覆盖，不分别开发三条端到端流程。
- P0 最小数据流：合成来源→三次行为观察→手写发现包聚合→同一事件回忆不得增加发生计数→明确克制动作形成例外→修订条目→源改稿/方法变化分别标需重验。以手写变化包作发现器替身，走明确的条目/版本/依赖缝，固定预期，不先实现通用发现算法或完成全部 P2。
- 作者注意：普通观察可静默入账；重要新关联/条件变化/可信反证在本轮摘要可见；经核验的来源矛盾、与适用范围内作者决定的冲突、影响当前任务的身份歧义、明确正式采用请求进入待裁定。来源/扫描缺失单列待检查，不能改称事实争议；未核实数量仅作聚合提示，不能独自判定紧急或强制审批。通知按条目修订去重，不新增独立通知平台。
- 身份权威需进一步修正用户提议：World 拥有正式对象/别名/对象合并，Story 拥有事件/线索/计划身份；派生的是提及绑定、发生实例聚合等判断。原领域新修订使依赖解析失效再重验，不能静默覆盖作者确认的绑定或改写旧历史。跨域引用分歧按原领域修复；全景不自建跨域 master identity。现有 identity.py 对精确证据冲突返回 ambiguous，可复用。
- 方法指纹进 P0：分别记录来源 manifest、方法版本/语义配置指纹、依赖层与契约版本；方法变化不等于来源失效。只对受影响的派生层标方法待复核，旧版本依然可回开；不得把展示样式/日志改动当语义变化触发全书重算。
- 人工评估首版集中于贯通案例，其他两个案例和权限/身份/过期保留少量确定性反例检查；不建设全量标注集或指标平台。冻结样本验证契约/回归，模型输出需语义评阅，作者试用验证可理解性和操作成本，三者证据分别记录。
- 作者修正作用域：默认仅当前条目中的本人物/本场景/确切观察，保存即确认该窄作用域。系统可另提议更广条件，作者主动确认或缩小，避免每次纠正都弹作用域审批。单场合需明确是确切场景还是条件类别；P0/P1 使用确切来源与场景，不仅靠自由文本标签自动继承。新场景在范围外只显示相关参考/候选，新反证留待核实，机器不强行套用或改作者决定。
- 修正保持作者决定轴独立：来源变化可使适用依据待重验，但旧人工修正不变回机器候选、不丢历史；扩大范围追加修订，不覆盖原作用域。方法版本、修正作用域和提示理由结构在 P0 确认；P2 接自动触发与继承应用。
- 阶段调整基本接受用户微调：P0 最小合成数据流；P1 全景/台账/排演只读+方法/身份依据/基础失效；P2 一类持续发现与注意触发/修正作用域；P3 扩类与纯记录终点；P4 受控未来推进/精细重算/规模与方法迁移策略。复杂方法迁移可推迟，方法变化的待重验标记和记录不可推迟。
