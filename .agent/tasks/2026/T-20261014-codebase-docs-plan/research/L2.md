## 高风险调用链与恢复行为

### 正文生成与候选采用

`POST /api/writing/generate` 先要求项目 active，通过 task operation receipt 幂等查询；随后用 Evidence facade 重物化 `writing.generate` confirmation，解析 Scene 和已采用 Story asset basis，固定 secret-free 项目 LLM snapshot，再入队并绑定确认结果。worker handler 检查必要元数据及模型快照后委托 generation service。

worker prepare 再次重物化相同 confirmation，验证请求章节和 task owner，冻结 Scene bundle、当前 Story asset basis、续写基稿快照、POV hidden guard 和知识范围；角色视角缺 Scene、人物或截止点时失败。外部 provider 等待发生在 transaction-free checkpoint 之后。付费候选可写入任务私有 checkpoint；重排时只有版本、结构和来源指纹仍匹配才复用，损坏或过期的冻结结果失败关闭，不盲目发起第二次付费调用。finalize 重新检查项目和 profile、锁定重物化 confirmation、Scene bundle、base draft 与隐藏 guard，再比较总来源 fingerprint；漂移时不落 candidate。通过后 candidate 与 Evidence result ref 在同一任务事务写入。

当前 Writing 文档已描述 operation receipt、source re-materialization、租约、冻结输出及失败关闭，基本准确。调用 seam 误写为 outline facade 是上列需要修订的一处。

采用时，chapter lock 与 draft row lock 后只接受 candidate；已采用 candidate 只有携带相同幂等键才返回原稿。首次采用重验原 confirmation 新鲜度、Scene bundle hash、知识复核 `passed`、独立 review 正文/context 指纹及 `pass`/无阻断项，再 copy-on-adopt 新建普通工作稿、软废弃候选并绑定来源结果。非阻断 finding 可随作者决定保留为 `adopted_with_open_issues`；这表示整份候选被采用并保留问题回执，不是只局部合并正文。当前文档已正确写明知识门禁与开放问题回执，只有重放说明失准。

### 正文保存与锁

草稿更新路径按 novel 校验稿件，先锁章节版本键，再锁 draft 行并读取章节最新稿，检查预期版本/时间戳和“目标仍是最新稿”；过期写入冲突失败。版本提升/正文替换继续在该锁内完成。Story fusion task 也在 provider 返回后重验项目，使用 writing facade 锁住证据覆盖章节，再行锁 Scene 并复验 source/evidence fingerprint。README 已写明 PostgreSQL advisory lock 和该公开锁 seam。模块文档 API 已列 `expected_version`，但 facade 清单遗漏跨模块锁函数。

### 冲突检查与连续性确认

规则检查只读取当前 Scene 的合法 chunk 与 continuity checkpoint；Scene、范围、hash 或投影不可用时记录 degraded/omission/not_checked，不把缺证据当作“无冲突”。AI review 通过 task receipt 入队，行锁使同一检查串行，任务 owner 防止旧任务回写；prepare 重物化 confirmation 并冻结检查和问题语义指纹。provider 返回后再次校验 owner、confirmation scope 与 source fingerprint，只有一致时追加 AI items 并绑定 Evidence result。无效输出可产生 partial 状态；失败保留既有规则项，状态标记 failed。单条 AI suggestion 也会对输入检查项和 confirmation 计算 fingerprint；漂移时标记 failed，而不留下永久 running 状态或覆盖新任务接管。

作者确认 continuity item 时重验 item 更新时间、检查正文 hash、draft id/version，以及 AI 问题的原 confirmation；在 Scene 事件锁中按 request hash 幂等写入 author-confirmation event，再更新旧 checkpoint 和确认回执。模块文档对这些路径与 degraded 覆盖边界描述准确，无需改动。

### Scene 章节映射、融合与截止

Scene 到章节的快速关联先验证章节存在，再行锁同 novel Scene，去重合并 `chapter_ids` 并保留 `scene_chunks`；快速新建在项目级 Scene-order lock 内分配尾部 index。此接口只增加章节级关联，不伪造正文位置。对应文档和 route tests 当前一致。

Fusion preview 固定来源 Scene fingerprint，task-mode 在生成结果后锁住相关 Writing 章节、重新锁读来源 Scenes，并重算 source/evidence fingerprint；漂移会拒绝结果。保存按“建议行先于 Scene 行”的锁顺序处理，支持 discard、保存并保留 originals、保存并废弃 originals。新 Scene、可选旧 Scene 废弃和持久 suggestion 的 adopted 状态同一事务提交。文档正确写明逐条作者选择、无“全部接受”、原 Scene 的处理方式和 suggestion 生命周期，无需改动。

### 六维 continuity、截止和 unknown

Scene memory contract V1 覆盖 entities/relations/locations/knowledge；V2 当前再加 timeline/causality。checkpoint 构建按 scene_index 顺序只处理到目标 Scene，并对每个维度分别生成；source basis 包含目标 Scene 及之前 Scene 结构，以及其章节范围内的 working manuscript manifest 和 contract version。视图截止章取当前 Scene 关联章节最大值；缺 checkpoint 显式标 missing，非 ready 或 source-basis 漂移标 degraded，reader 的 timeline 仍显式 unsupported/omission。空事实列表不表示已证明不存在。

知识契约严格区分 known、unknown 与 false_belief。known 需要 subject/value binding；unknown 保留文本摘要但没有值绑定；machine observation 恒为 unknown。角色知识投影只把 holder 匹配的 known 值授予角色，unknown 和误信都不授权。六维、来源 cutoff、missing/degraded/unsupported、unknown 与空态语义在 docs/modules/05_memory.md 和 docs/modules/19_story.md 已有清楚说明，未发现需要本轮重写。
