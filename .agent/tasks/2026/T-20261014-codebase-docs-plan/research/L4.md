## 主调用链

```text
小说上传
  → imports API 校验项目/文件大小/文件名
  → 统一解析器检查扩展名及实际内容，再分章
  → Writing facade 一次创建 published drafts
  → 每章投递 publish_chapter，Writing/RAG 后续建立索引

深度导入（独立于上传）
  → 作者确认 adoption_policy + 范围，任务持久化授权和脱密 LLM 执行快照
  → Phase 0 冻结 chapter/source draft/hash
  → Phase 1a 切片候选、Phase 1b enrichment、可选高质量 Phase 1c fusion
  → Scene commit 校验精确 span 无重叠、完整覆盖冻结 source、hash 未漂移
  → 通过 Story facade 以 workflow provenance 幂等写 Scene
  → Phase 2 世界对象/关系/别名候选，Phase 3 结构候选；Evidence snapshot/link 只记录来源
  → 作者结果按 adopted / review / not_adopted 显示；候选资产仍有各自领域采用门禁

Evidence 检索与上下文
  → Writing current source 或显式冻结 manifest
  → RAG 按 content_mode + draft ID/hash 过滤候选（索引不是事实源）
  → NovelEvidenceService 从 Writing 回读精确 SourceRangeRef，校验来源/版本/范围/可见性
  → Context compiler 编译 selected/excluded、budget、reveal 与 cutoff
  → confirmation 固定 options + selected assets + context fingerprint
  → 执行前重新物化同一确认并比较 fingerprint；不新鲜则拒绝
```

正文普通上传的稳定入口是 `POST /api/imports/upload`。API 按块读至 50 MiB 上限并取安全 basename；解析器再按白名单、签名/内容检查分派。`ImportService.upload_and_import` 在 savepoint 内解析并调用 `writing.facade.create_published_drafts_only`，随后为每章 enqueue `publish_chapter`。`import_records` 仅记导入元数据；当前主路径写入 `writing_drafts`，旧 `imported_chapters` 仍因来源 FK 留存。空章、非法文件、章节超限和解析/写入异常都会进入明确失败状态；一般内部异常只持久化通用错误文案，日志诊断脱敏。API 报业务异常前尝试提交失败记录，污染事务时回滚并保留原始异常。

普通文稿格式当前可对外表述为 TXT、EPUB、HTML、HTM。`ALLOWED_EXTENSIONS` 还含 MOBI/AZW3，但它们只过 PalmDB/PalmDOC/MOBI 结构检查，二者都分派到 `parse_mobi` 且需运行时 `mobi` 包；锁定依赖中未声明该包，源码文档明确称未完成真实文件验收。因此内部白名单不等于已验证支持。表格迁移另有独立扩展名集合与 API，不复用文稿解析白名单。

Interaction 的 RP source revision 也复用 imports parser，但入口不同：`import-preview` 只计算章节差异和 base manifest 的 preview hash；`import` 需重新传文件和 hash，做当前项目与 author owner 校验、授权、二次确认；完整稿修改/移除/重排需显式 destructive confirmation，append 从当前末章后开始。`SourceUpdateService.apply` 在项目排他锁内重新解析并重算同一 preview hash，hash 过期时拒绝写；改动通过 Writing facade 写新版本，移除版本只软废弃。apply 的嵌套事务失败会保留 failed ImportRecord 且回滚 drafts。

深度导入不能由“已上传”推导为已启动。请求须显式 `authorization_confirmed=true`；授权快照冻结 novel/章节/stage、provenance 要求和 workflow-owned soft-deprecate 回滚策略；任务同时冻结 secret-free 项目模型执行配置。Scene 阶段由 deterministic Phase 0、Phase 1a/1b、可选 Phase 1c、最终 Scene commit 构成。候选逐章引用 source draft/hash 与半开 offset；commit 检查无重叠，要求 frozen source 的精确 spans 无缝覆盖完整章节且 hash、draft、chapter 一致，才能通过 Story facade 落地。provenance key 使相同 workflow 重试时复用既有 Scene，不重复写入；deprecated provenance 冲突被跳过并记录。

授权快照把无复核标记 Scene 和工作态结构列为可自动采用，把需复核 Scene、entity/relation/alias candidates、不确定结构列为 review，忽略/temporary-only/provenance conflict 列为 not adopted。Phase 2 新实体写成 `status=candidate` 并保留 workflow、Scene、章号、字段证据等来源；新别名和关系也写 candidate / needs_review。完整导入后可创建 post-import adoption package，但它只是建议包：canonical 资产只作 no-op 预览，候选实体/关系与 World Bible revision 仍须作者显式 preview/apply。不得把「作者授权流水线」概括成「所有抽取资产自动成为正史」；结果统计也不是作者对每项质量的验收。

表格迁移由 `/api/imports/migrations` 专属子包处理，限定 1–5 个 `.xlsx/.csv`、文件大小和会话字符上限。会话通过当前 account principal 与 `novel_id` 同时隔离。草稿期暂存有界 `rows_json`；mapping/decisions 以 revision CAS，AI 只能基于上传行产生 preview，写回还要求 scope hash 匹配。apply 仅允许 draft 状态，重新组合计划、校验 expected preview hash、取得 project exclusive 锁，然后按 world → story facade 应用，并保存回执、清除原始行后提交。回滚先可 dry-run 查看，再按 story → world 逆序撤销；资产被后续修改或引用时保留并明确列出，支持部分回滚状态。此处的「确认即采用」是 ADR-0030 的表格预览语义，不应与深度导入 candidates 混为一谈。

Evidence indexing 将 Writing draft/hash 作为可重建 chunk 的来源身份，canonical/working 分流；不同 draft 的历史 chunks 可共存，替换只删除同一 source ID 的过期 chunk，不独立 GC 历史版本。显式 `source_manifest={draft_id: source_hash}` 会在候选排名前过滤准确版本；普通 author 检索和上下文编译会从 Writing 计算当前 manifest。RAG 只排候选，编译和面向作者的 read/search/inspect 仍从 Writing 重读并校验 `novel_id`、source ID/hash、offset/range 和 visibility/cutoff；失效候选丢弃并告警，不以旧 chunk 正文兜底。reader 有章节/可选同章 offset 上界，character 还需人物边界；Scene cutoff 绑定当前版本 SceneSpan，无法精确定位时保守拒绝。

Confirmation 的 preview 与 confirm 都编译同一 `CompileOptions`，覆盖 context mode、content mode、selected/excluded assets、pinned/excluded refs、budget、reveal 与 chapter/scene/offset 截止。确认存储实际 selected asset IDs、excluded IDs、compile options 与 fingerprint；执行前 `require_fresh_confirmation` 先检查 stale 状态，再重编译确认 options 并比对 fingerprint，任何输入变化都返回冲突/过期。只读 GET confirmation 按 `confirmation_id + novel_id` 读取已存摘要，不重新编译、不返还私有 options 或 rendered context。

索引新鲜度 summary/freshness 现在是 SQL `GROUP BY + COUNT/SUM(CASE)` 投影；fresh 条件保留 succeeded 状态及 nullable-safe requested/indexed hash 与 source ID 相等。针对性测试源码创建 600 条合成 state，核对范围/状态/空值计数并断言没有 ORM 行 hydration；本任务未执行该测试，也未单独验证两类真实数据库环境。应准确写成工程实现与测试断言，不推导性能基准或生产负载表现。

## 主要失败与恢复链

| 触发 | 当前保护/恢复 | 证据边界 |
|---|---|---|
| 普通上传的非法签名、空解析结果、超限或内部异常 | savepoint 隔离写入；ImportRecord 进入 failed；内部异常只对客户端存通用文案；同名并发成功由部分唯一索引拦截 | 只读服务/API 与合成 TXT 测试；未实测文件或 DB |
| source update 预览后正文/文件变化 | hash 不匹配返回冲突，需重新预览；危险变更要求作者二次确认；apply 失败回滚 drafts 留失败记录 | 静态 CAS/失败路径用例 |
| Scene provider 崩溃、结果不合约或失去 lease | workflow 按 `task + generation + attempt + lease` 持有写入；恢复需手动 resume，generation 增加，旧 attempt 不能 checkpoint；阶段 checkpoint/provenance 跳过已完成单元 | 当前测试源码覆盖 owner 失效/恢复；未执行，不证明真实 provider 恢复成功率 |
| deep-import 放弃恢复 | `abandon` 只处理本 workflow 自动派生资产并走领域回执；取消与软清理分开；取消后须先 preview，再带最新 fingerprint 显式清理，后续修改或被引用对象受保护、可部分完成 | 本任务只静态跟到接口/实现与模块 README；没有检查真实项目数据 |
| 不确定 provider 用量或恢复时请求仍在途 | request reserve 先持久 checkpoint，checkpoint 无权威或预算不足时 provider I/O 前失败关闭；已发送但无 usage 的请求记 `unknown/possible`；restart 将 in-flight 收敛为 unknown，usage 不完整不写成零 | workflow_budget 单测源码覆盖；未运行，可能费用不等于实际账单金额 |
| deep-import LLM 某些错误 | retry wrapper 最多自动重试一次，schema/quality gate 不重试；网络、timeout、429、422、empty result 默认可重试。模糊网络/超时可能在 provider 已处理请求后重试，不能宣称零重复费用 | retry policy 与调用 envelope 各自静态核对；账本会保留 unknown/possible，未证明供应商最终收费或退款 |
| 表格迁移预览过期或撤销冲突 | stale hash/CAS 失败关闭；回滚保留被改动或引用对象，记录 kept reasons，不冒充全撤销 | E2E/服务/API 测试源码是本地 DB 合成链，未在本任务运行；真实第三方导出样本仍缺 |
