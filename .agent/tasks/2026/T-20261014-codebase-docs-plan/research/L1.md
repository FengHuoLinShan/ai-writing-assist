## 关键调用链

```text
公开浏览器请求
  → AccountAuthMiddleware 验证 session、账号状态、写请求 origin/CSRF
  → account.context 绑定 AccountPrincipal（请求结束 reset）
  → account facade 取 principal.account_id
  → project facade.require_active_project / project service 按 owner_id + novel_id 校验
  → worker 无浏览器 principal 时仅在显式 system_execution_scope 内通过
```

公开项目 gate 对无 principal 请求失败关闭；worker/system 是显式不同身份。项目 context 取回的 owner 决定 account 凭据读取范围，Project facade 同时保留 `novel_id` 隔离。模块说明中关于 owner 门禁与 worker 范围的表述基本准确。

```text
账户设置连接文本模型
  → account settings API 不接受调用方 owner
  → settings service 从当前 principal 解析 owner，锁 owner/provider
  → 新 Key 做最小真实生成校验；成功后加密保存、记 fingerprint/verified_at
  → Project 读取 owner 关联的 secret-free runtime profile
  → open_project_llm_client 或 build_project_llm_execution_snapshot
```

同一已验证 fingerprint 的 Key 可跳过重复验证。Account README 和模块文档没有区分文本连接的最小真实生成校验与图片连接的 `credential_only` 校验；图片连接会调用 `OpenAIImageClient.verify_connection()`，API 返回的 `verification_scope` 明确是 `credential_only`。这是值得补的一句实现边界，而不是两个连接都通过同一类业务生成验证。

```text
可恢复文本任务提交
  → Project facade build_project_llm_execution_snapshot
  → 保存 secret-free 配置、provider/model、配置哈希、能力/路由快照
worker 恢复
  → restore_project_llm_execution_settings 校验版本、novel_id、profile_hash
  → 要求当前 owner 仍连接原 provider，并校验 base_url / extra 哈希
  → 取同 owner、同 provider 当前 Key，沿用冻结的 model/能力档案
  → 缺连接、Key、哈希不符或旧 local_agent 字段则失败关闭
```

因此 Key 轮换无需重建任务，但前提是原 provider 连接仍在、其 base URL 与 extra 配置未变化，轮换发生在同一 owner/provider 下；切换账户当前 active provider 不会把旧任务重定向到新 provider。Project README 已较完整描述该行为；`docs/modules/01_project.md` 只写了“按项目 owner 重新读取该 provider 的当前账户 Key”，没有列恢复拒绝条件，也没有列出当前 facade 的具体快照/客户端入口。

图片使用独立 Project image snapshot：冻结 `novel_id`、owner、provider、模型和 base URL；恢复校验 snapshot hash 及上述连接身份，再重新解析账户图片 profile。图片 Key 不写入快照。这里仅看到实现代码和 World 调用方；没有找到 Project 层专门覆盖 image snapshot restore/key rotation 的直接测试，World 测试多为 mock builder，不能据此扩大验证结论。

```text
世界对象图片 / 地图册图片
  → World 选择已配对设备并提交 image task
  → 作者确认该任务可使用 Mac 当前用户的文件/命令权限
  → run_local_image 校验 task lease、执行器、设备 owner/novel_id/撤销状态
  → 创建 mode=image invocation 和短暂输入文件
  → companion 以设备 bearer + invocation lease 领取/下载输入/上传 PNG/JPEG
  → 服务端复核图片，完成/失败/超时后清理输入输出暂存
```

设备令牌摘要、项目/owner 归属及 task/invocation leases 都在协议入口重验。输出端限制类型与 20 MiB，并经图片重解码/复核；失败或迟到请求由 lease/state gate 拒绝。World 是当前图片消费方，作者采用候选的职责仍由 World 负责。

## 正确或有边界的既有说明

- `docs/modules/17_account.md` 和 Account README 对 owner 来源、API 不接收 owner、凭据 secret-free 跨域 contract 的概括正确。文本连接“已验证”字段不能扩写为持续可用或真实作者接受。

- 当前正常新文本任务入口使用 Project 账户模型；Assistant 本机设备选择不能把普通文本 turn 路由到本地 CLI，测试源码覆盖此失败。旧 snapshot restore 的拒绝也明确实现。
