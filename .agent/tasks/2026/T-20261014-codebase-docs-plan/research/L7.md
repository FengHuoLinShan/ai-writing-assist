## 结论

- Vue 的实际接线是：认证/外壳启动 → 注册 route loader → hash router 按需加载 island → `mountIsland` 在 `#workspace-content` 挂载 SFC，并把离开守卫交还 router。组件访问 API、状态、router 和 toast 经 Vue bridge。README 与 `docs/modules/14_frontend.md` 对这条稳定边界基本准确，暂未发现值得重写架构段落的漂移。
- 作者正文在输入后立即更新内存，250ms 后尝试本机备份，约 3 秒后自动保存工作稿。服务端保存失败时保留原章和本地备份并允许重试；本机备份也失败时明确提示丢失风险，路由离开要再次确认，页面刷新触发浏览器离开警告。用户指南把“关键内容都有持久化和恢复机制”写成无条件保证，建议补上保存/备份失败时的可见保护边界。
- RP 正文通过服务端 attempt 的可见文本与 offset 接续流；出现重放冲突/缺口会重新读权威 attempt 快照。输入框、私语及部分编辑状态另存当前浏览器；本机写入失败时给警告并保护离开。用户指南可以说明已保存故事段和流的恢复；不要把本地输入草稿也概括成绝不会丢。
- 当前桌面主导航是“写作、人物与世界、故事结构、地图、查找”；手机主导航为“写作、世界、结构、全部”，更多入口另有作品档案与导入、作品偏好、高级生成工具、互动故事和账户设置。Word 源稿仍写六个左侧按钮及旧“更多”三项，已与当前入口不符。主页双入口的主文案仍存在，但启用公开演示时还有额外演示入口。
- RP 的当前可见开关名是“故事自主发展”；第一次启用前明确说明会使用模型额度并等待作者确认。新手指南和 Word 源稿都只写“看海”。建议按界面名称说明，将“看海”至多作为旧称，保留费用与离页停止说明。

静态读取 DOCX 包内 `word/document.xml` 和 `docProps/core.xml`，未执行导出，也未渲染页面。DOCX 共 220 个 Word 段落（212 个非空），标题为“NovelCraft 新用户指南（Word 版）”，章节标题采用“一、第一次使用：三步开始”“二、先认清三个‘总开关’位置”等；主要章节顺序、导航速查表、页面介绍和“看海”说明均与 `word-guide-source.md` 对应。DOCX 内含旧术语“看海”，与 Word 源稿相同；它不是当前较短的 `new-user-guide.md` 八节结构的直接导出。未发现可验证的生成脚本、生成命令或 DOCX 内嵌源稿标识，因此只能证明内容对应关系，不能证明具体转换工具。

建议 P2/P3 将 `docs/product/new-user-guide.md` 定为唯一当前内容源：它已是链接门禁指定的用户指南，`docs/README.md` 也已把它声明为 DOCX 源文。最小完整处理是将现存 DOCX 和 `word-guide-source.md` 明确标为历史/旧版导出，解除“两份可编辑源 + 一份交付件”的歧义；无需为了保留 Word 格式而新生成文件。若产品仍要把 DOCX 当当前交付，再先把其中仍有效且有读者价值的操作说明合入唯一源稿，按源稿重新生成并渲染检查，然后退役旧 Word 源稿。不要把现存 DOCX 当作已由 new-user-guide 生成。

## 最小有价值修订

优先更新用户指南，而不是扩写前端架构文档：

1. 用当前作者导航与 RP 按钮名称改写“点哪里”类说明；删除“今日工作”、六个侧栏按钮和旧“更多”菜单结构等过时定位。主页双入口说明标明公开演示配置可能增加演示入口。
2. 把“刷新/断网不会丢内容”改为可验证的条件式说明：服务端已保存内容和 RP 流有恢复入口；正文保存失败会留在当前章并可重试；若浏览器本地备份失败，应先复制并留在页面，离开确认可能丢失未保存输入。
3. 将 RP 开关称为“故事自主发展”，说明首次启用会先显示额度提示、由用户确认，离开故事页会停止。
4. 统一 Markdown 源稿与 DOCX 的当前/历史标记。若继续发布 DOCX，则由主代理按唯一源稿重新生成并渲染检查；若无明确 Word 交付需求，保留现文件作历史导出即可。本轮没有 DOCX 导出或页面渲染验证。
