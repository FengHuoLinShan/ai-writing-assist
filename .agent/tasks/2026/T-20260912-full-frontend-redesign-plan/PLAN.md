# NovelCraft 全前端重设计计划

状态：已按评审修订稿实施独立全前端预览；实际验证见TASK.md及COVERAGE.md。日期：2026-09-12。已吸收独立评审及汇总裁决中的必要澄清。

## 1. 目标与交付边界

将当前已确认的Apple式设计语言扩展到全部前端：作者工作区、读者体验、身份与账户、设置、AI中心，以及各页面的子视图、编辑态、结果态、浮层和异常提示。

**先完成整套新版前端的设计与交互表达，再单独处理真实业务接回和功能等价。** 设计阶段不以旧功能逐项可用、真实保存成功或真实模型任务完成作为门槛；允许重组导航、合并面板、改变操作路径和将适合的能力纳入AI中心。

沿用 `/prototypes/redesign.html` 作为隔离的新前端工作入口，把它扩展成能遍历全部设计的工作区。覆盖范围以正式前端全部界面为准，不以当前14个示例页面为上限。正式入口接管、后端接入和完整功能验证属于后续独立阶段，不把对现有生产界面的直接破坏当成“先设计”。

交付包括：可操作的新前端、全部界面的覆盖表、页面与状态索引、共享组件展示、浅深色、桌面/平板/手机设计、代表性录屏和评审结果。保留NovelCraft品牌、现有产品和全部WIP；不提交、合并、推送或部署。

## 2. 设计原则

- 延续当前精细层级、系统字体、中文排版、线性SVG和安静正文。以Apple产品的熟悉感和完成度为审美目标，不冒充Apple品牌归属。
- 蓝色引导操作与焦点，紫色表示AI及未采用候选，绿色表示明确完成，橙色表示待决定/可恢复问题，红色用于阻断风险和危险操作。关键状态同时用文字或图标表达，不能只靠颜色区分。封面、人物分类与地图另用内容配色。
- 控制层适度通透，正文及密集资料保持稳定实色；明暗模式分别校准，不只反转颜色。
- 高频操作就地，复杂配置渐进展开。按用户任务组织，避免恢复成旧版菜单和工具栏的集合。
- AI中心承接生成、审查、返修与跨对象整理；普通编辑、保存、查找、导出等操作保留不依赖模型的直接入口。统一入口不改变对象身份、作者决定和结果归属。
- 沿用已有控件动效规则：稳定命中区、连续选择、小幅反馈、可中断面板；正文不反复缩放/重排，输入光标与数值保持稳定。
- 每个页面同时设计常态和适用的空态、加载、失败、冲突、只读、待决定、完成；相同视觉模式复用，语义不能全部化成同一张通用提示卡。
- 保留基础可访问性、键盘路径、焦点恢复、减少动态效果与无模糊回退。它们属于设计质量，不延期到业务接回。

## 4. 执行顺序与阶段产物

### 阶段A：补齐界面清单与信息架构

核对正式路由、子视图、共享浮层和条件状态。覆盖表分开记录两类决定：**设计归属**为独立重设计、合并至明确入口或AI中心内的明确视图；**业务接回状态**另列，不得以“后续接回”代替设计去向。记录原入口、新入口、相关对象、适用状态及返回位置，不冻结原字段顺序、DOM和组件结构。

以写作21项评估为先例，对其他页面做同样取舍。兼容路由、重复工具和通用结果归并，但每项必须有明确去向，不能用“功能后面再说”跳过整个界面的设计。

保存恢复、候选/批次审阅、导入整理和读者生成只摘录设计必须知道的现行语义：当前对象、采用粒度、过期依据、停止/恢复含义及接回耦合点；不提前接API或复制完整业务状态机。既有合同未支持的“部分采用”等行为不得直接当成可用能力。A–F各域同时记录多栏对照、悬停和长内容的移动替代方向，详细适配仍在G。

产物：全站设计覆盖表、导航与页面层级图、通用状态清单。覆盖表区分“状态样式已查看”和“连续路径已验证”，附对应证据与评审结论；同类实例可复用共享模式证据，不机械展开所有组合。该清单是设计范围，不是旧功能测试的新门禁。

### 阶段B：定稿公共设计语言与外壳

整理已有样式与动效，补齐字体层级、语义色、材质、边界、焦点、密度以及窗口/抽屉/比较等模式。确定作者工作区、文档写作、读者阅读三种外壳。

保留当前风格基础，通过浅深色与真实长度中文样例校准。只提取确实跨页面复用的实现，不新增UI框架、动画库或通用状态引擎。

以写作、密集资料、候选审阅三个代表样板校准公共设计，形成可修订的v1：

- 明确中文排版、语义色与浅深色表面、密度和材质的使用依据；设计令牌用于复用，字号/圆角数量及硬编码值扫描仅作诊断，不成为CSS写法门禁。
- 继承已验证的菜单/对话框/非模态面板初始焦点、关闭与还原规则，明确“关闭”和“返回上一步”的区别。保护输入、选区和阅读锚点，允许必要重排，不强制历史栈、逐层Escape或固定面板形态。
- 确定候选身份、原稿与来源、比较、审查、决定和返回的共同表达；区分“待采用候选→采用到工作稿→作者设为正式正文”，以及来源变化和结果已过期。
- 给出空态、加载、失败、冲突、待决定、完成在不同容器内的代表表达；演示标识随结果一起呈现，材质设计同时提供实色回退。

产物：可操作外壳、共享组件与状态展示、公共样板及更新后的设计标准。C做首个完整写作审阅样板，E沿用并扩展领域/批次差异；C结束及D首个密集资料页完成时校准B，发现不适用即可修订，不把“定稿”理解为冻结。

### 阶段C：完成文稿与创作管理设计

顺序为写作→版本/候选/恢复→创作首页与计划→作品档案与导入入口。

优先解决上一轮缺项：标题和正文真正具备本地编辑手感，文稿身份清楚，保存/失败/恢复/正式确认/候选审阅有专属样式。业务动作由显式演示状态驱动，不能只是静态h1或一个没有目标的按钮。

使用B的审阅规则完成首个写作样板，避免E再建另一套候选界面。检查中文输入法合成、撤销、选区/光标、长文滚动与面板切换的本地编辑手感；保存、恢复和正式确认的设计入口可直接操作，不必经过AI对话。

产物：围绕同一虚构作品可遍历的创作桌面，包括正常和高风险状态；不要求真实保存或版本API可用。

### 阶段D：完成世界、结构、场景、地图与查找

顺序为人物与世界→故事结构→场景工作台→地图→查找与证据。

补齐主页面、编辑/详情、筛选/批量、来源、结果和异常。用长标题、多段中文、多列资料、复杂关系和较多条目校准密度，避免所有页面复用同一种大卡片模板。

产物：作者各工作区全部可到达，并能从写作中的人物、场景、地图、结构和来源进入相应设计视图，再返回原设计上下文。

### 阶段E：统一AI中心、审阅与任务表达

将重复AI入口归并到同一设计体系，提供自然语言输入和少量意图快捷项。用实际候选/来源/审查/结果结构设计“开始→进行中→待决定→结果/失败”的界面表达。

沿用C的候选审阅样板，扩展不同领域与批次的必要差异。候选审阅可从文稿或待决定入口重开；任务进度可从当前页或任务入口查看，同一示例对象从不同入口进入时呈现一致的身份和状态。批次部分完成、来源变化、结果过期、返修、停止与恢复各有明确表达；已失效结果不显示可直接采用的假象。助手不能只剩聊天气泡，普通保存/搜索/导出也不能变成必须聊天才能操作。

长结果、并排比较与问题定位须可阅读、可扫描；等待与流式节奏明确为设计假设，后续真实业务接回时校准，不用定时进度证明任务完成。

产物：AI中心、候选及批次审阅、任务反馈、导入整理全流程样板。调用真实Agent和领域工作流延期。

### 阶段F：完成读者、账户与辅助流程

完成互动故事列表、来源准备、身份/开场、阅读/输入、分支、回顾、约定和恢复；随后统一登录、账户、模型连接、作品偏好、主题资源与帮助。

这些流程必须使用和作者页相同的组件质量，但保留独立的读者节奏。阅读壳同步给出手机主任务与控制收纳草案，供G深化。不要把账户/导入/失败处理留在旧风格里。

产物：全站没有未纳入新设计的现行入口；辅助流程能够通过示例状态完整查看。

### 阶段G：平板与手机设计

在桌面样板基础上按设计域重组平板和手机布局，允许修订先前桌面决定并回写覆盖表。平板优先保留必要对照，手机以当前任务为中心；章节/资料/任务使用可返回的抽屉或独立视图，不把桌面面板全部压缩成窄列。

先做G1：写作和互动阅读两个代表场景，校准软键盘、选择、抽屉/独立页和比较方式；再做G2：将适用模式扩展到其余设计域，处理密集资料及地图/关系图的差异。涉及拖动时提供可操作的非拖动替代，不靠悬停才能发现必要操作。

补软键盘空间、触摸热区、长标题、多行工具项、横竖屏、选区与滚动连续性。移动端保留完整正文编辑能力；只读历史和候选审阅沿用相应状态表达。二维地图/关系图使用合理的局部浏览方式。

产物：各设计域在桌面、平板和手机都有明确方案。C–F验收桌面样板，G/H再验收设备设计。实机清单包括软键盘下输入/选区、抽屉焦点返回、触控操作、阅读安全区和横竖屏；设备不可用时可交付设计及待验证清单，不能标记实机通过，后续具备设备条件时逐项核验。

### 阶段H：整站评审、修正与设计交付

逐页检查视觉层级、颜色职责、组件一致性、交互反馈、长内容、浅深色、键盘、浮层中断、快速切换、减少动态效果与无模糊路径。记录关键动效的中间帧，修复文字塌陷、残影、焦点丢失、布局跳动与状态混淆。

安排独立设计评审，对照Apple式精细层级与当前产品任务评估实际效果；反馈按影响修正。评审范围是设计质量，不能将“业务尚未接回”当作失败，也不能将一个好看的首页当成全站完成。

除逐页查看状态，至少录制三条会话内连续路径：①编辑示例→查找/来源→返回原章和编辑位置；②候选审阅→离开→从待决定重开同一候选→决定→返回正文；③阅读→设置→回到同一旅程位置。检查示例对象、输入、选择和适用返回位置，按需扩展导入与任务路径；无需真实模型、任务服务或跨刷新存储。

产物：覆盖表、代表截图/录屏、独立评审、实际验证记录，以及单独的后续业务接回清单。

## 5. 原型的交互与数据边界

**设计阶段做：** 页面导航、菜单、页签、筛选/选择、输入编辑、面板开关、主题、侧栏、专注、对比展示、必要的局部交互以及手动状态切换。保持示例对象和返回位置一致，让界面能被真实操作评阅。

**设计阶段不要求：** 正式路由接管、完整API接线、真实账户/作品读写、真实上传/下载流程、真实LLM生成、跨刷新持久化、任务服务恢复或完整业务幂等验收。

使用统一虚构内容和少量内存示例数据，允许会话内连续操作与预置流程状态。为评审提供简单的页面/状态入口参数（如查询参数），仅在初始化时读取；刷新恢复该入口的初始示例，不持久化编辑，不新增路由框架。状态展示器也能直接进入待检查页面/状态。不新增模拟后端，不用定时器伪装真实任务完成，不读取真实密钥或作品存储。“已保存/已采用/已连接”等结果必须标明演示。

功能延后不等于修改真实产品的保护规则：现行鉴权、项目隔离、确认、保存恢复、并发/幂等测试继续保留。设计完成后再按新路径接回这些能力。
