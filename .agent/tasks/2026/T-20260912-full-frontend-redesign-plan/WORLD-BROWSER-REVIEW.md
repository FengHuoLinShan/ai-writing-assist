## 发现

### P1：关系候选“查看差异”打开错误对象

可复现步骤：

1. 进入“人物与世界”→“关系”→“关系审阅”。
2. 点击第一条“林舟 与 沈雁”的“查看差异”。
3. 弹出的“审阅世界资料”比较面板标题为“落潮时出现的石路”，来源范围为“白沙港 · 地点资料”，正文差异也是白沙港的石路内容。

实际候选是“共同守着灯塔熄灭的秘密”，来源为“第三章 · 潮汐之间”；比较面板没有携带该候选身份。

### P1：别名候选“查看差异”同样打开错误对象

可复现步骤：

1. 进入“别名”。
2. 点击第一条“守塔人 → 沈雁”的“查看差异”。

结果仍为“落潮时出现的石路 / 白沙港 · 地点资料”比较内容，而不是“守塔人”别名候选。说明比较入口当前统一使用默认主壳候选，关系、别名及待决定候选均存在身份错配风险。

### P2：世界书重扫后全局错误提示仍在

以 `?page=world&state=error&section=世界书` 进入，点击“重新扫描示例”后，世界书自身显示“示例目录已重新扫描”和准备好的候选内容，但页面顶部仍显示全局“最新资料暂时无法读取 / 重试读取示例”。局部成功和全局失败同时可见，容易让作者误以为重扫没有恢复。该现象不阻断目录页操作，但建议重扫成功后同步清除或降级全局错误状态。

复验时间：2026-09-12；使用 Chrome 独立临时标签，桌面内容视口约 1163×654（浏览器显式设置 1280×720 后的可用内容区）。

- 关系审阅第一条“林舟 与 沈雁”点击“查看差异”后，比较面板现在标题为“林舟 与 沈雁”，来源为“第三章 · 潮汐之间”，正文原文/候选建议均对应关系候选。
- 别名审阅第一条“守塔人 → 沈雁”点击“查看差异”后，比较面板现在标题为“守塔人 → 沈雁”，来源为“世界资料 · 人物整理”，候选建议为附着到已有对象“沈雁”。此前两处错误默认对象已修复。
- 别名第二条过期候选“旧港 → 白沙港”确认按钮仍禁用；点击“拒绝这项”后，待决定从 2 项降为 1 项，项目移入“已处理 / 已拒绝”，并显示“重开差异”。点击重开可恢复同一候选身份，面板显示“旧港 → 白沙港”、来源“第二章 · 一封迟到的信”、来源已变化且暂不能采用。
- 对关系第一条候选执行“状态演示 → 审查通过 → 确认资料候选”后，候选从待决定移到已确认；关闭比较面板后原触发点已移除，焦点实际落在 `main#rd-main`，符合触发点消失时的焦点回退要求。
- 以 `?page=world&state=error&section=世界书` 进入并点击“重新扫描示例”后，顶部全局错误提示和目录局部错误提示均消失；同时出现“示例资料已重新载入”和“示例目录已重新扫描”成功反馈，无错误/成功共存。

修复后定点结果：四项均通过；未重做整站浏览器审查。
