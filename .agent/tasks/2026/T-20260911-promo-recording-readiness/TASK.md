## 目标与验收

### 目标

用既有演示项目完成一条“长篇结构化管理 → Agent 自然语言调用 → 基于作品资料的私人 RP”宣传主片设计。以真实展示任务反向检查、补强后端能力和前端流程，使实施结束后，用户按录制清单操作即可获得主要产品素材。

核心表达：**把长篇写清楚，把故事走进去。**

封面标题：**AI 长篇小说创作系统。**

辅助表达：**人物、关系、剧情有据可查；一句话调动创作系统；整理好的世界成为私人 RP 的基础。**

目标用户：A 长篇作者，B 想进入作品世界的 RP 用户。产品假设是结构化成果能增加作者掌控感，Agent 能减少查找入口和搬运资料的负担，资料绑定能让 RP 开场更有依据；不把这些假设写成已经量化证明的效率或质量承诺。

### 两个完成层级

1. 本轮计划交付：完整剧本、逐镜头展示契约、现状/缺口核查入口、分阶段实施、验证门禁及录屏操作册模板均齐备。
2. 后续实施交付：全部主镜头通过真实浏览器演练，涉及生成的镜头经真实模型运行；素材对应的产品版本、数据、入口、动作、保存与恢复证据齐全。用户无需临时改数据库、写提示词模板或手工拼接界面即可录屏。

最终视频剪辑、配音、音乐、字幕制作与对外发布不属于本轮计划编制；后续实施须交付录屏就绪包及一次完整彩排录屏，商业成片可以在此基础上制作。不自动授权部署、付费素材采购或公开传播。

### 非目标

- 不新增宣传专用假数据 API、自动表演模式、只为截图存在的产品页面或“演示时必成功”分支。
- 不另建全套前端、不更换框架或全站视觉系统、不为视频增加多 Agent 产品运行时。
- 不把完整导入过程、所有设置页、所有生成工具、看海/联网研究/生图同时塞入主片。
- 不扩展 RP 公开分享、跨作品混合、自动写回作者正史、实时同步所有作者变更等产品语义。
- 不重新创建/清空既有诡秘验收项目，不为漂亮结果删掉待确认项、关闭安全门禁或篡改源文。

## 封面驱动的宣传设计 v2

详细设计、90秒主片剧本、30秒/15秒剪辑版、逐镜头能力契约、录屏规则和发布文案统一维护在 [封面驱动宣传方案](artifacts/cover-led-promotion-plan.md)。旧120秒脚本被本版本替代，不再作为实施依据。

新版结构为：

1. 封面建立“AI长篇小说创作系统”的承诺。
2. 真实产品依次兑现正文、人物、关系、剧情和地图的基本功。
3. Agent 用自然语言完成查证与可确认的工作稿，证明低使用门槛。
4. 同一作品资料成为私人RP的起点，展示行动、分支和恢复。
5. 回到封面，以“把长篇写清楚，把故事走进去”收束。

主片缩短为90秒。封面材质只用于视频包装，产品界面延用现有视觉系统；不开发宣传主题、伪数据接口或专用演示页。

3. 对 S03–S10 建立事实/素材清单：事实短述、对象/章节锚点、来源版本、可见范围、是否示意、权利状态。内部 ID 仅存脱敏证据，不能出现在面向作者的字幕。
4. 核实是否已有 ready 的作品资料版本及可用剧情点。若没有，走原准备流程，先评估未完成整理/歧义和模型成本，不跳过门禁，也不为60章项目清空或重导入。

交付：`artifacts/baseline.md`（脱敏环境与素材矩阵）、确定的 RP 剧情锚点、现状缺口清单。公开素材权利待确认时仍继续内部验收。

### P1：先跑通主片最重要的三个闭环

依次真实演练：①人物→关系/结构→原文；②助手查资料→拟地点工作稿→确认保存→刷新打开；③同作品资料→指定位置→原创身份→行动→分支→恢复。

先验证入口与数据，再读真实调用链、所有调用方和模块 README 定位根因。每个缺口写清镜头 ID、实际/期望、所在层、最小修复与测试；不能因“剧本需要”直接判定要新增 API。

主片硬阻塞：S04/S07 查不到依据，S08 只有文字无成果，S09 绑定资料未就绪或需手工数据库绕过，S10/S11 串分支、恢复失败或写回源作品。必须修复或明确阻塞，不能剪掉后宣称完整交付。

地图需保留“示意”时按事实拍摄；若地图存储等非核心依赖长期不可用，可先完成其余镜头，但本计划的全量验收仍不完成；删镜属于显式范围调整。

### P2：按展示契约补强代码与前端

按“证据和正确性 → 保存/恢复 → 操作路径 → 视觉可读性”顺序修复。每次改动必须对应至少一个镜头验收项，除直接调用链和安全回归外不做全库清理。

- 后端复用各领域 facade/contracts，助手只组织任务和确认；来源、截止、项目隔离、事务、幂等、候选/正式资产保持原归属。
- 前端优先修复结果入口、状态用语、邻近来源展示、返回恢复和步骤摘要，保持作者壳和 RP 壳独立。
- 如存在从作者到 RP 的导航断点，先复用互动故事选择作品入口；确需便捷入口时只预选作品，不静默创建旅程/扩大资料范围，不新建另一套开场向导。
- 尽量保留数据库 schema。确实涉及 schema/契约的缺口按现有迁移、兼容和文档规则处理，不因宣传任务规避门禁。
- 同步受影响模块 README、前端流程文档及必要 Prompt 契约；不为留痕修改无关权威文档。

交付：按镜头归因的代码 diff、对应测试、修复后截图/回执。旧 UX 修复只复用，不重复列为本次新增成果。

### P3：真实数据与真实模型验收

1. 在确认过的专用复制库跑当前应用；先完成自动化失败路径验证，再真实浏览器逐镜头走通。
2. S07 验证普通问法的检索结果及来源；S08 验证真实模型调用领域工具并持久保存；S09–S11 验证真实 source-bound RP，不允许用纯模型知识路径代替。
3. 固定一套来源、模型配置和素材起点，做至少两次有限的关键链路试跑，记录成功/失败及真实耗时；不要求模型逐字相同，不无限重抽直到挑出漂亮样本。失败继续根因排查并如实记录。
4. 新手代理任务：给未熟悉项目的人三个自然语言目标，观察是否能找到人物依据、保存草稿、开启/继续旅程。无人可参与时记为操作代理验收，不冒充真实用户研究。
5. 验证桌面、窄屏、键盘和数据保护；记录画面可读性与模型质量分别是否通过。

交付：`artifacts/acceptance.md`，逐项证据、实际时间/版本和未验证项。两次样本不等于稳定性统计或“减少出戏”盲评结论。

### 工程验证

- 非平凡实现开始前 `make docs-check`；结束运行 `make docs-check BASE_REF=origin/main` 和 `git diff --check`。纯计划本轮只运行文档门禁与差异检查。

- 后端按实际改动跑 Assistant、Evidence、World、Story、Writing、Interaction 受影响测试；共享 gateway 或核心变更扩大对应回归。完整测试命令在实施定位后从 testing-guide 选定并写入验收记录。
- 变更路径完成 Python lint、前端 lint/build；分支隔离、源版本失效、确认幂等、保存并发需要真实 PostgreSQL 覆盖。沿用现有专用库门禁，不对验收原库运行重置型 E2E。
- 实际覆盖至少包括：未 ready 禁止开始；同 owner 合法绑定/跨 owner 拒绝；截止后证据不进入资料；未选分支不进入后续上下文/回顾；取消草稿不写入；409 不丢输入；保存后刷新；网络失败恢复；原作数据不被 RP 更改。
- “资料范围正确”与“模型输出绝无剧透”分别验收；模型自身知识仍可能带来风险，不宣传百分百防剧透/永不失忆。

### 展示指标（本任务目标，不是已测结果）

| 指标 | 就绪要求 |
|---|---|
| 来源可达性 | 从可见结果至原文不超过2个明确动作；原文能对应当前对象/关系/回答 |
| 助手低门槛 | 两轮普通语言完成查证和草稿准备；保存保留必要确认；无手工复制来源、工具名/ID/JSON输入 |
| RP 开场 | 已准备作品下，经现有4步以内向导完成资料/位置/身份选择；不要求维护作者对象/Prompt；准备任务真实耗时单列 |
| 成果真实 | 助手草稿、旅程与分支均可刷新/回访；仅有 toast 或聊天宣称不算通过 |
| 流程恢复 | 离开后重新打开，当前选中分支、已显示正文、用户输入和合理阅读位置可恢复 |
| 录屏可读 | 桌面与竖版素材中的关键姓名、关系、来源、行动无需暂停放大才能辨认；每个关键信息至少保留约2秒 |
| 功能反馈 | 所有实际长任务有真实状态、失败说明及适用恢复入口，不设虚假完成时间 |
| 内容一致 | S03–S10 复用同一已核实人物/地点/事件链，不为不同镜头偷换作品或数据 |
| 材料可复拍 | 每镜头有确定起点、动作、停止点、重录路径及素材文件；不依赖开发者现场介入 |
| 数据保护 | 原始验收项目保留；新增演练成果有清单；源作品与 consumer 的写入边界经验证 |

没有真实用户数据时只能说“对话可以调用这些功能”，不能把以上目标换算成“效率提升X倍”。模型连接仍是前置条件，在录屏说明写明，不把省略设置过程说成无需设置。
