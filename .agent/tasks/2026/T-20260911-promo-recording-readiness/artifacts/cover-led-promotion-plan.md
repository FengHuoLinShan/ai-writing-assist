# NovelCraft 封面驱动宣传方案

状态：宣传设计稿，待按真实产品、演示数据与模型输出复验后封稿。

封面母版：[cover-master.png](cover-master.png)（1024×1536，SHA-256 `6b1727e989a557f72a1e57105d2e78b5e1bf10fa1dd2fde3f51050fbe0dee4db`）。

## 1. 宣传主线

封面已经给出了完整的产品叙事，不需要再另造一个概念：

1. 打开的书和执笔的手代表作者拥有创作权。
2. 人物、关系、场景、章节、时间线、地图和资料代表长篇结构化管理的基本功。
3. 中央 AI 核心代表 Agent：理解当前目标，查找依据，组织工具和结果。
4. 从书页中展开的世界代表基于作品资料的私人 RP。
5. 金色路径代表作者真正选择的发展；蓝色节点代表可回读的资料与来源。

因此，统一叙事改为：

> **把长篇写清楚，把故事走进去。**

封面主标题继续使用“AI 长篇小说创作系统”。视频和正文用三个可验证承诺展开：

- **写清楚**：正文、人物、关系、剧情、时间与地点形成可追溯的故事结构。
- **推进它**：直接说出创作目标，Agent 查资料、组织步骤、准备可审阅成果。
- **走进去**：选择作品资料版本与剧情位置，以自己的身份进入私人分支。

“会聊天”“自动写作”“记得设定”不单独作为卖点。真正需要演示的是：回答能打开来源，方案能形成工作稿，RP 使用指定作品资料和选中分支。

## 2. 封面使用规则

### 视觉角色

- 暖象牙白：背景和呼吸空间。
- 深海军蓝：标题、正文和产品可信度。
- 雾蓝：资料节点、结构和空间。
- 香槟金：作者选择、确认和当前发展。
- 半透明面板：只用于视频包装中的信息层，不要求产品界面改成玻璃风。

产品录屏保持现有品牌和真实界面。封面色彩只用于字幕、章节转场、光标强调和结尾卡；不为宣传制作产品专用主题。

### 静态封面

- 2:3 母版保持原图完整，不叠加功能角标。
- 封面本身没有明显的 NovelCraft 品牌名。平台标题、发布正文和视频结束卡必须出现 `NovelCraft`；母版不因这个问题临时重绘。
- 9:16 使用完整母版居中，上下扩展暖象牙白，不裁掉左上标题、执笔双手和底部标语。
- 4:5 使用完整母版居中，两侧补暖象牙白；允许轻微放大，但不得裁掉标题或笔尖。
- 1:1 只作信息流预览：截取上半部“标题＋AI 核心＋结构面板”，并在发布正文补全 RP 主张；它不是新的主封面。
- 16:9 缩略图使用“左侧标题与一句主张、右侧完整竖版封面”的版式。不要把整张竖图直接缩到中央，导致文字无法阅读。

### 动态开场

只使用最小包装：静帧淡入、2% 缓慢推近、金色路径一次点亮。之后用封面面板与真实产品的匹配剪辑进入录屏。无需拆分整张图做复杂 3D，也不生成伪产品画面。

匹配关系：

| 封面元素 | 真实产品画面 |
|---|---|
| CHAPTERS / SCENE | 正文、章节与场景定位 |
| CHARACTERS / RELATIONSHIPS | 人物资料与关系依据 |
| TIMELINE / PLOT STRUCTURE | 剧情结构、进展与章节回查 |
| MAP / SETTING | 地图、地点与来源/示意状态 |
| AI CREATIVE CORE | 项目助手的自然语言查证和成果准备 |
| 书页中展开的世界 | 使用作品资料开启私人旅程 |
| 金色路径 | 当前选中的 RP 发展 |

## 3. 内容矩阵

一次录屏产出五类内容，不为每个平台重新演示一套产品：

| 内容 | 时长/比例 | 任务 | 封面用法 |
|---|---|---|---|
| 主片 | 90 秒，16:9 母版 | 完整证明“结构 → Agent → RP” | 首尾完整出现 |
| 作者版 | 30 秒，9:16 | 强调长篇结构与 Agent | 开头完整，结尾上半部裁切 |
| RP 版 | 30 秒，9:16 | 强调资料基础与私人分支 | 以书页世界局部开场，结尾完整 |
| 15 秒钩子 | 15 秒，9:16 | 建立记忆，不承担完整证明 | 封面 → 三次匹配剪辑 → 封面 |
| 静态帖 | 2:3 / 4:5 | 发布理念和招募反馈 | 使用原封面母版 |

## 4. 90 秒主片剧本

实际人物、地点、关系、章名和 RP 起点在产品复验后替换；表中不要求模型生成固定台词。

| 镜头 | 时间 | 画面与实际操作 | 旁白/屏幕文案 | 必须证明 |
|---|---:|---|---|---|
| S01 | 00–04 | 封面完整淡入，轻推近中央 AI 核心 | “AI 长篇小说创作系统。” | 产品类别与视觉记忆 |
| S02 | 04–10 | 封面 CHAPTERS/SCENE 面板匹配切到真实项目正文和章节目录 | “一本长篇，真正难的从来不只是写下一段文字。” | 这是实际产品，不是概念图 |
| S03 | 10–18 | 当前章定位、场景和版本状态；打开一处正文 | “正文、章节和场景，需要始终找得到。” | 章节定位、版本/保存状态真实可读 |
| S04 | 18–27 | 搜索人物，打开局部关系，查看一条关系的原文依据 | “人物为什么成为今天的他，关系从哪里开始，都能回到原文。” | 名称命中、关系方向、来源回读 |
| S05 | 27–36 | 剧情进展跳回章节，再切地点地图 | “剧情、时间与地点，组成同一个不断变化的世界。” | 结构与正文相连；地图明确来源或示意 |
| S06 | 36–41 | 项目概览或三组真实页面快速收束；一条金色包装线贯穿选中项 | “先把世界写清楚，故事才走得更远。” | 结构不是孤立卡片；金线只作剪辑强调 |
| S07 | 41–53 | 打开项目助手，用普通语言要求核对一个已确认素材事实并给出来源；打开来源 | “不熟悉菜单也可以。告诉助手你想做什么，它会查资料，带着依据回来。” | 普通语言、真实查证、可打开来源 |
| S08 | 53–62 | 要求整理为地点/人物资料工作稿；查看预览、确认保存、打开工作稿 | “它负责组织步骤和准备成果；什么进入作品，由你决定。” | 具体预览、确认、真实保存、候选与正式内容分开 |
| S09 | 62–71 | 进入互动故事，选择同一作品资料、剧情位置和原创身份 | “而整理好的作品资料，还能成为私人旅程的起点。” | 冻结资料版本、剧情范围、身份选择 |
| S10 | 71–81 | 发送自然语言开场/行动，展示真实流式故事，再输入下一步行动 | “选择故事走到哪里，再以自己的身份行动。” | source-bound RP、自由输入、真实生成 |
| S11 | 81–86 | 在同一分岔选择另一发展，再切回原路线 | “每一个选择，都会长出不同的发展。” | 两条真实分支、当前选中态和历史保留 |
| S12 | 86–90 | 金色选中路径回到封面笔尖，切独立结束卡 | “NovelCraft。把长篇写清楚，把故事走进去。” | 品牌、主张与前面证据闭环 |

结束卡只保留三行：`NovelCraft`、`把长篇写清楚，把故事走进去`、一个实际可用的行动入口。没有开放试用入口时使用“关注开发进展 / 告诉我你最想解决的长篇难题”，不放虚假按钮。

## 5. 剪辑版脚本

### 30 秒作者版

- 00–03：封面标题。
- 03–10：正文/章节 → 人物 → 关系依据。
- 10–16：剧情进展 → 地图。
- 16–25：一句自然语言查证 → 打开来源 → 工作稿确认。
- 25–30：结束卡：“长篇有结构，创作有依据。”

旁白：

> 长篇真正难的，不只是写下一段文字。人物、关系、剧情、时间和地点，都需要长期保持联系。NovelCraft 把这些基本功放在同一个创作系统里；你也可以直接告诉助手想做什么，让它查资料、准备成果，再由你决定是否采用。

### 30 秒 RP 版

- 00–04：封面书页世界局部 → 已整理的作品资料。
- 04–10：人物关系及来源，证明 RP 有资料基础。
- 10–17：选择作品版本、剧情位置和原创身份。
- 17–25：自然语言行动与故事生成。
- 25–30：切换另一发展 → 结束卡。

旁白：

> 当人物、剧情和世界资料准备好，它们也可以成为私人故事的起点。选择从哪里开始，以自己的身份行动；不满意，就从那个选择走向另一种可能。私人分支会保留，但不会改写原作。

### 15 秒钩子

屏幕文案依次为：

1. “先把长篇写清楚。”
2. “再用一句话调动整个创作系统。”
3. “最后，走进自己的故事。”
4. “NovelCraft”

这条短片不解释全部边界，发布正文链接到主片。

## 6. 产品能力和前端展示契约

封面上的能力必须在产品里有对应证据。已有能力先复验，复现缺口才改代码。

| 镜头 | 产品能力 | 前端必须呈现 | 失败/恢复要求 | 主要入口 |
|---|---|---|---|---|
| S03 | Writing 正文、章节、场景、版本 | 当前章可见，保存/正式状态不矛盾，来源文本可读 | 切章/刷新恢复位置；未保存内容受保护 | `vue/views/writing/`、Writing |
| S04 | World 人物/关系 + Evidence | 名称/别名优先；关系方向和具体类型；原文邻近可达 | 无定位依据时明确待核对；返回保留搜索与位置 | `WorldLibrary*`、`WorldBibleKnowledgeGraph.vue`、World/Evidence |
| S05 | Story 结构 + World 地图 | 进展可回到章节；地图首屏可读；示意位置有标记 | 未知坐标留空；历史/冲突不丢当前状态 | `Outline*`、`MapWorkspaceView.vue`、Story/World |
| S06 | Project/作者工作区概览 | 同一项目的当前任务和资料关系可理解，不暴露内部 ID | 局部数据失败不宣告全部完成 | 既有项目概览，不新增宣传仪表盘 |
| S07 | Assistant 查证 + Evidence | 普通语言输入；真实阶段反馈；答案附可打开来源 | 无证据明确不足；断线/超时保留请求与恢复入口 | `ProjectAssistant.vue`、Assistant/Evidence |
| S08 | Assistant 组织领域工作稿 | 具体预览、影响对象、确认保存、保存后打开成果 | 取消不写；冲突保留内容并重新查证；重放不重复写 | `AssistantValue.vue`、Assistant operations、World draft facade |
| S09 | source-bound RP 准备 | 作品、版本、就绪状态、剧情位置、身份摘要可见；高级固定资料次级展开 | 未就绪可恢复；不静默换源或扩大剧情范围 | `RpSourceSetup.vue`、Interaction source service |
| S10 | RP 流式生成与行动 | 连续阅读为主；输入邻近；生成/停止状态真实 | 已见正文不因断流丢失；重复触发不重复计费任务 | `InteractionView.vue`、Interaction services |
| S11/验收 | 不可变消息树、分支选择、旅程恢复和源作品隔离 | 当前发展有文字状态；其他发展就地可达；重新打开回到当前路径和合理阅读位置 | 晚到结果不切换当前路径；切回不重新生成；私人故事不写回作者正文/World/Story | `InteractionView.vue`、Journey list、branch/attempt services 与隔离测试 |
| S01/S02/S12 | 封面与后期包装 | 只承接前述真实证据，不伪装成产品功能 | 包装失败不影响核心说明与产品操作 | 剪辑工程，不进入产品代码 |

共同前端要求：一屏一个主要动作；来源和结果在相邻层打开；技术字段折叠；加载阶段可证实；保存只在持久化成功后宣告；键盘焦点和返回位置可恢复；1440×900 与 390/360 CSS 像素下核心任务可完成。

## 7. 录屏与后期规则

- 产品录屏使用真实浏览器、真实数据和真实模型结果。允许剪掉等待，但须标注“过程已加速”。
- 旁白描述结果时，画面必须能看到对应证据。不要在人物页旁白“全书一致性”，也不要在聊天回答旁白“已经保存”。
- 封面金线、节点高亮和文字标题属于后期包装，不能覆盖真实错误、伪造点击或冒充产品动画。
- 产品界面不强行套封面的玻璃材质；录屏通过裁切、局部放大和匹配剪辑建立统一感。
- 每个关键信息至少停留约 2 秒。竖版另排字幕和局部画面，不把 16:9 桌面整屏缩小。
- 正文引用只展示证明当前操作所需的短范围；公开发布前完成素材权利核对。
- 音乐采用克制的钢琴/弦乐与轻微机械脉冲；Agent 出现时增加节奏，不用强烈科幻音效压过作者气质。

## 8. 发布文案

主标题：

> **一本长篇小说，怎样变成一个可以走进去的世界？**

发布正文：

> 长篇创作真正难的，不只是写下一段文字。人物会变化，关系会推进，伏笔要回收，地点和时间必须彼此成立。NovelCraft 先做好这些基本功：让正文、人物、关系、剧情和来源形成可追溯的故事结构。然后，你可以直接告诉 Agent 想做什么，让它查资料、组织步骤、准备成果；最终是否采用，仍由作者决定。整理好的作品资料，还可以成为私人 RP 的起点——选择剧情位置，以自己的身份进入另一条只属于你的故事。

互动句：

> 你最希望它先解决哪件事：整理人物关系、找回伏笔，还是走进自己的故事？

不使用“自动写完整本书”“永不遗忘”“彻底杜绝剧透”“最强一致性”等未经验证的正文承诺。封面已有的情绪化文案不扩展为功能声明。

## 9. 录屏就绪门槛

宣传方案只有在下列证据齐备后才能封稿：

- S03–S05 的人物—关系—剧情—地点来自同一条已核实资料链。
- S07 的普通问法能返回并打开正确来源。
- S08 的确认产生可刷新打开的真实工作稿，取消和冲突路径不丢内容。
- S09 使用 ready 的冻结作品资料版本和明确剧情位置。
- S10 是真实 source-bound RP，不以纯模型知识旅程替代。
- S11 切换后只有选中分支进入后续上下文，旧发展仍可找回。
- 重新进入旅程后正文、当前分支和阅读位置可恢复，源作品未被私人剧情改写。
- 完成 90 秒主片的一次连续彩排，并能从同一批原始录屏剪出两个 30 秒版本。
- 公开版封面、引用、图片和正文范围通过素材权利检查。

## 10. 本轮刻意不做

- 不开发宣传专用主题、仪表盘、动画模式或伪数据接口。
- 不为了匹配封面而把所有工作台改成透明卡片。
- 不在产品里实现后期金线、景深、光晕和标题动画。
- 不额外制作 3D 封面动画；静帧、推近和匹配剪辑足够支撑首版。
- 不要求 RP 用户先学习作者后台；视频用剪辑说明资料基础，实际入口仍保持独立。
