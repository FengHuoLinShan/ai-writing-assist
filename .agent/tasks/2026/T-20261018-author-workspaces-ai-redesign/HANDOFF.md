## 3. 产品交付要求

### 3.1 写作台

- 四条高频路径：“查这里”打开对象、前文和依据并可固定参考；“修改这里”从选区填写意图和保留项；“想下一步”连接短期前瞻与导演探索；“检查本章”将可定位意见送入批注修订。
- 正文编辑器保持稳定。资料栏突出本场与固定参考，批注和前瞻按当前任务展示，避免全部纵向堆叠。长讨论、审稿、导演可临时扩大工作空间。
- 窄屏一次突出一个主工作面；开关助手、切断点、切主题后恢复正文位置、选区、未发送要求和候选，不重建编辑会话。
- 局部修改组提供差异比较及整章对照。重叠或语义依赖修改成组；无法可靠拆分时只支持整组。
- 选择修改组后由服务端组成新的完整候选，重新执行适用治理与独立审查，再走原采用入口。改变选择即使原批准与审查失效，不把界面勾选直接解释为合法正文写入。
- 采用后继续手改；撤销采用沿用历史恢复。有后续编辑时先比较，不静默覆盖新文字。修订范围外正文保持一致。
- 系统审稿、剧情探索结束后提供回到原文、比较修改、存为参考的明确出口；候选思路不自动变成已发生剧情。

### 3.2 世界对象

- 保留“资料库／关系／待处理资料”，详情按“概览／设定档案／关系／经历与来源”组织。经历组合现有只读资料，不新建另一份经历事实；未覆盖项说明并链接原领域。
- 概览承载名称、类型、简介、状态和高频操作；稳定设定进入档案面向；剧情时点状态进入所属领域。合并重叠入口时保留旧字段兼容，不搬迁事实存储。
- 对象与档案条目提供就地提问，分别支持解释和来源、检查缺漏、构思方案、准备修改、教我操作。
- 对象内添加关系，统一关系新增、修改、结束有效期、移除和恢复的预览与回执。结束有效期与删除是不同操作；移除仍遵守删除人工确认边界。
- 对象表单和档案编辑增加按账户／作品／对象隔离的本地草稿保护。刷新恢复核对服务端版本；冲突保留双方内容，备份失败明示并保留保护路径。本地备份成功不显示为服务端已保存。
- 保留查询、筛选与返回定位；明确本页选择和全部匹配范围。大库继续采用分页，关系图只作为任务视角，精确维护保留文本列表。
- 全库整理先冻结服务端目标清单，分页检查、分组处置；同名只是查重线索。已有专项查漏流程保留其授权、恢复和实际回执。

### 3.3 共用协作与跨页返回

- 正文进入对象快览／详情后能回到原段；对象影响查询能定位相关正文，区分字面提及、证实依赖与待核实影响。
- 正文修改涉及世界设定时形成关联但独立的领域提案。分别显示拟修改、已修改、未完成和已失效，不声称跨域整体事务或整体撤销。
- 上下文摘要展示当前焦点、提供给助手的资料、叙事截止／角色视角、保存版本和关键遗漏。详情按需展开；提供过资料不等于模型真正利用或结论正确。
- 临时草稿讨论不得产生可直接执行的正式事实批准；保存后基于已保存版本重新准备预览。旧任务仍绑定提交时来源，移动光标或切换对象不改变其目标。
- 产品操作帮助使用版本化短说明，绑定真实导航和能力条件，覆盖查找、档案、关系、采用、时间范围和恢复。能力不可用时说明实际原因，不靠模型猜路径。
- 保留独立手动操作。提醒按既有来源／问题标识关联，保存风险及时反馈，风格建议按需查看；不新增默认持续打扰或自动全库改写。

## 4. 自动修改的完整契约

### 4.1 决策链

依次执行：确定性权限和任务范围检查 → 准备具体修改预览 → 独立轻量模型判断 → 执行前重验 → 原领域执行 → 回执和恢复。

借鉴 Claude Code 的权限规则先于分类器的结构，而非复制任意命令权限。参考：[官方 auto mode 文档](https://code.claude.com/docs/en/auto-mode-config)，于 2026-10-18 核查。以下具体规则是本产品决定，不声称官方产品提供相同领域能力。

开启自动模式时展示并冻结任务目标、允许对象／章节、保留要求、预算与停止条件。判断器读取作者要求、修改差异、来源、影响、恢复能力和已完成操作，只能返回：

| 决定 | 行为 |
| --- | --- |
| 允许执行 | 为当前具体预览生成绑定回执，再重验并执行 |
| 需要作者决定 | 保留输入和预览，解释缺少什么或存在何种创作取舍 |
| 拒绝执行 | 不执行，展示违反的明确约束及可调整范围 |

模型不生成额外操作、不扩范围、不自授权限。作品、网页、候选和工具输出均是证据数据，不能提供新授权。分类器不是文学审查器，不能替代原正文质量、知识与事实审查。

### 4.2 绑定、并发与撤回

- 批准绑定 owner／作品／任务、目标集合、预览指纹、来源版本、授权版本、操作版本和判断策略；任一变化重新准备／判断。
- 原 owner、novel 隔离、Evidence confirmation、角色知识、预算、独立审查、CAS、幂等和事务在执行端继续检查。
- 模式撤回使排队和未执行批准失效；正在写入的事务按实际回执收尾。页面“停止”不等于撤销已完成操作。
- 已执行项凭幂等键返回原结果；未知结果先读领域回执，不盲目重试。判断超时、无效输出、模型不可用或未知用量转人工处理，不放行或重新开任务绕过账本。
- ActionBatch 与 Goal 共用批准判断，现有浏览器／API 执行入口都不能只相信客户端传来的“已批准”。作者手工直接编辑维持原有流程。
- 现行 Goal 的 R3 逐步确认、auto_r2 窄白名单与本次用户决定存在明确语义差异：先同步契约与测试，再增加新的任务级代批授权；旧运行不自动升级权限。

### 4.3 模型与预算

- 在账户当前已验证连接中指定一个轻量判断模型，能力配置明确支持结构化输出和 low 思考档；实际模型 ID 当前尚未配置或实测确认。
- 所有调用经 Project facade；冻结 secret-free provider/model/能力/low 配置快照，Key 使用当前有效账户凭据，不记录明文。
- 无合格模型时禁用自动代批、转人工；不猜价格、不用附加模型首项冒充选择、不回退其他供应商或思考档。
- 判断消耗进入父任务根预算；日志只记简短理由、模型／策略版本、指纹与执行回执，不展示私有思考内容。
- 将用户明确要求记录为“批准判断能力专用 low 档例外”。其他业务 LLM 继续遵守当前运行时约定，不能全局将生成／审查降低为 low。
- 自动模式在固定案例与指定模型实测通过后开放任务级启用；不因离线 mock 通过宣称模型可以安全代批。

## 5. 批次、依赖与验收出口

按 1 → 2 → 3 → 4 → 5 → 6 推进；产品能力保持可分批交付，后批不能假定前批“规划过”就已经实现。

| 批次 | 必须交付 | 完成条件 |
| --- | --- | --- |
| 1：上下文与恢复 | 正文／对象／档案条目／关系定位；临时草稿讨论；对象备份与跨页返回 | “这里／这一条”可核验，切换、刷新、失败和冲突不丢输入；跨作品拒绝 |
| 2：工作台重组 | 写作四路径、资料固定与按需助手、世界详情分层、对象内关系维护 | 手动与 AI 路径均闭环，窄屏和键盘可完成；不缩掉既有功能 |
| 3：统一批准 | 模式、授权、模型配置、判断及审计回执；接入 ActionBatch／Goal | 入口一致，人工保留项不被代批，模式撤回／过期／重放正确 |
| 4：精细修改 | 局部修改组、派生候选重新审查、采用／恢复；关系助手补齐 | 部分采用不借旧审查，关系方向／有效期正确，重复操作不重复写入 |
| 5：复杂任务 | 全库冻结范围、分页检查、批次提案、依赖任务、影响查证和恢复 | 覆盖范围如实报告，部分成功不冒充全成，预算和回执可续接 |
| 6：整体交付 | 跨页验收、操作帮助、提醒整合、兼容清理与文档 | 硬条件和浏览器流程通过；实际模型、作者体验及未验事项分别报告 |

批次 5 的受限组合任务复用已注册操作和既有预算／租约。新建对象后先读回真实身份，再准备依赖关系并按当前模式重新批准；不能让 depends_on 被误当成自动注入新 ID。每个关联组显示真实依赖，按现有批次容量切分，不能绕过容量或授权限制。

## 7. 验证清单与交付界限

### 工程硬条件

- 权限：跨账户／跨作品拒绝；排除资料、时点和角色知识边界不被 UI 或自动批准扩大。
- 定位：中文、emoji、重复引文、长稿滚动、输入法组合正确；定位不仅检查 DOM 存在，还检查原文实际进入视口。
- 保存：临时讨论与正式来源分明；服务端保存／本地备份失败、409、迟到响应、切章切对象、刷新恢复均保留作者输入。
- 候选：只读；范围外不变；修改组重审；旧来源不可采用；重复采用幂等；后续手改不会被撤销覆盖。
- 自动模式：允许／需确认／拒绝，注入内容，失效授权，模式撤回，超时／无效输出，预算耗尽，模型不符与 low 不支持。
- 批量：冻结范围、分页边界、目标变化、依赖顺序、部分成功、未知回执；恢复不重复写入或重复计费。
- 兼容：旧运行、旧目录、现有手动入口、按来源分类的恢复都可用；不能删除旧视觉测试时一并丢掉功能断言。

### 浏览器与真实质量

完整走查：查设定 → 回原段；改对白 → 比较 → 采用 → 手改 → 恢复；想下一步 → 存参考；审稿 → 选意见 → 修订；新建人物 → 添加关系；整理同名候选；临时草稿讨论；自动模式运行／撤回／恢复。

覆盖桌面、平板、手机、浅深色、键盘焦点与软键盘影响；真实查看渲染，不以组件测试证明可用性。先复用现有 Writing、Comments、Assistant、World 与跨设备测试，再按新增行为补充失败路径。
