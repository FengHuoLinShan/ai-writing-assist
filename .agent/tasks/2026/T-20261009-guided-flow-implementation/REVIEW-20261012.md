## Standards：2 项 P1

### S1 [P1] 并发开始流程可以生成两个活动 run（BR-3）

`backend/modules/assistant/guided_flow/runtime.py:254` 的 `start()` 在 274–304 先查询活动 run，再插入；无作品/流程锁或对应唯一约束。`backend/modules/assistant/models.py:64` 的活动唯一索引只约束非空 session，而此处未填 session。两个设备同时开始可以各自看到空列表，创建不同 run；后续按 run 派生 operation_id，可能产生重复付费任务。顺序重入测试无法验证该竞态。

修复需在数据库事务边界确保同作品/流程只有一个活动运行，并以真实 PostgreSQL 双连接竞争验证同输入返回同 run、不同输入冲突。

### S2 [P1] 方向卡在 HTTP 事务中直接付费，结果缺少崩溃恢复（BR-5/BR-3）

`backend/modules/assistant/guided_flow/flows.py:1398` 的 `_run_direction_cards()` 直接调用 `draft_direction_cards()`，完成后才把结果返回给运行层冻结。模型已返回而后续事务失败/进程退出时，付费输出丢失；重试会重新生成。与同文件世界骨架任务使用稳定 operation_id 的恢复路径不同。需接入可恢复任务和已付费结果冻结，并验证响应后、检查点提交前故障重试不会再次调用模型。
