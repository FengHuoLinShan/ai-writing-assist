## 共享事实（供 W3 链 4 与链 8 使用）

### 1. 保存/发布状态机（编辑器→保存→离开/切章/刷新→冲突保留恢复的权威语义）

- **状态词汇**：DB `status ∈ {draft, published, candidate, canonical, deprecated}`（canonical 为语义模式非持久状态）；作者投影 `display_state ∈ {active, review, archived}`、`source`（manual/ai_generated）、`attention_reasons` 由 `schemas.project_writing_draft_state` 派生（candidate→review、deprecated→archived；pov_validation/independent_review/upstream_validation 生成 pov_risk/parse_warning/fact_risk/semantic_review_required/semantic_review_blocked/upstream_stale）。`version_origin ∈ {auto, manual, legacy}` 区分自动/手动版本；`deprecated_from_status` 保留软废弃前原状态且重复 DELETE 幂等不覆盖。
- **写入口径**（全部先 `require_active_project`→章节 advisory lock（`writing_versions:{novel_id}:{chapter}` 升序）→`get_for_update` 重读→`expected_version/expected_updated_at` 对章节最新快照校验，过期 409 且不产生写入）：
  - `POST /drafts/autosave`（api.py:359）→ `create_draft_only` 新建纯草稿版本（不发布）+ working 索引标脏。
  - `PUT /drafts/{id}`（api.py:584）→ 仅最新 working 可原地改（services.py:533-624）：published 首次实质编辑 copy-on-write 新 working（继承 conflict_check_snapshot）；manual 工作稿实质编辑 copy-on-write；auto 工作稿改回基线内容=自动撤销（deprecated + 回基线）；空白差异不建版。
  - `POST /drafts/{id}/checkpoint`（api.py:606）→ auto 稿原地转 manual 或新建 manual 版；`force=true` 允许无实质变化留版（二确认）。
  - `POST /drafts/{id}/discard`（api.py:631）→ 仅 draft 可弃，回 `base_draft_id`/前一 working 基线。
  - `POST /drafts`（发布，api.py:470）→ 无实质变化复用已发布版本（`new_version=false` 且不入队）；draft 原位提升 published；auto 已撤回时废弃 auto、原位发布 manual 基线；`restore_source_version` 从历史恢复（校验 `version_number` 未变 + 最新快照，过期 409 不建版不入队）；新发布才归档冲突快照 + `mark_chapter_index_dirty(canonical)` + 入队 `publish_chapter`。
  - `POST /drafts/{id}/adopt`（api.py:558）→ copy-on-adopt：新建最高 version 的普通 draft（`adopted_from_candidate_id/at/by`），原 candidate deprecated（`adoption_result_draft_id`）；采用前 `validate_candidate_upstream`（见共享事实 2）。
  - `DELETE /drafts/{id}` / `DELETE /chapters/{i}` → 软废弃；工作稿删除前 `count_working_versions<=1` 拒绝；candidate 删除记录 `rejected_at/rejected_by`。版本号永不重排。
- **事务边界**：正文保存 API 共享 function-scope `DbSession`，提交成功才发成功响应（README:186-190）——前端收到 201/200 即服务端可读，这是链 8"已保存"展示与本地备份判定的依据。
- **发布任务**（tasks.py handle_publish_chapter，restart_origin）：Step1 RAG 索引（task-only DI port，重试 3）→ Step2 memory 快照（begin_nested，重试 3，project FOR SHARE 先于 memory 写）；重复发布已发布基线不再入队。
- **多 Tab/恢复**：`expected_version`+`expected_updated_at` 是多 Tab 冲突检测唯一机制（无 draft_id 的旧发布调用同样校验）；candidate/deprecated 仅历史视图预览，PUT 一律 409。前端本地备份/恢复指针与光标记录在 D8a（useWritingWorkspace/controllers），服务端侧对应的保护点是上述 409 语义与 autosave 队列。

### 2. AI candidate 生成与 confirmation 绑定语义（安全不变量，勿当优化对象）

- **provenance 冻结字段**（services.py:2050-2078）：`source=writing_generate`、`source_confirmation_id`+`context_confirmation_id`（双键冗余）、`source_task_id`、`context_action`、`context_result_refs`、`generation_profile/generation_mode`、`base_draft_id/base_content_hash`、`scene_id`、`scene_execution_bundle_hash`（=bundle `contract_hash`）、`upstream_manifest`、`review_required=true`、`prompt_name/prompt_hash/model`、`managed_llm_steps`（secret-free）、`pov_view/pov_validation`。targeted revision candidate 额外冻结 `source_review_context_fingerprint`、`applied_patches`、`supersedes`、`review_task_id`、`finding_ids`，且 `independent_review=None`（返修后必须重新独立审查才能采用）。
- **提交链**：API/assistant→`submit_generation`（prepare_confirmed_ai_action 验证 action=writing.generate + Scene 资产 basis_hash 过期需 `confirm_stale_story_assets`）→`enqueue_task_with_optional_operation`（幂等：同 confirmation 重复入队，后绑 task 取代旧 task，`_require_task_confirmation_owner` 校验 result_refs 末位==本 task）→ worker `generate_candidate_for_task`：prepare（fenced session 内冻结 plan+指纹）→ checkpoint（commit+断言无事务+expire_all）→ 无事务 provider 等待/解析/清洗/hidden guard → finalize（project-first 重验项目、profile 快照恢复、confirmation owner、bundle、base draft、完整指纹逐一比对，漂移丢弃不落 candidate）→ 同事务 create candidate + `bind_confirmed_action_result(writing_draft, done)`。
- **打开/采用门禁**：`validate_candidate_upstream`（semantic_review.py:213-260）= `require_fresh_confirmation(writing.generate)` + bundle hash 比对 +（require_review 时）`independent_review` 必须存在且 `context_checked/context_fingerprint` 非空（旧非 context-aware 回执不可用）+ `draft_hash==content_hash` + verdict=pass 且 blocking=0。get_draft 用 require_review=False 仅追加 `upstream_stale` 提示，不阻断读取。缺/失 confirmation 一律 fail-closed（409）。
- **重生成入口**：`GET /drafts/{id}/regeneration-context` 只读原选择/排除项，不 freshen、不重绑旧 candidate；新生成走独立 writing.generate confirmation。
- **独立审查/定向返修**：审查冻结正文 hash、相邻章回归上下文、Scene bundle、AI candidate 的原 generation confirmation（prepare_confirmed_ai_action 重新物化同一 confirmation），冻结 context/hidden-guard 指纹；hidden guard 词条只在服务端运行，确定性命中直接合并 finding；回执 `writing_semantic_review.v2` 落入各 target 的 `provenance_json.independent_review`（逐 draft verdict/blocking_count/coverage/finding_ids/`reviewer_separate_from_generator`）。返修 `prepare_targeted_revision` 重取审查任务回执、重验 draft hash/frozen context fingerprint/bundle hash 三重一致才执行；patch 由服务端按唯一定位区间应用，范围外正文逐字不变。
- **hidden guard 边界**：guard terms 由 Evidence facade 提供，只服务端执行；进 LLM payload 的 pov_view 先经 `_redact_guard_phrases` 过滤（test_semantic_review.py:124-217 固化"绝密守卫词不出现在 payload"）；人工正文无 confirmation 时 prose-only、`not_checked` 明示知识边界未覆盖、不得签署 PASS。

### 3. 冲突审查双轨现状

- **同步轨**（deprecated，前端零调用，仅 real-llm 验收使用）：`POST /conflict-checks/{id}/ai-review`、`POST /conflict-check-items/{id}/ai-suggestion` → `ConflictCheckAiReviewService.run` / `ConflictSuggestionService.generate`。单事务语义（LLM 等待期间持有事务）、无 snapshot/owner fence/checkpoint；错误只置 ai_review_status=failed 不删规则层结果。
- **任务轨**（前端实际路径）：`-task` 端点（202）→ `enqueue_task_with_optional_operation`（operation_id 幂等 + llm_execution_snapshot 入 meta）→ `start_ai_review_task(activate=False)` 预检 confirmation scope（作者请求章优先 `requested_chapter_index`，旧 confirmation 才回退 `chapter_index`）→ `bind_ai_review_task_owner` 把 task_id 写入 `summary_json[AI_REVIEW_TASK_OWNER_KEY]`（内部 owner 不出 API：响应经 `public_conflict_summary` 剥离）→ worker `run_for_task`：fenced session + prepare（owner fence + 完成态短路 + 指纹冻结）→ checkpoint → 无事务 LLM → finalize（owner/scope/指纹复验，漂移写 `_TASK_STALE_ERROR` failed；取消 shield 收敛 failed；transient 错误按 attempt 决定是否落终态）。
- **两条轨共用**：`_validate_confirmation_scope`（章/Scene 匹配）、LLM 输出逐条 Pydantic 校验（非法条目丢弃计 `discarded_count`，status=partial）、`is_ai_judgment=true` 项保留 `source_confirmation_id/confidence/llm_rationale`，`needs_review` 由 include_pending 或依赖待确认对象派生，`author_action` 纯投影不入库。
- **规则层**（`create_check`）：仅 Scene 字面规则（must/must_not 逐字扫描限定 scene_chunks 范围 + source_content_hash 校验，范围缺失/越界/hash 失效→`degraded_sources`/`omissions`，绝不回退整章）；README 所称 continuity 位置证据已不存在（D4-1）。发布时归档最近检查快照（保留 source/open_target，剥离 text_range，之后状态变化不改写快照）。
