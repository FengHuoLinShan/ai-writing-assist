### F2-1
- **ID**：F2-1
- **位置/符号**：`backend/infrastructure/tasks/api.py:66-104` `_MODULE_API_ONLY_TASK_TYPES`（37 项）；`submit_task`（:202-271）
- **问题与触发**：37 项任务类型手工黑名单与 registry 的 `generic_submit_schema` 机制并行维护。生产 47 个 handler 均未传 `generic_submit_schema`（rg 全仓证实，仅 contracts/registry/api 自身与测试引用），因此对所有已注册生产类型，黑名单命中与否最终都落在 :229-235 的 `submit_schema is None → 403`。黑名单唯一独立作用：对"已列入名单但未注册"的类型把响应从 400（Unknown task type + 注册清单回显）改为 403，并阻止类型名枚举。新增任务类型时存在漏登记黑名单的维护漂移面。
- **调用链证据**：`POST /api/tasks` → `_MODULE_API_ONLY_TASK_TYPES` 命中 403（:214）→ 未命中且未注册 400（:219-225）→ 注册但无 schema 403（:229-235）。测试 `test_api.py::test_generic_submit_keeps_explicit_custom_task_available_and_guarded`（:340-396）证明通用提交是受测活机制而非死端点。
- **现有契约**：README（tasks）"通用 submit 保留'模块专属类型/未知类型'的原有校验顺序"；测试固化 403/400/422 三种响应。
- **最小方案**：不改对外行为的部分——无（黑名单删减会改变未注册名单类型的 403→400）。可做的纯维护收敛：把黑名单改为"注册表推导 + 显式允许清单"（只允许 `generic_submit_schema` 非空类型），未注册类型统一固定文案，403/400 差异作为功能变更单独立项评审。
- **预期收益**：消除 37 项手工清单与 registry 的双维护点；新增 handler 不再需要同步两处。
- **风险**：响应码/文案变化触及前端错误分支与测试断言；枚举防护语义需保留。
- **依赖**：无（独立）；与 E1 的 tasks api 测试联动。
- **验证命令/断言**：`make test TESTS="infrastructure/tasks"`；对 37 个名单类型逐一断言状态码与文案不变。
- **回滚**：单文件 revert。
- **裁定**：实施候选（需按功能变更处理响应差异部分）

### 3. 租约/幂等/取消/超时语义摘要

- **租约**：claim 时 `mark_running` 物化新 `lease_id`+`attempt++` 并独立 commit；心跳/检查点/终态全部 `task_id + running + lease_id` fence，不匹配即回滚（旧 worker 不能覆盖新 attempt）。心跳独立 session；心跳失败仅告警，stale scanner（`TASK_MAX_HEARTBEAT_GAP`）按 recovery_policy 收敛（auto_requeue 有 1/2/4/8/16/30s `updated_at` 退避；manual_resume→failed+双标记 recovery_required；restart_origin/never_retry→failed）。
- **提交 fence**：worker `_TaskHandlerSession.commit` 先 `checkpoint_running_attempt`（project guard + lease 校验 + detached progress/result/meta 合并）再真提交；guard 拒绝→rollback+CancelledError。finalize 前 disable hook 并按 project FOR SHARE→lease 顺序短临界区线性化。preflight 严格只读（ORM 状态与 Core DML 双路径丢弃）。
- **幂等**：`enqueue_operation_task`（客户端 UUID=task id + canonical request fingerprint，复用含终态、异请求拒绝）；`enqueue_coalescing`（SHA-256 key + 部分唯一索引 pending/running 各一 + pg_advisory_xact_lock；reuse_active / one_pending_follower 两模式）；`replace_completed_task_result`（revision CAS）；业务侧另有领域 fence（rag generation、world CAS、imports workflow run epoch）。
- **取消**：API cancel 仅 pending/running→cancelled；`cancel_exact` 按子（inline_only）→父锁序；`cancel_unfinished_for_novel` 供软删；孤儿 inline 子任务由 stale scan 收敛（resumable 父保留子）。
- **inline 子任务**：`run_task_inline` 要求原父 task scope+共享预算（`task_inline_execution_enabled`），commit 复用 worker fence，心跳/清理绑定调用者 session 工厂，父 fence 失效时仅独立事务收束任务元数据。
- **恢复 fail-closed**：worker 启动先 stale recovery 再 startup reconcilers（RAG/imports/interaction 领域 owner 收敛），任一失败则 `_TaskWorkerRecoveryError` 停机；stale 实际转换后再触发 reconciler 覆盖宽限窗口。

### 4. 状态枚举现状地图（供 X1-6 裁定）

- **队列运行态**（AsyncTask.status，DB String(32)，对外 API 直传）：`pending/running/done/failed/cancelled`。权威源=infrastructure/tasks；枚举 `shared.enums.TaskStatus` 已存在但仅 api.py 2 处使用，生产 94 处裸字符串（F2-5）。**合法转换**：pending→running（claim）；running→done/failed/cancelled（finalize/cancel，均需 lease）；running→pending（handler_error_retry 有界退避 / transient_retry / auto_requeue stale）；failed→pending（manual_retry：auto_requeue 且 attempt 未满；manual_resume：resume_manual，含 allow_completed 窄口）；failed/done/cancelled→pending（restart_origin 由业务来源重新发起，不入队复用）；任意活动态→cancelled（superseded 当存在 pending follower）。`transition_reason` 是独立词汇（handler_error_retry/transient_retry/manual_resume/manual_retry/superseded/heartbeat_timeout/user_cancelled/parent_cancelled/parent_unavailable/recovery_abandoned/project_soft_deleted），不在 TaskStatus 收敛范围。
- **恢复展示态**：`result/meta.recovery_required` 双标记 + `lifecycle.reason/transitions` + contract `available_actions`（cancel/resume/abandon/retry/restart_origin/dismiss）——前端只渲染后端 action。
- **领域工作流态（不等价，勿并入）**：imports `workflow_runs.status`（D5b 域词汇，worker startup reconciler 与 task 状态收敛）；imports phase/进度词汇；interaction attempt 状态；writing review 状态。各自有权威源与转换图，X1-6 机制侧仅收敛队列运行态。
