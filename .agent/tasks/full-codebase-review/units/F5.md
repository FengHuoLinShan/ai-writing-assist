### CI 工作流步骤图与已知冗余

- 5 个 workflow，全部 `permissions: contents: read`（codeql 更细）、SHA 固定 action、concurrency 按 ref 取消。事件：PR + push main；e2e 仅夜间 cron+手动；codeql 另有周 cron。
- 共同入口：checkout（fetch-depth 0，e2e workflow 除外）→ `scripts/classify_ci_changes.py`（F6 所有；PR 按 diff 分类 backend/postgresql/frontend/browser/images 五门禁，`.md` 全跳过、`README.md`→images、`deploy/`→backend+images、未知路径→全门禁；push main 恒全门禁）。
- backend-ci：quality job（secret-hygiene 无条件 + audit-backend-deps + uv sync --extra ci + lint + test-deploy + fast coverage TEST_WORKERS=2 `-W error::RuntimeWarning` + push 时非阻塞 eval-ask-world 门禁并传 artifact）；postgresql-critical job（独立 pgvector service，alembic upgrade head + 前后诊断 artifact + 12 个串行 critical 合同测试）。
- frontend-ci：unit job（npm ci+audit+lint+vitest）；functional-browser job（pgvector service + MinIO root 密码用 `github.run_id`、`PW_REUSE_EXISTING_SERVER=0`、uv+npm 双装、Playwright chromium、`docker compose up minio`+minio-init 复用 dev compose；PR 跑 smoke 子集、main 跑全量 functional，`--workers=1 --retries=0`）。
- production-image-ci：`make test-production-images`（双镜像构建+容器硬化冒烟+真实隔离 restore drill）→ Trivy CycloneDX SBOM×2（先 exit-code 0 生成+验证+上传 artifact 14 天）→ HIGH/CRITICAL 可修复漏洞门禁×2（exit-code 1，ignore-unfixed）。
- backend-postgresql-e2e（夜间）：pgvector service + apt.postgresql.org（GPG 指纹校验）装 pg17 客户端 + 全量 `pytest tests/e2e` + 诊断 artifact。
- codeql：actions/javascript-typescript/python 三语言 matrix，build-mode none，security-extended。
- architecture-docs：push 全量校验；PR 用 `base.sha` + event-path 做影响面检查（唯一 ubuntu-latest，其余 ubuntu-24.04）。
- **已知冗余/成本点**：deploy/ 或 Makefile 变更在 PR 中会点亮 backend 门禁（含 5 分钟级 fast coverage），保守但偏重；Playwright 浏览器与 docker 层无缓存（F5-6）；audit 步骤与本地 `make test-ci` 有意重复保持门禁对等；postgresql-critical 与 quality 各自完整 uv setup（GHA 缓存共享，可接受）。`make audit-backend-deps` 带 `--ignore-until-fixed GHSA-w8v5-vhqr-4h9v --ignore-until-fixed GHSA-95ww-475f-pr4f`（两个"修复前忽略"顾问，按禁令未执行 audit，仅记录存在）；`audit-frontend-deps` 为 `npm audit --package-lock-only --audit-level=high`。
