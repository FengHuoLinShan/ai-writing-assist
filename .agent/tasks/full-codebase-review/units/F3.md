### F3-1 已定义未接线的 API 契约（含死包装）

- **ID**：F3-1
- **位置/符号**：`frontend-console/apiContracts.js` API_CONTRACTS 中 `world.createCocreationSession/listCocreationSessions/getCocreationSession/updateCocreationSession/listCocreationMessages/appendCocreationMessage/advanceCocreationCheckpoint/confirmMapAtlasPrompts/updateMapAtlasNode/uploadMapAtlasPage`、`context.activationPreview`；`frontend-console/api.js:2078-2080` `api.activationPreview`
- **问题与触发**：这 11 个契约已定义，但 api.js 中同名方法全部是手写路径（如 `api.js:1597` createCocreationSession 用 `post("/world/cocreation-sessions", …)`，`api.js:1924` confirmMapAtlasPrompts 手写 post，`api.js:1935` updateMapAtlasNode 手写 patch，`api.js:1927` uploadMapAtlasPage 走 XHR multipart）。生产视图（GenerateView.vue、CocreationHistory.vue、MapWorkspaceView.vue、generateIsland.js）调用的都是 api.js 手写方法，契约定义零生产消费（仅 tests/api-contract.test.js:302/304 断言 confirmMapAtlasPrompts、updateMapAtlasNode 的 contractPath）。`context.activationPreview` 更深一层：契约被 `api.activationPreview` 使用，但 `api.activationPreview` 本身全仓（生产+测试+e2e）零调用，是死包装。同族 `world.cocreationChat`、`world.enqueueCocreationTurn` 已切契约，说明该批迁移中途停止，留下两套并行定义。运行时无双轨 bug（单一手写路径在跑），风险是契约表腐化：契约的 requiredBody/timeout 语义与手写路径脱钩，后续维护者按契约理解请求约束会失真（如 `world.updateCocreationSession` 契约要求 body.novel_id 必填，手写路径无该校验）。
- **调用链证据**：`rg "world.createCocreationSession" frontend-console` 仅命中 apiContracts.js 定义、GenerateView.vue 对 `api.world.createCocreationSession`（手写方法）的调用与测试 mock；`rg activationPreview`（排除 node_modules/dist）仅命中 apiContracts.js:339 与 api.js:2078-2079。api.js 手写/契约调用比约 254:153。
- **现有契约**：§2 HTTP 兼容面——所有端点的实际行为以 api.js 手写路径为准，本发现不改变任何请求。
- **最小方案**：二选一，逐契约独立小步：(a) 把 api.js 同名方法切到契约（先逐字段核对 body/query 等价，特别是 cocreation* 契约的 requiredBody 与手写宽松行为的差异——切换=收紧，需按 §2 单列验证）；(b) 删除死契约与 api-contract.test.js 对应断言。`context.activationPreview`：连同 api.activationPreview 一起删除（后端 `/evidence/compilation/activation-preview` GET 是否 legacy 死路由归 D6 核实后联动）；同路径的 POST 版 `previewActivationProfile` 有真实消费者（useWorldBible.js:1731），不得误删。
- **预期收益**：契约表与实际请求面一致；减少 11 个腐化定义与 1 个死方法；后续契约迁移（A8-4 收尾）不再被死项干扰。

### F3-2 超时双权威源与 timeoutKind 死字段

- **ID**：F3-2
- **位置/符号**：`frontend-console/api.js:18` `API_TIMEOUT = 15000`；`frontend-console/apiContracts.js:9` `DEFAULT_TIMEOUT = 15000`；`apiContracts.js:589/595` `timeoutKind: "aiTaskSubmit"`；`api.js:311` `timeout || API_TIMEOUT`
- **问题与触发**：(1) 手写路径超时由 api.js 的 API_TIMEOUT 决定，契约路径由 contractRequest 的 `transportOptions.timeout ?? contract.timeout` 决定，两处 15s 各自独立定义、互不引用；端点从手写切到契约时若有人只改一处，超时语义静默漂移（历史候选 A8-4 记录的“timeout 默认 15s vs 契约 600s”分歧即此类，当前数值已一致但机制未收敛）。(2) `writing.semanticReview`/`writing.targetedRevision` 契约定义传了 `timeoutKind: "aiTaskSubmit"`，但 `define()`（apiContracts.js:70-86）不解构该字段，返回的 frozen 对象也不含它——写了即丢，全仓无消费者，纯误导性配置。(3) `request()` 用 `timeout || API_TIMEOUT`（falsy 判断），`contractRequest` 用 `??`；传 `timeout: 0` 时两路径行为不同（回退 15s vs 真的 0）。当前无调用方传 0，无实际故障。
- **调用链证据**：读 apiContracts.js define 全文（无 timeoutKind）；`rg timeoutKind frontend-console` 仅命中定义处两行与注释。
- **现有契约**：§2 HTTP 兼容面——超时是客户端行为，不改后端契约。
- **最小方案**：api.js 改为 `import/读取 apiContracts 导出的 DEFAULT_TIMEOUT`（apiContracts 先于 api.js 加载，globalThis.apiContracts 已是既有序）或抽单一定义；删除两处 `timeoutKind` 行；`timeout || API_TIMEOUT` 改 `timeout ?? API_TIMEOUT`。
- **预期收益**：消除超时漂移隐患；删除死字段。
- **风险**：极低；`??` 改动需确认无调用方依赖 `timeout:0` 回退（已核实无）。
- **依赖**：无。
- **验证命令/断言**：`npm test -- tests/api-contract.test.js`、`rg -n "timeoutKind" frontend-console` 零命中、`npm run lint && npm run build`。
- **回滚**：单提交 revert。
- **裁定**：实施候选。
- **优先级建议**：P3

### 2. island ↔ 路由 ↔ 视图装载关系图

- **路由表（router.js routes，15 个）**：home, project, journeys, interaction, today, world(5 subView), rag(2), outline(4), scene(dynamic), writing, map, generate, llm, settings, project-settings。
- **归一化别名（_normalizeRoute）**：today→writing(home=1)；scene→outline/scenes(scene_id)；outline 的 foreshadowing/reveals→threads(information)；context→generate→world|writing(owner_ai)；llm→project-settings|settings；world 的 candidates/review-*→review(kind)、objects/aliases(带定位)→bible。
- **island 注册面（registerView，12 个，模块加载自注册）**：world←worldIsland、map←mapIsland、project←projectIsland、today←todayIsland、home/journeys/interaction←interactionIsland、outline←outlineIsland、writing←writingIsland、rag←ragIsland、settings/project-settings←settingsIslands、generate←generateIsland。**其中 today、generate 两个 renderer 不可达**（归一化吞掉，F3-3）；llm/scene/context 三个路由名无 renderer 也不需要（归一化转走）。
- **viewLoaders（app.js 启动注册 13 条）**：为每条可达路由注册动态 import；加载器仅在实际渲染该路由时触发（认证后），模块自注册与 loader 机制互为两侧（loader 完成后从 viewRenderers 取）。
- **mountIsland 生命周期契约**：onEnter（await load() 预取 props，含 generation 失效）→ render()（返回 `<div class="vue-island" data-vue-island>` 挂载点字符串）→ onRendered（query 漂移补载→卸载残留→createApp 挂载，el.dataset.projectId 供 assistantContext 归属判断）→ onLeave（loadGeneration++ 失效在途 load + unmount）。canLeave 单槽守卫（useLeaveGuard provide）。**无 keep-alive**：离开即卸载，恢复语义由各视图显式持久化（viewStates、sessionStorage、localStorage pointer、模块级 manager recover）。
- **outline island 特例**：包装 onLeave 停 5 条轮询线（generate/analysis/plotAutoExtract/sceneAutoExtract/sceneRuntime/storyOutline）+ subnav 滚动存取（state.viewStates.outline.scrollTop）；ADR-0009 附录 A 记录其移出 keep-alive 的原因。
- **shell 与 route host**：WorkspaceHost 提供 `#workspace-content`（data-imperative-route-host），router 继续命令式拥有该子树；ServiceHosts 提供 toast/modal DOM host（data-imperative-service-host，modal inert 租约与 useModalDialog 的嵌套协调均豁免 service host）。

### 3. bridge / seam 清单（制度性 seam，不轻动）

- **vue/bridge/index.js**：Vue 组件访问 vanilla 基建唯一入口（getApi/getRouter/getAppState/getRouteQuery/getToast/getConfirm/getPrompt/getShowModalHtml/getConfirmAction/getCloseModal/getEsc/getErrorLog/useStateKey/tryMigrateLocalAuthorPreferences/openSmartDedupTask/openProjectAssistant/getAssistantWorkContext/getCurrentWritingFingerprint；setBridgeOverrides 仅测试）。历史审查已裁定为安全 seam。
- **shellServices.js**：shell 侧 service 工厂（router/commands/modal/health/account/workspace/toast 的 fallback 包装）；`workspace.triggerAction/autosave/quickopen/toggleOutlineFloat/moveSelection` 是 shell 快捷键操作业务视图 DOM 的既定 seam（data-action 约定 + `shell:*-request` 自定义事件）。
- **mountIsland ISLAND_LEAVE_GUARD**：provide key，组件注册 canLeave 守卫。
- **全局 DOM 事件 seam**：`workspace:content-rendered`（Vue 视图→app.js smartDedup 按钮重渲染）、`writing:dashboard-update`（writing 视图→useWordcountDashboard）、`shell:save-request/shell:quickopen-request/shell:toggle-outline-float`（shell→视图）、`novel:account-invalidated`（accountStorage→app.js/useProjectAssistant）。
- **跨层状态接缝（注意，非 seam 而是接缝）**：bridge.getCurrentWritingFingerprint 与 assistantContext.captureWorkContext 直接读 `appState._currentChapter/_currentDraftId/_currentSceneId`、`viewStates.writing.projectId`、`#writing-editor` DOM——这些下划线字段由 writing 视图（D8）写入，是 vanilla state 上的视图私有状态被 shell 侧读取的耦合点；writing 视图重构时必须保持这三个字段名与 viewStates.writing 形状，或同步改 bridge+assistantContext。
- **storage key 清单（账号边界，accountStorage.js 前缀）**：local 清理 `novel_`、`draft_backup_`、`world_draft_backup_`、`generate_world_workspace_state_v2_`、`writing_scene_cockpit_order:`、`writing_resume_pointer:v1:`、`worldBible:`、`worldBibleProjection:`、`_errorLog:` + 精确 `_errorLog`；session 清理 `novel_`、`workspace-rail:`、`workflow-progress-card:`、`workflow-progress-details:`、`rpSourceSetupDraft:v1`；保留 `novel_theme`（主题）与可选 `novel_accountId` 标记。**不在清单**：`nc-theme*`（F3-10）、`nc-entry-mode-after-auth`（sessionStorage，会话级自灭）。新增前端持久化键必须落入上述前缀或在 accountStorage 登记，否则跨账号泄漏。

### 4. 状态权威源现状

- **state Proxy（state.js）**：UI 全局态唯一权威（currentProjectId/currentProject/currentView/currentSubView/selectedItem/loading/projects/toast/backendConnected/viewStates + 遗留 mode）。set 时依次：stateSlices 副作用（currentProjectId/currentProject 持久化 localStorage、currentProjectId 变化删 viewStates.writing）→ 通知 listeners → updateUIForState（toast/error→toast 组件）。shell 经 useShellState 订阅 5 键；Vue 组件经 bridge.useStateKey 单键订阅。**无双向绑定问题：Vue 不反写 shell 态，唯二反写是 shellServices.workspace.moveSelection 写 selectedItem 与 useHealthPolling 写 backendConnected（设计内）。**
- **项目元数据权威**：router `_syncCurrentProject`（generation+AbortController，失败分类 account/temporary/inaccessible，inaccessible 清 currentProjectId 并入失败页）。localStorage 恢复仅存摘要（stateSlices.projectStorageSummary：id/title/name，summaryOnly 标记），完整对象以 api.projects.get 为准。
- **任务/工作流运行态**：后端 async_tasks 为权威；前端恢复凭据在 localStorage `novel_active_workflows_v1`（workflowProgress.persistActiveWorkflow，全 workflow manager 共用）；进度归一 normalizeTaskProgress 单点（状态词汇 done/failed/cancelled/pending/running/unknown 的前端权威映射），作者可读标签在 WORKFLOW_LABELS/STATUS_LABELS（与后端 TaskStatus 的对齐靠约定，X1-6 收敛时的前端对端）。
- **视图私有状态**：viewStates（state 内，切项目清 writing）；模块级 session 单例（worldSession/outlineSession/ragSession/generateSession，含 bulkSelections/filter 草稿，各带 scopeToProject 作用域清空）；writing 指针在 `writing_resume_pointer:v1:` 与 `state._current*`（见接缝）。
- **API 层缓存**：模块级 `_apiCache/_pendingRequests/_cacheGenerations`（api.js 内聚，clearCache 是唯一外部清理口；账号切换/切换项目由 accountStorage→app.js 触发）。
- **路由态**：URL hash 为事实源（query 驱动视图以 query 为筛选权威，worldIsland 注释明确），`_lastSubViewMap`（内存）记忆各视图最后子标签，`_currentQuery` 由 router 独占、bridge.getRouteQuery 发副本。
