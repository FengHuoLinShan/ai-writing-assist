### D1-4 legacy 去重 apply 路径 confirmed=false 返回 500 而非 4xx
- 位置/符号：`backend/modules/project/smart_dedup.py:547-548`（`SmartDedupService.apply` 首行 `raise ValueError("confirmed=true is required")`）；调用方 `backend/modules/project/api.py:198-226`（`api_apply_smart_dedup` 无 ValueError 捕获）。

## 共享事实（供 W3 链 1：账户连接→创建项目→项目配置→LLM snapshot→worker 恢复）

### 1. 连接/偏好权威源地图
- **LLM 连接（含 Key）唯一权威源 = account**：`account_llm_credentials`（owner+provider 唯一，`encrypted_api_key` JSON 加密 + `key_fingerprint` + `verified_at`）+ `global_llm_defaults`（owner 唯一的 active provider 与非 secret 默认）。写入口仅 `SettingsService.connect/activate/clear_account_llm_provider`（settings_service.py:251-343；连接时真实验证经 `LLMHealthChecker`，验证通过才落库）。读运行时唯一入口 `resolve_account_llm_runtime_profile`（:345-383，fail-closed：未连接/解密失败/空 Key 均报错；仅 LLM_RUNTIME_TUNING_FIELDS 五个调优字段从 defaults 叠加，连接身份字段不跨连接覆盖）。项目 settings["llm"] 的 provider/model/base_url 是**兼容读取/工作流配置**，运行时不消费（llm_runtime._resolve_project_runtime_profile 用账户 profile 整体覆盖 materialized["llm"]，tests/test_llm_runtime.py:93-127 钉住）。
- **图片连接权威源 = account**（`openai-image` provider 复用 account_llm_credentials），project 只经 `image_runtime` seam 固定 `OPENAI_IMAGE_BASE_URL/MODEL` 常量，不读文本 provider。
- **作者偏好三级源**：project（project_author_preferences 覆盖）→ global（global_author_preferences）→ system（AUTHOR_PREFS_DEFAULTS 常量）。合成入口：`ProjectSettingsService.get_effective_author_prefs`（project/settings_service.py:96-122，FieldValueSource 带 source 标注）；account 侧契约 `get_account_author_preferences_contract` 返回 values+sources（SOURCE_GLOBAL/SOURCE_SYSTEM）。
- **owner 解析**：全部经 `modules.account.facade.current_account_id()/current_owner_id_or_system_none()/require_account_active()`；public 浏览器路径 principal 必在（AccountAuthMiddleware 绑定并复核 pending_deletion 白名单/同源/CSRF），worker/系统显式 None；local/closed_test 回落 BOOTSTRAP_ACCOUNT_ID（nil UUID）。project 每个服务方法用 `_request_owner_id()`（services.py:733-736）按 owner 过滤 repo 调用；`get_project_context/require_active_project(_exclusive)` 另做 `require_account_active(project.owner_id)` 账户状态复核（services.py:576/622/651）。
- **项目配置（非 secret）**：`projects.settings` JSON 持有 workflow 设置与 `deep_import` 覆盖；跨模块 context（`get_project_context`）经 `_secret_free_project_context_settings` 递归剥离 api_key/api_keys_by_provider 及 llm 内 api_key_configured*（services.py:64-102）。

### 2. snapshot seam 语义（链 1 核心契约）
- **构建**（任务提交时）：`build_project_llm_execution_snapshot(db, novel_id)` → 账户 profile + capability registry 冻结 + deep_import 物化（含 env 覆盖）；持久化字段仅 provider_id/label/model/base_url_host/base_url_hash/timeout/max_tokens/temperature/top_p/api_key_configured/extra_keys/extra_hash/creative_mode + sources + profile_hash（全量 payload 的 `_stable_hash`）；**无 Key、无完整 URL、无 extra 值**（llm_runtime.py:99-158）。
- **恢复**（worker 领取时）：`restore_project_llm_execution_settings`（:161-250）五重 fail-closed——version、novel_id 一致、profile_hash 复算、api_key_configured 必须 true（先于任何 DB 查询）、base_url/extra hash 与当前比对（漂移拒绝）；provider 按 snapshot 固定（账户切模板不影响旧任务），Key 用当前轮换值；capability 无字段时 legacy 短窗 fallback（不写回当前默认）。返回 dict 含 `_RUNTIME_SOURCES_KEY`、`_llm_execution_profile_hash`、`DEEP_IMPORT_FROZEN_SETTINGS_KEY=True`。
- **客户端**：`create_project_snapshot_llm_client(project_settings, novel_id=…)`（worker 用，调用方负责 close）与 `open_project_llm_client`（请求内 CM，finally close，timeout_override 上限 1800）。runtime scope：snapshot 路径 `profile_source="project_snapshot"`，db 路径 `profile_source=sources["model"]`（恒 "account"）。
- **补建**：旧 pending 任务缺 snapshot 时 worker 先 build+持久化并 `db.commit()` checkpoint（tasks.py:33-40，lease fencing 由 worker session 负责）——这是 A1-7 收敛必须**排除**的合法 commit。assistant 提交路径透传 `context.llm_snapshot/internal_meta`（assistant_dedup_tool.py:52-61），与前端 receipt 共用 `enqueue_task_with_optional_operation` 的 operation_id 恢复。
- 图片侧对称三件套在 image_runtime.py（snapshot_hash 校验 + 固定 model/base_url 比对）。

### 3. 项目删除/恢复路径（含与账户清库的关系）
- **软删除**：`DELETE /api/projects/{id}` → `repo.soft_delete`（owner 过滤、FOR SHARE guard 同事务）+ 同事务 `cancel_unfinished_tasks_for_novel(reason="project_soft_deleted")`；恢复 `POST /{id}/restore` 只恢复可见性，不重启任务（tests/test_project_api.py:300-350 钉住 lease 清除/终态不动/跨项目不动）。
- **永久删除（单个/批量）**：`confirmed=true` 必须 + 仅回收站内 + `lock_deleted_ids_for_update`（FOR UPDATE）→ `interaction.count_source_references` DI port 检查（RP 仍绑定则 409）→ 逐项目 cancel(reason="project_permanent_delete") → `world.enqueue_map_atlas_cleanup`（global scope、novel_id=NULL 的 map-atlas/与 world-objects/ 前缀清理任务）→ `permanent_delete(_many)`（DB CASCADE 级联领域资产）→ `delete_tasks_for_novel(s)`。批量原子：任一不在回收站整批 404，count 不符抛 Conflict。
- **interaction 隐藏项目**：archive/restore/permanently_delete 专用 facade 三件套（kind 过滤，reason=interaction_*），不进作者回收站。
- **账户级清库**：`scripts/manage_accounts.py purge-due --execute` → `AccountService.purge_due`（services.py:676-718，FOR UPDATE skip_locked 取到期 pending_deletion）→ 逐账户 cancel 任务 + `purge_projects_for_owner`（project/facade.py:354-389：FOR UPDATE 全项目行锁 → cancel → atlas cleanup → delete_tasks_for_novels → 批量 DELETE Project 靠 CASCADE）→ 清 30 天前 security events/1 天前 challenges/过期 sessions → 删 Account。申请删除 30 天恢复期内 `restore_account` 可撤销；pending_deletion 账户在 middleware `_PENDING_ALLOWED_PATHS` 白名单外一律 403。
