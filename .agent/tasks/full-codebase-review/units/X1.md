## 发现

### X1-1（P2）assistant 恢复路径的预算/生命周期错误未映射 DomainError，用户可达恢复按钮返回 500

- **位置/符号**：`backend/modules/assistant/service.py:670-675`（`resume` 调 `AgentRunBudget...reserve()` 与 `resume_manual_task`，无捕获）；`backend/infrastructure/llm/agent_runtime.py:87-105`（`reserve` 抛 `AgentBudgetError(ValueError)`）；`backend/infrastructure/tasks/lifecycle.py:151,157`（`resume_manual` 抛裸 ValueError）；`backend/modules/assistant/api.py:222-225`（端点无异常映射）；`frontend-console/vue/components/ProjectAssistant.vue:26`（`failed` 状态无条件渲染"恢复本次查证"按钮）。
- **问题与触发**：`AgentRunBudget.reserve()` 无参调用在 `remaining_seconds<=0`（提交后 30 分钟）时抛 `AgentBudgetError`。run failed 后超过 30 分钟点"恢复本次查证"→ 500（稳定 JSON）。同函数 :671 的另一失败分支走 `ConflictError(code="assistant_new_budget_required")` 409——同一恢复路径一半 409 一半 500。lifecycle 的 `ValueError("task not found")/("task does not require manual recovery")`（run 与 task 双状态源漂移时可达）同样 500。
- **调用链证据**：F1 共享事实——全局唯一 handler 仅处理 DomainError（main.py:559）；`AgentBudgetError` 全仓生产引用仅 agent_runtime.py:46/105/306/487 与 service.py:1045（后者只覆盖 worker 任务期，不覆盖 API 请求期 :672）。官方 tasks API 同层错误是 404/400（`backend/infrastructure/tasks/api.py:351-359`），对照成立。
- **现有契约**：领域恢复类错误现为 ConflictError+code（`assistant_not_resumable`/`assistant_new_budget_required`）；`AgentBudgetError` docstring 自述"needs explicit continuation"语义即"需新一轮查证"。
- **最小方案**：`service.resume` 捕获 `AgentBudgetError` 转 `ConflictError(code="assistant_new_budget_required")`；对 `resume_manual_task`/`stop_run` 的 ValueError 捕获转 NotFoundError/ConflictError（或在 assistant api 层统一映射）。前端可选增强：failed 超 30 分钟只显示"开始新一轮查证"。
- **预期收益**：用户可达恢复按钮不再 500；与项目侧 seam（`ProjectLLMConfigurationError`=ValidationError 的既有转换模式，llm_runtime.py:69-76）对齐。
- **风险**：低；错误码/文案变化需核对 ProjectAssistant toast 处理。
- **依赖**：无。
- **验证命令/断言**：`make lint`；`make test TESTS="modules/assistant/tests"` 补断言：failed+过期 budget 的 `POST /runs/{id}/resume`（renew_budget=false）→ 409 而非 500。
- **回滚**：单提交 revert，无数据步骤。
- **裁定**：实施候选。与 D7-1、D5b-2、D1-4 同型（裸 ValueError→500 错误语义不一致），主 Agent 可合并同批。cross-ref：X1-6 词汇划界不受影响。
- **优先级**：P2。
