### E3-1 | `make generate-e2e`（Makefile:194-195）与 e2e 配置守卫不兼容，目标必然失败
- **问题与触发**：任何人按 Makefile 注释「Run Generation Center Playwright E2E」执行 `make generate-e2e`，Playwright 配置加载阶段即抛错退出，一次测试未跑。
- **调用链证据**：`Makefile:195` 仅设 `BACKEND_PORT=18000 FRONTEND_PORT=18080` 后执行 `npx playwright test e2e/generate.spec.js`（默认走 `playwright.config.js` → `playwright.functional.config.js`）；`playwright.base.config.js:16` 无条件调用 `validateE2EDatabaseEnvironment(profile)`；`e2e/helpers/database-guard.js:5-24` 在 `DATABASE_URL` 缺失或 `PW_REUSE_EXISTING_SERVER !== "0"` 时 `throw`。两环境变量该目标均未提供。
- **现有契约**：testing-guide.md 规定所有浏览器入口需显式专用 PostgreSQL + `PW_REUSE_EXISTING_SERVER=0`；base config 是权威实现。
- **最小方案**：二选一——a) 目标改为 `cd $(FRONTEND_DIR) && DATABASE_URL='$${E2E_DATABASE_URL:?requires E2E_DATABASE_URL}' PW_REUSE_EXISTING_SERVER=0 BACKEND_PORT=18000 FRONTEND_PORT=18080 npx playwright test e2e/generate.spec.js`；b) 若该目标已被 `test:e2e:functional -- generate.spec.js` 取代则删除目标并同步 README 引用。
- **预期收益**：消除一个必败入口；避免误导回归执行者。
- **风险**：极低；仅改 Make 目标。
- **依赖**：无。
- **验证命令/断言**：`E2E_DATABASE_URL='<dedicated-url>' make generate-e2e --dry-run` 后实跑应进入 webServer 启动；未设变量时应报清晰错误。
- **回滚**：git revert 单 hunk。
- **裁定**：实施候选（属构建/测试提效）。**P2**

### E3-2 | `frontend-console/e2e/helpers/fixtures/oversized.bin` 53MB 二进制入库

- **现有契约**：文稿 ≤50MB 前端拦截（AGENTS 产品边界）；无任何契约要求固定字节内容。
- **最小方案**：测试内运行时生成（`fs.writeFile(tmp, Buffer.alloc(50 * 1024 * 1024 + 1))`）后删除 `oversized.bin`；或至少改为 commit 时生成脚本。历史大对象若需彻底移出历史另需 filter-repo（超范围，不做默认建议）。
- **预期收益**：工作树与 clone 减重 ~53MB；消除「仓库里为什么有个 53MB bin」的维护疑问。
- **风险**：低；生成 50MB 零缓冲毫秒级。
- **依赖**：无。
- **验证命令/断言**：`npm --prefix frontend-console run test:e2e:functional -- import-errors.spec.js`（需专用环境）在删除后仍通过；`git ls-files | xargs du` 复核。

### E3-3 | 定宽 sleep 型同步残留（flaky 面）
- **问题与触发**：4 处以固定毫秒等待代替条件等待，慢机/CI 负载下概率性失败：`world-review-phase4.spec.js:218` 与 `world-cocreation.spec.js:171` 均「`waitForTimeout(1500)` 等自动保存落库→API 读回断言」；`visual-project-rag.spec.js:58` `waitForTimeout(1100)` 注释自述「稳定 created_at 排序」；`world-bible.spec.js:40` 用 `setTimeout(1000)` 后仅查 `exitCode !== null` 判断 worker 就绪（未就绪不报错，首个投影任务可能竞态）。
- **调用链证据**：同仓 `world-bible-reliability.spec.js:25-27` 已示范正确范式（`data-autosave-status` 属性等待）；visual-suite 其余截图用 toast 退场+`fonts.ready` 条件等待。
- **现有契约**：testing-guide 强调 workers=1/retries=0 的确定性运行；无契约要求 sleep。
- **最小方案**：两处 1500ms 改 `waitForAutosave(page,'idle')` 等价断言或 `expect.poll` 读 API；排序处改按已确定性 seed（固定 `created_at` 由 mock/seed 决定）或对卡片集合排序断言；world-bible worker 就绪改为轮询 worker stdout 标记（参照 `playwright.worker.config.js:22` 的 `wait: { stdout: /TaskWorker started/ }`）。
- **预期收益**：移除主要 flaky 源；减少偶发 main 红灯（testing-guide：main 全量 functional）。
- **风险**：低；断言语义不变。
- **依赖**：无。
- **验证命令/断言**：受影响 spec 连跑 3 次（专用环境）。
- **回滚**：单 spec revert。
- **裁定**：实施候选。**P2**

### E3-4 | worker 启动解释器三套并存：`uv run python` vs 裸 `python` vs `.venv/bin/python`
- **问题与触发**：API 服务由 `playwright.base.config.js:46` 用 `uv run python -m uvicorn` 启动；worker 由 `playwright.worker.config.js:18`（`APP_ENV=test python run_worker.py`）和 `world-bible.spec.js:32-35`（`spawn("python", ["run_worker.py"])`）用环境裸 `python` 启动；`playwright.assistant.config.js:5` 硬编码 `.venv/bin/python`。在裸 `python` 非 backend venv（无依赖/版本不符）的机器上，worker 启动即失败或行为漂移；world-bible 的 1s 探测只能抓「已退出」抓不到「未就绪」。

### 环境隔离约定实现图

- **强制门**：`playwright.base.config.js:16` → `database-guard.js`：显式 `DATABASE_URL`（PostgreSQL 协议）+ 库名含 `audit|e2e|test` 分隔标记 + `PW_REUSE_EXISTING_SERVER=0`，fail-closed，profile 名进错误信息。七个 config 全部经此门（assistant 复用后覆写 command）。
