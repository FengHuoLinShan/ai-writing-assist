### D7-1
- **ID**：D7-1
- **位置/符号**：`backend/modules/interaction/services.py:2841-2864` `_enqueue_overview_refresh` 与 `backend/modules/interaction/generation.py:1431-1454` `_enqueue_summary`（逐字相同）；跨类私有访问簇——generation.py/agent_runtime.py 对 `InteractionService` 私有成员（`_best_overview_for_path`/`_overview_matches_path`/`_overview_coverage_matches_path`/`_overview_coverage_anchor`/`_overview_manual_ancestor`/`_overview_refresh_is_due`/`_see_sea_is_authorized`/`_story_task_meta`/`_branch_hint`，及 `workflow._repo`/`workflow._task_ids`/`workflow._validate_context_chain`/`workflow._service._sources`）与 services.py 对 `source_service` 私有成员（`_find_anchor`/`_reference_visible`/`_object_response`）
- **问题与触发**：`InteractionService`（2936 行）与 `InteractionGenerationWorkflow`（1627 行）实为同一个工作流拆成两个类，靠约 15 处私有成员互访协作；概要入队 helper 在两文件各有一份完全相同的实现（同 task_type/scope/meta 六字段）。新增概要相关行为需同步两处，读者无法从类边界判断归属。A5-7 领域侧的现状证据。
- **调用链证据**：`rg -n "_enqueue_summary|_enqueue_overview_refresh"` 两函数体逐行比对相同；`rg -n "_service\._|workflow\._|self\._sources\._" backend/modules/interaction` 命中位置见上。
- **现有契约**：纯内部实现，无对外契约；测试大量 patch `tasks._workflow`/`service._repo`/`service._sources` 私有符号（test_tasks/test_services/test_sources），重构需同步测试桩。
- **最小方案**：第一步（无行为变化）：删除两份入队 helper 之一，统一调一处；把 overview/summary 共享谓词（`_overview_matches_path` 等纯函数族）提升为 generation.py 或独立模块的模块级函数，两个类共同引用。第二步（P3 裁定）：正式合并两类的职责边界（服务层权威 vs 任务执行权威），不做跨模块改动。
- **预期收益**：约 -30 行重复；概要/回顾行为变更传播点从 2 收敛到 1；类边界与实际耦合一致。
- **风险**：低（第一步）/中（第二步）。测试桩同步量大是主要实施成本；指纹/状态语义零变化。
- **依赖**：无外部依赖；与 F2-3（snapshot CM 收敛）无耦合（interaction 不在六处清单内，已自带 `create_project_snapshot_llm_client` 包装）。
- **验证命令/断言**：`rg -n "_enqueue_summary|_enqueue_overview_refresh" backend/modules/interaction` 归一；`make lint`；实施时 `make test TESTS="modules/interaction"`。
- **回滚**：单 commit revert（第一步）；第二步按类拆 commit。
- **裁定**：实施候选（第一步）；第二步归 P3 架构裁定。**优先级：P2**

- **版本推进**：`update_journey_source` 仅允许同作品（source_novel_id 相同）、不回退剧情位置、固定项 remap 失败即 Conflict"请新建旅程"；`source_context_epoch` 单调递增，进行中 attempt 的 source 读取按启动 epoch 失效（finalize 时 `source_context_stale` failed，test_sources.py:663）。

### 2. 提案确认流状态机（assistant 成组执行，链 7 的确认段）

- **生成段**：run `pending→running→(waiting_approval 若有 actions | completed | failed | cancelled | budget_exceeded)`。`execute` 内每个 provider/工具阶段经 checkpoint（run 行 FOR UPDATE + status==running + task_id 匹配 + owner 重验后 commit）；`model_history` 只存私有 checkpoint（终态/预算耗尽/停止即清除，公开响应不返回）。幂等：`operation_id`=run 主键，`request_hash` CAS（web_backend 缺省兼容双 hash）。
- **提案段**：`prepare_actions` 校验 capability∈catalog（运行期冻结 manifest 亦重验）、参数 schema、target_key 去重（同资产合并强制）、`depends_on` 拓扑排序（缺依赖/环→ValidationError）；每个 action 携带 `baseline_hash=fingerprint(preview)` 与 `operation_manifest`（schema_hash+revision）。
- **确认段**：`decide_batch`（FOR UPDATE）：① run.owner 校验；② `batch.fingerprint == decision.fingerprint` 否则 `assistant_batch_stale`；③ selected ⊆ actions；④ 已有 authorization 时 selected 集合必须一致（不同决定→`assistant_batch_decided`），retry 需新 operation_id 且记录进 `retries` 列表（同一回执重放直接返回旧结果，不重复写入）；⑤ 逐未完成操作 `operation.prepare` 重跑并比对 `baseline_hash`（资料变化→`assistant_source_stale`），per-operation `operation_manifest` 重新 `resolve_operations`（版本漂移拒绝）。
- **执行段**：每操作 `db.begin_nested()` 内 apply + `record_confirmed_write`（只冻结该写操作的真实目标后置状态：work 的 draft_id/source_hash 换新、被写目标 inspection 刷新；原 confirmation 与 source_guard 不替换）；DomainError→savepoint 回滚、标 failed、依赖它的操作标 blocked；结果分 `completed/failed/blocked`。终态 `partial`（有 failed）/`completed`/`declined`（未选任何）；run.status→completed。
- **恢复段**：partial 批次两条恢复路——`recheck_batch`（新建一轮查证运行，quoted_discussion 注入未完成项 JSON、保留原 work/excluded/web 授权，成功组不重做）与同批 `decide_batch(retry_operation_id=…)`（原 confirmation/guard 不替换重验）；`resume(renew_budget)` 用新 operation_id 重建运行并保留 web_backend 授权快照（缺 backend 标记的旧请求不继承 SearXNG）。提交侧写操作不在此流（suggest 工具 `execute_suggestion` 走领域子任务 inline，`_parent_task_id`+`inline_only`，失败保留领域部分回执）。
- **recheck 通知流（主动检查）**：`recheck_notice` 以 `recheck_operation_ids` 幂等（重放返回 queued/replayed）、活跃任务不重复执行、恢复 change_key（准备失败也可恢复）、重排 `mark_changed` 并受每日额度限制。

### 3. 预算与重试语义（链 7 计量段、链 6 RP 段）

- **AgentRunBudget**（infrastructure，F2 主审，此处记领域用法）：`reserve` 先于 provider I/O 并 checkpoint 持久化（断线/取消后旧 worker 不能改写）；`mode`：assistant 会话默认、`background`（主动检查）、`rp`（interaction）。web 子预算 `limits[2]`（web_requests 上限）+ `future_requests` 预留最终故事调用。预算耗尽→`AgentBudgetError`→assistant run `budget_exceeded`（保留讨论+过程资料+初步答案）。
- **assistant_turn**：manual_resume；同一 session 并发 run 互斥（`assistant_busy`）；失败 resume 需 task 未终态失效且预算有剩余，续额度走新 run（`continuation_of` 保留链）。
- **interaction story**：`restart_origin`（失败后由用户显式 retry，禁止自动重放，避免重复付费/幽灵 sibling）；同一 length attempt 至多续写一次（`continuation_count`，第二次截断直接落 selected partial）；账户 8 并发槽（owner 级 advisory 锁）；紧急整理在同一 attempt 内最多 4 pass（`_MAX_URGENT_SUMMARY_PASSES`），pass 间 fail-closed。
- **interaction summary_refresh**：auto_requeue max_attempts=2 + 应用层 `retry_with_backoff(max_attempts=2)`（仅瞬时连接类；schema 失效一次修复后不重试）；失败 latch 到 `journey.overview_failure`（path+epoch fence），显式 `retry_overview` 清除；崩溃恢复从最近已提交 coverage prefix 继续（segment/revision 同事务写入）。
- **主动检查执行**：`execute_review_task` 用 `workflow_budget`（工具准备/读取中的模型调用与最终生成同预算）+`asyncio.timeout(remaining_seconds)`；授权变化/关闭→下一模型请求前 fail-closed；新变化抑制旧通知（fresh 判定），部分成功只记真实回执。
- **RP agent**：v1/v2 冻结 policy（精确 dict 匹配，未知拒绝）；guard 每工具步校验 task fence+selection/source epoch+双侧 owner；工具响应/联网结果入故事前经 `remember`（排除项过滤）+`factual_result_allowed`/`search_snippet` 禁用；`asyncio.timeout(budget.remaining_seconds)` 包裹故事流，取消时不追加 checkpoint（租约已失）。
