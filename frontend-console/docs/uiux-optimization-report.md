# NovelCraft 前端 UI/UX 优化建议报告

> 视角：网文作者（日更 / 长周期创作场景）
> 版本：v2.0 前端当前实现
> 生成时间：2025-07-03

---

## 1. 全局架构与导航

### 当前设计概览

- **布局**：顶部状态栏（56px）+ 左侧图标导航（64px）+ 主工作区 + 右侧批注区（220~280px，可折叠）
- **路由**：10 个一级视图（项目 / 写作 / 世界 / 地图 / 检索 / 大纲 / 场景 / 生成 / 编译 / 设置）
- **主题**：浅色 Apple 极简风 + 杂志不对称排版，支持暗色模式
- **交互**：快捷键体系（`hjkl` Vim 风格、`n` 新建、`e` 编辑、`s` 保存、`g` 生成、`x` 删除）、底部命令栏（Spotlight 风格）

### 1.1 问题：视图入口过多，认知负荷高

**现状**：左侧导航有 10 个图标入口，对网文作者来说，核心路径是「写作 → 偶尔查设定/大纲 → 回来继续写」。10 个入口中，场景、生成、编译、检索对创作流程来说是低频但高认知成本的模块。

**网文作者心声**："我不是来管理系统的，我是来写字的。"

**建议**：

1. **引入「工作模式」概念**：
   - **写作模式**（默认）：只保留「写作」「世界」「大纲」三个入口，其他模块折叠进「更多 ▾」
   - **管理模式**（展开）：显示全部 10 个入口
   - 在设置页提供「默认模式」配置，让作者按需选择

2. **右侧批注区（`#contextual-notes`）目前为空**，建议将其变为「**写作副驾驶面板**」：
   - 在写作视图时，右侧自动显示当前 Scene 的关联设定（人物状态、地点、伏笔提醒）
   - 在世界视图时，右侧显示选中对象的关联关系预览
   - 在大纲视图时，右侧显示选中剧情线的章节覆盖度
   - 这样就不需要离开写作页面去查设定，心流不被打断

3. **导航图标增加文字说明**（当前只有 9px 小字标签）：
   - 新用户第一次看到「地图」和「场景」图标，很难区分其用途
   - 建议首次使用时显示导航引导气泡，或者鼠标 hover 时 tooltip 更详细

---

### 1.2 问题：状态栏信息密度不足

**现状**：顶部状态栏显示 `Logo · 项目名 · 模块名 · 状态 dot · 头像`，对创作者而言没有提供真正需要的状态信息。

**网文作者真正需要的状态**：
- 当前项目字数统计（总字数 / 今日字数）
- 保存状态（已保存 / 未保存 / 同步中）
- 当前章节进度（本章字数 / 目标字数）
- 后端连接状态（只在断连时提醒即可）

**建议**：

```
左侧:  Logo                    右侧:
       灵境行者 · 第47章         3,847字 / 本章  |  今日 4,200字  |  ✓ 已保存
```

- 当连接断开时，状态 dot 变红并 toast 提示即可，不需要常驻文字
- 增加「今日字数」自动统计（基于版本 diff），这对网文作者有极强的激励作用
- 鼠标悬停字数区时显示：总字数、章节数、预计剩余字数

---

### 1.3 问题：全局快捷键缺乏写作场景优化

**现状**：快捷键体系偏「开发者工具」风格（`j/k` 上下移动、`h/l` 左右切换区域）。网文作者在使用编辑器时，手指在键盘中央区域，不太会频繁按 `j/k` 进行导航。

**建议**：

1. **编辑器快捷键**（当前写作页没有绑定专用快捷键）：
   - `Ctrl/Cmd + Enter`：AI 生成草稿（基于当前上下文）
   - `Ctrl/Cmd + Shift + S`：发布章节
   - `Ctrl/Cmd + B`：快速查询选中文本在世界对象中的匹配（类似「边写边查」）
   - `Ctrl/Cmd + Shift + O`：打开大纲浮窗，不离开写作页

2. **快捷键帮助面板当前信息过载**：
   - 将快捷键按「写作时」「管理时」「全局」分组
   - 写作时只显示写作相关快捷键，降低认知负荷

## 2. 写作工作台（核心页面）

### 当前布局

```
+------------------------------------------+
| 左侧 Scene 树  | 中间编辑器  | 右侧场景面板 |
|  (200px)      | (flex)    |  (260px)   |
+------------------------------------------+
```

编辑器：450px 高 textarea，等宽字体，13px，行高 1.8

### 2.1 问题：编辑器体验像代码编辑器，不像写作工具

**现状**：
- 字体使用 `var(--font-mono)`（JetBrains Mono / SF Mono），这是代码编辑器的字体选择
- 文本区域高度固定 450px，对于网文作者一次写 3000~5000 字来说，需要频繁滚动
- 背景是灰色边框的 box，有「在网页表单里填表」的感觉
- 没有字数统计、没有段落计数、没有阅读时间估算

**网文作者的写作习惯**：
- 喜欢「全屏沉浸」或「页面模拟」的感觉（类似 Ulysses / Scrivener / 橙瓜）
- 需要实时看到字数，因为平台（起点、番茄等）有字数要求
- 写作时不需要代码字体，需要舒适的宋体/黑体/仿宋（中文排版）
- 长文本编辑时，「当前行高亮」很有帮助，但目前是 subtle 的灰色背景

**建议**：

1. **字体分层**：
   - 标题输入框：使用 `var(--font-ui)`（无衬线，用于操作）
   - 正文编辑器：使用 `var(--font-body)`（Noto Serif SC / 思源宋体），字号 16~18px，行高 1.8
   - 当前 `--font-mono` 只用于代码片段和版本号显示

2. **编辑器全屏/专注模式**：
   - 增加一个「专注模式」按钮，隐藏左右两侧面板和顶部栏，只保留编辑器 + 底部字数条
   - 专注模式下背景使用 `#FDFCF8`（宣纸色），更符合中文写作的心理预期
   - 专注模式可配置：保留 Scene 面板（悬浮形式）或完全隐藏

3. **字数实时统计条**：
   - 编辑器底部增加固定栏：`本章 3,847 字 | 段落 28 | 预计阅读 12 分钟`
   - 当字数达到常见平台阈值（2000/3000/5000）时，用 subtle 的彩色标记提醒
   - 今日字数 vs 目标字数（如设定日更 4000，则显示 3847/4000 的进度环）

4. **编辑器区域高度自适应**：
   - 改为 `min-height: 60vh`，让编辑器尽可能占据可用空间
   - 或者支持编辑器区域拖拽调整大小

5. **段落间视觉呼吸**：
   - 当前段落之间没有额外间距，长文本看起来是一整块
   - 在 `<p>` 之间增加 `margin-bottom: 1.2em`，让段落感更清晰

---

### 2.2 问题：左侧 Scene/章节树与写作流程不够贴合

**现状**：左侧是 Scene 树（ collapsible 分组），每个章节一行，带有复选框和删除按钮。复选框和批量操作在日常写作中几乎不用。

**网文作者的日常操作**：
- 快速切换上一章 / 下一章（继续写）
- 查看章节标题和状态（是否已发布、字数多少）
- 新建下一章（不需要选择多章批量删除）

**建议**：

1. **简化章节树**：
   - 去掉复选框，批量操作只在「项目管理」视图中提供
   - 每行显示：章节号 + 标题 + 字数 + 状态 dot（已发布/草稿/未写）
   - 增加「上一章 / 下一章」快速切换按钮（在编辑器顶部或底部）

2. **章节树增加写作进度可视化**：
   ```
   第1章  · 觉醒 ✓  (2,340字)
   第2章  · 测试 ⚪  (5,100字)
   第3章  · 危机 ✓  (3,200字)
   第4章  · 决战 ○  (未写)
   ```
   - `✓` = 已发布，`⚪` = 有草稿但未发布，`○` = 空白

3. **当前章节高亮更明显**：
   - 当前左侧使用 `border-left: 3px solid var(--accent)`，这很好
   - 但背景色 `var(--hover-bg)` 在浅色主题下几乎不可见
   - 建议增加更明显的背景色或轻微阴影

---

### 2.3 问题：右侧场景面板（Scene Cockpit）内容过载

**现状**：右侧显示 Scene 的关联信息（人物、地点、事件、势力、危机等），但所有内容挤在一个小卡片里，且用 `details/summary` 折叠。对于网文作者，写作时需要快速扫一眼设定参考，而不是逐个点开折叠面板。

**建议**：

1. **右侧面板改为「写作参考面板」**，采用 Tab 切换而非折叠：
   - **Tab 1 — 人物**：当前 Scene 出场人物列表，点击展开人物卡片（外貌、性格、当前状态）
   - **Tab 2 — 地点**：当前 Scene 地点的环境描述、关键物品
   - **Tab 3 — 设定**：时间线、世界观规则、需要注意的伏笔
   - **Tab 4 — 地图**：迷你地图缩略图 + 点击打开大地图

2. **人物卡片显示关键信息**：
   - 头像占位符（即使没有图片也可以有颜色块区分）
   - 当前状态标签（如：受伤、愤怒、秘密身份）
   - 与主角的关系（一句话）
   - 作者最近给这个人物设定的内容（倒序）

3. **增加「快速插入」功能**：
   - 在人物/地点卡片上增加「插入到正文」按钮，点击后在编辑器光标处插入该对象的名称（带格式标记）
   - 避免作者因为不确定角色名怎么写而中断思路去查

---

### 2.4 问题：版本管理和发布流程太工程化

**现状**：编辑器顶部有「暂存」「发布」「剧情设定冲突检查」按钮，以及版本选择器。对网文作者来说，「暂存」和「发布」的概念偏技术（Git 的 stage/commit 类比）。

**建议**：

1. **术语贴近网文平台**：
   - 「暂存」→「保存草稿」
   - 「发布」→「发布新版本」或「定稿」
   - 版本号 `v1/v2/v3` 保留，但增加时间标注（如 `v3 · 今天 14:32`）

2. **保存状态更直观**：
   - 当前「未保存」「已保存」「保存中...」文字在顶部右侧，很不起眼
   - 建议改为编辑器底部的进度条/状态 dot，更靠近作者视线
   - 未保存时，标题栏的章节名旁边增加 `*` 标记（如 `第47章 *`）

3. **冲突检查的结果展示更友好**：
   - 当前冲突检查显示为横向按钮条（`14:32 · 发现 3 个冲突`），点击后弹模态框
   - 建议改为：发现冲突时，在编辑器对应行旁边显示红色/黄色标记，hover 时显示具体问题
   - 或在右侧 Scene 面板增加「冲突提醒」Badge，让作者知道有东西要处理但不打断写作

---

### 2.5 问题：AI 工具菜单（AI 工具 dropdown）太技术化

**现状**：AI 工具菜单包含「AI 生成草稿」「场景自动提取」「世界对象自动提取」「剧情线自动提取」「AI 提取章节卡」「剧情设定冲突检查」「断章至此」「打开地图」。

**建议**：

1. **按创作阶段组织 AI 工具**：
   ```
   当前写作辅助
   ├── 续写本章（基于上下文 AI 生成后续）
   ├── 润色选中（对当前选中文本进行润色）
   ├── 检查设定一致性（当前章节）
   └── 查询人物状态（快速打开右侧人物面板）
   
   结构化辅助
   ├── 从本章提取场景（自动分析）
   ├── 提取世界对象（自动分析）
   └── 生成章节大纲卡
   ```

2. **「续写」功能前置**：
   - 网文作者最常用 AI 的场景是「卡文了，帮我续一段」
   - 建议增加一个更明显的「✨ 续写」按钮在编辑器工具栏（不仅仅是藏在 dropdown 里）
   - 续写结果以「建议」形式插入，作者可以一键接受或拒绝，而非直接替换全文

## 3. 项目页面（入口页）

### 当前设计

- 项目以卡片网格展示，支持创建、编辑、导入
- 导入区可折叠，有上传进度条
- 回收站以模态框展示

### 3.1 问题：项目卡片信息展示不够创作导向

**现状**：卡片显示：状态 dot + 题材标签 + 阶段标签 + 描述 + 创建时间 + 编辑/删除按钮。

**网文作者想一眼看到的信息**：
- 总字数（最重要的！）
- 已发布章节数 / 总章节数
- 最近写作时间（如「3小时前」）
- 连载状态（连载中 / 已完结 / 暂停）

**建议**：

1. **项目卡片增加写作统计**：
   ```
   ┌─────────────────────────────┐
   │  ● 灵境行者                │
   │  [仙侠] [连载中]           │
   │  黑暗幽默，都市异能        │
   │                             │
   │  347,200字  ·  142章      │
   │  今日 +2,400字            │
   │  最近写作：2小时前        │
   │                             │
   │  [编辑] [删除]             │
   └─────────────────────────────┘
   ```

2. **「最近写作」排序**：
   - 当前项目按创建时间排列，建议增加「最近活跃」排序
   - 网文作者通常同时有 2~3 个项目，最关心的是「我最近在写的那个」

3. **快速续写入口**：
   - 卡片上增加「继续写作」按钮（不是打开项目，而是直接进入写作页到最后编辑的章节）
   - 减少一次点击

---

### 3.2 问题：导入流程与项目创建耦合

**现状**：导入文件时自动创建项目，或者在项目页选择项目后导入。但导入后没有直接进入写作流程，而是停留在项目页。

**建议**：

- 导入完成后自动进入写作视图，并提示「是否启动深度导入？」
- 深度导入进度条在写作页底部显示（floating bar），作者可以一边写/看，一边等后台处理
- 当前「深度导入进度」在页面底部固定显示，这是好的，但建议增加「完成后自动提取世界对象」的一键确认

---

## 4. 世界对象页面

### 当前设计

- 子视图：对象库 / 候选清洗 / 关系 / 别名 / 地图
- 对象以表格展示，支持筛选、分页、批量操作
- 候选对象需要逐条确认处理方式

### 4.1 问题：表格形式不适合网文作者的「翻阅设定」需求

**现状**：对象库用 `data-table` 表格展示，字段有状态、类型、名称、来源、复核、重要度、摘要。对网文作者来说，「查设定」是高频场景，但不是「管理数据」的心态。

**建议**：

1. **对象库增加「卡片视图」切换**：
   - 表格视图适合管理（筛选、排序、批量）
   - 卡片视图适合浏览和查阅：大卡片展示名称、类型图标、一句话描述、关键属性
   - 卡片视图可以按类型分组（人物 / 地点 / 组织 / 物品）

2. **人物卡片增加头像/色块**：
   - 即使没有真实图片，也可以根据角色类型（主角/反派/配角）显示不同颜色头像
   - 人物卡片上直接显示「关系网」缩略（如：与主角的关系）

3. **「候选清洗」术语优化**：
   - 「候选」和「清洗」对网文作者来说太抽象
   - 建议改为「AI 发现的新设定」或「待确认的新角色/地点」
   - 处理方式标签：「创建新对象」「合并到已有」「忽略」「设为临时」
   - 增加「批量确认」（AI 建议创建新对象的，一键全部确认）

4. **搜索优化**：
   - 当前搜索框在筛选区，需要点击「应用」才执行
   - 建议增加全局搜索框（实时搜索），支持模糊匹配和别名匹配
   - 网文作者经常记不清角色全名，只记得「那个红头发的」或「简称」

---

### 4.2 问题：关系页过于技术化

**现状**：关系表显示 `source_id`（截断为 8 字符...）、relation_type、target_id（截断...）。网文作者看不懂 ID。

**建议**：

- 关系视图改为「关系图谱」的简化版：
  - 选中人物时，显示与之关联的人物和关系类型（如「朋友」「敌人」「师徒」）
  - 用颜色区分关系亲疏（红色 = 敌对，绿色 = 友好，灰色 = 中立）
  - 如果技术栈允许，小型的力导向图（D3.js 或 ECharts）比表格直观得多
- 至少，表格中显示对象名称而非 ID

---

## 5. 大纲页面

### 当前设计

- 子视图：场景工作台 / 剧情线 / 篇章纲 / 伏笔 / 揭示
- 以表格和卡片列表展示

### 5.1 问题：大纲与写作视图割裂

**现状**：大纲和写作是两个独立的视图。网文作者写的时候经常需要「看一眼大纲，再回来写」。当前切换需要点击导航、等待加载，心流中断。

**建议**：

1. **写作页增加「大纲浮窗」**：
   - 按 `Ctrl/Cmd + Shift + O` 或点击按钮，从右侧滑出大纲面板
   - 显示当前篇章的剧情线，当前 Scene 高亮
   - 点击大纲节点可以跳转到对应章节，但不离开写作视图（在新编辑器 tab 中打开）

2. **大纲页增加「去写这章」快捷入口**：
   - 在 Scene 卡片或剧情线节点上，增加「去写作」按钮，直接跳转到对应章节的写作视图
   - 当前已经有这种跳转能力，但入口不够明显

3. **伏笔/揭示状态更可视化**：
   - 当前伏笔状态用文字标签（已埋下 / 已触发 / 已兑现）
   - 建议改为时间线或状态条的形式，让作者一眼看到哪些伏笔还没回收
   - 例如：一个横向进度条，从「埋下」→「触发」→「兑现」，当前状态用高亮标记

---

### 5.2 问题：场景卡（Scene Card）与网文创作习惯不匹配

**现状**：Scene 以结构化卡片展示，有标签（draft, hook, inciting_incident, rising_action, climax, valley, transition, payoff）。这些标签偏编剧术语（如 `inciting_incident` 激励事件）。

**网文作者习惯的说法**：
- 不是「激励事件」，而是「转折点」「爽点」「压抑点」「爆发点」
- 网文的结构更多是：日常 → 矛盾 → 升级 → 高潮 → 收获 → 新地图

**建议**：

1. **标签本土化**：
   - 将 `hook` 译为「钩子/开篇吸引」
   - 将 `inciting_incident` 译为「矛盾触发」
   - 将 `rising_action` 译为「冲突升级」
   - 将 `climax` 译为「阶段高潮」
   - 将 `valley` 译为「低谷/压抑」
   - 将 `payoff` 译为「爽点/收获」
   - 增加网文特有的标签：「日常铺垫」「打脸反杀」「身份揭露」「情感线」

2. **Scene 卡片增加「情绪曲线」**：
   - 每个 Scene 标注一个「情绪值」（-5 到 +5），在大纲页以折线图展示整本书的情绪走势
   - 网文作者非常关心「情绪节奏」，这是防止读者流失的关键

---

## 6. 地图页面

### 当前设计

- 基于 Leaflet 的地图引擎
- 支持地形编辑、图层切换、场景关联
- 有动态摘要和回放功能

### 6.1 问题：地图与写作流程的衔接不够丝滑

**现状**：地图是一个独立的功能模块，作者需要切换到地图视图才能查看/编辑。但网文作者在写作时，经常需要「确认一下角色从 A 地到 B 地用了多久」「这个地点之前描述过什么」。

**建议**：

1. **写作页右侧 Scene 面板增加「迷你地图」**：
   - 显示当前 Scene 关联地点的位置，周围有标记
   - 点击迷你地图可以打开大地图（新 tab 或弹窗）
   - 不需要离开写作页就能确认地理信息

2. **地图增加「时间线模式」**：
   - 当前地图是空间视图，网文作者也关心「时间线视图」：角色在不同时间位于何处
   - 增加时间轴滑块，拖动时地图上显示角色在该时刻的位置
   - 这对处理多线叙事、确认时间线合理性非常有用

3. **地点卡片增加「出场记录」**：
   - 点击地图上的地点，除了显示描述，还显示「这个地点在第几章出场过」
   - 作者可以一键跳转到对应章节确认之前的描写

---

## 7. 生成中心与编译页面

### 当前设计

- 生成中心：选择类型（世界/剧情/章节）→ 输入意图 → 启动生成 → 查看结果
- 编译页面：配置上下文参数 → 编译 → 查看输出

### 7.1 问题：生成流程对作者不够透明

**现状**：生成中心有 6 步流程（输入意图 → 编译上下文 → 生成候选 → 预览结果 → 结构复查 → 确认写入正史），但作者看不到中间过程在做什么。

**建议**：

1. **增加「生成预览」步骤**：
   - 在「生成候选」完成后，不要直接弹最终结果，而是让作者先预览
   - 预览时支持：接受 / 修改 / 拒绝 / 重新生成
   - 当前 workflow 中已经有 candidate 状态，但 UI 上需要更明确的「确认/修改」入口

2. **生成结果与写作页直接关联**：
   - 生成章节卡后，在写作页左侧章节树显示「AI 建议：新增第 X 章」的提示
   - 生成世界对象后，在写作页右侧 Scene 面板显示「新发现：3 个角色」红点提醒

3. **编译页面增加「模板收藏」**：
   - 当前只有 3 个预设模板（生成剧情线、润色、冲突检查）
   - 作者经常需要重复执行类似的编译任务（如「每次润色都用 4000 tokens + 角色视角」）
   - 建议增加「保存为模板」功能，让作者自定义常用配置

---

## 8. 设置页面

### 当前设计

- LLM 供应商配置（模板选择、API Key、Base URL、模型、参数）
- 表单布局，两列网格

### 8.1 问题：设置页对网文作者不友好

**现状**：设置页展示大量技术参数（Temperature、Top P、Max tokens、Timeout、Extra JSON）。网文作者不懂这些参数的含义。

**建议**：

1. **参数预设包**：
   - 将参数打包为「创作模式」：
     - **创意模式**（高 temperature）：适合头脑风暴、生成剧情
     - **精确模式**（低 temperature）：适合润色、检查一致性
     - **快速模式**（小模型）：适合简单查询
   - 作者只需要选择模式，不需要调参数

2. **API Key 配置增加「测试连接」按钮**：
   - 当前保存后才知道是否可用
   - 增加「测试连接」按钮，显示延迟和可用性

3. **增加「作者偏好设置」**：
   - 默认日更目标字数（用于写作页字数统计）
   - 默认编辑器字体/字号
   - 是否开启专注模式（默认开启/关闭）
   - AI 辅助的侵入程度（被动提醒 / 主动建议 / 关闭）

## 9. 暗色模式与视觉疲劳

### 当前设计

- 暗色模式基于 `prefers-color-scheme` 自动切换，或手动设置
- 暗色背景 `#0B1120`，文字 `#E2E8F0`

### 9.1 问题：长时间写作的视觉疲劳

**建议**：

1. **增加「护眼模式」**：
   - 背景色 `#1a1a1a`（纯黑对比度太高），建议用 `#1e1e2e` 或 `#2b2b2b`
   - 文字色不要太白，用 `#c0c0c0` 或 `#d0d0d0`
   - 增加「纸张模式」：背景 `#f4f1ea`（米黄），文字 `#2c2c2c`，模拟实体书写作感

2. **编辑器增加行高和段距调节**：
   - 当前行高固定 1.8，但不同作者习惯不同（1.5 ~ 2.2）
   - 增加设置项，让作者自定义

3. **当前行高亮更明显**：
   - 当前 `active-line` 只有左边 3px 竖线和 subtle 灰色背景
   - 建议增加更柔和的高亮，或可选的「打字机模式」（当前行始终固定在屏幕中央）

## 10. 响应式与移动端

### 当前设计

- 响应式断点：900px、720px、600px
- 小屏幕下隐藏右侧面板、导航栏收缩、表格变为卡片列表

### 10.1 问题：移动端写作体验缺失

**现状**：600px 以下时，写作布局变为单列（左侧 Scene 树在上方，编辑器在中间，右侧面板在下方或隐藏）。但网文作者偶尔会在手机/平板上记录灵感或修改。

**建议**：

1. **移动端增加「快速记录」模式**：
   - 不是完整的三栏编辑器，而是全屏 textarea + 底部「保存为第 X 章草稿」
   - 适合通勤时记录灵感，回到电脑后继续编辑

2. **平板横屏优化**：
   - iPad 横屏（~1024px）目前显示的是 900px 断点样式，右侧面板被隐藏
   - 建议增加 `1024px` 断点，在平板横屏时保留三栏布局但缩小左右栏宽度

## 11. 总结：优先级排序

| 优先级 | 页面 | 优化项 | 影响 |
|--------|------|--------|------|
| **P0** | 写作 | 编辑器改为正文字体 + 全屏专注模式 | 核心体验，每天使用 |
| **P0** | 写作 | 实时字数统计 + 今日目标进度 | 网文作者刚需 |
| **P0** | 全局 | 右侧面板变为「写作副驾驶」（关联设定） | 减少心流中断 |
| **P1** | 写作 | 简化章节树（去掉复选框，增加字数/状态） | 高频操作 |
| **P1** | 写作 | AI 工具增加「续写」快捷按钮 | 核心 AI 场景 |
| **P1** | 项目 | 项目卡片增加字数统计 + 最近活跃 | 入口体验 |
| **P1** | 全局 | 状态栏增加字数/保存状态 | 信息感知 |
| **P2** | 世界 | 对象库增加卡片视图 + 头像 | 查阅体验 |
| **P2** | 大纲 | 增加大纲浮窗（不离开写作页） | 减少切换 |
| **P2** | 设置 | 参数预设包（创意/精确/快速模式） | 降低门槛 |
| **P3** | 地图 | 写作页迷你地图 | 辅助参考 |
| **P3** | 全局 | 护眼模式/纸张模式 | 长时间写作 |
| **P3** | 响应式 | 移动端快速记录模式 | 补充场景 |

## 12. 一句话设计原则

> **网文作者打开这个工具，应该感觉像打开一本自己正在写的书，而不是打开一个项目管理后台。**

- 减少管理感，增加沉浸感
- 减少切换操作，增加上下文关联
- 减少技术术语，增加创作语言
- 减少等待焦虑，增加进度感知
