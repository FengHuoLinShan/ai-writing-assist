## 新发现的优化点

### 1. 全局快速搜索（P0）

**问题**：网文作者的核心痛点是「快速找到一个角色/地点/章节」。当前只有 RAG 的「搜索测试」子视图，需要切换到检索页才能搜索，且结果偏技术化（向量片段、embedding 状态）。

**网文作者场景**：
- "我忘了那个反派角色叫啥了，只记得姓李" → 需要快速搜索
- "第37章主角在哪里？" → 需要跨章节搜索
- "我之前写过一个神器叫啥？" → 需要搜索世界对象

**建议**：

增加一个 **全局 Spotlight 搜索（`Cmd/Ctrl+K`）**，覆盖所有创作资产：

```
快捷键：Cmd/Ctrl + K
界面：从顶部中心滑下的搜索框（类似命令栏风格）
搜索范围：
  - 世界对象（人物、地点、物品）
  - 章节标题 + 内容摘要
  - 剧情线名称
  - 场景标题
  - 地图地点

结果分组显示：
  [人物] 李墨白 — 天玄宗掌门 · 第12章出场
  [地点] 墨白峰 — 天玄宗主峰 · 第12章
  [章节] 第12章 觉醒 — 3,200字
  [剧情线] 主线：天玄宗覆灭 — 覆盖 12-45章

回车直接跳转，Esc 关闭
```

**实现位置**：在 `index.html` 增加全局搜索 DOM，在 `app.js` 绑定 `Cmd/Ctrl+K` 快捷键，在 `commands.js` 中增加搜索命令。

### 2. 大纲浮窗快捷键绑定（P1）

**问题**：当前大纲浮窗有 UI 按钮（`writingView.js` 第 843 行），但标题写的是 `大纲浮窗 (Ctrl+Shift+O)`，实际上 `app.js` 的 `_bindKeyboard` 中没有绑定这个快捷键。

**建议**：在 `app.js` 第 517 行附近的快捷键 switch 中增加：

```javascript
case "O":
  if (e.shiftKey && (e.ctrlKey || e.metaKey)) {
    e.preventDefault()
    if (state.currentView === "writing" && typeof writingView?._toggleOutlineFloat === "function") {
      writingView._toggleOutlineFloat()
    }
  }
  break
```

### 3. 主题切换 UI 入口（P1）

**问题**：`styles.css` 已有 `[data-theme="dark-soft"]`（第 245 行）和 `[data-theme="paper"]`（第 267 行），但用户没有办法手动切换。当前只有 `prefers-color-scheme` 自动切换 light/dark。

**网文作者场景**：白天写作用 paper 模式，晚上切换到 dark-soft 模式。没有切换入口，用户只能改系统主题。

**建议**：

在顶部状态栏（`#topbar`）的 `.avatar` 左侧增加一个主题切换按钮：

```html
<!-- index.html 第 40 行附近 -->
<button id="theme-toggle" class="btn-icon" title="切换主题">
  <span id="theme-icon">&#9728;</span>
</button>
```

点击后弹出小菜单：
```
☀ 浅色（默认）
🌙 暗色
👁 护眼（柔和暗色）
📄 纸张（米黄）
```

选择后写入 `localStorage` 的 `novel_theme` 并即时生效。`app.js` 的 `_initTheme` 已经支持从 localStorage 读取。

### 4. 灵感速记/便签（P1）

**问题**：网文作者写作时经常突然想到：
- "这里后面要埋一个伏笔"
- "这个人物后面要背叛主角"
- "下一章需要交代这个设定"

这些灵感不能打断当前写作，否则心流就断了。当前没有快速记录的地方。

**建议**：

在写作页增加一个 **「灵感便签」浮窗**（类似大纲浮窗但更轻量）：

```
位置：编辑器右下角，一个小的 📝 图标按钮
点击后弹出 mini 浮窗：
  ┌─────────────────┐
  │ 灵感便签       │
  │ ─────────────── │
  │ 李墨白后面要背叛 │
  │ 主角，需要铺垫   │
  │                 │
  │ [人物] [地点]   │
  │ [伏笔] [其他]   │
  │                 │
  │ [保存]          │
  └─────────────────┘
```

保存后，这些便签在右侧 Scene Cockpit 的「设定」Tab 中显示，或者在专门的「便签」面板中展示。可以拖拽便签到编辑器插入为标记。

### 5. 章节字数目标（P1）

**问题**：当前只有全局「日更目标」，但网文作者每章通常有目标字数（如本章目标 3000 字）。当前底部字数条只显示「今日 X / 4000」，没有本章目标。

**建议**：

在底部字数条中增加本章目标：

```
本章 2,847 / 3,000 字  |  段落 28  |  阅读 12 分钟        今日 6,847 / 8,000
```

当字数接近目标时（80%），进度条变为黄色；达到目标时变为绿色，并显示 ✓ 标记。超出目标时继续统计，显示 `+X 字`。

在设置页的「作者偏好」中增加「默认章节字数目标」字段（默认 3000）。

---

### 6. 写作时间追踪（P2）

**问题**：网文作者关心「今天写了多久」。当前没有任何时间追踪。

**建议**：

在顶部状态栏字数仪表盘旁边增加「写作时间」：

```
第 47 章  |  3,847字 / 3,000  |  今日 6,847 / 8,000  |  今日已写 2小时32分
```

「今日已写」从第一次编辑器 focus 开始计时，blur 后 5 分钟内继续计时，超过 5 分钟暂停。数据保存在 localStorage，按天统计。

在设置页增加「每日目标写作时间」（默认 2 小时）。

增加「连续写作 30 分钟，建议休息」的 subtle 提醒（右下角 toast，非阻塞）。

### 7. 版本对比（Diff 视图）（P2）

**问题**：当前版本管理只有下拉选择器，网文作者改稿时不知道改了什么。需要「当前版本 vs 上一版本」的对比视图。

**建议**：

在版本选择器旁边增加「对比」按钮，点击后：

```
┌─────────────────────────────┐
│ 版本对比：v3 vs v2           │
│ ───────────────────────────── │
│ 新增：+1,234 字              │
│ 删除：-567 字                │
│ 修改：3 处                   │
│                             │
│ [第47章 觉醒]                │
│ v2: 主角站在山巅...         │
│ v3: 主角站在【天玄峰】巅...  │
│                             │
│ [第47章 冲突]                │
│ v2: 李墨白冷笑一声          │
│ v3: 李墨白【冷笑】一声      │
└─────────────────────────────┘
```

使用简单的文本 diff（行级对比）即可，不需要复杂算法。标记新增（绿色）、删除（红色）、修改（黄色）。

### 8. 导出功能（P2）

**问题**：没有导出功能。网文作者需要：
- 导出当前章节为 .txt 给编辑看
- 导出整本为 .txt 备份
- 导出大纲为 .md 分享给合作者

**建议**：

在写作页增加「导出」按钮（在发布按钮旁边）：

```
导出 ▾
  ├── 导出当前章节（.txt）
  ├── 导出整本（.txt）
  ├── 导出大纲（.md）
  └── 导出世界设定（.md）
```

前端直接生成文件，无需后端支持。整本导出时按章节顺序拼接，自动添加标题和分隔线。

### 10. RAG 检索体验升级（P2）

**问题**：当前 RAG 的「搜索测试」子视图是技术测试界面，不是作者日常使用的搜索工具。搜索框在页面底部，结果以技术卡片展示（片段、chunk、embedding 状态）。

**建议**：

将 RAG 搜索从「测试工具」升级为「创作助手搜索」：

1. **搜索框前置**：在检索页顶部增加大搜索框，类似 Google 的居中搜索框
2. **搜索范围选择**：默认搜索正文，可选搜索世界对象、大纲、地图
3. **结果卡片化**：
   ```
   ┌─────────────────────────────┐
   │ "天玄宗" 的搜索结果（3条）   │
   │                             │
   │ 📄 第12章 觉醒              │
   │    "天玄宗掌门李墨白站在..."│
   │    [跳转到章节]             │
   │                             │
   │ 👤 人物 · 李墨白            │
   │    "天玄宗掌门，主角的师父"  │
   │    [查看详情]               │
   │                             │
   │ 🗺 地点 · 天玄峰            │
   │    "天玄宗主峰，海拔..."    │
   │    [查看地图]               │
   └─────────────────────────────┘
   ```
4. **高亮上下文**：在结果中显示搜索词周围的文本，高亮关键词

### 11. AI 续写前端准备（P2）

**问题**：当前 AI 续写只有 disabled 的 placeholder 按钮。虽然后端接口没接，但前端可以先把 UI 和交互流程做好，等后端接口一接就能用。

**建议**：

将 placeholder 按钮改为实际按钮（去掉 disabled），点击后：

1. 在编辑器下方显示「AI 续写建议」面板（`ai-suggestion-panel` 的 DOM 已存在）
2. 显示 loading 状态（「正在分析上下文...」）
3. 如果后端返回 404/未实现，toast 提示「AI 续写功能即将上线」
4. 等后端接口 ready 后，只需替换 API 调用即可

这样用户不会感到「按钮永远点不了」，而是知道「正在开发中」。

**问题**：世界对象的关系页仍然是表格（`source_id` 截断显示），网文作者看不懂 ID。需要关系图谱。

**建议**：

在关系子视图增加一个「图谱视图」切换（与表格视图并列）：

```
[表格视图] [图谱视图]
```

### 13. 连续写作提醒（P3）

**问题**：网文作者经常久坐，没有健康提醒。当前没有任何休息提示。

**建议**：

在 `app.js` 中增加一个轻量的计时器：

```javascript
// 连续写作 30 分钟后，右下角显示 subtle toast
"已连续写作 30 分钟，建议站起来活动一下 🚶"

// 连续写作 60 分钟后，显示更明显的提醒
"已连续写作 1 小时，休息一下眼睛吧 👀"

// 可以关闭，设置页增加「关闭休息提醒」选项
```

Toast 不阻塞，3 秒后自动消失。只提醒一次，直到下次重新计时。

### 14. 批量操作残留（P3）

**问题**：`writingView.js` 第 798 行仍有 `_renderChapterBulkToolbar`，虽然视觉上章节树简化了，但代码中仍有「全选当前章节」和「批量删除章节」的按钮。这在日常写作中几乎不用，且占据空间。

**建议**：

将批量操作折叠进「更多 ▾」按钮，或者在非管理模式下完全隐藏。只在「管理视图」下显示批量操作。日常写作模式下，章节树只显示章节列表。

### 15. AI 工具菜单重新组织（P3）

**问题**：当前 AI 工具 dropdown 分类是「生成/提取/检查/地图」，对网文作者来说不够直观。

**建议**：

重新组织为「我现在需要什么」：

```
AI 助手 ▾
  当前写作
    ├── 续写本章（AI 生成后续）
    ├── 润色选中文本
    ├── 检查设定一致性
    └── 生成章节标题建议
  结构分析
    ├── 从本章提取场景
    ├── 提取世界对象
    └── 生成/更新大纲卡
  辅助工具
    ├── 打开地图
    ├── 断章至此
    └── 剧情设定冲突检查
```

这样作者按「当前状态」选择，而不是按「技术功能」选择。

|--------|--------|------|--------|

| **P1** | 灵感速记/便签 | 写作时记录灵感不中断心流 | 中（浮窗 + 存储） |
| **P1** | 章节字数目标 | 网文平台每章有字数要求 | 小（UI + 统计） |
| **P2** | 写作时间追踪 | 网文作者关心效率 | 小（计时器 + localStorage） |
